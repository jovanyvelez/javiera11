📊 SELECT: pidiendo datos a la BD

Misión 01 · Columnas, asterisco, COUNT, DISTINCT · ~35 min

El SELECT es el comando más usado de SQL — y el más versátil. Su trabajo es leer datos: decirle a la BD qué columnas quieres, de qué tabla, y (con WHERE) qué filas. Hoy lo llevamos a fondo: qué columnas pedir, cómo contar, cómo evitar duplicados.

🧩 Anatomía de un SELECT

La estructura del SELECT ya la vimos en la Clase 6, pero la repaso porque es el orden fijo que debes memorizar:

SQL — anatomía de un SELECT 
SELECT nombre, precio              -- 1. QUÉ columnas quieres ver
FROM   productos                    -- 2. DE QUÉ tabla
WHERE  precio > 30000               -- 3. QUÉ filas (filtro)
ORDER BY precio DESC;               -- 4. CÓMO ordenarlas

Las cláusulas van siempre en ese orden: SELECT → FROM → WHERE → ORDER BY → LIMIT. Olvidarlo es el error #1 de principiantes.

🌟 El asterisco: todas las columnas a la vez

El * significa «todas las columnas». Es útil para explorar una tabla que no conoces, pero en producción conviene listar las columnas que necesitas:

SQL — SELECT * vs SELECT columnas 
-- ✅ Explorar: trae todas las columnas (útil al principio)
SELECT * FROM productos;

-- ✅ Producción: pide sólo lo que necesitas (más rápido y claro)
SELECT nombre, precio FROM productos;

🦹 El villano: "SELECT * en producción"

SELECT * trae todas las columnas, incluyendo las que no necesitas (fechas internas, IDs de auditoría, blobs grandes…). En una tabla con millones de filas, eso es ancho de banda y memoria desperdiciados. Regla: en código real, lista las columnas. SELECT * se reserva para explorar a mano en psql.

🔢 COUNT: contar filas sin traerlas

Una de las consultas más comunes: «¿cuántos productos hay?». No necesitas traerlos todos — le pides a la BD que los cuente y te devuelva un solo número:

SQL — COUNT(*) 
-- ¿Cuántos productos hay en total?
SELECT COUNT(*) FROM productos;

-- ¿Cuántos productos tienen precio mayor a 30000?
SELECT COUNT(*) FROM productos WHERE precio > 30000;

El COUNT(*) cuenta todas las filas (incluyendo las que tienen NULL). Si quieres contar sólo los no-nulos de una columna: COUNT(correo) cuenta cuántas filas tienen un correo registrado (no NULL).

🔀 DISTINCT: elimina duplicados

A veces quieres saber qué valores distintos hay en una columna, sin repetidos. Por ejemplo: ¿qué categorías tienen productos en stock?

SQL — DISTINCT 
-- ¿Qué categorías (sin repetir) tienen productos?
SELECT DISTINCT categoria_id FROM productos;

-- Combina con WHERE: categorías de productos activos
SELECT DISTINCT categoria_id FROM productos WHERE activo = TRUE;

💡 DISTINCT vs COUNT

SELECT DISTINCT categoria_id te muestra los valores distintos (1, 2, 3, 4). SELECT COUNT(DISTINCT categoria_id) te dice cuántos valores distintos hay (4). El primero lista; el segundo cuenta. Elige según lo que necesites.

🎯 WHERE: filtrando filas

Misión 02 · Operadores de comparación · AND / OR / NOT · ~35 min

El WHERE es el filtro del SELECT: le dice a la BD qué filas quieres, descartando las que no cumplen la condición. Sin WHERE, SELECT trae todas las filas de la tabla. Con WHERE, trae sólo las que te interesan. Es la diferencia entre leer 10 productos y leer 10 millones.

⚖️ Operadores de comparación

Los operadores básicos comparan una columna con un valor. Son los mismos que en cualquier lenguaje:

OperadorSignificadoEjemplo
=Igual aWHERE categoria_id = 1
<> o !=Distinto deWHERE precio <> 45000
>Mayor queWHERE precio > 30000
<Menor queWHERE stock < 10
>=Mayor o igual queWHERE precio >= 20000
<=Menor o igual queWHERE stock <= 5
SQL — WHERE con operadores 
-- Productos que cuestan más de 30000
SELECT nombre, precio FROM productos WHERE precio > 30000;

-- Productos de la categoría 1 (Alimentos)
SELECT nombre FROM productos WHERE categoria_id = 1;

-- Productos inactivos (activo = FALSE)
SELECT nombre FROM productos WHERE activo = FALSE;

💡 Los strings van entre comillas simples

Los valores numéricos van sin comillas (WHERE precio = 45000), pero las cadenas van entre comillas simples (WHERE nombre = 'Croquetas'). Las comillas dobles son para identificadores, no para valores. Y cuidado: '45000' (con comillas) es un string, no un número — la comparación puede dar resultados raros.

🔗 Combinando condiciones: AND, OR, NOT

Rara vez filtrarás por una sola condición. AND exige que ambas se cumplan; OR basta con que se cumpla cualquiera; NOT niega la condición:

SQL — AND, OR, NOT 
-- AND: productos de Alimentos (cat 1) Y con precio mayor a 40000
SELECT nombre FROM productos
WHERE categoria_id = 1 AND precio > 40000;

-- OR: productos de Higiene (cat 3) O Juguetes (cat 4)
SELECT nombre FROM productos
WHERE categoria_id = 3 OR categoria_id = 4;

-- NOT: productos que NO son de la categoría 1
SELECT nombre FROM productos
WHERE NOT categoria_id = 1;

📐 Precedencia: AND tiene más prioridad que OR

SQL evalúa NOT primero, luego AND, y por último OR. Esto significa que A OR B AND C se lee como A OR (B AND C), no como (A OR B) AND C. Si quieres forzar el otro orden, usa paréntesis:

SQL — paréntesis para forzar agrupación 
-- Sin paréntesis: AND se evalúa primero
-- categoria_id = 1 OR (categoria_id = 2 AND precio > 40000)
SELECT nombre FROM productos
WHERE categoria_id = 1 OR categoria_id = 2 AND precio > 40000;

-- Con paréntesis: (categoria_id = 1 OR categoria_id = 2) AND precio > 40000
SELECT nombre FROM productos
WHERE (categoria_id = 1 OR categoria_id = 2) AND precio > 40000;

🦹 El villano: "WHERE con tipos que no coinciden"

Si comparas un string con un número (WHERE precio = '45000'), PostgreSQL puede hacer una conversión implícita y funcionar… o no. La regla: compara números con números y strings con strings. WHERE precio = 45000 (sin comillas) es correcto; WHERE nombre = 45000 fallará porque nombre es texto. Conocer los tipos de tus columnas (Clase 6) te ahorra errores misteriosos.

🧮 Operadores avanzados del WHERE

Misión 03 · LIKE · BETWEEN · IN · IS NULL · ~40 min

Los operadores de comparación (=, >, <…) son útiles, pero a veces necesitas filtros más expresivos: «productos cuyo nombre contiene "Gato"», «productos con precio entre 10000 y 30000», «productos de las categorías 3 o 4 o 5». Para eso existen LIKE, BETWEEN, IN e IS NULL.

🔍 LIKE: patrones de texto

LIKE compara strings con un patrón que usa dos comodines:

  • % — secuencia de cero o más caracteres (como * en glob).
  • _ — exactamente un carácter (como ? en glob).
SQL — LIKE con patrones 
-- Nombres que EMPIEZAN por 'C' (Croquetas, Comida, Collar, Cama, Cepillo...)
SELECT nombre FROM productos WHERE nombre LIKE 'C%';

-- Nombres que CONTIENEN 'Gato' (Comida Gato, Croquetas Gato)
SELECT nombre FROM productos WHERE nombre LIKE '%Gato%';

-- Nombres que TERMINAN por 'Goma'
SELECT nombre FROM productos WHERE nombre LIKE '%Goma';

-- Nombres de exactamente 5 letras que empiezan por 'C' (C_+_+_+_+_: no aplica aquí)
SELECT nombre FROM categorias WHERE nombre LIKE 'A_c_s%'; -- Accesorios

💡 LIKE es case-insensitive en el playground (pero no siempre)

En el playground de esta clase, LIKE es insensible a mayúsculas/minúsculas (como en PostgreSQL por defecto con acentos). En algunas BD (MySQL con collation binario) LIKE sí distingue. Si necesitas una búsqueda sin distinguir mayúsculas en un motor estricto, usa ILIKE (PostgreSQL) o LOWER(col) LIKE '%gato%'.

🦹 El villano: "LIKE sin %"

WHERE nombre LIKE 'Gato' (sin %) sólo coincide con el nombre exactamente igual a «Gato». Olvidar el % es el error #1 de LIKE: pensabas buscar «los que contienen Gato» y no te devuelve nada porque ningún producto se llama sólo «Gato». Si quieres contener, usa '%Gato%'; si quieres empezar por, 'Gato%'.

📏 BETWEEN: filtrar por rango

BETWEEN es un atajo para «mayor o igual que X AND menor o igual que Y». Incluye los dos extremos:

SQL — BETWEEN 
-- Productos con precio entre 10000 y 30000 (inclusive)
SELECT nombre, precio FROM productos
WHERE precio BETWEEN 10000 AND 30000;

-- Equivale a:
SELECT nombre, precio FROM productos
WHERE precio >= 10000 AND precio <= 30000;

BETWEEN también funciona con fechas: WHERE fecha BETWEEN '2026-01-01' AND '2026-12-31'.

📋 IN: comparar contra una lista

IN verifica si el valor está en una lista. Es un atajo para varios OR:

SQL — IN 
-- Productos de las categorías 3 o 4 (Higiene o Juguetes)
SELECT nombre FROM productos
WHERE categoria_id IN (3, 4);

-- Equivale a:
SELECT nombre FROM productos
WHERE categoria_id = 3 OR categoria_id = 4;

-- IN con strings: productos con estos nombres exactos
SELECT nombre FROM productos
WHERE nombre IN ('Pelota de Goma', 'Ratón de Juguete');

🌑 IS NULL: trabajar con ausencia

NULL significa «sin valor» o «desconocido» (Clase 6). No es lo mismo que 0 ni que '' (string vacío). Para filtrar por NULL no puedes usar = — tienes que usar IS NULL o IS NOT NULL:

SQL — IS NULL / IS NOT NULL 
-- Clientes que NO tienen teléfono registrado (NULL)
SELECT nombre FROM clientes WHERE telefono IS NULL;

-- Clientes que SÍ tienen teléfono
SELECT nombre FROM clientes WHERE telefono IS NOT NULL;

-- ⚠️ Esto NO funciona (NULL no se compara con =)
SELECT nombre FROM clientes WHERE telefono = NULL; -- devuelve 0 filas

🧠 ¿Por qué NULL no se compara con =?

Porque NULL no es un valor: es la ausencia de valor. Decir telefono = NULL es como preguntar «¿es la nada igual a la nada?» — la respuesta no es «sí» ni «no», es «no se sabe». SQL lo trata como NULL (que no es TRUE), así que la fila no pasa el filtro. Por eso existe IS NULL: es la forma correcta de preguntar «¿este valor es nulo?».

↕️ ORDER BY: ordenando los resultados

Misión 04 · ASC / DESC · Multicolumna · LIMIT · ~30 min

Por defecto, las filas que devuelve un SELECT vienen en un orden impredecible (el que PostgreSQL decida según sus índices). Si necesitas un orden garantizado — los más caros primero, alfabético, por fecha — tienes que pedirlo explícitamente con ORDER BY. Y si sólo quieres los primeros N, usas LIMIT.

🔼🔽 ASC y DESC

ORDER BY columna ASC ordena de menor a mayor (ascendente). ORDER BY columna DESC ordena de mayor a menor (descendente). Si omites la dirección, el default es ASC:

SQL — ORDER BY ASC / DESC 
-- Los 3 productos más caros (mayor a menor)
SELECT nombre, precio FROM productos
ORDER BY precio DESC
LIMIT 3;

-- Los productos por nombre, alfabético (A a Z)
SELECT nombre FROM productos
ORDER BY nombre ASC;  -- ASC es el default, se puede omitir

💡 LIMIT va siempre después de ORDER BY

El orden de cláusulas es SELECT → FROM → WHERE → ORDER BY → LIMIT. Si pones LIMIT antes de ORDER BY, PostgreSQL te dará un error de sintaxis. LIMIT recorta las filas ya ordenadas: por eso «los 3 más caros» funciona — primero ordenas por precio descendente, y luego tomas los primeros 3.

🔀 ORDER BY multicolumna

Puedes ordenar por varias columnas: la primera es el criterio principal, la segunda es el desempate, y así sucesivamente. Cada columna puede tener su propia dirección:

SQL — ORDER BY multicolumna 
-- Ordena por categoría (ASC) y, dentro de cada categoría, por precio (DESC)
SELECT nombre, categoria_id, precio FROM productos
ORDER BY categoria_id ASC, precio DESC;

Así obtienes los productos agrupados por categoría (1, 2, 3, 4) y, dentro de cada grupo, del más caro al más barato. Es como ordenar una biblioteca: primero por sección (ASC), luego por autor (ASC), luego por año (DESC).

🦹 El villano: "resultados en orden aleatorio"

Sin ORDER BY, no hay garantía sobre el orden de las filas. Puede parecer que vienen ordenadas por id (porque PostgreSQL las lee en ese orden), pero eso es coincidencia: si se borra una fila y se reinserta, el orden puede cambiar. Si tu app depende del orden (una lista paginada, un top 10, un ranking), siempre escribe ORDER BY. Dejarlo al azar es un bug invisible que estalla en producción.

✂️ LIMIT: sólo los primeros N

LIMIT recorta el resultado a un número máximo de filas. Combinado con ORDER BY, es la forma de hacer «top N» y «últimos N»:

SQL — LIMIT para top N 
-- Los 5 productos más baratos
SELECT nombre, precio FROM productos
ORDER BY precio ASC
LIMIT 5;

-- El producto más caro (top 1)
SELECT nombre, precio FROM productos
ORDER BY precio DESC
LIMIT 1;

🛡️ ¿Dónde se usa esto en la vida real?

«Los 10 productos más vendidos», «los 5 clientes con más compras», «las últimas 20 órdenes», «el top 3 de cada categoría» — todos son ORDER BY ... DESC LIMIT N. Las apps de redes sociales (feed), e-commerce (recomendaciones) y dashboards (métricas) viven de este patrón. Es, literalmente, una de las consultas más útiles que existen.

📦 Taller entregable: "Biblioteca online"

Misión 06 · Caso end-to-end: consulta los datos de una biblioteca · ~50 min

Taller final · Entregable Sistema de consultas para la biblioteca "Letras Voladoras"

La biblioteca Letras Voladoras ya tiene su BD montada con libros, autores y prestamos. El bibliotecario te pide consultas para responder las preguntas que le hacen los estudiantes todos los días. La entrega es un archivo SQL .sql con 6 consultas que respondan cada pregunta, ejecutable en PostgreSQL sin errores.

📋 Enunciado

Letras Voladoras tiene tres tablas:

  • autores(id PK, nombre, pais)
  • libros(id PK, titulo, autor_id FK → autores.id, anio, categoria, prestado BOOLEAN)
  • prestamos(id PK, libro_id FK → libros.id, lector, fecha_prestamo, fecha_devolucion)

El bibliotecario necesita responder estas 6 preguntas con SELECT:

  1. ¿Cuántos libros hay en total?
  2. ¿Qué libros contienen la palabra "SQL" en el título?
  3. ¿Qué libros fueron publicados entre 2010 y 2020?
  4. ¿Cuáles son los 5 libros más antiguos?
  5. ¿Qué libros están en la categoría "Programación" o "Bases de Datos"?
  6. ¿Qué libros no están prestados (prestado = FALSE) y están en "Programación"?

🎯 Objetivos del entregable

Tu entrega, en pareja, debe contener seis consultas dentro de un único archivo .sql, una por pregunta. Cada consulta debe usar al menos uno de los operadores de hoy (WHERE, LIKE, BETWEEN, IN, ORDER BY, LIMIT, COUNT). Al final, una reflexión en un bloque de comentarios.

1 ¿Cuántos libros hay? (COUNT)

Escribe un SELECT COUNT(*) para saber cuántos libros tiene la biblioteca. No necesitas WHERE.

-- Pregunta 1: ¿Cuántos libros hay en total?
SELECT COUNT(*) FROM libros;

2 Libros con "SQL" en el título (LIKE)

Usa LIKE '%SQL%' para encontrar los libros que contienen la palabra "SQL" en el título (sin importar mayúsculas/minúsculas).

-- Pregunta 2: Libros con "SQL" en el título
SELECT titulo, anio FROM libros
WHERE titulo LIKE '%SQL%';

3 Libros entre 2010 y 2020 (BETWEEN)

Usa BETWEEN 2010 AND 2020 sobre la columna anio. Ordena por anio DESC para ver los más recientes primero.

-- Pregunta 3: Libros publicados entre 2010 y 2020
SELECT titulo, anio FROM libros
WHERE anio BETWEEN 2010 AND 2020
ORDER BY anio DESC;

4 Los 5 libros más antiguos (ORDER BY + LIMIT)

Ordena por anio ASC (de menor a mayor) y limita a 5. Los más antiguos son los de menor año.

-- Pregunta 4: Los 5 libros más antiguos
SELECT titulo, anio FROM libros
ORDER BY anio ASC
LIMIT 5;

5 Libros de Programación o Bases de Datos (IN)

Usa IN ('Programación', 'Bases de Datos') sobre la columna categoria (recuerda: strings entre comillas simples).

-- Pregunta 5: Libros de Programación o Bases de Datos
SELECT titulo, categoria FROM libros
WHERE categoria IN ('Programación', 'Bases de Datos');

6 Libros no prestados de Programación (AND)

Combina dos condiciones con AND: prestado = FALSE Y categoria = 'Programación'. Ordena por titulo ASC.

-- Pregunta 6: Libros no prestados de Programación
SELECT titulo FROM libros
WHERE prestado = FALSE AND categoria = 'Programación'
ORDER BY titulo ASC;

Nota: prestado = FALSE también se puede escribir NOT prestado o prestado IS FALSE.
