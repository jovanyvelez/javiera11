📦 def: tu primera función

⏱️ 35 minutos · "Una receta con nombre: le das ingredientes, te da un plato"

🧠 La idea central

Una función es un bloque de código con nombre que puedes ejecutar (llamar) cuantas veces quieras. Tú ya venías usando funciones: print(), len(), input(), conn.fetch()… todas son funciones que alguien más escribió. Hoy pasas al otro lado: tú las escribes. La palabra clave es def — definir — y tiene 4 piezas:

anatomía de una función — las 4 piezas 
def calcular_multa(dias_atraso):          # 1️⃣ def + nombre + (parámetros)
    """Calcula la multa de un préstamo atrasado."""   # 2️⃣ docstring: qué hace
    tarifa_por_dia = 500                   # 3️⃣ cuerpo: la lógica
    return dias_atraso * tarifa_por_dia   # 4️⃣ return: la salida

# Llamarla (ejecutarla) — aquí sí pasa algo:
multa = calcular_multa(3)       # multa = 1500
print(calcular_multa(7))       # 3500

💡 Definir no es ejecutar

Entre def y el final, la función no se ejecuta: solo queda registrada con su nombre. El código de adentro corre cada vez que la llamas con paréntesis: calcular_multa(3). Olvidar los paréntesis es el error #1: calcular_multa sin () es "la receta"; con () es "cocinar el plato". 🍳

🦹 Villano: el número mágico

Ver esto regado por el código: multa = dias * 500, recargo = 500 * 0.1, tope = 500 * 30… ¿Qué es ese 500? ¿Pesos? ¿Días? ¿La altura de un edifico? Y peor: si la tarifa sube, hay que cazarlo en 20 lugares. La función con su tarifa_por_dia = 500 nombrado (o una constante TARIFA_POR_DIA = 500 en mayúsculas, arriba del archivo) mata al villano: un nombre que explica, un lugar que cambia.

constantes + funciones — el dúo profesional 
# Arriba del archivo: constantes del negocio, en MAYÚSCULAS
TARIFA_POR_DIA = 500
MAX_DIAS_PRESTAMO = 15

def calcular_multa(dias_atraso: int) -> int:
    """Multa = días de atraso × tarifa. 0 días → $0."""
    if dias_atraso <= 0:
        return 0
    return dias_atraso * TARIFA_POR_DIA

# Type hints: pistas de qué entra (int) y qué sale (int)
# No son obligatorios, pero FastAPI los usa para validar y documentar 😉

📦 Funciones que ya usabas sin saberlo

Todo lo que llamabas con () en tus clases anteriores era una función. Mira el patrón:

mismas piezas, distintas funciones — todas las conoces 
# Python integradas ("builtin"):
longitud = len("biblioteca")           # parámetro: un string → retorno: 11

# De asyncpg — funciones (métodos) de tu conexión:

# De FastAPI — la propia app es un objeto con funciones:
app = FastAPI()                       # crear la app: una llamada más

💡 Cómo nombrar una función (para que se lea como prosa)

  • Verbos + objeto, en minúsculas con guion bajo: calcular_multa, formatear_dinero, validar_isbn.
  • El nombre debe responder ¿qué hace? sin abrir el código. Si necesitas un comentario para explicarlo, el nombre está mal.
  • Una función = una tarea. Si el nombre necesita la palabra "y" (calcular_y_guardar), son dos funciones.
  • Máximo ~20 líneas por función. ¿Más? Huele a que hay dos tareas adentro.

🔌 Parámetros: la entrada de tu función

⏱️ 35 minutos · "La misma receta, distintos ingredientes"

🧠 La idea central

Los parámetros son las variables que la función recibe en su definición; los argumentos son los valores concretos que le pasas en cada llamada. Es la diferencia entre la receta ("necesito harina y huevos") y cocinarla ("200 g de harina, 3 huevos"). Gracias a los parámetros, una misma función sirve para mil casos distintos: calcular_multa(3), calcular_multa(7), calcular_multa(0)…

posicionales, nombrados y valores por defecto 
def formatear_dinero(valor: int, simbolo: str = "$") -> str:
    """Pinta 3500 como '$3.500' (o con el símbolo que pidan)."""
    return f"{simbolo}{valor:,}".replace(",", ".")

# 1. Posicional: el orden manda
print(formatear_dinero(3500, "€"))       # €3.500 — valor→valor, "€"→simbolo

# 2. Nombrado: el nombre manda (¡orden libre!)
print(formatear_dinero(simbolo="€", valor=3500))   # €3.500

# 3. Por defecto: si no lo envían, se usa el predefinido
print(formatear_dinero(3500))           # $3.500 — simbolo tomó "$" solo

🦹 Villano: el mutable default (la trampa clásica)

¿Recuerdas que simbolo = "$" se evaluaba una vez? Si el valor por defecto es una lista o un dict (mutables), esa misma lista se comparte entre TODAS las llamadas que no la envíen — y lo que una llamada appendea, ¡la siguiente lo ve! 😱 Regla de oro: defaults mutables = NO. Usa None y crea la lista adentro:

la trampa del mutable default — verla para creerla 
# ❌ VILLANO: la misma lista para todos
def registrar_prestamos(nuevo, prestamos=[]):        # ¡trampa!
    prestamos.append(nuevo)
    return prestamos

registrar_prestamos("Ana")      # ['Ana']
registrar_prestamos("Brayan")    # ['Ana', 'Brayan'] ← ¿¡Por qué Ana sigue ahí!?

# ✅ HEROE: None + crear adentro
def registrar_prestamos(nuevo, prestamos=None):
    if prestamos is None:
        prestamos = []                     # lista fresca en CADA llamada
    prestamos.append(nuevo)
    return prestamos

🏠 ¿Dónde vive esto? 🐍 Python🚀 FastAPI

Aquí viene el "ajá" de la clase: los parámetros de una ruta FastAPI son los parámetros de una función normal. El decorador @app.get(...) solo registra la función como ruta; lo que llega en la URL o en el body, FastAPI te lo pasa como argumentos:

FastAPI: los parámetros de la ruta = parámetros de la función 
from fastapi import FastAPI, Depends

app = FastAPI()

# path parameter: lo que va en /prestamos/3 → llega como prestamo_id=3
@app.get("/prestamos/{prestamo_id}")
async def ver_prestamo(prestamo_id: int):
    #                 ^^^^^^^^^^^ parámetro de función normal y corriente
    return {"id": prestamo_id, "multa": calcular_multa(prestamo_id)}

# query parameter: /multas?dias=7&formato=pdf → llega como argumentos
@app.get("/multas")
async def ver_multas(dias: int = 0, formato: str = "json"):
    #              ^^^ valor por defecto: si la URL no trae ?dias=, llega 0
    return {"dias": dias, "formato": formato, "total": calcular_multa(dias)}

# ¡Es la MISMA mecánica que aprendiste arriba! Solo cambia quién llama:
# en la terminal la llamas tú; en FastAPI la llama el framework.

💡 ¿Parámetro o argumento? (vocabulario fino)

  • Parámetro: el nombre en la definición. def f(simbolo="$") — simbolo es parámetro.
  • Argumento: el valor concreto en la llamada. f("€") — "€" es argumento.
  • En la práctica se mezclan, pero saberlo te hace sonar pro en la sustentación. 😎

📤 Retorno: la salida de tu función

⏱️ 35 minutos · "No me digas 'lo imprimí': devuélvemelo"

🧠 La idea central

El return es lo que la función le devuelve a quien la llamó. Sin return, la función hace cosas… pero el resultado se pierde (técnicamente devuelve None). Con return, el resultado vive en una variable y puedes reutilizarlo, pasarlo a otra función, mandarlo al contexto de una plantilla o — en FastAPI — convertirlo en la respuesta HTTP.

return vs print — la diferencia que separa a los pros 
# ❌ VILLANO: calcula y "devuelve" imprimiendo
def mostrar_multa(dias_atraso):
    print(dias_atraso * 500)

total = mostrar_multa(3)       # imprime 1500… pero total = None 😱
# No puedes sumarlo, mandarlo al contexto, ni reutilizarlo. Se perdió.

# ✅ HEROE: calcula y devuelve
def calcular_multa(dias_atraso):
    return dias_atraso * 500

total = calcular_multa(3)          # total = 1500: reutilizable ✨
suma  = calcular_multa(3) + calcular_multa(7)   # 5000

🦹 Villano: la función que hace de todo

Una función que calcula, imprime y guarda en la BD a la vez no se puede reutilizar: cada vez que la llamas hace las tres cosas quieras o no. Una función, una tarea: calcular_multa solo calcula y devuelve; quien la llama decide qué hace con el resultado (imprimirlo, guardarlo, sumarlo). Por eso las funciones que retornan se componen como piezas de LEGO. 🧱

📦 Volver varios valores: la tupla

¿Y si necesitas devolver dos cosas? Python lo hace fácil: el return puede llevar varias expresiones separadas por coma — y quien llama puede desempaquetarlas:

retorno múltiple + desempaquetado 
def analizar_prestamo(dias_atraso):
    """Devuelve la multa y si está atrasado."""
    atrasado = dias_atraso > 0
    return dias_atraso * 500, atrasado        # retorna una tupla (1500, True)

multa, atrasado = analizar_prestamo(3)   # desempaquetado en 2 variables
print(multa, atrasado)                                  # 1500 True

# ¿Recuerdas del módulo 5 de la clase 9? ¡enumerate hace esto mismo!
for posicion, prestamo in enumerate(prestamos, start=1):
    ...  # cada vuelta desempaqueta una tupla (posicion, prestamo)
early return — validaciones que cortan temprano 
def calcular_multa(dias_atraso):
    """Multa de un préstamo. Casos raros resueltos PRIMERO."""
    if dias_atraso is None:       # caso raro 1: sin dato
        return 0
    if dias_atraso <= 0:         # caso raro 2: a tiempo (o negativo)
        return 0
    # camino feliz: el código principal queda plano, sin indentar
    return dias_atraso * TARIFA_POR_DIA

# Ojo: return CORTA la función en seco. Todo lo que sigue, no corre.

🏠 ¿Dónde vive esto? 🐍 Python🚀 FastAPI

En FastAPI, lo que tu ruta retorna es literalmente la respuesta que viaja al navegador como JSON (o HTML, si retornas un TemplateResponse). Cuando devuelves un dict, FastAPI lo convierte a JSON por ti. Otra vez: misma mecánica de función, el framework hace el resto.

el retorno de la ruta ES la respuesta HTTP 
# Retornas un dict → el navegador recibe JSON:
@app.get("/api/prestamos/{prestamo_id}")
async def ver_prestamo(prestamo_id: int):
    return {
        "id": prestamo_id,
        "multa": calcular_multa(7),          # ← reutilizando tu función 😉
        "estado": "atrasado",
    }
# → GET /api/prestamos/3 responde: {"id":3,"multa":3500,"estado":"atrasado"}

# Retornas un TemplateResponse → el navegador recibe HTML pintado:
@app.get("/prestamos")
async def listar_prestamos(request: Request):
    contexto = {"prestamos": filas, "total": len(filas)}
    return templates.TemplateResponse(request, "prestamos.html", context=contexto)

💡 Tipos de retorno con type hints

  • def calcular_multa(dias: int) -> int: — "entra entero, sale entero".
  • -> str, -> bool, -> list, -> dict — FastAPI los lee para documentar y validar automáticamente.
  • Función sin return explícito → devuelve None (en FastAPI eso sería una respuesta vacía: evítalo).
  • return sin nada al lado también corta la función y devuelve None.

💡 ¿Sabías que…?

La palabra return tiene casi 60 años: viene de ALGOL 60, y la idea de "subrutina que devuelve un valor" es de los años 50. Antes, los programas eran un solo bloque gigante de líneas en orden (¡como tus rutas de 100 líneas!). ♻️ Reutilización: el superpoder DRY

⏱️ 35 minutos · "Don't Repeat Yourself — un cambio, un lugar"

🧠 La idea central

Todo lo de hoy (def, parámetros, return) existe para un solo propósito: reutilizar. El principio DRY (Don't Repeat Yourself) dice que cada pieza de conocimiento de tu app debe vivir en un único lugar. Si la fórmula de la multa está escrita en 5 rutas, no son 5 líneas: son 5 oportunidades de olvidar una cuando la tarifa cambie. La técnica se llama extract function: cortas el código repetido, lo pones en una función con nombre, y llamas la función donde estaba cada copia.

antes — tres rutas, tres copias de lo mismo (DRY llora 😭) 
# ❌ La fórmula de la multa vive en 3 lugares distintos:
async def registrar_prestamo(datos: PrestamoIn):
    multa = datos.dias_atraso * 500          # copia 1
    ...

async def reporte_prestamos(request: Request):
    for p in filas:
        p["multa"] = p["dias_atraso"] * 500  # copia 2
    ...

async def pagar_multa(prestamo_id: int):
    multa = dias * 500                       # copia 3 — ¡y esta usa 'dias'!
    ...

# 🦹 Mañana la tarifa sube a $800 → hay que cazar las 3 copias.
# ¿Las 3? ¿Seguro que son 3? Ese es el problema del copy-paste.
después — extract function: la fórmula vive en UN lugar 
# ✅ Un solo lugar define la fórmula (encima del archivo o en helpers.py):
TARIFA_POR_DIA = 500

def calcular_multa(dias_atraso: int) -> int:
    """Multa = días de atraso × tarifa vigente."""
    if dias_atraso is None or dias_atraso <= 0:
        return 0
    return dias_atraso * TARIFA_POR_DIA

# Y las 3 rutas ahora LA LLAMAN:
async def registrar_prestamo(datos: PrestamoIn):
    multa = calcular_multa(datos.dias_atraso)     # 1 línea, 0 riesgo
    ...

async def reporte_prestamos(request: Request):
    for p in filas:
        p["multa"] = calcular_multa(p["dias_atraso"])
    ...

# ¿La tarifa subió a $800? Cambias UNA línea. Las 3 rutas (y las 20
# que vengan) quedan actualizadas al instante. Un cambio, un lugar. ♻️

🦹 Villano: la conexión repetida en cada ruta

¿Te acuerdas de la clase 2? Cada ruta necesitaba una conexión a la BD, y copiar el await pool.acquire() en 50 rutas era inviable. La solución de FastAPI también es una función reutilizable: una dependencia con Depends. Ya escribiste esa función — hoy entiendes por qué funciona: es una función con parámetros (los que necesita), retorno (yield de la conexión) y reutilización (las 50 rutas la comparten).

Depends — la función que FastAPI reutiliza por ti en cada request 
from fastapi import FastAPI, Depends

# 1. La dependencia: una función como cualquier otra
async def get_db():
    conn = await pool.acquire()      # antes del yield: "preparar"
    try:
        yield conn                  # la entrega a la ruta (return pausado)
    finally:
        await pool.release(conn)    # después: "limpiar", siempre

# 2. Las rutas solo declaran el parámetro — FastAPI llama a get_db()
#    en CADA request y le inyecta el resultado. Una definición, N usos.
@app.get("/prestamos")
async def listar_prestamos(conn = Depends(get_db)):
    return await conn.fetch("SELECT * FROM prestamos")

@app.get("/libros")
async def listar_libros(conn = Depends(get_db)):
    return await conn.fetch("SELECT * FROM libros")

# ¿Cambió la forma de conectar? Solo tocas get_db. Cero copy-paste. ♻️

💡 Checklist del refactor DRY

  • ¿El mismo código (o casi) aparece 2+ veces? → extrae función.
  • ¿Se parece pero cambia un dato? → parámetro: calcular_multa(dias), no calcular_multa_3_dias.
  • ¿Muchas rutas necesitan lo mismo antes de empezar? → dependencia con Depends.
  • Nombra la función por qué hace, no por dónde se usa: formatear_dinero sí, cosa_de_reporte no.
  • Regla de los 3 pasos: copia 1 tolerable, copia 2 sospechosa, copia 3 refactor YA.

🧬 Métodos: funciones que viven dentro de una clase

⏱️ 35 minutos · "Una función con acceso a sus propios datos"

🧠 La idea central

Un método es una función definida dentro de una clase. La diferencia práctica: un método ya conoce sus datos (los atributos del objeto) y no se los tienes que pasar como parámetros. Ya usaste miles: conn.fetch() es el método fetch del objeto conn; texto.strip() es el método strip del string; lista.append(x), el de la lista. El punto . significa "llama esta función que vive dentro de este objeto".

de función suelta a método — el mismo def, ahora dentro 
# Función suelta: tú llevas los datos a la función
def esta_atrasado(dias_atraso):
    return dias_atraso > 0

esta_atrasado(prestamo["dias_atraso"])   # le PASAS el dato

# Método: el objeto YA tiene el dato — self es "este objeto"
class Prestamo:
    def __init__(self, estudiante, dias_atraso):   # constructor
        self.estudiante = estudiante
        self.dias_atraso = dias_atraso

    def esta_atrasado(self):                   # método: sin parámetros extra
        return self.dias_atraso > 0           # self = "YO (este préstamo)"

    def calcular_multa(self):                 # ¡reutilizando tu función!
        return calcular_multa(self.dias_atraso)

p = Prestamo("Camila", 7)
p.esta_atrasado()       # True — no le pasaste nada: él ya lo sabe
p.calcular_multa()     # 3500

💡 La regla de self

self es "el objeto mismo". Cuando escribes p.esta_atrasado(), Python traduce a esta_atrasado(p): el objeto que va antes del punto entra como self. Por eso todo método lleva self como primer parámetro — y por eso p.dias_atraso adentro se escribe self.dias_atraso. El punto . es un paso de parámetro invisible. 🕵️

🏠 ¿Dónde vive esto? 🐍 Python🛡️ Pydantic🚀 FastAPI

Tus modelos Pydantic (clase 5) son clases perfectas para colgarles métodos: el modelo ya guarda dias_atraso, estudiante… y puedes pedirle al propio modelo lo que necesites. Y las rutas FastAPI son funciones decoradas que agrupas con APIRouter — mismas piezas de siempre, un escalón más de organización.

modelos Pydantic con métodos y field_validator (clase 5, nivel pro) 
from pydantic import BaseModel, Field, field_validator

class PrestamoIn(BaseModel):                       # modelo de entrada (clase 5)
    estudiante: str = Field(min_length=2, max_length=50)
    libro: str
    dias_atraso: int = Field(default=0, ge=0)

    @field_validator("estudiante")                  # método-especial: valida al crear
    def sin_espacios(cls, valor):                    # (cls = la clase, no un objeto)
        if valor.strip() == "":
            raise ValueError("El nombre no puede ser solo espacios")
        return valor.strip()

    # ✨ Método normal y corriente: el modelo calcula su propia multa
    def multa(self) -> int:
        return calcular_multa(self.dias_atraso)   # reutilización total ♻️

# Uso: FastAPI recibe el JSON, crea el objeto y YA puedes llamar métodos
@app.post("/prestamos")
async def crear_prestamo(datos: PrestamoIn, conn = Depends(get_db)):
    return {"recibido": datos.estudiante, "multa": datos.multa()}

🦹 Villano: cuándo NO hacer un método

Si el cálculo no toca ningún dato del objeto (self queda sin usarse), no es un método: es una función normal. formatear_dinero(valor) no necesita saber nada del préstamo → función. prestamo.esta_atrasado() sí necesita self.dias_atraso → método. Pregúntalo así: "¿el objeto ya sabe lo que la función necesita?" Sí → método. No → función.

🧠 Reto 1 — La función calcular_multa y la constante

Extrae la fórmula (dias * 500) a una función calcular_multa(dias_atraso) -> int con su constante TARIFA_POR_DIA, docstring y early return para None/negativos. Escribe también formatear_dinero(valor, simbolo="$") -> str. En la terminal, prueba: calcular_multa(7), calcular_multa(0), calcular_multa(None), formatear_dinero(3500).

💡 Pista Reto 1

TARIFA_POR_DIA = 500

def calcular_multa(dias_atraso: int | None) -> int:
    """Multa = días × tarifa. None o ≤0 → $0."""
    if dias_atraso is None or dias_atraso <= 0:
        return 0
    return dias_atraso * TARIFA_POR_DIA

def formatear_dinero(valor: int, simbolo: str = "$") -> str:
    """3500 → '$3.500'."""
    return f"{simbolo}{valor:,}".replace(",", ".")

💡 Pista Reto 3

from pydantic import BaseModel, Field, field_validator

class Prestamo(BaseModel):
    estudiante: str = Field(min_length=2)
    libro: str
    dias_atraso: int = Field(default=0, ge=0)

    @field_validator("estudiante")
    def limpiar_nombre(cls, v):
        v = v.strip()
        if not v:
            raise ValueError("estudiante vacío")
        return v

    def multa(self) -> int:
        return calcular_multa(self.dias_atraso)   # ♻️ reutilización

    def estado(self) -> str:
        return "atrasado" if self.dias_atraso > 0 else "a tiempo"
