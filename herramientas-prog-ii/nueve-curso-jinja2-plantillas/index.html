🎨 La última milla del monolito

Cuando ves la página de la biblioteca en el navegador, la mayor parte del trabajo ya está hecho: el SQL de PostgreSQL (Neon) filtró y agregó; FastAPI ya calculó totales en Python; lo que llega a la plantilla es una lista de dicts casi lista para pintar. Tu trabajo —el que vamos a practicar hoy— vive en templates/*.html con Jinja2.

💡 ¿Por qué Jinja2?

Cuando SQL ya hizo el JOIN y FastAPI ya calculó el total, lo único que queda es convertir filas en HTML. Jinja2 es un motor de plantillas que hace exactamente eso: datos dentro, HTML legible fuera. Te ahorra el copy-paste de filas, deja que la lógica compleja viva donde corresponde (en el SQL y en Python) y produce plantillas que un humano puede leer sin saber programar. 📄

🔁 El {% for %}: de filas a filas HTML

⏱️ 35 minutos · "Por cada fila del contexto, una fila de la tabla"

🧠 La idea central

FastAPI te entrega un context con una lista de diccionarios: cada elemento es una fila. Tu trabajo es recorrer esa lista con {% for %} y, por cada fila, generar un <tr> (o un <li>, o un <article>). SQL filtra, Python arma, Jinja2 pinta.

🏠 ¿Dónde vive esto? 🎨 Jinja2

El {% for %} vive en la plantilla. Lo que iteras ya viene en el contexto: no vuelves a hacer la consulta a la BD ni calculas nada dentro.

vistas.py — lo que YA está hecho antes de tocar la plantilla 
# Esto vive en vistas.py: SQL filtra, Python arma el context.
# Tú, en la plantilla, recibes 'autores' como lista de dicts.
{
    "autores": [
        {"id": 1, "nombre": "Gabriel García Márquez", "pais": "Colombia",        "nacimiento": 1927},
        {"id": 2, "nombre": "Mario Vargas Llosa",     "pais": "Perú",            "nacimiento": 1936},
        {"id": "3", "nombre": "J. R. R. Tolkien",       "pais": "Reino Unido",     "nacimiento": 1892},
        {"id": 4, "nombre": "Terry Pratchett",        "pais": "Reino Unido",     "nacimiento": 1948},
    ],
    "total": 4,
}
templates/autores.html — tu trabajo real 
<table class="table table-striped">
  <thead>
    <tr><th>ID</th><th>Nombre</th><th>País</th><th>Nacimiento</th></tr>
  </thead>
  <tbody>
    {% for autor in autores %}
    <tr>
      <td>{{ autor.id }}</td>
      <td>{{ autor.nombre }}</td>
      <td>{{ autor.pais }}</td>
      <td>{{ autor.nacimiento }}</td>
    </tr>
    {% endfor %}
  </tbody>
</table>

<p class="mt-3">Hay {{ autores|length }} autores en la base.</p>

🦹 Villano: la tabla escrita a mano

Imagina escribir un <tr> por cada autor y copiar-pegar 9 veces. Si mañana el SQL filtra 200 autores, ¿escribes 200 filas a mano? El {% for %} escribe la fila una sola vez y deja que el navegador la duplique por cada elemento. La plantilla no cambia cuando cambian los datos: los datos cambian dentro del mismo molde. 🍰

La variable loop: superpoderes del for de Jinja2 
{% for autor in autores %}
  <tr>
    <td>{{ loop.index }}</td>            <!-- contador: 1, 2, 3… -->
    <td>{{ autor.nombre }}</td>
    {% if loop.first %}<td>⭐ primer registro</td>{% endif %}
    {% if loop.last %}<td>🏁 último registro</td>{% endif %}
  </tr>
{% endfor %}

💡 Atributos útiles de loop

  • {{ loop.index }} — número de vuelta empezando en 1.
  • {{ loop.index0 }} — igual pero empezando en 0.
  • loop.first / loop.last — True solo en la primera/última vuelta.
  • loop.length — total de elementos (igual que autores|length).
  • loop.cycle('a', 'b', 'c') — rota valores entre vueltas (útil para alternar colores de fila).
El bloque {% else %}: lista vacía sin error 
{% for autor in autores %}
  <li>{{ autor.nombre }}</li>
{% else %}
  <li class="text-muted">Aún no hay autores registrados 📭</li>
{% endfor %}

🎚️ Filtros: transformar un valor al imprimirlo

⏱️ 35 minutos · "El formato vive en la plantilla, el cálculo vive en Python"

🧠 La idea central

Un filtro se aplica al valor justo antes de imprimirlo, con el operador |. {{ autor.nombre | upper }} muestra el nombre en mayúsculas. Sirven para dar formato (fechas, números, mayúsculas), manejar vacíos (|default), contar (|length) o incluso agrupar una lista en el último momento (|groupby).

🏠 ¿Dónde vive esto? 🎨 Jinja2

Los filtros son de Jinja2: viven en la plantilla y solo afectan cómo se imprime un valor, no los datos. La suma real la hace Python/SQL; |length solo la lee.

Los filtros que usarás una y otra vez

filtros básicos — formato y seguridad 
{{ autor.nombre | upper }}                          <!-- "GABRIEL GARCÍA MÁRQUEZ" -->
{{ autor.pais | default("Sin país") }}             <!-- si pais es None o vacío → "Sin país" -->
{{ libro.titulo | truncate(30) }}                  <!-- "Cien años de soledad" → "Cien años de soled…" -->
{{ 1234567 | int }}                                 <!-- convertir string a int -->
{{ fecha | date("Y-m-d") }}                       <!-- formatear fecha -->
filtros de colecciones — listas y conteo 
{{ autores | length }}                            <!-- 4 -->
{{ autores | first }}                            <!-- primer dict -->
{{ autores | last }}                             <!-- último dict -->
{{ autores | map(attribute='pais') | list | unique }}   <!-- ['Colombia', 'Perú', 'Reino Unido'] -->

{% set nombres = autores | map(attribute='nombre') | join(', ') %}
<p>Autores: {{ nombres }}</p>
<!-- Autores: Gabriel García Márquez, Mario Vargas Llosa, J. R. R. Tolkien, Terry Pratchett -->
groupby: agrupar filas para pintarlas juntas 
{% for grupo in libros | groupby('decada') %}
  <h3>{{ grouper }}</h3>            <!-- "1960s", "1990s"… -->
  <ul>
    {% for libro in grupo %}
      <li>{{ libro.titulo }}</li>
    {% endfor %}
  </ul>
{% endfor %}

🦹 Villano: el cálculo escondido en la plantilla

¿|sum para sumar? Sí existe. Pero si tu HTML tiene que sumar muchas cosas, algo se quedó en el contexto que debió llegar hecho. Pide el total en context={...} y déjalo en una variable con nombre (total_libros, promedio_anio). Una plantilla que solo pinta y formatea es una plantilla que se mantiene.

filtrar filas por atributo: selectattr / rejectattr 
<h3>Solo autores vivos en 2026 (nacidos < 2000)</h3>
<ul>
{% for autor in autores | selectattr('nacimiento', '<', 2000) %}
  <li>{{ autor.nombre }} (n. {{ autor.nacimiento }})</li>
{% endfor %}
</ul>

<h3>Autores sin país registrado</h3>
<ul>
{% for autor in autores | rejectattr('pais') %}
  <li class="text-muted">{{ autor.nombre }}</li>
{% endfor %}
</ul>

💡 Truco: {% set %} para nombres legibles

Si una expresión larga aparece varias veces en la plantilla, guárdala en una variable local con {% set %}. La plantilla se vuelve más fácil de leer y cambias la fórmula en un solo lugar.

🚦 Decisiones visuales con {% if %}

⏱️ 35 minutos · "La vista cambia según el dato"

🧠 La idea central

Los datos que llegan al contexto no son uniformes: hay un país que es None, un año que es muy antiguo, un libro sin portada. El {% if %} te permite pintar HTML distinto según el valor: badge de "clásico", mensaje de "vacío", clase CSS de "alerta". El motor de la decisión es la plantilla; la lógica de qué decidir sigue en SQL/Python.

🏠 ¿Dónde vive esto? 🎨 Jinja2

El {% if %} vive en la plantilla: solo decide cómo se ve cada fila. La clasificación ("este libro es antiguo") puede llegar pre-calculada desde Python en el contexto, así la plantilla no inventa reglas.

if / elif / else básico 
{% if autor.pais %}
  <span class="badge bg-primary">{{ autor.pais }}</span>
{% elif autor.nacimiento %}
  <span class="badge bg-secondary">n. {{ autor.nacimiento }}</span>
{% else %}
  <span class="badge bg-warning text-dark">Sin datos</span>
{% endif %}
badge según la era del libro 
{% for libro in libros %}
  <tr>
    <td>{{ libro.titulo }}</td>
    <td>{{ libro.anio }}</td>
    <td>
      {% if libro.anio < 1950 %}
        <span class="badge bg-warning text-dark">Clásico</span>
      {% elif libro.anio >= 2000 %}
        <span class="badge bg-info">Moderno</span>
      {% else %}
        <span class="badge bg-secondary">Siglo XX</span>
      {% endif %}
    </td>
  </tr>
{% endfor %}
estado vacío amigable 
{% if not libros %}
  <div class="alert alert-info">
    📭 Aún no hay libros en el catálogo. Vuelve pronto.
  </div>
{% else %}
  <table class="table">…</table>
{% endif %}

🦹 Villano: la página rota cuando no hay datos

Si tu plantilla solo tiene el {% for %} sin un {% else %} o un {% if not lista %}, el día que la lista viene vacía el usuario ve una tabla en blanco o un error. Una buena plantilla siempre tiene un mensaje para el caso vacío.

💡 Verdadero / Falso en Jinja2

Para Jinja2, None, "", [], {}, 0 y False son falsy. El resto es truthy. Por eso {% if autor.pais %} cubre tanto None como cadena vacía.

combinar if + loop: clases CSS por fila 
{% for autor in autores %}
  <tr class="{% if loop.index is even %}fila-par{% else %}fila-impar{% endif %}">
    <td>{{ loop.index }}</td>
    <td>{{ autor.nombre }}</td>
  </tr>
{% endfor %}

📊 Bucles anidados en HTML: listas dentro de listas

⏱️ 35 minutos · "Un {% for %} por cada nivel del JOIN"

🧠 La idea central

En la app de biblioteca ya existe la tabla intermedia autoria: une autores con sus libros. Una sola consulta SQL con JOIN devuelve filas planas (autor, libro). La plantilla puede anidar dos {% for %} para pintarlo en dos niveles: un encabezado por autor y, debajo, una lista de sus libros.

🏠 ¿Dónde vive esto? 🐘 SQL (JOIN)🐍 Python (armar)🎨 Jinja2 (pintar)

El JOIN vive en SQL. Python puede agrupar las filas en una estructura anidada o pasarlas planas. La plantilla solo decide la jerarquía visual. Si ves anidamiento de 3 niveles, probablemente el SQL no está haciendo su parte.

vistas.py — la consulta que ya devuelve lo necesario 
# Esto vive en SQL/Python. El JOIN une cada autor con sus libros.
{
    "autores_con_libros": [
        {"autor": "Gabriel García Márquez", "libro": "Cien años de soledad",        "anio": 1967},
        {"autor": "Gabriel García Márquez", "libro": "El amor en los tiempos del cólera", "anio": 1985},
        {"autor": "Mario Vargas Llosa",      "libro": "La ciudad y los perros",        "anio": 1963},
        {"autor": "J. R. R. Tolkien",        "libro": "El hobbit",                     "anio": 1937},
        {"autor": "J. R. R. Tolkien",        "libro": "El Señor de los Anillos",        "anio": 1954},
        {"autor": "Terry Pratchett",         "libro": "Buenos presagios",               "anio": 1990},
    ],
    "total": 6,
}
biblioteca.html — tu trabajo: anidar para pintar jerarquía 
{% set actual = namespace(nombre=None) %}
{% for fila in autores_con_libros %}
  {% if fila.autor != actual.nombre %}
    {% if not loop.first %}</ul></li>{% endif %}
    <li><strong>{{ fila.autor }}</strong>
    <ul>
    {% set actual.nombre = fila.autor %}
  {% endif %}
  <li>{{ fila.libro }} ({{ fila.anio }})</li>
{% endfor %}
{% if autores_con_libros %}</ul></li>{% endif %}

🦹 Villano: anidar lo que SQL ya agrupó

El patrón de arriba con namespace + {% if %} funciona, pero hace el HTML frágil. Si el SQL puede devolver la lista ya agrupada ({autor: [libros…]}), la plantilla es más limpia: una sola decisión visual, no dos niveles de coordinación.

la versión limpia: SQL + Python ya agruparon por autor 
# Lo que llega al contexto, ya agrupado en Python:
{
    "autores": [
        {"nombre": "Gabriel García Márquez",
         "libros": [
            {"titulo": "Cien años de soledad",          "anio": 1967},
            {"titulo": "El amor en los tiempos del cólera", "anio": 1985},
         ]},
        {"nombre": "J. R. R. Tolkien",
         "libros": [
            {"titulo": "El hobbit",               "anio": 1937},
            {"titulo": "El Señor de los Anillos",  "anio": 1954},
         ]},
    ],
}
biblioteca.html — un {% for %} limpio por nivel 
<ul class="biblioteca">
{% for autor in autores %}
  <li>
    <h3>✍️ {{ autor.nombre }}</h3>
    <ul>
      {% for libro in autor.libros %}
        <li>📖 {{ libro.titulo }} ({{ libro.anio }})</li>
      {% endfor %}
    </ul>
  </li>
{% endfor %}
</ul>

💡 Cuándo anidar en Jinja2 y cuándo no

  • 2 niveles (autor → libros): casi siempre viene bien pre-agrupado del SQL/Python.
  • 3 niveles o más: sospecha. Probablemente el SQL no hizo el JOIN correcto o te falta una vista materializada.
  • Solo 1 nivel pero con jerarquía visual: usa |groupby('autor') en la propia plantilla — sin tocar la consulta.
|groupby en la plantilla — sin tocar SQL ni Python 
<ul>
{% for grupo in autores_con_libros | groupby('autor') %}
  <li>
    <strong>{{ grupo.grouper }}</strong>
    <ul>
      {% for fila in grupo.list %}
        <li>{{ fila.libro }} ({{ fila.anio }})</li>
      {% endfor %}
    </ul>
  </li>
{% endfor %}
</ul>

🧩 Macros e {% include %}: componentes en Jinja2

⏱️ 35 minutos · "Reutilizar sin copiar-pegar"

🧠 La idea central

Jinja2 tiene dos mecanismos para reutilizar HTML: macros (parecidas a funciones: reciben datos y devuelven HTML) y {% include %} (incluir un archivo de plantilla tal cual). Son el equivalente Jinja2 de los componentes de React o Svelte. La pieza se define una vez y se usa muchas.

🏠 ¿Dónde vive esto? 🎨 Jinja2

Macros e {% include %} son puro Jinja2: viven en templates/. Son la respuesta al "tengo que repetir este pedazo de HTML en 8 archivos": se hace un componente y se reutiliza.

templates/componentes/badge.html — un macro reutilizable 
{% macro badge(texto, color="secondary") %}
  <span class="badge bg-{{ color }}">{{ texto }}</span>
{% endmacro %}

{% macro era(anio) %}
  {% if anio < 1950 %}
    {{ badge('Clásico', 'warning') }}
  {% elif anio >= 2000 %}
    {{ badge('Moderno', 'info') }}
  {% else %}
    {{ badge('Siglo XX', 'secondary') }}
  {% endif %}
{% endmacro %}
templates/libros.html — usar los macros 
{% from "componentes/badge.html" import badge, era %}

<h1>📚 Catálogo</h1>
<table class="table">
  {% for libro in libros %}
    <tr>
      <td>{{ libro.titulo }}</td>
      <td>{{ libro.anio }}</td>
      <td>{{ era(libro.anio) }}</td>
    </tr>
  {% endfor %}
</table>

<p>Hay {{ badge(total, 'primary') }} libros en el catálogo.</p>
templates/componentes/fila_autor.html — un include 
<tr>
  <td>{{ autor.id }}</td>
  <td>{{ autor.nombre }}</td>
  <td>{{ autor.pais }}</td>
</tr>
templates/autores.html — incluir filas 
<table class="table table-striped">
  <thead>
    <tr><th>ID</th><th>Nombre</th><th>País</th></tr>
  </thead>
  <tbody>
    {% for autor in autores %}
      {% include "componentes/fila_autor.html" %}
    {% endfor %}
  </tbody>
</table>

🦹 Villano: copiar-pegar filas HTML

¿Ves una etiqueta <tr> con cuatro <td> que se repite en 6 archivos? Eso es un componente esperando nacer. Con {% include %} lo extraes a componentes/fila.html y lo metes con una línea. Mañana agregas una columna: tocas un solo archivo.

💡 Macro vs include — ¿cuándo?

  • Macro: cuando quieres parametrizar (ej. era(anio) elige color según valor).
  • Include: cuando la pieza es siempre la misma con los datos que ya vienen en el contexto.
  • Ambos pueden anidarse: un include que dentro tiene {% from ... import %} y usa un macro.

🧠 Reto 2 — La tabla de libros con badge de era

Recorre libros con un {% for %}. Por cada libro muestra titulo, autor, anio y un badge de era (Clásico si anio < 1950, Moderno si >= 2000, Siglo XX si no). Si libros viene vacío, muestra una alerta "Sin libros todavía".

💡 Pista Reto 2

{% if not libros %}
  <div class="alert alert-info">📭 Sin libros todavía.</div>
{% else %}
<table class="table table-striped">
  <thead><tr><th>#</th><th>Título</th><th>Autor</th><th>Año</th><th>Era</th></tr></thead>
  <tbody>
    {% for libro in libros %}
    <tr>
      <td>{{ loop.index }}</td>
      <td>{{ libro.titulo }}</td>
      <td>{{ libro.autor | default('—') }}</td>
      <td>{{ libro.anio }}</td>
      <td>
        {% if libro.anio < 1950 %}<span class="badge bg-warning text-dark">Clásico</span>
        {% elif libro.anio >= 2000 %}<span class="badge bg-info">Moderno</span>
        {% else %}<span class="badge bg-secondary">Siglo XX</span>
        {% endif %}
      </td>
    </tr>
    {% endfor %}
  </tbody>
</table>
{% endif %}

🧠 Reto 4 — Extrae el badge a un macro

Crea templates/componentes/era.html con un macro era(anio) que reciba un año y devuelva el badge correcto (Clásico/Moderno/Siglo XX). Úsalo en la tabla del Reto 2 con {% from ... import %}.

{% macro era(anio) %}

  {% else %}<span class="badge bg-secondary">Siglo XX</span>
  {% endif %}
{% endmacro %}

🦹 Reflexión final

En este taller no tocaste vistas.py, no escribiste SQL, no calculaste nada. Solo dibujaste. La información venía armada porque SQL hizo el JOIN con autoria y Python empaquetó el resumen y decadas. Esa es la frontera del trabajo en una plantilla: lo que llega se pinta, lo que falta se pide. Si te toca calcular algo dentro del HTML, algo se quedó en el camino.
