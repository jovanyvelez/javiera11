🔁 El for ... in: recorrer lo que ya tienes

⏱️ 35 minutos · "Por cada elemento adentro, haz esto"

🧠 La idea central

En Python el for no cuenta vueltas: visita elementos. La palabra clave es in — "dentro de". for libro in libros: se lee: "para cada libro que está dentro de la lista libros, haz esto". La pregunta que siempre se hace un for ... in es: ¿qué hay adentro? Y lo visita uno por uno, en orden, sin saltarse ninguno.

🏠 ¿Dónde vive esto? 🐍 Python

Este for ... in vive en vistas.py, en la lógica de tu app FastAPI: procesas las filas que SQL te devolvió y armas el context. (Tranquilo: en el módulo 5 verás que Jinja2 usa la misma sintaxis para pintar HTML.)

lo que devuelve tu consulta — una lista de dicts 
# Esto vive en vistas.py: prestamos = await conn.fetch(...)
prestamos = [
    {"estudiante": "Ana",     "libro": "Cien años de soledad",  "dias_atraso": 0,  "multa": 0},
    {"estudiante": "Brayan",   "libro": "El hobbit",              "dias_atraso": 3,  "multa": 1500},
    {"estudiante": "Camila",   "libro": "Buenos presagios",        "dias_atraso": 7,  "multa": 3500},
    {"estudiante": "Daniela",  "libro": "El Señor de los Anillos", "dias_atraso": 0,  "multa": 0},
]
for ... in — visitar cada préstamo y hacer algo 
# "para cada préstamo DENTRO de prestamos"
for prestamo in prestamos:
    estado = "a tiempo" if prestamo["dias_atraso"] == 0 else "atrasado"
    print(f"{prestamo['estudiante']}: {prestamo['libro']} — {estado}")

# Ana: Cien años de soledad — a tiempo
# Brayan: El hobbit — atrasado
# Camila: Buenos presagios — atrasado
# Daniela: El Señor de los Anillos — a tiempo

🦹 Villano: el copy-paste por elemento

El anti-patrón es escribir procesar(prestamos[0]), procesar(prestamos[1]), procesar(prestamos[2])… Eso funciona hasta que mañana hay 200 préstamos. El for ... in escribe el proceso una sola vez y Python lo repite por cada elemento. Cambian los datos, no el código. 🍰

📦 ¿Qué puede haber "adentro"? Casi todo

La potencia de in es que muchas cosas contienen cosas. El mismo for las recorre a todas:

in sobre listas, dicts, strings y rangos 
# 1. Una LISTA de diccionarios (lo que devuelve conn.fetch)
for prestamo in prestamos:
    ...

# 2. Un DICT: 'in' visita las CLAVES
conteo = {"novela": 4, "ciencia": 2}
for categoria in conteo:
    print(categoria, conteo[categoria])   # novela 4 / ciencia 2

# 3. Un STRING: 'in' visita cada carácter
for letra in "ISBN":
    print(letra)                          # I / S / B / N

# 4. range(n): la lista de vueltas cuando NO tienes elementos todavía
for i in range(3):
    print(i)                              # 0 / 1 / 2

💡 El operador in tiene dos vidas

Como operador, pregunta pertenencia y responde True/False: "Ana" in prestamos[0]["estudiante"]. Como parte del for, recorre: for p in prestamos:. Mismo in, dos superpoderes. Y fíjate: if categoria in conteo: es el guardián perfecto antes de sumar a un dict contador.

enumerate() — el elemento Y su posición 
# ¿Necesitas el número de fila además del dato? No cuentes tú: enumera
for posicion, prestamo in enumerate(prestamos, start=1):
    print(f"#{posicion} — {prestamo['estudiante']}")

# 1 — Ana / 2 — Brayan / 3 — Camila / 4 — Daniela
# (enumerate regala la posición; tú NO mantienes un contador a mano… todavía 😏)
for anidado: filas de un JOIN (autor → sus libros) 
# El JOIN devuelve filas planas (autor, libro). Agrupamos recorriendo:
filas = [
    {"autor": "García Márquez", "libro": "Cien años de soledad"},
    {"autor": "García Márquez", "libro": "El amor en los tiempos del cólera"},
    {"autor": "Tolkien",        "libro": "El hobbit"},
    {"autor": "Tolkien",        "libro": "El Señor de los Anillos"},
]

for autor in {f["autor"] for f in filas}:          # autores únicos (set)
    libros = [f["libro"] for f in filas if f["autor"] == autor]
    print(f"✍️ {autor} ({len(libros)} libro(s)):")
    for libro in libros:                              # bucle ANIDADO: uno por autor
        print(f"   📖 {libro}")

# ✍️ García Márquez (2 libro(s)):
#    📖 Cien años de soledad
#    📖 El amor en los tiempos del cólera
# ✍️ Tolkien (2 libro(s)):
#    📖 El hobbit
#    📖 El Señor de los Anillos

🧮 Contadores y acumuladores: los dos patrones que lo automatizan todo

⏱️ 35 minutos · "Contar es preguntar cuántos; acumular es ir sumando"

🧠 La idea central

Casi todo proceso automatizado se reduce a dos patrones. El contador: una variable que empieza en 0 y suma 1 cada vez que algo cumple una condición — ¿cuántos préstamos están atrasados? El acumulador: una variable que empieza en 0 y suma un valor en cada vuelta — ¿cuánto dinero hay en multas? Se escriben casi igual:

el patrón clásico — contador y acumulador a mano 
atrasados = 0          # CONTADOR: cuántos cumplen la condición
total_multas = 0       # ACUMULADOR: la suma de los valores

for prestamo in prestamos:
    if prestamo["dias_atraso"] > 0:
        atrasados += 1                       # contar: +1
        total_multas += prestamo["multa"]         # acumular: +valor

print(f"Préstamos atrasados: {atrasados}")        # 2
print(f"Total en multas: ${total_multas}")        # $5000

🏠 ¿Dónde vive esto? 🐍 Python

Contar y acumular es trabajo de Python (o de SQL, como verás en el módulo 6). El resultado llega a la plantilla como un número más del context: context={"atrasados": atrasados, "total_multas": total_multas}. Jinja2 nunca acumula — solo muestra el resultado.

💡 ¿Contador o acumulador? Pregúntalo así

  • "¿Cuántos…?" → contador: x += 1.
  • "¿Cuánto en total…?" → acumulador: x += valor.
  • El acumulador no siempre es dinero: puede acumular textos (saludo += " " + nombre) o listas (libros_atrasados.append(...)).
  • Ambos empiezan en 0 (o vacíos) ANTES del bucle. Inicializarlos adentro es el error clásico: se reinician en cada vuelta. 💥
contador con teclado (dict) — contar por categorías 
# ¿Y si hay que contar VARIAS cosas a la vez (por categoría)?
# El dict es un contador con teclado: una llave por categoría.

libros = [
    {"titulo": "Cien años de soledad",  "categoria": "novela"},
    {"titulo": "El hobbit",             "categoria": "fantasía"},
    {"titulo": "El Señor de los Anillos", "categoria": "fantasía"},
    {"titulo": "Breve historia del tiempo", "categoria": "ciencia"},
    {"titulo": "Pedro Páramo",           "categoria": "novela"},
]

por_categoria = {}                        # contador vacío, ANTES del bucle
for libro in libros:
    cat = libro["categoria"]
    por_categoria[cat] = por_categoria.get(cat, 0) + 1   # ¿existe? suma 1; si no, nace en 1

print(por_categoria)   # {'novela': 2, 'fantasía': 2, 'ciencia': 1}

🐍 Los superpoderes de Python: contar y sumar SIN bucle

El patrón manual enseña qué está pasando. Pero Python trae herramientas que lo hacen en una línea, y el código profesional las usa:

len(), sum(), min(), max() — las funciones integradas 
# len()  → el contador universal: cuántos elementos hay
total_prestamos = len(prestamos)                       # 4

# sum()  → el acumulador universal: suma una secuencia
total_multas = sum(p["multa"] for p in prestamos)   # 5000

# sum() con condición (generator + if): contar atrasados SIN contador
atrasados = sum(1 for p in prestamos if p["dias_atraso"] > 0)   # 2

# min() / max() sobre los días de atraso
peor_atraso = max(p["dias_atraso"] for p in prestamos)     # 7

# any() / all(): ¿hay alguno? ¿están todos?
hay_atrasados = any(p["dias_atraso"] > 0 for p in prestamos)  # True
todos_atrasados = all(p["dias_atraso"] > 0 for p in prestamos)  # False
collections.Counter — el contador profesional 
from collections import Counter

# Counter cuenta por ti lo que el dict contador contaba a mano:
por_categoria = Counter(libro["categoria"] for libro in libros)
print(por_categoria)        # Counter({'novela': 2, 'fantasía': 2, 'ciencia': 1})

# Y regala herramientas extra:
print(por_categoria["novela"])     # 2  (0 si la clave no existe: sin KeyError)
print(por_categoria.most_common(2))  # [('novela', 2), ('fantasía', 2)] — ¡el top N!

# En FastAPI, el context queda elegantísimo:
context = {
    "libros": libros,
    "total": len(libros),
    "por_categoria": dict(por_categoria),
}

💡 ¿Cuál uso? La guía de estilo de esta clase

  • Aprendiendo / depurando: el bucle manual con contador += 1. Se ve todo lo que pasa.
  • Código real de la app: len(), sum(...), Counter. Una línea, cero errores de inicialización.
  • Conteos y totales de la BD: ni Python — SQL con COUNT/SUM/GROUP BY (módulo 6).
  • Regla: primero entiendes el patrón a mano, después lo delegas al lenguaje. Nunca al revés.

🌀 El while: repetir mientras algo sea verdad

⏱️ 35 minutos · "No sé cuántas vueltas: sé hasta cuándo"

🧠 La idea central

El while repite un bloque mientras una condición sea verdadera. No sabe cuántas vueltas dará — sabe cuándo parar. En una app sirve para: seguir pidiendo un dato hasta que sea válido, seguir procesando páginas de una API hasta que llegue una vacía, seguir intentando una conexión hasta que logre. Su estructura siempre es la misma:

anatomía del while — 3 piezas obligatorias 
# 1️⃣ Preparar: la variable de la condición, ANTES del bucle
respuesta = ""

# 2️⃣ La condición: mientras sea True, el bloque se repite
while respuesta != "s" and respuesta != "n":
    respuesta = input("¿Registrar otro préstamo? (s/n): ").strip().lower()
    # 3️⃣ Avanzar: algo debe poder cambiar la condición

print(f"Respuesta válida: {respuesta}")

🦹 Villano: el bucle infinito

Si la condición nunca se vuelve falsa, el while jamás termina: la app se cuelga. 💀 La causa #1 es olvidar la pieza 3 (avanzar): while respuesta != "s": ... sin volver a preguntar dentro. Receta anti-infinito: preparar antes, avanzar dentro. Y si mientras pruebas algo se cuelga: Ctrl + C lo corta.

🏠 ¿Dónde vive esto? 🐍 Python

El while es 100% Python: valida entradas en tus rutas, procesa lotes, reintenta conexiones. Jinja2 no tiene while — sus plantillas solo usan {% for %}, porque pintar HTML siempre es "por cada elemento del contexto".

while + acumulador: registrar préstamos hasta que diga basta 
# El patrón "carga de datos" de toda la vida:
prestamos = []                    # acumulador de listas
total_multas = 0               # acumulador de dinero
continuar = "s"                 # preparar la condición

while continuar == "s":
    estudiante = input("Estudiante: ")
    multa = float(input("Multa: $"))
    prestamos.append({"estudiante": estudiante, "multa": multa})
    total_multas += multa                                  # acumular
    continuar = input("¿Otro? (s/n): ").strip().lower()   # avanzar

print(f"Se registraron {len(prestamos)} préstamos (contador de regalo).")
print(f"Total en multas: ${total_multas}")
while en FastAPI: validar hasta que el dato sea correcto 
# En una ruta, validar la entrada de un formulario:
from fastapi import FastAPI, Request
from fastapi.responses import HTMLResponse

app = FastAPI()

def validar_isbn(texto: str) -> str | None:
    # While seco: pedir-consigo-mismo hasta lograr
    isbn = texto.strip()
    intentos = 0                                # contador de reintentos
    while not (isbn.isdigit() and len(isbn) == 13) and intentos < 5:
        isbn = input("ISBN inválido (13 dígitos). Reintenta: ").strip()
        intentos += 1                        # avanzar: el contador pone tope
    return isbn if isbn.isdigit() and len(isbn) == 13 else None

def paginar_api(url_inicial: str) -> list:
    # While "hasta que llegue una página vacía" — clásico de APIs:
    resultados = []                              # acumulador
    url = url_inicial
    while url:                                 # mientras haya página siguiente…
        datos = requests.get(url).json()          # (ejemplo ilustrativo)
        resultados.extend(datos["items"])       # acumular
        url = datos["next"]                   # avanzar: None cuando no hay más
    return resultados
break y continue — control fino del bucle 
# break: CORTA el bucle completo (encontré lo que buscaba)
for prestamo in prestamos:
    if prestamo["estudiante"] == "Camila":
        print("Camila tiene un préstamo activo")
        break                        # no sigo recorriendo: ya la encontré

# continue: SALTA esta vuelta (este no me interesa, siguiente)
for prestamo in prestamos:
    if prestamo["dias_atraso"] == 0:
        continue                     # a tiempo: saltarlo
    print(f"Atrasado: {prestamo['estudiante']}")   # solo los atrasados

# Funcionan igual en for y en while. Úsalos para CLARIDAD, no para acrobacias.

💡 ¿for o while? La tabla de decisión

  • ¿Sabes cuántas vueltas o tienes una colección? → for ... in. Recorrer filas, listas, dicts, strings.
  • ¿Solo sabes la condición de paro? → while. Validar, reintentar, "hasta que llegue vacío".
  • Truco mental: si tu while empieza con i = 0 y hace i += 1 para recorrer una lista… ese es un for ... in disfrazado. 🥸 Cámbialo.

💡 ¿Sabías que…?

El while nació antes que el for: viene de los lenguajes de los años 60 (ALGOL, C) donde todo bucle era "mientras una condición". El for ... in moderno es herencia de ABC y Python, que pensaron: "si casi siempre recorremos una colección, el bucle debería hablar de la colección, no del contador". Por eso el de Python no necesita i = i + 1 — el in ya sabe dónde va. 📜

🎨 Bucles en Jinja2: {% for ... in %} para pintar HTML

⏱️ 35 minutos · "El mismo 'in', pero cada vuelta pinta HTML"

🧠 La idea central

¿Recuerdas el módulo 1? for prestamo in prestamos: visitaba cada elemento de una lista. En Jinja2 es exactamente la misma idea con sintaxis de plantilla: {% for prestamo in prestamos %}...{% endfor %}. La diferencia es qué hace cada vuelta: en Python procesa datos; en Jinja2 pinta un trozo de HTML. El in pregunta lo mismo: ¿qué hay adentro del contexto?

🏠 ¿Dónde vive esto? 🐍 Python (arma)🎨 Jinja2 (pinta)

Lo que iteras ya viene en el contexto: FastAPI hizo la consulta y te entregó la lista. La plantilla la recorre con {% for %} y genera una fila de tabla (o una tarjeta, o un <li>) por elemento. No consultas la BD ni calculas nada aquí.

vistas.py — la ruta arma el contexto (repaso) 
# Python ya contó y acumuló: la plantilla solo recibe resultados
from collections import Counter

async def prestamos(request: Request):
    filas = await conn.fetch("SELECT * FROM prestamos")
    atrasados = sum(1 for p in filas if p["dias_atraso"] > 0)
    total_multas = sum(p["multa"] for p in filas)
    return templates.TemplateResponse(
        request, "prestamos.html",
        context={"prestamos": filas, "atrasados": atrasados, "total_multas": total_multas},
    )
templates/prestamos.html — el for pinta una fila por elemento 
<table class="table table-striped">
  <thead>
    <tr><th>#</th><th>Estudiante</th><th>Libro</th><th>Días de atraso</th></tr>
  </thead>
  <tbody>
    {% for prestamo in prestamos %}
    <tr>
      <td>{{ loop.index }}</td>
      <td>{{ prestamo.estudiante }}</td>
      <td>{{ prestamo.libro }}</td>
      <td>{{ prestamo.dias_atraso }}</td>
    </tr>
    {% endfor %}
  </tbody>
</table>

<p>Hay {{ prestamos|length }} préstamos, {{ atrasados }} atrasados.</p>

🦹 Villano: el contador a mano en la plantilla

Alguien siempre inventa esto: {% set i = 0 %} … {% set i = i + 1 %} dentro del {% for %}. No. Jinja2 te regala el contador incorporado loop, que se reinicia solo en cada bucle y nunca se desincroniza. Y si necesitas contar o sumar la lista completa: eso vino calculado desde Python en el contexto (o lo lees con |length).

la variable loop — tu contador incorporado y gratuito 
{% for prestamo in prestamos %}
  <tr class="{% if loop.index is even %}fila-par{% else %}fila-impar{% endif %}">
    <td>{{ loop.index }}</td>        <!-- 1, 2, 3… (desde 1) -->
    <td>{{ prestamo.estudiante }}</td>
    {% if loop.first %}<td>🆕 primer préstamo</td>{% endif %}
    {% if loop.last %}<td>🏁 último</td>{% endif %}
  </tr>
{% endfor %}

💡 Atributos de loop (el contador de Jinja2)

  • {{ loop.index }} — contador desde 1 (el número de fila).
  • {{ loop.index0 }} — contador desde 0 (como Python).
  • loop.first / loop.last — True solo en la primera/última vuelta.
  • {{ loop.length }} — el total de vueltas (= prestamos|length).
  • loop.cycle('par', 'impar') — alterna valores vuelta a vuelta.
else del for, groupby y sum — contar/sumar al pintar 
{# 1. Lista vacía sin tabla en blanco: {% else %} del for #}
{% for prestamo in prestamos %}
  <li>{{ prestamo.estudiante }} — {{ prestamo.libro }}</li>
{% else %}
  <li class="text-muted">📭 No hay préstamos registrados todavía</li>
{% endfor %}

{# 2. Contar al pintar: |length  (sin bucle, sin loop) #}
<p>{{ prestamos|length }} préstamos en total.</p>

{# 3. Sumar al pintar: |sum sobre un atributo #}
<p>Suma de días de atraso: {{ prestamos|sum(attribute='dias_atraso') }}.</p>

{# 4. Anidado con groupby: pintar por categorías #}
{% for grupo in libros|groupby('categoria') %}
  <h3>{{ grupo.grouper }} ({{ grupo.list|length }})</h3>
  <ul>
    {% for libro in grupo.list %}
      <li>{{ libro.titulo }}</li>
    {% endfor %}
  </ul>
{% endfor %}

💡 El caso especial: namespace() cuando NO hay otra

¿Y si de verdad necesitas un acumulador dentro de la plantilla (p. ej. marcar "ya imprimí este autor")? Jinja2 ofrece {% set visto = namespace(valor=False) %} y se muta con visto.valor = True. Existe — pero es una señal de alerta: casi siempre ese cálculo debió llegar hecho desde Python en el contexto. Úsalo como último recurso, con comentario explicando por qué. 🚨

🤖 Automatizar un proceso en las tres capas

⏱️ 35 minutos · "Quien puede contar en SQL, que cuente en SQL"

🧠 La idea central

Un mismo proceso — el reporte de préstamos atrasados con total de multas — puede automatizarse en tres capas. La pregunta profesional no es "¿dónde puedo?" sino "¿dónde conviene?". La respuesta corta: el que tiene los datos cuenta. Si son todos los de la BD → SQL. Si son datos ya en Python → sum()/Counter. Si es solo pintar cada elemento → Jinja2.

versión 1 — todo lo cuenta SQL (la más eficiente) 
-- El motor de PostgreSQL (Neon) cuenta y suma SIN sacar las filas de la BD.
SELECT
    COUNT(*)                                    AS total_prestamos,
    COUNT(*) FILTER (WHERE dias_atraso > 0)    AS atrasados,
    COALESCE(SUM(multa), 0)                    AS total_multas
FROM prestamos;

SELECT categoria, COUNT(*) AS cantidad
FROM libros

versión 2 — Python arma el contexto con sus superpoderes 
async def reporte_prestamos(request: Request):
    # Ya tengo las filas en Python: sum() y Counter hacen el resto
    filas = await conn.fetch("SELECT * FROM prestamos")

    def estado(p):
        return "atrasado" if p["dias_atraso"] > 0 else "a_tiempo"

    por_estado = Counter(estado(p) for p in filas)   # {'a_tiempo': 2, 'atrasado': 2}
    contexto = {
        "prestamos": filas,
        "total": len(filas),                        # contador delegado
        "atrasados": por_estado["atrasado"],
        "total_multas": sum(p["multa"] for p in filas),  # acumulador delegado
        "por_estado": dict(por_estado),
    }
    return templates.TemplateResponse(request, "prestamos.html", context=contexto)

🦹 Villano: contar en la capa equivocada

Tres pecados que verás en código real: (1) traer 10.000 filas a Python para que SQL "no se canse" y contarlas con un bucle manual → el motor de BD cuenta millones de filas sin sudar, mándale el COUNT a SQL. (2) Contar en la plantilla con namespace() y |sum por todos lados → eso vivía en el contexto. (3) Recorrer en Python la lista dos veces (una para contar, otra para sumar) → len() + sum() lo hacen claro y sin bucles extra.

proceso completo — validar y registrar préstamos (automatizado) 
async def registrar_prestamos(request: Request, datos: list[dict]):
    # 1. FOR: recorre y valida cada préstamo que llegó del formulario
    validos, rechazados = [], []                      # dos acumuladores de listas
    for prestamo in datos:
        if prestamo["dias_atraso"] < 0:
            rechazados.append(prestamo)               # acumular rechazos
        else:
            validos.append(prestamo)                  # acumular válidos

    # 2. Los inserto en la BD de uno en uno (for sobre los válidos)
    for p in validos:
        await conn.execute(
            "INSERT INTO prestamos (estudiante, libro, dias_atraso, multa) VALUES ($1, $2, $3, $4)",
            p["estudiante"], p["libro"], p["dias_atraso"], p["multa"],
        )

    # 3. Reporte con contadores delegados al lenguaje
    return {"registrados": len(validos), "rechazados": len(rechazados)}

💡 Checklist del proceso automatizado

  • ¿El proceso repite algo? → for ... in una vez, no copy-paste.
  • ¿Se repite "hasta que pase algo"? → while con avance garantizado.
  • ¿Hay un "¿cuántos?" o "¿cuánto?" → len()/sum()/SQL, no bucle manual.
  • ¿Es por categorías? → Counter en Python o GROUP BY en SQL.
  • ¿La plantilla necesita ese número? → llega por el context, calculado.
