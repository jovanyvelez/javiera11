0.1 · Dónde vive cada cosa

Una aplicación web tiene tres capas, y cada una habla un idioma distinto. En las clases 1 a 3 escribiste la primera. La segunda —la que decides ahora— es la que decide de verdad.

El navegador
HTML, CSS y JavaScript. Es lo que el usuario ve y con lo que interactúa. Todo lo que vive aquí es público: cualquiera que abra las herramientas de desarrollo lo puede leer y modificar.
El servidor
Python. Aquí viven las reglas: qué datos son válidos, cuánto cuesta un préstamo, si el estudiante puede pedir tres libros o cinco. Nadie ve este código desde fuera, y por eso es el lugar donde se decide lo que es verdad.
La base de datos
Dónde se guardan los registros. El servidor le pregunta y el servidor responde; el navegador nunca habla con ella directamente.
Distinción — por qué el backend necesita un lenguaje «de verdad»

En el navegador, un error en JavaScript molesta a un usuario. En el servidor, un error en la validación puede dejar sin registrar un préstamo, duplicar un cobro o dejar abierta una puerta que no debería estarlo. Por eso el lenguaje del servidor se elige pensando en cómo se lee, en cómo se detectan los errores y en cómo se documenta. Python fue diseñado con esa prioridad desde el principio: se lee casi como una frase.

Variables y tipos de datos

Todo lo que un programa hace es guardar datos y transformarlos. Esta unidad construye el vocabulario con el que se nombran esos datos, explica de qué tipos existen y qué significa exactamente que Python no te obligue a declararlos.

1.1 · Una variable es una etiqueta

En Python, una variable no es una caja con un contenido: es una etiqueta pegada a un valor. El valor puede ser un número, un texto, una lista o un diccionario. La etiqueta se puede mover: apuntar a otro valor, o dejar de apuntar al anterior.

ejemplo — la etiqueta se mueve 
estudiante = {"nombre": "Ana Torres", "edad": 17}

# La etiqueta "otro" se mueve; "estudiante" sigue apuntando al primer diccionario
otro = estudiante
otro = {"nombre": "Luis Díaz", "edad": 18}

print(estudiante["nombre"])   # Ana Torres — "otro" no lo cambió
print(otro["nombre"])         # Luis Díaz
Nota — aquí todavía no hay clases

Para entender una etiqueta no necesitas objetos: un diccionario es un valor como cualquier otro. Las class, los objetos y self llegan en la clase 6B, después de funciones y métodos. En esta clase solo importa que la etiqueta apunta a un valor.

Nombre válido
Letras, dígitos y guiones bajos; no puede empezar por un dígito; no puede ser una palabra reservada. La convención de Python es snake_case: dias_solicitados.
Palabras reservadas
if, else, for, while, class, def, import, return, True, False, None… No se pueden usar como nombre.
Constante
Una variable que no debería cambiar. No hay ninguna palabra clave que lo imponga: es una convención escribirla en mayúsculas, MAX_DIAS = 30.

Sirve para lo que parece: len(disponible) da 1 cuando el libro está disponible, y 0 cuando no.

Nota — las comparaciones se pueden encadenar

Python permite escribir 0 <= dias <= 30 en una sola línea, y funciona exactamente como parece: se cumple si las dos condiciones se cumplen. En la mayoría de lenguajes habría que escribir dias >= 0 and dias <= 30. Se lee tan bien que conviene usarlo siempre que se pueda.

Precisión — == no es =

= asigna: dias = 7 guarda el valor 7 en la variable. == compara: dias == 7 pregunta si lo que hay dentro de la variable es 7, y devuelve True o False. Es el error más frecuente de quien empieza, y el mensaje de error que produce Python ayuda: SyntaxError apunta a la línea exacta.

En Python no hace falta escribir if disponible == True. Basta con if disponible. El intérprete decide si un valor es «verdadero» o «falsy» usando una regla sencilla: solo unos pocos valores son falsos.

1.5 · Convertir texto en número

La función input() devuelve siempre texto, aunque el usuario escriba 7. Eso es deliberado: el teclado solo produce caracteres. Convertir es responsabilidad del programa.

ejemplo — leer y convertir 
dias = input("¿Cuántos días quieres? ")
print(type(dias))          # <class 'str'> — siempre texto

dias = int(dias)                      # ahora sí es un entero
print(dias + 1)                  # 8
Advertencia — lo que pasa si el usuario escribe letras

int("siete") no da 0: lanza un ValueError y el programa se detiene. Y int("3.5") también lanza el error, porque el texto "3.5" no representa un entero. Este error es tan común que merece una regla: siempre que leas un número del usuario, espera un ValueError. En la unidad 3 se ve cómo capturarlo.

Precisión — round() no redondea como en la escuela

Python redondea al par más cercano, no siempre hacia arriba: round(0.5) da 0, round(1.5) da 2 y round(2.5) da 2. Se llama «redondeo del banquero» y evita el sesgo sistemático de siempre subir. No es un error: es una decisión deliberada. Si necesitas el redondeo escolar, escribe math.floor(valor + 0.5).

Y una segunda precisión, de la misma familia: los decimales se guardan en binario, así que 0.1 + 0.2 no da exactamente 0.3. Por eso, cuando se comparan decimales, hay que comparar con una tolerancia, no con igualdad.

1.6 · Anotaciones de tipo: el contrato

Como Python no obliga a declarar el tipo, nada te impide equivocarte al escribirlo. Las anotaciones de tipo son la forma moderna de declararlo: se añaden después del nombre, con dos puntos.

ejemplo — anotaciones modernas 
titulo: str = "El principito"
dias: int = 7
precio: float = 3.5
disponible: bool = True

# "int o nada": se escribe con | desde Python 3.10
prestamo_pendiente: int | None = None

# Las anotaciones de colecciones también son modernas
prestamos: list[str] = []
indice: dict[str, int] = {}
Distinción — anotar no es convertir

La anotación no convierte nada. Si escribes edad: int = "17", Python no da ningún error al ejecutar el programa: la variable contiene un texto y punto. La anotación es una declaración de intenciones que lees tú y, sobre todo, leen las herramientas de análisis estático.

Consecuencia práctica: las anotaciones solo dan resultado cuando hay alguien —o algo— que las compruebe. En Python 3.14 las anotaciones se evalúan de forma perezosa por defecto, así que escribir list[str] no cuesta nada aunque el entorno no tenga esa versión.

Sintaxis esencial de Python

Un lenguaje es un contrato de forma. Esta unidad recorre lo mínimo imprescindible para que un archivo de Python sea legible por otra persona: cómo se marcan los bloques, cómo se escriben los textos, cómo se entra y se sale, y qué herramientas trae el lenguaje ya incorporadas.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: script con entrada y salida

2.1 · La indentación es la sintaxis

En la mayoría de los lenguajes, un bloque se delimbra con llaves: { }. En Python no hay llaves: el bloque se delimita con la indentación. Lo que está sangrado pertenece a la instrucción que lo precede.

ejemplo — el bloque y la sangría 
prestamos_disponibles = 3

if prestamos_disponibles > 0:
    print("Hay libros disponibles")
    if prestamos_disponibles > 2:
        print("Y son varios")
else:
    print("No hay ninguno")
Los dos puntos
El : al final de la línea abre un bloque. Lo que viene después, más sangrado, es su contenido.
Cuatro espacios
Es la convención de Python (PEP 8). Nunca mezcles tabuladores y espacios: Python lanza un TabError y no te deja adivinar qué quiso decir el archivo.
El final de un bloque
Se deduce de la siguiente línea con menos sangrado. No hay llaves ni palabra de cierre: la sangría dice dónde acaba.
Nota — la sangría es una decisión del editor, no tuya

Nunca escribas los espacios a mano. Configura el editor para que Enter añada automáticamente la sangría del bloque anterior, y para que la tecla de tabulación inserte espacios. En VS Code, el ajuste es Espacios: 4 en la barra de estado. La mayoría de los editores modernos traen un formateador que deja el archivo bien indentado con un comando.

2.2 · Comentarios y documentación

ejemplo — comentarios y cadena de documentación 
# Un comentario: empieza con almohadilla y acaba en el salto de línea
MAX_DIAS = 30  # también puede ir al final de una línea


def dias_permitidos(tipo: str) -> int:
    """Devuelve cuántos días se pueden pedir según el tipo de libro.

    Las cadenas de documentación se abren con tres comillas y son el
    texto que muestra help() y los editores de código.
    """
    if tipo == "normal":
        return 15
    return 30
Precisión — la diferencia entre un comentario y una cadena de documentación

Un comentario con # es para quien lee el código. Una cadena de documentación —las tres comillas— es documentación del objeto: queda guardada en el programa, aparece con help(dias_permitidos) y la lee cualquier herramienta que genere automáticamente la referencia de la API. En un proyecto de backend, esa documentación es lo que verá el equipo que use tu código. Se escribe en la primera línea de la función o de la clase, y explica qué hace, no cómo está hecho.

2.3 · Las cadenas y las cadenas con formato

Un texto en Python va entre comillas. Da igual si son simples ('texto') o dobles ("texto"); lo único que no se puede es empezar con una y terminar con la otra. Las tres comillas permiten escribir texto de varias líneas.

ejemplo — cadenas con formato 
titulo = "El principito"
autor = "Antonio Machado"
dias = 15
precio = 3.5

# La forma moderna: la cadena con formato, marcada con f delante
print(f"{titulo}, de {autor}")
print(f"{dias} días")

# Formato de un número con dos decimales
print(f"Precio: {precio:.2f}")

# Alineación a la derecha en 12 columnas
print(f"{titulo:>12}")

# Separador de millares
print(f"{1234567:,}")

# El especificador = muestra además el nombre de la variable
print(f"{dias=}")   # dias=15
Precisión — las llaves admiten expresiones, y a veces hay que alternar las comillas

Dentro de las llaves de una cadena con formato se puede escribir cualquier expresión, no solo un nombre: f"{len(titulo)} caracteres". Si la expresión contiene comillas, hay que tener cuidado con las comillas exteriores. Desde Python 3.12 se puede repetir la misma comilla sin problema —f"{d['clave']}"—, pero en versiones anteriores había que alternar: esa forma no era válida y había que escribir f'{d["clave"]}'. La clase usa siempre la forma que funciona en cualquier versión reciente.

Aplicación — por qué .strip() va siempre después de input()

El usuario escribe «Ana Torres⏎» y el teclado manda también el salto de línea. Sin .strip(), la variable contiene un espacio invisible al principio y otro al final, y cualquier comparación con el nombre exacto fallará. Es un detalle de una línea que evita un error de una hora.

2.5 · Desempaquetado y herramientas ya incorporadas

Python trae muchas operaciones resueltas. No hace falta escribirlas: solo hay que llamarlas bien.

ejemplo — desempaquetado y funciones incorporadas 
# Desempaquetar: un valor a la vez, sin posiciones
a, b = 1, 2
a, b = b, a                       # intercambio en una sola línea

# Recorrer con el número de posición
for posicion, titulo in enumerate(["A", "B"], start=1):
    print(f"{posicion}. {titulo}")

# Recorrer dos listas a la vez
for titulo, dias in zip(["A", "B"], [7, 15]):
    print(f"{titulo}: {dias} días")

print(sum([3, 7, 15]))     # 25
print(max([3, 7]))             # 7
print(sorted(["b", "a"]))        # ['a', 'b']
print(abs(-5))                     # 5
print(divmod(7, 2))                # (3, 1) — cociente y resto
print(any([False, True]))            # True — alguno es verdadero
print(all([True, True]))             # True — todos son verdaderos
Nota — sorted() no modifica la lista original

sorted(lista) devuelve una lista nueva y deja la original intacta; para cambiar la original hay que escribir lista.sort(). La diferencia importa cuando la lista es un dato que viene de otro sitio: sorted() es más seguro, porque no puede sorprender a quien la pasó.

Unidad 03 · El control

Estructuras de control

Un programa que solo calcula en línea recta no decide nada. Esta unidad le da las tres herramientas que necesita: decidir, repetir y agrupar. Y cierra con la manera correcta de reaccionar cuando algo sale mal.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: control del flujo completo

3.1 · Decidir: if, elif, else

La estructura más básica del lenguaje. La condición se evalúa: si resulta verdadera, se ejecuta el bloque; si no, se busca el siguiente elif, y si ninguno se cumple, se ejecuta el else.

ejemplo — la decisión completa 
dias = 20

if dias > 30:
    print("El préstamo es demasiado largo")
elif dias > 15:
    print("Préstamo largo: pide autorización")
elif dias > 0:
    print("Préstamo normal")
else:
    print("No hay préstamo")
Precisión — elif, nunca else if

En C, Java o JavaScript se escribe else if. En Python no: se escribe elif. Y el orden importa, porque se evalúa de arriba abajo y se detiene en la primera condición que se cumple. Si el primer if fuera dias > 0, los otros dos bloques nunca se ejecutarían. Al escribir una cadena de condiciones, conviene ordenarlas de la más restrictiva a la más general.

3.2 · match: cuando el valor tiene pocas formas posibles

Cuando un valor puede estar en un conjunto pequeño y conocido de estados, el match se lee mejor que una cadena de if. Está disponible desde Python 3.10.

ejemplo — el estado de un préstamo 
estado = "devuelto_tarde"

match estado:
    case "en_prestamo":
        print("El libro está fuera de la biblioteca")
    case "devuelto":
        print("El libro ya volvió")
    case "devuelto_tarde":
        print("Hay que pagar la multa")
    case _:
        print("Estado desconocido")
case _
El comodín: se cumple si ningún caso anterior coincidió. Es el equivalente al else final.
Sin break
A diferencia de C o JavaScript, no hay salto entre casos: al terminar un case se sale del match. No se puede «caer» al siguiente caso por accidente.
Guardas
case _ if dias > 30: añade una condición extra a un caso.
Nota — cuándo usar match y cuándo if

match funciona bien cuando comparas un valor contra casos concretos. if funciona bien cuando lo que evalúas son condiciones distintas (dias > 30, dias > 15). No es que uno sea mejor: es que cada uno dice algo distinto. Y las dos cosas se pueden mezclar sin problema.

Advertencia — while True sin salida es un ciclo infinito

Si la condición de un while nunca deja de cumplirse, el programa se queda colgado. La forma segura es escribir siempre un break dentro. Y un detalle práctico: si el programa no parece terminar, comprueba primero si te has olvidado de actualizar la variable de control —el intentos += 1 del ejemplo—, porque eso es lo que hace avanzar el ciclo.

3.4 · Las comprensiones

Una comprensión es un ciclo escrito en una sola línea, que produce una lista. Se lee de izquierda a derecha: «toma esto, y para cada elemento, guarda esto».

ejemplo — comprensiones 
prestamos = ["El principito", "Cien años", "Pedro Páramo"]
dias = [15, 7, 30]

# Lista: cada título en mayúsculas
mayusculas = [titulo.upper() for titulo in prestamos]

# Lista con una condición
largos = [d for d in dias if d > 10]

# Diccionario: de título a días
indice = {titulo: d for titulo, d in zip(prestamos, dias)}

print(mayusculas)
print(largos)
print(indice["Cien años"])
Precisión — cuándo no usar una comprensión

Una comprensión sustituye a un ciclo de una sola instrucción. Si el cuerpo necesita dos o más pasos —un if y una llamada, por ejemplo— ya no cabe, y la versión con comprensión se vuelve ilegible. La regla práctica: si tienes que escribir la comprensión en dos líneas, escribe el ciclo normal. Una comprensión larga es difícil de leer y más difícil de depurar.

3.5 · El operador morsa

A veces la condición que decide el bucle es un cálculo que te gustaría reutilizar. El operador morsa := asigna y devuelve el valor en una sola expresión.

ejemplo — el operador morsa 
texto = "El principito"

if (longitud := len(texto)) > 10:
    print(f"{longitud} caracteres: es un título largo")
Nota — el nombre en inglés

El operador := se llama «morsa» (walrus operator, en inglés), por su forma de sideways. Su uso más común es exactamente el del ejemplo: evitar calcular dos veces lo mismo. Se escribe := sin espacios y solo puede usarse dentro de una expresión, entre paréntesis.

3.6 · Cuando algo sale mal: try

Un backend recibe datos de desconocidos. Algún día alguien escribirá «quince» donde esperaba un número. Si el programa no está preparado, se cae entero; si está preparado, responde con un mensaje claro. Eso es lo que hace el bloque try.

ejemplo — las cuatro partes del manejo de errores 
try:
    dias = int(input("Días: "))
except ValueError:
    print("Eso no es un número. Escribe un entero.")
else:
    print(f"Préstamo de {dias} días registrado")
finally:
    print("Fin de la operación")
try
El bloque que puede fallar. Solo lo que está dentro.
except
Lo que se hace cuando falla. Se escribe el tipo de error concreto: ValueError, TypeError, KeyError, ZeroDivisionError.
else
Se ejecuta solo si el try no falló. Es donde va el código que depende del valor que se acaba de leer.
finally
Se ejecuta siempre, haya pasado lo que haya. Es el sitio para cerrar archivos o escribir en el registro.
Advertencia — nunca captures «cualquier error»

Escribir except: a secas, o except Exception:, para «no complicarse» es un error grave: también captura errores de programación que no tienen nada que ver con lo que el usuario escribió, y los esconde. Si el error es de tipado, el programa tiene un fallo que hay que arreglar, no un dato malo que hay que perdonar. Captura solo el error que sabes que puede ocurrir, y deja que los demás se vean.

Aplicación — lanzar un error propio

Cuando tu código detecta un dato que no debería aceptarse, no lo corrijas en silencio: lanza un error con un mensaje que explique qué pasó. raise ValueError("El préstamo no puede ser de 0 días"). Esa línea corta el flujo, y el mensaje es lo que el usuario o el registro del servidor acaba viendo. En las clases siguientes, la biblioteca de validación hará esto mismo por ti y de forma automática.

Modelo de respuesta

No es la única manera de resolverlo. Lo que importa es que las tres reglas —rango de días, umbral de autorización y multa— estén escritas una sola vez y que la validación no se pueda saltar.

calculadora.py — solución de referencia 
"""Calculadora de préstamos de la biblioteca del colegio."""

MAX_DIAS = 30
DIAS_SIN_AUTORIZACION = 15
MULTA_POR_DIA = 500


def leer_dias() -> int:
    """Pide los días del préstamo y vuelve a preguntar si no son válidos."""
    while True:
        texto = input("¿Cuántos días dura el préstamo? ")
        try:
            dias = int(texto)
        except ValueError:
            print("Eso no es un número entero. Escribe solo el número.")
            continue
        if not 1 <= dias <= MAX_DIAS:
            print(f"El préstamo debe durar entre 1 y {MAX_DIAS} días.")
            continue
        return dias


def mostrar_resumen(titulo: str, estudiante: str, dias: int) -> None:
    """Imprime el resumen del préstamo."""
    print()
    print("=== Resumen del préstamo ===")
    print(f"Libro:      {titulo}")
    print(f"Estudiante: {estudiante}")
    print(f"Días:       {dias}")
    if dias > DIAS_SIN_AUTORIZACION:
        print("Aviso: este préstamo necesita autorización del coordinador.")
    print(f"Multa por día de retraso: {MULTA_POR_DIA} pesos")


def main() -> None:
    titulo = input("Título del libro: ").strip()
    estudiante = input("Nombre del estudiante: ").strip()
    dias = leer_dias()
    mostrar_resumen(titulo, estudiante, dias)


if __name__ == "__main__":
    main()

Una variación habitual: muchos programadores alivian el bloque try usando int() dentro de una función aparte que devuelve None cuando falla. Es correcta, pero exige una comprobación extra en el llamador. La versión de arriba es más simple porque el bucle vive dentro de la función que valida.

5.3 · Ejemplo guiado 5.1 — Tres decisiones que hay que tomar antes de escribir (10 min)

Ejemplo guiado 5.1 — Decidir antes de teclear 10 min

El enunciado de la biblioteca es corto, pero esconden tres decisiones de programación. Resolverlas por escrito antes de abrir el editor es lo que separa un programa que funciona de uno que funciona bien.

1
¿Qué entra y qué sale?

Entran tres datos: título, estudiante y días. Sale un texto: el resumen. Ningún dato intermedio se muestra a medio camino. Si decides esto, ya sabes que leer_dias() devuelve un número y que mostrar_resumen() no devuelve nada.

Regla: una función que devuelve algo se puede probar sola. Una que solo imprime, no. Por eso la que valida devuelve el valor y la que muestra no devuelve nada.

2
¿Quién valida?

La validación puede vivir dentro de leer_dias() o repartida por el programa. Si vive dentro de la función, es imposible saltársela: quien llama recibe un int válido o no recibe nada. Esa es la diferencia entre validar y confiar en que el usuario se portó bien.

3
¿Qué hace main()?

Solo tres cosas, en este orden: pedir el título, pedir el estudiante, pedir los días. Y después, mostrar el resumen. Todo lo demás —validar, calcular, imprimir— vive en las funciones. main() se lee como la lista de pasos del programa, y esa es exactamente su función.

Por qué importa: cuando el programa crezca, main() seguirá siendo legible. Un main() de 200 líneas es la señal de que las funciones están mal repartidas.

5.4 · La validación que no se puede saltar

La parte más difícil del ejercicio es el bucle de validación. La estructura tiene tres piezas que ya conoces, montadas una dentro de otra.

calculadora.py — leer y validar los días 
def leer_dias() -> int:
    """Pide los días del préstamo y vuelve a preguntar si no son válidos."""
    while True:
        texto = input("¿Cuántos días dura el préstamo? ")
        try:
            dias = int(texto)
        except ValueError:
            print("Eso no es un número entero. Escribe solo el número.")
            continue
        if not 1 <= dias <= MAX_DIAS:
            print(f"El préstamo debe durar entre 1 y {MAX_DIAS} días.")
            continue
        return dias
Distinción — continue y break dentro del bucle

Los dos caminos de error se resuelven con palabras distintas. Un continue vuelve al principio del bucle: el programa vuelve a preguntar, que es lo que queremos cuando el usuario se equivocaba. Un break sale del bucle: tiene sentido cuando ya tienes el dato bueno y solo querías abandonar una búsqueda. En leer_dias() ninguno de los dos caminos usa break: cuando el valor es válido, la función devuelve y el bucle termina solo.

Advertencia — el error que se repite cada tres minutos

Si el try no tiene un except que capture ValueError, el programa se cae en cuanto alguien escriba letras. Y si el except captura Exception a secas, el programa nunca se caerá… pero tampoco te avisará de los errores de programación, que son los que de verdad hay que arreglar. Captura el error que sabes que puede ocurrir, y solo ese.

6.1 · El enunciado

Ejercicio

Analizador de un mes de préstamos

La biblioteca guarda un registro de cada préstamo del mes. Escribe un programa, analizador.py, que lea ese registro y responda cinco preguntas: cuántos préstamos hubo, qué libro se prestó más, cuál fue el promedio de días, cuántos siguen sin devolverse y cuántos estudiantes distintos participaron.

Restricción La última línea del archivo es if __name__ == "__main__":

Requisitos

  1. Cinco funciones de cálculo: total_prestamos(), titulo_mas_prestado(), promedio_dias(), prestamos_vencidos() y resumen(). Cada una recibe la lista de préstamos y devuelve un valor.
  2. Una función main() que llame a las otras, muestre los cinco indicadores y después liste los préstamos pendientes, uno por línea.
  3. Anotaciones de tipo en todas las funciones y una cadena de documentación en cada una.

Modelo de respuesta

La parte interesante de este ejercicio es titulo_mas_prestado(): cuenta cuántas veces aparece cada título y devuelve el mayor conteo. La forma de hacerlo con un contador en un diccionario es la que se usa en la práctica.

analizador.py — solución de referencia 
"""Analizador de un mes de préstamos de la biblioteca."""

PRESTAMOS = [
    {"estudiante": "Ana Torres", "titulo": "El principito", "dias": 15, "devuelto": True},
    {"estudiante": "Luis Díaz", "titulo": "Cien años de soledad", "dias": 30, "devuelto": False},
    {"estudiante": "Sara Ríos", "titulo": "El principito", "dias": 7, "devuelto": True},
    {"estudiante": "Julián Mora", "titulo": "Pedro Páramo", "dias": 22, "devuelto": False},
    {"estudiante": "Ana Torres", "titulo": "Pedro Páramo", "dias": 9, "devuelto": True},
    {"estudiante": "Carla Restrepo", "titulo": "La casa de los espíritus", "dias": 12, "devuelto": True},
]


def total_prestamos(prestamos: list[dict]) -> int:
    """Cuenta cuántos préstamos hay en el registro."""
    return len(prestamos)


def titulo_mas_prestado(prestamos: list[dict]) -> str | None:
    """Devuelve el título del libro que más veces se prestó."""
    conteo: dict[str, int] = {}
    for prestamo in prestamos:
        titulo = prestamo["titulo"]
        conteo[titulo] = conteo.get(titulo, 0) + 1
    if not conteo:
        return None
    return max(conteo, key=lambda titulo: conteo[titulo])


def promedio_dias(prestamos: list[dict]) -> float:
    """Calcula el promedio de días de préstamo."""
    if not prestamos:
        return 0.0
    return sum(p["dias"] for p in prestamos) / len(prestamos)


def prestamos_vencidos(prestamos: list[dict]) -> list[dict]:
    """Devuelve los préstamos que todavía no se devolvieron."""
    return [p for p in prestamos if not p["devuelto"]]


def resumen(prestamos: list[dict]) -> dict:
    """Reúne todos los indicadores del mes en un solo diccionario."""
    return {
        "total": total_prestamos(prestamos),
        "titulo_mas_prestado": titulo_mas_prestado(prestamos),
        "promedio_dias": promedio_dias(prestamos),
        "vencidos": len(prestamos_vencidos(prestamos)),
        "estudiantes": len({p["estudiante"] for p in prestamos}),
    }


def main() -> None:
    datos = resumen(PRESTAMOS)
    print("=== Resumen del mes ===")
    print(f"Préstamos registrados:  {datos['total']}")
    print(f"Libro más prestado:     {datos['titulo_mas_prestado']}")
    print(f"Promedio de días:       {datos['promedio_dias']:.1f}")
    print(f"Préstamos sin devolver: {datos['vencidos']}")
    print(f"Estudiantes distintos:  {datos['estudiantes']}")

    print("\nPendientes:")
    for prestamo in prestamos_vencidos(PRESTAMOS):
        print(f"  - {prestamo['titulo']} ({prestamo['estudiante']})")


if __name__ == "__main__":
    main()

Una variación más corta para el título más prestado, aunque pierde el orden estable en caso de empate:

analizador.py — la variante breve 
def titulo_mas_prestado(prestamos: list[dict]) -> str | None:
    """Variante breve: cuenta con count() y se queda con el mayor conteo."""
    titulos = [p["titulo"] for p in prestamos]
    if not titulos:
        return None
    return max(set(titulos), key=titulos.count)

Por qué la primera es mejor: max() con key=titulos.count recorre un set, y el orden de un conjunto no está garantizado; en un empate puede devolver cualquiera de los dos títulos. Con el diccionario de conteo, el orden es el de inserción y el resultado es siempre el mismo. En un informe que se imprime dos veces, eso no es un detalle menor.

Nota — por qué un diccionario y no cinco variables sueltas

Podrías guardar estudiante_1, titulo_1, dias_1… y añadir un _2, un _3. Funciona hasta el tercer préstamo. En el cuarto, el código se vuelve imposible de escribir y de leer. El diccionario resuelve el problema de raíz: el número de registros deja de estar escrito en el código, y por eso el mismo programa sirve para seis préstamos o para seis mil.

6.3 · Recorrer un diccionario

Un diccionario se recorre de dos formas, y conviene saber cuál se está usando en cada momento.

ejemplo — recorrer diccionarios 
prestamo = {"estudiante": "Ana Torres", "titulo": "El principito", "dias": 15}

# 1. Por las claves: devuelve el nombre de cada clave
for clave in prestamo:
    print(clave)                  # estudiante, titulo, dias

# 2. Por los pares: devuelve la clave y el valor juntos
for clave, valor in prestamo.items():
    print(clave, "=", valor)

# 3. Acceder a una clave que puede no existir
print(prestamo.get("multa", 0))      # 0 — el valor por defecto
print(prestamo["multa"])                # KeyError — el programa se cae
Precisión — prestamo["multa"] no es lo mismo que prestamo.get("multa")

Con corchetes, si la clave no existe, Python lanza KeyError y el programa se detiene. Con .get(), si la clave no existe, devuelve el valor por defecto que le indiques. En un backend que recibe datos de fuera, esa diferencia es la que separa «este registro no trae esa información» de «este programa tiene un fallo».

6.4 · Contar y quedarse con el máximo

Contar cuántas veces aparece cada título es un problema clásico: se recorre la lista y se guarda el conteo en un diccionario. Después, se busca el mayor conteo.

analizador.py — contar títulos y quedarse con el máximo 
def titulo_mas_prestado(prestamos: list[dict]) -> str | None:
    """Devuelve el título del libro que más veces se prestó."""
    conteo: dict[str, int] = {}
    for prestamo in prestamos:
        titulo = prestamo["titulo"]
        conteo[titulo] = conteo.get(titulo, 0) + 1
    if not conteo:
        return None
    return max(conteo, key=lambda titulo: conteo[titulo])

La línea final merece un aparte. max(conteo, key=...) no compara los títulos: compara lo que devuelve la función. Es decir, busca la clave cuyo conteo es el más alto, y devuelve la clave.

Aplicación — key= es un comparador, no un filtro

max() y min() aceptan key=, y lo que reciben es una función que dice qué comparar. En el ejemplo, la clave es lambda titulo: conteo[titulo]: para cada título, mira su conteo; el título con el conteo más alto gana. Con min() y la misma función se obtiene el título menos prestado. Es el mismo mecanismo, en dos direcciones.

Modelo de respuesta

El módulo completo, tal como quedaría en prestamos.py. Las seis funciones de abajo son las que usará el servidor de la clase siguiente.

prestamos.py — solución de referencia 
"""Módulo de préstamos de la biblioteca del colegio.

Reúne el modelo de datos, la validación de las reglas y el resumen del mes.
"""

MAX_DIAS = 30
DIAS_SIN_AUTORIZACION = 15
MULTA_POR_DIA = 500


def validar_dias(dias: int) -> int:
    """Comprueba que la duración del préstamo sea admisible.

    Devuelve los días si la regla se cumple. Si no se cumple, lanza un error
    explicando qué está mal.
    """
    if not isinstance(dias, int):
        raise TypeError("Los días deben ser un número entero.")
    if not 1 <= dias <= MAX_DIAS:
        raise ValueError(f"El préstamo debe durar entre 1 y {MAX_DIAS} días.")
    return dias


def crear_prestamo(estudiante: str, titulo: str, dias: int) -> dict:
    """Arma el registro de un préstamo nuevo.

    Devuelve un diccionario con cuatro claves: estudiante, titulo, dias y devuelto.
    """
    if not estudiante.strip():
        raise ValueError("El nombre del estudiante no puede estar vacío.")
    if not titulo.strip():
        raise ValueError("El título del libro no puede estar vacío.")
    return {
        "estudiante": estudiante.strip(),
        "titulo": titulo.strip(),
        "dias": validar_dias(dias),
        "devuelto": False,
    }


def registrar_prestamo(registro: list[dict], prestamo: dict) -> list[dict]:
    """Añade el préstamo al registro y devuelve la lista actualizada."""
    registro.append(prestamo)
    return registro


def titulo_mas_prestado(registro: list[dict]) -> str | None:
    """Devuelve el título del libro que más veces se prestó."""
    conteo: dict[str, int] = {}
    for prestamo in registro:
        titulo = prestamo["titulo"]
        conteo[titulo] = conteo.get(titulo, 0) + 1
    if not conteo:
        return None
    return max(conteo, key=lambda titulo: conteo[titulo])


def prestamos_vencidos(registro: list[dict]) -> list[dict]:
    """Devuelve los préstamos que todavía no se devolvieron."""
    return [p for p in registro if not p["devuelto"]]


def resumen(registro: list[dict]) -> dict:
    """Calcula los indicadores del mes."""
    promedio = sum(p["dias"] for p in registro) / len(registro) if registro else 0.0
    return {
        "total": len(registro),
        "promedio_dias": promedio,
        "titulo_mas_prestado": titulo_mas_prestado(registro),
        "vencidos": len(prestamos_vencidos(registro)),
    }


def main() -> None:
    registro: list[dict] = []

    while True:
        print("\n1. Registrar un préstamo")
        print("2. Ver el resumen del mes")
        print("3. Salir")
        opcion = input("Elige una opción: ").strip()

        if opcion == "3":
            print("Hasta pronto.")
            break

        if opcion == "2":
            datos = resumen(registro)
            if datos["total"] == 0:
                print("Todavía no hay préstamos registrados.")
            else:
                print(f"Préstamos registrados:  {datos['total']}")
                print(f"Promedio de días:       {datos['promedio_dias']:.1f}")
                print(f"Libro más prestado:     {datos['titulo_mas_prestado']}")
                print(f"Sin devolver:           {datos['vencidos']}")
            continue

        if opcion == "1":
            nombre = input("Nombre del estudiante: ").strip()
            titulo = input("Título del libro: ").strip()
            try:
                dias = int(input("Días del préstamo: "))
            except ValueError:
                print("Los días deben escribirse como número entero.")
                continue
            try:
                prestamo = crear_prestamo(nombre, titulo, dias)
            except (TypeError, ValueError) as error:
                print(f"No se pudo registrar: {error}")
                continue
            registrar_prestamo(registro, prestamo)
            print("Préstamo registrado.")
            continue

        print("Opción no válida.")


if __name__ == "__main__":
    main()

El párrafo escrito (modelo): el enunciado pedía un módulo, no un programa suelto, así que decidí que ninguna función imprimiera: todas devuelven valores y es main() la que muestra los resultados. Aparté la validación del menú y la puse en validar_dias(), porque desde ahí la regla no se puede saltarse. Mantuve el registro en memoria porque todavía no hay base de datos; cuando la haya, esa lista pasará a ser una consulta y las funciones de cálculo no tendrán que cambiar.

7.3 · Las dos reglas que un backend no puede saltarse

Hay una diferencia entre un programa de escritorio y un servidor. En el escritorio, si el usuario escribe mal, el problema es suyo y el programa puede pedirle que lo repita. En un servidor, los datos llegan de la red, y lo que llega mal hay que rechazarlo con un mensaje que el otro programa pueda entender. Para eso existe raise.

prestamos.py — la función que valida 
def validar_dias(dias: int) -> int:
    """Comprueba que la duración del préstamo sea admisible.

    Devuelve los días si la regla se cumple. Si no se cumple, lanza un error
    explicando qué está mal.
    """
    if not isinstance(dias, int):
        raise TypeError("Los días deben ser un número entero.")
    if not 1 <= dias <= MAX_DIAS:
        raise ValueError(f"El préstamo debe durar entre 1 y {MAX_DIAS} días.")
    return dias
Precisión — un detalle que casi nadie ve: True también es un entero

La comprobación isinstance(dias, int) acepta True, porque bool es una subclase de int — lo viste en la unidad 1 —. Es decir, validar_dias(True) devuelve True en lugar de fallar. En este módulo no importa: True vale 1 y 1 es un préstamo válido. Pero es el tipo de detalle que se convierte en un error real cuando el dato viene de fuera y nadie revisó lo que se guardó. Conviene tenerlo en la cabeza.

Aplicación — el contrato entre dos programas

Cuando crear_prestamo() lanza ValueError, no está fallando: está cumpliendo su parte del contrato. Dice: «o te devuelvo un préstamo válido, o te explico por qué no hay préstamo». Quien llama decide qué hacer con ese error. En el taller el menú lo captura con except (TypeError, ValueError) y lo muestra; en la clase siguientes, una biblioteca de validación hará exactamente esto mismo por ti, y además.

7.5 · Síntesis: siete ideas para llevarse

01

Una variable es una etiqueta: lo que importa no es el nombre, sino el valor al que apunta ahora mismo.

02

La anotación de tipo no convierte nada: es una declaración de intenciones que comprueban las herramientas, no el intérprete.

03

La indentación es la sintaxis, y el error de sangría es el más frecuente de quien empieza.

04

Los ciclos existen para repetir; las comprenciones existen para repetir una sola instrucción.

05

except es una puerta, no una aspiradora: se abre solo para el error que uno sabe que puede ocurrir.

06

Una función que devuelve se puede probar sola; una función que solo imprime, no. Por eso conviene devolver.

07

Un programa que se rompe con datos raros todavía no está terminado: la robustez también se diseña.
