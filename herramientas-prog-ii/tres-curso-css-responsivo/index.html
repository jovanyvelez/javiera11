⏱ 20 minutos 📄 Lectura y preparación 🧭 Producto: entorno listo

0.1 · El problema que el CSS no resuelve solo

La reacción natural ante una página que se ve mal en el celular es hacer una versión aparte para el celular: index-movil.html. Es la respuesta que se da por costumbre, y es una trampa por tres razones: duplica el trabajo, obliga a mantener dos versiones en paralelo y nunca termina. En cuanto alguien cambia un texto, hay que cambiarlo en dos sitios.

La respuesta correcta es otra: una sola página, y una descripción de en qué momento cambia cada cosa. Esa descripción es CSS. Un sitio responsive no tiene dos versiones: tiene una versión y un conjunto de reglas que dicen «a partir de aquí, esto se reorganiza».

Distinción — «responsive» no significa «versión para el celular»

Diseño responsivo no es «adaptar la página al teléfono». Es adaptar la página al ancho disponible, sea ese ancho el de un teléfono, el de una tableta en horizontal o el de un monitor de 27 pulgadas. La consequence práctica es que no se pregunta «¿cuál es el tamaño del celular?», sino «¿qué información sobra, o qué se vuelve ilegible, cuando el espacio aprieta?». La segunda pregunta tiene respuesta; la primera no, porque el ancho disponible varía más que la lista de dispositivos.

El editor

Está dentro de las DevTools y permite elegir un tamaño de pantalla concreto (390 × 844, 768 × 1024, 1440 × 900) y ver la página a ese ancho. Es la herramienta central de la unidad 2.

Bootstrap y sus sucesores resuelven problemas reales, pero usarlos sin saber qué hay debajo produce proyectos que se rompen en cuanto algo no está previsto. 0.4 · La estructura de hojas de estilo del proyecto

La clase 2 dejó un proyecto de FastAPI con plantillas en templates/. Esta clase añade la carpeta estilos/, dividida en tres archivos con una responsabilidad cada uno. La división no es puramente estética: es la forma más barata de evitar que dos reglas compitan por el mismo elemento.

estructura del proyecto 
biblioteca/
├── main.py                 ← la aplicación de FastAPI (clase 2)
├── templates/
│   ├── base.html            ← el esqueleto de todas las páginas
│   └── index.html           ← el catálogo
├── estilos/
│   ├── base.css             ← lo que aplica a todo el documento
│   ├── componentes.css      ← lo que aplica a las piezas (ficha, botón)
│   └── responsivo.css       ← lo que cambia con el ancho disponible
└── static/                  ← archivos que se sirven tal cual

Las tres hojas se enlazan desde templates/base.html, y el orden de esos enlaces es el orden de prioridad. No es una convención: es el mecanismo por el que el navegador decide a qué regla recurre cuando dos reglas compiten.

templates/base.html — el orden importa 
<link rel="stylesheet" href="/estilos/base.css">
<link rel="stylesheet" href="/estilos/componentes.css">
<link rel="stylesheet" href="/estilos/responsivo.css">
Precisión — por qué la carpeta static/

Los archivos que el navegador pide directamente (CSS, JavaScript, imágenes) se sirven desde static/. En FastAPI eso significa montar esa carpeta en la aplicación, algo que ya hace el esqueleto de la clase 2. Si un archivo CSS está en la raíz del proyecto y no en static/, el servidor respondirá con un 404 y la página aparecerá sin estilos: es el error más común al empezar, y su síntoma —«el CSS no se aplica»— no dice nada sobre la causa. Cuando una hoja no se aplique, lo primero es abrir la pestaña de red de las DevTools y comprobar si el archivo se descargó.

Unidad 01 · La medida

Una página, muchas pantallas

Antes de escribir la primera consulta de medios hay que decidir dos cosas: cómo se mide el espacio y cómo se reparte. Esta unidad construye el vocabulario con el que se toman esas decisiones, y explica por qué la pregunta correcta no es «¿qué tamaño tiene el celular?».

⏱ 30 minutos 📄 Lectura y análisis 🧭 Producto: criterio de medida

1.1 · La ventana de visualización

La primera decisión responsive no es de CSS: es de HTML. En la clase 2, el esqueleto base.html no incluía la etiqueta viewport. Sin ella, un teléfono interpretaba la página como si midiera 980 píxeles de ancho y luego la encogía para que cupiera en pantalla: el texto quedaba diminuto y el usuario tenía que ampliar con los dedos.

templates/base.html — la línea que no puede faltar 
<meta name="viewport" content="width=device-width, initial-scale=1">
width=device-width
El ancho de la ventana de visualización es el ancho real del dispositivo. Es lo que permite que una consulta de medios con min-width: 390px se active en un teléfono de 390 píxeles y no en uno de 980.
initial-scale=1
El contenido arranca a escala 1:1, sin que el navegador aplique su propio factor de reducción.
Precisión — no es lo mismo que «usar el ancho del dispositivo»

device-width mide el ancho del aparato, no el de la ventana que el usuario puede redimensionar. En un monitor de escritorio, device-width sigue siendo el ancho del monitor, así que una consulta con ese valor nunca se activaría por el hecho de que el usuario encogió la ventana. device-width pertenece a la era de los dispositivos con tamaños fijos; hoy se usa width, que es el ancho disponible. Por eso las consultas de medios bien escritas usan (min-width: …) sin device-.

1.2 · Tres formas de medir

Todo el diseño responsivo se decide en estas dos preguntas: ¿cuánto espacio ocupa esto? y ¿cómo se reparte el espacio que hay?. La primera tiene cuatro respuestas posibles, y cada una tiene un coste.

Maneras de expresar una medida
MedidaSe escribeCuándo usarlaSu riesgo
Absoluta width: 320px Detalles, bordes, iconos, la altura de un botón Se desborda cuando el espacio aprieta
Relativa al contenedor width: 100%
max-width: 68ch		 Cajas de contenido, columnas de una rejilla 100% sin tope se estira hasta el infinito
Relativa a la ventana 40vw, 100dvh Tipografía fluida, fondos a pantalla completa No distingue el móvil del escritorio
Fluida con topes clamp(1rem, 2vw + 0.8rem, 1.5rem) Títulos y cuerpos de texto Hay que entender qué significan sus tres valores

clamp() merece una explicación aparte, porque resuelve de una vez el problema de los dos extremos. Su firma es clamp(mínimo, valor-preferido, máximo): el navegador toma el valor preferido —que puede depender del ancho de la ventana— pero nunca baja del mínimo ni sube del máximo. En el ejemplo de la tabla, el título mide 1rem en un teléfono pequeño, crece con la ventana y se detiene en 1.5rem en un monitor.

estilos/base.css — tipografía fluida 
:root {
  --texto-base: clamp(1rem, 0.95rem + 0.2vw, 1.15rem);
}

body {
  font-size: var(--texto-base);
  line-height: 1.7;
}

.ficha__titulo {
  font-size: clamp(1.1rem, 1rem + 0.8vw, 1.6rem);
}
Nota — la altura de la ventana en el móvil

La unidad vh mide el 1 % de la altura de la ventana asumiendo que la barra de direcciones del navegador no existe. En un teléfono, esa barra aparece y desaparece, y durante el desplazamiento cambia el alto real disponible. Por eso existen unidades nuevas: dvh (dynamic) sigue el valor real en cada momento, y svh (small) toma siempre el más pequeño, que es el valor estable. Para una sección que ocupa toda la pantalla, min-height: 100dvh es la respuesta correcta en los navegadores actuales.

1.3 · Las dos herramientas de distribución

Medir es la mitad del trabajo; la otra mitad es repartir. CSS ofrece dos mecanismos para eso, y son complementarios, no alternativos.

Dos formas de colocar elementos
FlexboxRejilla (CSS Grid)
IdeaUna fila o una columna, y se reparte el espacioFilas y columnas a la vez, como una hoja de cálculo
EjesUno principal y otro transversalHorizontal y vertical, simétricos
Repartojustify-content, align-items, gap, flex: 1grid-template-columns, grid-template-rows, gap
Se usa cuandoAlinear botones en una barra, distributing el espacio de una cabeceraUn catálogo de tarjetas, la estructura general de la página
Distinción — la regla práctica

Si la decisión que estás tomando es «¿cuántas columnas y de qué ancho?», es rejilla. Si la decisión es «¿cómo se alinean estos tres elementos entre sí?», es flexbox. En la práctica se combinan: la rejilla decide la estructura de la página, y flexbox alinea el contenido dentro de cada celda.

Y hay un caso donde la decisión ni siquiera hace falta tomarla, porque CSS ya sabe resolverlo. Una rejilla de tarjetas que se adapta sola, sin una sola consulta de medios:

estilos/componentes.css — la rejilla que se adapta sola 
.catalogo {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(16rem, 1fr));
  gap: 1.25rem;
}

Léelo despacio: «tantas columnas como quepan, cada una de al menos 16 remes, y el sobrante repartido a partes iguales». En una ventana de 360 píxeles cabe una sola columna; en una de 1200 caben tres; en una de 1600, cuatro. El navegador lo recalcula solo en cada redimensionamiento. Es la respuesta correcta para un catálogo de tarjetas, y es un buen recordatorio de que no todo necesita una consulta de medios.

Precisión — auto-fit frente a auto-fill

Los dos términos existen y se parecen, pero no son lo mismo. Con auto-fill, las columnas vacías se conservan: el hueco mínimo de 16 remes se calcula siempre contra el número máximo de columnas que cabrían, y si sobran huecos, ahí se quedan. Con auto-fit, las columnas vacías se colapsan y las que quedan se estiran para llenar el espacio. Si tienes una sola tarjeta en una pantalla ancha, con auto-fill esa tarjeta se queda angosta a la izquierda con un vacío enorme a la derecha; con auto-fit ocupa todo el ancho. Para un catálogo de fichas, casi siempre quieres auto-fit.

1.4 · La pregunta de diseño

Hay una diferencia entre lo que se le pregunta al CSS y lo que debería preguntarse. «¿Cómo se ve esto en un celular de 390 píxeles?» es una pregunta mal planteada: no hay un «celular de 390 píxeles», hay muchos, y el ancho puede cambiar en cualquier momento. La pregunta útil es «¿qué contenido no cabe, o qué se vuelve incómoda, cuando el espacio aprieta?».

Esa pregunta tiene respuestas concretas, y cada respuesta es un punto de corte. «En el ancho mínimo, la portada y el texto van apilados porque no caben en fila». «A partir de cierto ancho, caben tres fichas en una fila sin que el texto quede ilegible». «A partir de un ancho mayor, el texto principal ya no debe ocupar toda la pantalla, porque una línea de 200 caracteres es incómoda de leer».

Unidad 02 · La regla que cambia

Media queries: la regla que cambia con el ancho

Una consulta de medios es una regla CSS que dice «esto solo se aplica cuando se cumple esta condición». Es la herramienta que convierte una maqueta fija en un diseño que se adapta. Esta unidad explica su sintaxis, justifica el orden en que se escriben y enumera los errores que más tiempo consumen.

⏱ 30 minutos 📄 Lectura y práctica guiada 🧭 Producto: mapa de puntos de corte

2.1 · La sintaxis

La forma completa de una consulta de medios tiene cuatro piezas: la palabra @media, una condición, y un bloque de CSS que solo se aplica si la condición se cumple.

estilos/responsivo.css — la forma completa 
@media (min-width: 768px) and (orientation: landscape) {
  .ficha__portada {
    aspect-ratio: 16 / 9;
  }
}
and
Las dos condiciones deben cumplirse a la vez. «La ventana es ancha y el dispositivo está en horizontal».
, (coma)
Equivale a «o». «La ventana es ancha o el dispositivo está en horizontal».
not
Niega la condición: @media not (min-width: 768px) se cumple cuando la ventana es más estrecha que 768 píxeles.
min-width
La condición se cumple cuando el ancho disponible es igual o mayor que el valor dado. Es la forma que se usa en esta clase, siempre.

2.2 · Móvil primero: la decisión de fondo

Hay dos manera posibles de escribir una hoja responsiva, y la elección tiene consecuencias que se notan meses después.

Dos estrategias y sus consecuencias
Partiendo del escritorioPartiendo del móvil
Condición @media (max-width: 768px) @media (min-width: 768px)
El estilo base es el de la pantalla grande el de la pantalla pequeña
Dirección del trabajo hay que «deshacer» al achicar hay que «añadir» al ensanchar
Riesgo las reglas se acumulan y se pisan entre sí cada consulta de medios suma; nada se contradice

La segunda columna de la tabla es la que explica por qué el enfoque «móvil primero» es el estándar. Con max-width, cada punto de corte reduce el espacio de acción: el escritorio escribe las reglas, y cada consulta posterior tiene que deshacer lo que hizo la anterior. Con dos o tres cortes, el resultado es una maraña de reglas que se contradicen y en la que el orden de escritura termina importando más que el orden del HTML.

Con min-width, el mecanismo es el contrario y mucho más limpio: el estilo base describe la pantalla más estrecha —el caso más difícil, porque ahí es donde menos cabe— y cada consulta de medios añade lo que la pantalla más ancha permite. El resultado es que nunca hay que «deshacer» nada.

Nota — por qué «móvil primero» también es más rápido

El estilo base es el que el navegador aplica antes de descargar el resto de las hojas, y el que se descarga primero en una conexión lenta. Con el enfoque «móvil primero», ese primer estilo es el más sencillo —el que exige menos trabajo de renderizado— en lugar de ser la versión completa del escritorio a la que luego hay que recortar. En una red del colegio, con treinta estudiantes cargando la misma página, esa diferencia se nota.

2.3 · Los puntos de corte que usaremos

Los anchos en los que el diseño cambia se llaman puntos de corte. No hay un número oficial, pero sí hay un conjunto de valores que casi todo el mundo usa, porque corresponden a los anchos de pantalla donde un diseño de contenido cambia de naturaleza. La tabla siguiente es la que vamos a usar en toda la clase.

sm 576 px ¿Cabe ya una segunda columna de contenido sin que el texto quede estrecho?
md 768 px ¿La pantalla ya es de tableta? Dos columnas cómodo, tres apretado.
lg 992 px ¿Entra una barra lateral junto al contenido principal?
xl 1200 px ¿El texto central necesita un tope para no quedar ilegible?
xxl 1400 px ¿El diseño aprovecha el sobrante o deja un vacío enorme?
Precisión — estos son los mismos de Bootstrap

La tabla anterior no es una invención de esta clase: son exactamente los seis puntos de corte de Bootstrap 5.3 (el primero, «extra pequeño», es el estilo base y no tiene nombre). No es casualidad. Si tu CSS propio usa 768, 992 y 1200, y más adelante añades Bootstrap, las dos cosas hablan el mismo idioma y el resultado se ve coherente. Si usaras 700 y 950, cada regla de Bootstrap entraría en juego en un ancho distinto al tuyo, y la página se vería «rota» justo en los bordes. Elegir los cortes que usa Bootstrap es la decisión más barata que puedes tomar en esta clase.

2.4 · Condiciones que no son de ancho

El ancho es la condición más usada, pero no la única. Estas otras son todas admitidas dentro de @media y resuelven problemas distintos.

Condiciones de medios y su uso
CondiciónSe cumple cuando…Para qué sirve
(orientation: landscape)el dispositivo está tumbadoUna tabla ancha gana sentido en horizontal
(prefers-color-scheme: dark)el sistema pide tema oscuroSeguir la preferencia del usuario sin pedirle nada
(prefers-reduced-motion: reduce)el usuario pidió menos movimientoDesactivar transiciones y animaciones
(hover: hover)el puntero es un ratónNo mostrar «pasa el cursor» en una pantalla táctil
(pointer: coarse)el puntero es un dedoBotones más grandes, porque el dedo es impreciso
(min-resolution: 2dppx)la pantalla es de alta densidadCargar imágenes más definidas
Aplicación — el movimiento reducido no es opcional

prefers-reduced-motion existe porque hay personas a las que el movimiento — transiciones, paralaje, animaciones de desplazamiento— les causa malestar real, y en algunos casos dolor. No es un detalle de gusto. La forma correcta de aplicarlo es al revés de lo habitual: se escribe la animación con normalidad y se desactiva dentro de la consulta.

estilos/base.css — el tema del sistema 
:root {
  --color-fondo: #ffffff;
  --color-texto: #16181d;
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-fondo: #12141a;
    --color-texto: #e8eaf0;
  }
}

body {
  background: var(--color-fondo);
  color: var(--color-texto);
}

@media (prefers-reduced-motion: reduce) {
  * {
    transition-duration: 0.01ms important;
    animation-duration: 0.01ms important;
  }
}

2.5 · Cuatro errores que cuestan horas

1
Olvidar la etiqueta viewport

El síntoma es desconcertante: la página se ve diminuta en el teléfono y las consultas de medios no se activan como se espera. La causa es que, sin esa etiqueta, el teléfono usa un ancho de simulación de 980 píxeles, y tus cortes de 768 y 992 nunca se cumplen.

2
Escribir la condición al revés

«Quiero que esto se vea grande» produce (max-width: 768px), que en realidad significa «esto se ve pequeño». La forma de evitarlo es leer la condición en voz alta: min-width: 768px se lee «desde 768 píxeles hacia arriba», que es exactamente lo que quieres.

3
Encadenar condiciones max-width

Con tres reglas max-width —para 1200, para 992 y para 768— hay tres zonas que se solapan, y en la zona de solape gana la que se escribió después, no la más específica. Es el problema que el enfoque «móvil primero» elimina de raíz.

4
Una llave de más o de menos

Una regla que se cierra de más queda fuera de la consulta de medios y se aplica siempre; una que se cierra de menos deja reglas huérfanas y el resto de la hoja deja de funcionar. El síntoma clásico es «las reglas que vienen después de este punto no se aplican». En el panel de estilos de las DevTools, una regla que aparece tachada está siendo pisada por otra; una regla que aparece en gris está siendo anulada.

Precisión — cómo se comprueba qué regla se aplica

El panel de estilos de las DevTools (Ctrl + Shift + C en Windows y Linux, Cmd + Option + C en macOS) tiene un casillero de «Simular» que permite forzar el tamaño de pantalla sin tocar el código. Cada regla que se aplica aparece marcada; las que no, tachadas. Con eso, un error de cascada se diagnostica en segundos en lugar de horas.

Unidad 03 · Taller de aplicación

Ejercicio 3.1 · Una ficha que se adapta sola

Las dos unidades anteriores dieron el vocabulario y la sintaxis. Ahora toca escribir. En los próximos 30 minutos construirás, desde cero y sin ningún marco de trabajo, la ficha de un libro que se lee bien en un teléfono, en una tableta y en un monitor.

⏱ 30 minutos 💻 Ejercicio de desarrollo 🧭 Producto: ficha responsiva con tres cortes

3.1 · El enunciado

Ejercicio

Ficha de libro del catálogo de la biblioteca

La biblioteca del colegio quiere presentar su catálogo. Por ahora solo hay una ficha de ejemplo, pero la estructura debe servir para muchas. Escribe el HTML y el CSS de esa ficha en dos archivos nuevos: templates/ficha.html y estilos/componentes.css. No uses Bootstrap todavía: esta unidad es sobre CSS propio.

Requisitos

  1. HTML semántico. Un elemento <article> con la clase ficha, un <h2> para el título, un <p> para el autor, otro para el resumen y un elemento para la disponibilidad. Los tres últimos llevan clases propias: ficha__autor, ficha__resumen y ficha__estado.
  2. Variables de diseño declaradas en :root: el ancho máximo de la ficha, el color de fondo, el color del texto, el radio de las esquinas y la separación interior. Ningún color escrito directamente en el resto de la hoja.
  3. Estilo base de móvil. Sin ninguna consulta de medios, la ficha debe verse correctamente en una ventana de 360 píxeles: una sola columna, todo el texto legible, sin desbordamiento horizontal.
  4. Tres consultas de medios, con min-width, en 768, 992 y 1200 píxeles. Cada una tiene que hacer algo distinto y justificado:
    • 768: la portada pasa a estar al lado del texto en lugar de encima.
    • 992: el resumen puede ocupar una columna propia porque ya no se estrecha tanto.
    • 1200: la ficha deja de crecer y se ancla a un ancho cómodo de lectura.
  5. Una tipografía fluida con clamp() en el título de la ficha.
  6. Un estado de foco visible en el enlace «Ver disponibilidad», y una transición desactivada dentro de (prefers-reduced-motion: reduce).

Modelo de respuesta

A. La plantilla

<article class="ficha">
  <div class="ficha__portada" aria-hidden="true"></div>

  <div class="ficha__cuerpo">
    <h2 class="ficha__titulo">El principito</h2>

Unidad 05 · El sistema propio

Clases propias y capas de CSS

Escribir CSS que funciona en una página es fácil; escribir CSS que siga funcionando cuando la página crezca es otra cosa. Esta unidad trata de las dos decisiones que convierten un conjunto de reglas en un sistema: cómo se nombran las clases y en qué orden se aplican las hojas.

⏱ 35 minutos 📄 Lectura y práctica guiada 🧭 Producto: hoja con sistema de clases

5.1 · De selectores sueltos a un sistema

La forma más rápida de escribir CSS es también la que peor escala. Se escribe .card h3 { … }, luego .card > .titulo { … }, luego .card .card__titulo { … }, y un día aparece otro .card en otra parte del proyecto y cada regla empieza a depender de la estructura del HTML que la rodea.

El problema de fondo no es el estilo: es la acoplamiento. Una regla como .card h3 dice «cualquier h3 que esté dentro de una tarjeta». Si mañana la tarjeta lleva otro título, la regla deja de aplicarse. El selector no nombra la pieza: nombra una coincidencia de estructura, y la estructura cambia.

La solución es usar clases que nombran las piezas. Una clase es un nombre explícito que se pone en el HTML y que el CSS puede buscar sin depender de nada más. Y para que esos nombres no se conviertan en un caos, se usa una convención.

Nota — la convención de esta clase

Se usa una versión simplificada de la convención BEM, que divide cada nombre en tres partes separadas por dos guiones bajos y dos guiones:

  • Bloque: ficha. La pieza completa.
  • Elemento: ficha__titulo. Una parte de la pieza.
  • Modificador: ficha--destacada. Una variante de la pieza.

La ventaja concreta no es estética: es que se puede buscar. Escribe ficha__ en la búsqueda del editor y aparecen todos los lugares donde se usa ese elemento, en el HTML y en el CSS. Con nombres sueltos como .titulo o .sub, esa búsqueda devuelve resultados de media clase.

HTML y CSS con la convención aplicada 
<article class="ficha ficha--destacada">
  <h2 class="ficha__titulo">El principito</h2>
  <p class="ficha__resumen">…</p>
</article>
estilos/componentes.css — cada regla nombra una pieza 
.ficha { }
.ficha__titulo { }
.ficha__resumen { }

/* La variante se declara aparte y solo cambia lo que debe cambiar */
.ficha--destacada {
  box-shadow: 0 0 0 3px rgb(0 0 0 / 0.12);
}
Precisión — la especificidad no desaparece

Nombrar las piezas con clases no elimina la especificidad: la sigue existiendo. Lo que hace es ponerla a trabajar a tu favor. Una clase tiene siempre la misma especificidad, así que dos reglas que compiten por la misma pieza se resuelven por orden (gana la última) y no por «qué selector parece más complicado». Ese orden es exactamente lo que controlan las capas del punto 5.3.

5.2 · Las variables CSS como contrato de diseño

Una variable CSS es un nombre que guarda un valor. Se declara en :root —que representa el elemento raíz del documento— y se usa después con var().

estilos/base.css — el contrato de diseño 
:root {
  --color-fondo: #ffffff;
  --color-texto: #16181d;
  --color-tenue: #5b6472;
  --color-acento: #2563eb;

  --ancho-contenido: 68rem;
  --ancho-lectura: 42rem;
  --separacion: 1rem;
  --radio: 10px;
}

body {
  background: var(--color-fondo);
  color: var(--color-texto);
}

.contenido {
  max-width: var(--ancho-contenido);
  margin-inline: auto;
  padding-inline: var(--separacion);
}

.contenido__texto {
  max-width: var(--ancho-lectura);
}

La ventaja no es la abreviatura del código: es que el contrato de diseño queda escrito en un solo lugar. Si mañana el colegio cambia de color institucional, se cambia en cuatro líneas del :root y el resto del proyecto sigue igual. Si el ancho máximo del contenido cambia, tampoco hay que buscarlo por todas las hojas.

Precisión — var() admite un valor por defecto

La sintaxis var(--nombre, valor-por-defecto) es más de lo que parece. Si la variable no está definida —porque alguien la borró o porque se usó un nombre con una errata—, el navegador usa el valor por defecto en lugar de dejar la propiedad sin valor. Es la forma de escribir una regla que no se rompe por un descuido en el nombre de una variable.

Advertencia — las variables CSS no sirven dentro de las condiciones

Una variable CSS no puede usarse en la condición de una consulta de medios. Esto es una limitación del lenguaje, no una torpeza de CSS: escribir @media (min-width: var(--corte-md)) es inválido y el navegador descarta la consulta completa. Bootstrap lo dice con todas las letras en su propia documentación: «aunque incluimos los puntos de corte de la rejilla como variables CSS, ten en cuenta que las variables CSS no funcionan dentro de las consultas de medios».

Consecuencia práctica: sí puedes declarar los cortes como variables para documentarlos y para usarlos en el resto del CSS, pero dentro de @media hay que escribir el número. Es un poco incómodo, y es una de esas cosas que conviene saber antes de perder una hora buscando el error.

5.3 · Las capas: el orden de las hojas es el orden de la prioridad

CSS se aplica en cascada: cuando dos reglas dicen la misma propiedad de un elemento, gana la que tiene mayor especificidad; si empatan, gana la que llegó después. El orden de llegada es el de los <link> en el HTML.

Esa última fila es la que resuelve el problema clásico de combinar un marco de trabajo con CSS propio, y se explica con detalle en la unidad 6: si las consultas de medios van al final, entonces el CSS responsive puede corregir cualquier cosa que haya puesto el marco de trabajo, sin recurrir a selectores gymnastics.

Aplicación — el orden de los archivos <link>

En el proyecto de esta clase, el orden queda así: base.css, después componentes.css, después responsivo.css. La hoja de componentes va después de la base porque una pieza necesita poder sobrescribir el estilo general de un elemento (un <h2> dentro de una ficha no puede heredar el tamaño del h2 del documento). Y la hoja responsive va al final porque sus reglas tienen que poder aplicarse a cualquier capa.

Unidad 06 · La herramienta

Bootstrap: la rejilla que ya está resuelta

Escribir una rejilla que se adapte, con sus puntos de corte, sus clases de columna y sus utilidades, lleva tiempo. Bootstrap es ese trabajo ya hecho, revisado y documentado. Esta unidad explica qué trae, cómo se instala sin compilar nada, qué personaliza y qué no.

⏱ 35 minutos 📄 Lectura y práctica guiada 🧭 Producto: la ficha con Bootstrap

6.1 · Qué es y qué no es un marco de trabajo de CSS

Bootstrap es un archivo de CSS escrito por otras personas. Eso es todo. No es un lenguaje, ni tiene compilador, ni ejecuta lógica: son clases que ya sabes usar porque las has usado sin saber que existían —btn, card, navbar— en cientos de páginas.

Qué aporta Bootstrap y qué queda en tus manos
Lo que ya viene hechoLo que sigue siendo tuyo
La rejilla de 12 columnas y sus puntos de corteDecidir en qué momento el diseño cambia y por qué
Los componentes: botones, tarjetas, formularios, avisosQué componentes usar y cómo se combinan entre sí
Las utilidades de espaciado, color y tamañoLa identidad visual: los colores y la tipografía del colegio
Los detalles de accesibilidad de los componentesLa jerarquía de la información y el contenido
Un sistema de nombres consistenteEl orden en que se cargan las hojas y quién puede sobrescribir a quién
Nota — el marco de trabajo no sustituye el criterio

Bootstrap no decide por ti cómo se ve tu página: te da un catálogo de piezas y un sistema de rejilla. Lo que tú decides es qué piezas usar y en qué momento dejar de usar el catálogo. Un sitio hecho con Bootstrap se parece a otros miles de sitios hechos con Bootstrap; se parece a tu colegio cuando le cambias los colores, la tipografía y el orden de las secciones.

6.2 · Instalación sin compilación

Bootstrap se enlaza desde un CDN. No hay que instalar nada, ni configurar un empaquetador, ni compilar: una etiqueta <link> y listo. La versión se fija siempre, por la misma razón que en la clase 2 con HTMX: lo que no se fija, puede cambiar sin aviso.

templates/base.html — Bootstrap y el CSS propio 
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">

  <!-- Primero Bootstrap: es la base sobre la que todo lo demás se apoya -->
  <link rel="stylesheet"
        href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css">

  <!-- Después el CSS propio: así puede sobrescribir a Bootstrap -->
  <link rel="stylesheet" href="/estilos/base.css">
  <link rel="stylesheet" href="/estilos/componentes.css">
  <link rel="stylesheet" href="/estilos/responsivo.css">
</head>
Precisión — qué versión de Bootstrap se usa hoy

La versión estable es la 5.3.8. En el registro de paquetes, la etiqueta latest apunta a ella, pero la etiqueta next apunta a 6.0.0-alpha.1: una versión alpha, es decir, en desarrollo y sin garantía de estabilidad. Si enlazas bootstrap@6 o bootstrap@next en un trabajo del aula, estás trabajando con código que todavía puede cambiar. La clase usa 5.3.8, fijada de forma explícita.

Sobre el JavaScript: Bootstrap incluye componentes que necesitan scripting — los menús desplegables, las ventanas modales, los mensajes emergentes—. Para usarlos hace falta bootstrap.bundle.min.js, que ya incluye la biblioteca Popper que los menús necesitan. Pero si tu página solo usa rejilla, botones, formularios y tarjetas — que es el caso del taller de esta clase—, no necesitas ningún JavaScript.

6.3 · El sistema de rejilla

La rejilla de Bootstrap divide el ancho en doce columnas. Esa cifra no es arbitraria: doce es divisible por 1, 2, 3, 4 y 6, así que permite la mayoría de las combinaciones que se necesitan en la práctica.

templates/index.html — el catálogo con la rejilla de Bootstrap 
<div class="container">
  <div class="row g-4">

    <div class="col-12 col-md-6 col-lg-4">
      <div class="card h-100">
        <div class="card-body">
          <h2 class="card-title h5">El principito</h2>
          <p class="card-text">Un poeta busca su camino…</p>
        </div>
        <div class="card-footer text-body-secondary">Disponible</div>
      </div>
    </div>

  </div>
</div>
.container
Una caja con un ancho máximo que cambia según el punto de corte, centrada y con márgenes laterales. Es el contenedor de la página.
.container-fluid
La misma idea sin tope: ocupa el 100 % del ancho disponible en cualquier tamaño.
.row
La fila: contiene columnas. Aplica un margen negativo que compensa el margen de las columnas, para que la fila quede al ras del contenedor.
.col-12 col-md-6 col-lg-4
La columna: ocupa las 12 columnas por defecto; desde 768 píxeles, la mitad; desde 992, un tercio. La última regla que se cumple es la que manda.
g-4
La separación entre columnas. El número va de 0 a 5 y son pasos de media rem.
h-100
Altura completa: hace que la tarjeta ocupe toda la celda, para que varias tarjetas de la misma fila queden alineadas.
Precisión — por qué col-12 va primero

El orden de las clases no es decorativo: Bootstrap genera las reglas de las columnas en orden creciente de punto de corte —primero las de xs, luego sm, md…— y dentro de una misma fila, gana la que aparece más abajo. Como col-12 pertenece al grupo sin punto de corte, se escribe primero y las demás la sobrescriben a partir de su corte. Si se invirtiera el orden (col-lg-4 col-md-6 col-12), la regla de 992 píxeles se aplicaría también por debajo, y en un teléfono la columna ocuparía un tercio en lugar de todo el ancho.

6.4 · Las utilidades responsivas

Las utilidades son clases de un solo propósito. Se pueden aplicar en cualquier momento, pero lo interesante es que también aceptan un punto de corte, y entonces solo actúan a partir de ese ancho.

Visualización

d-none · d-block · d-flex · d-grid

Con punto de corte: d-none d-md-block —oculto por defecto, visible desde 768 píxeles.

Texto

text-start · text-center · text-end · text-uppercase

Con punto de corte: text-center text-lg-start.

Separación

m-0 · mt-3 · mb-auto · p-2 · px-4

Con punto de corte: mb-2 mb-md-4.

Tamaño y forma

w-100 · h-100 · rounded · rounded-circle · border

Con punto de corte: w-50 w-md-auto.

Aplicación — el patrón que más se usa

d-none d-md-block es el patrón más frecuente de Bootstrap responsivo, y merece entenderse bien. Significa: «oculto por defecto; a partir de 768 píxeles, visible». Como el estilo base manda mientras no se cumple ninguna condición, el elemento está oculto en el teléfono; en cuanto la ventana llega a 768, la segunda regla se activa y lo muestra.

Su equivalente en CSS propio sería display: none; en la regla base y display: block; dentro de @media (min-width: 768px). La diferencia es que en Bootstrap cabe en un fragmento de atributo, y en CSS propio ocupa un bloque. Las dos formas son correctas: la primera es más corta, la segunda es más explícita.

6.5 · Personalizar sin recompilar

Bootstrap 5 expone sus decisiones de diseño como variables CSS con el prefijo --bs-. Cambiar una de ellas cambia el comportamiento de todos los componentes que la usan, sin compilar nada y sin reescribir una sola clase.

estilos/base.css — la identidad del colegio sobre Bootstrap 
:root {
  --bs-primary: #6d28d9;
  --bs-body-bg: #fbfaf7;
  --bs-body-color: #1b1d23;
  --bs-border-radius: 0.5rem;
}
Advertencia — los botones tienen sus propias variables

Cambiar --bs-primary repinta los enlaces y los componentes que usan ese color, pero no repinta los botones. El motivo es que .btn-primary no usa var(--bs-primary): define su propio juego de variables (--bs-btn-bg, --bs-btn-hover-bg, --bs-btn-border-color…) con valores concretos. Para cambiar el color de los botones hay que sobrescribir esas.

estilos/base.css — repintar los botones 
.btn-primary {
  --bs-btn-bg: #6d28d9;
  --bs-btn-border-color: #6d28d9;
  --bs-btn-hover-bg: #5b21b6;
  --bs-btn-hover-border-color: #5b21b6;
  --bs-btn-active-bg: #4c1d95;
}
Nota — el tema oscuro con una sola etiqueta

Bootstrap trae un tema oscuro completo que se activa escribiendo data-bs-theme="dark" en la etiqueta <html>. También se puede activar solo en una parte de la página, por ejemplo en la barra de navegación, escribiendo el atributo en el <body> o en un contenedor. Es la forma más barata de probar cómo se ve el catálogo con el tema del sistema.

Precisión — la misma limitación de siempre

Las variables de Bootstrap tampoco funcionan dentro de las condiciones de las consultas de medios. Los puntos de corte de la rejilla están expuestos como --bs-breakpoint-md y compañía, pero no se pueden escribir así: @media (min-width: var(--bs-breakpoint-md)). La documentación de Bootstrap lo advierte de forma expresa. Se pueden usar para documentar los cortes en el :root, pero las condiciones llevan los números escritos.

  3. El componente card para la ficha, con card-body, card-title y card-text. La clase h-100 es obligatoria si quieres que las tarjetas de una misma fila queden alineadas.
  4. La identidad del colegio: sobrescribe --bs-primary, --bs-body-bg y el radio de las esquinas en tu base.css, y comprueba que la página cambia de color.
  5. Un párrafo comparativo de cinco líneas: qué líneas de tu CSS propio desaparecieron al usar Bootstrap, y cuáles tuvo que seguir escribiendo.

7.1 · El encargo

Encargo

Catálogo de la biblioteca del colegio, para teléfono y para monitor

La biblioteca quiere publicar su catálogo. No es una página nueva: es la que ya construiste, con el formulario de la clase 2 al lado, y ahora tiene que verse bien en la pantalla de un teléfono, en la de una tableta y en la del monitor del aula. El contenido no cambia: cambia cómo se reparte.

Ficha del sistema

Entregables

  2. La versión con Bootstrap: templates/index_bootstrap.html con el mismo contenido, usando la rejilla de Bootstrap y las variables --bs- para la identidad del colegio.
  3. El fragmento de HTMX: el catálogo devuelto por el servidor como fragmento (templates/fragmento_catalogo.html), con las mismas clases que la página completa. Explica por qué los estilos viven en las hojas globales y no dentro del fragmento.
  4. La lista de puntos de corte que usaste, con una frase que justifique cada uno: qué cambia en la página en ese ancho y por qué ese ancho y no otro.

B. El fragmento de HTMX

<div class="catalogo__rejilla">
  {% for libro in libros %}
    <article class="ficha">
      <h2 class="ficha__titulo">{{ libro.titulo }}</h2>
      <p class="ficha__resumen">{{ libro.resumen }}</p>
    </article>
  {% endfor %}
</div>

Por qué el fragmento no lleva estilos dentro: una etiqueta <style> dentro de un fragmento se insertaría en el documento, pero el navegador aplicaría sus reglas al documento entero, no al fragmento. Si el mismo catálogo se inserta dos veces con variantes distintas, la segunda insertada hereda las reglas de la primera. La solución correcta es que las clases del fragmento (ficha, ficha__titulo, ficha__resumen) ya existan en las hojas globales: el fragmento trae la estructura, las hojas traen el estilo.

C. El argumento (modelo)

Decisión: usar CSS propio en el catálogo y dejar Bootstrap para el formulario. Motivo: el catálogo tiene cuatro tarjetas que deben verse iguales en cualquier ancho, y la rejilla repeat(auto-fit, minmax(16rem, 1fr)) lo resuelve sin ninguna consulta de medios; mientras que el formulario de la clase 2 tiene campos de tres tipos distintos, etiquetas, mensajes de error en línea y estados de carga, y eso ya es un catálogo de componentes con accesibilidad que Bootstrap resuelve mejor y con menos código propio. Consecuencia: hay dos sistemas de estilo conviviendo, así que el orden de las hojas queda fijado por escrito: Bootstrap primero, después base.css, después componentes.css, y responsivo.css al final. Alternativa descartada: usar Bootstrap para todo, que habría dejado la identidad visual del colegio en manos de un archivo que no controlamos y que cambia en cada actualización de versión.

7.3 · Síntesis: siete ideas para llevarse

01

No hay dos versiones de una página: hay una página y un conjunto de reglas que dicen cuándo cambia.

02

La etiqueta viewport es la condición de posibilidad: sin ella, las consultas de medios miden otra cosa.

03

Se escribe primero para la pantalla más estrecha y luego se amplía: cada consulta min-width solo añade.

04

Los puntos de corte los decide el contenido, no el dispositivo; los de Bootstrap ya están elegidos y conviene usarlos.

05

Las clases que nombran piezas y las variables en :root son lo que convierte un montón de reglas en un sistema.

06

El orden de las hojas es el orden de la prioridad: el CSS propio va después de Bootstrap y las consultas de medios al final.

07

Las variables CSS no funcionan dentro de las condiciones de las consultas de medios: es una limitación del lenguaje, y hay que conocerla.

7.4 · Puente hacia la próxima clase

La próxima clase trabaja con los datos: el catálogo que has maquetado necesitará algún origen real de libros. Tres cosas de lo que has hecho hoy siguen vivas allí:

  1. La estructura de la ficha —ficha, ficha__titulo, ficha__resumen— es la que se va a rellenar con los registros que vengan de la base de datos. Los nombres de clase no se tocan: son el contrato entre el HTML y el CSS.
  2. El fragmento de HTMX que preparaste es el punto exacto donde el servidor entregará los datos. Todo lo que aprendiste en la clase 2 sobre errores y estados sigue vigente: un fragmento que llega con datos puede llegar también con un mensaje de error.
  3. La separación de hojas te va a ahorrar un problema: cuando los datos cambien, solo cambian las plantillas; el CSS no se toca, salvo que la forma del dato cambie.
