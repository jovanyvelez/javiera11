🌊 El flujo completo: de la URL a la BD

⏱️ 35 minutos · "El viaje de una petición"

🧠 La idea central

Cuando un usuario visita /autores, ocurre una cadena de eventos. Entender este flujo es entender cómo funciona toda la app. Sigamos el viaje paso a paso.

PasoQuiénQué hace
1NavegadorEnvía GET /autores
2FastAPIEncuentra la ruta en vistas.py
3get_connectionPide prestada una conexión del pool
4repositorioEjecuta SELECT * FROM autores
5PostgreSQLDevuelve las filas
6Jinja2Rellena la plantilla con los datos
7FastAPIDevuelve el HTML al navegador

🦹 El villano: el flujo que se rompe

Si una pieza falla (la conexión, la consulta, la plantilla), todo el flujo se rompe. Por eso cada pieza tiene su responsabilidad y su manejo de errores. Entender el flujo te ayuda a saber dónde mirar cuando algo falla.

🛡️ Validación en el flujo

⏱️ 35 minutos · "Dónde encaja Pydantic"

🧠 La idea central

La validación con Pydantic ocurre antes de tocar la base de datos. Cuando el usuario envía un formulario, la ruta recibe los datos, los valida con el modelo, y solo si son válidos llama al repositorio. Si no, responde 422.

vistas.py — el flujo de crear 
@router.post("/autores")
async def crear_autor(nombre: str = Form(), ...):
    # 1. validar con Pydantic
    autor = AutorCrear(nombre=nombre, pais=pais, nacimiento=nacimiento)
    # 2. si es válido, guardar en la BD
    await crear_autor(conn, autor.nombre, autor.pais, autor.nacimiento)
    # 3. devolver la tabla actualizada
    return templates.TemplateResponse(...)

💡 Validar antes de guardar

El orden importa: primero validar, después guardar. Nunca al revés. Si guardas datos inválidos, ensucias la base de datos. Pydantic es el guardián que protege la puerta de entrada.

🖥️ El frontend: Jinja2 + htmx + Bootstrap

⏱️ 35 minutos · "La cara visible de la app"

🧠 La idea central

El frontend combina tres herramientas: Jinja2 genera el HTML con los datos, Bootstrap le da estilo, y htmx lo hace interactivo. Juntas forman una página completa sin escribir JavaScript a mano.

📄

Jinja2

Genera el HTML con variables y bucles.

🎨

Bootstrap

Da estilo con clases listas (btn, table, card).

⚡

htmx

Hace la página interactiva sin recargar.

💡 Tres piezas, un objetivo

Jinja2 responde "¿qué muestro?", Bootstrap responde "¿cómo se ve?", y htmx responde "¿cómo interactúa?". Cada una resuelve un problema distinto, y juntas forman el frontend completo.
