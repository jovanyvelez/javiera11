0.1 · El diccionario que se equivocó de llave

El catálogo de TechStore empezó como una lista de diccionarios. Funcionaba hasta que alguien escribió producto["presio"] en el informe y el programa respondió con un KeyError. Después, otro archivo calculó el total con la cantidad equivocada. Y cuando llegó el momento de validar que el precio fuera positivo, la validación quedó copiada en tres lugares distintos.

Un diccionario guarda datos, pero no sabe nada de ellos. No puede impedir una llave mal escrita, no puede calcular su propio total y no puede avisar que un precio es inválido. Un objeto sí: reúne los datos y las operaciones que tienen sentido para esos datos en una sola pieza.

Distinción — dato suelto y objeto

Un diccionario es una colección de pares clave-valor. Un objeto es una instancia de una clase: tiene atributos con nombre, métodos que los usan y reglas que se cumplen al construirlo. La diferencia no es la sintaxis: es que el objeto puede hacer cosas con su propia información.

Unidad 01 · El molde

La clase es el molde; el objeto es la copia

Una clase define qué atributos tendrá cada objeto y cómo se construye. Al llamarla con argumentos se crea una instancia. Dos instancias de la misma clase comparten el molde, pero no sus datos: cambiar el precio de una no cambia el de la otra.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: dos productos independientes

1.1 · La clase más pequeña que sirve

Una clase se declara con class y un nombre en PascalCase. El método __init__ se ejecuta al construir el objeto y recibe self, que es la instancia que se está creando. Dentro, cada self.algo crea un atributo de esa instancia.

producto.py — la clase y dos instancias 
class Producto:
    def __init__(self, nombre: str, precio: float, cantidad: int = 0) -> None:
        self.nombre = nombre
        self.precio = precio
        self.cantidad = cantidad

    def __repr__(self) -> str:
        return f'Producto("{self.nombre}", {self.precio}, {self.cantidad})'


p1 = Producto("Teclado mecánico", 189900, 12)
p2 = Producto("Mouse inalámbrico", 89900, 25)

print(p1)
print(p2)

p1.cantidad = 10
print(p1.cantidad)   # 10
print(p2.cantidad)   # 25: son objetos distintos
salida

Declara el molde. Por convención, el nombre de una clase empieza con mayúscula.

El método que inicializa la instancia cuando escribes Producto(...). No devuelve nada; solo llena el objeto.

La instancia concreta. Python la pasa automáticamente: p1.vender() equivale a Producto.vender(p1).

Precisión — __init__ no es el «constructor» completo

En Python, el objeto se crea con __new__ y se inicializa con __init__. En el día a día decimos «constructor» a la llamada Producto(...), pero lo que escribes tú es __init__. No necesitas tocar __new__ en este curso.

1.2 · Cada instancia tiene su propio estado

p1 y p2 salen del mismo molde, pero son dos objetos separados en memoria. Cambiar p1.cantidad no toca p2.cantidad. Esa independencia es la base de un catálogo: cada producto tiene su precio y su stock.

Advertencia — un atributo inexistente no se crea solo

Si escribes p1.presio = 10, Python no corrige la ortografía: crea un atributo nuevo llamado presio y el original precio sigue igual. Los objetos no adivinan nombres. Para eso existe la validación y, más adelante, los modelos de Pydantic, que rechazan campos que no declaraste.

Unidad 02 · El comportamiento

Métodos: el objeto hace cosas con sus datos

Un objeto no es una bolsa de atributos. Sabe calcular su total, aplicar un descuento, vender una unidad y reponer stock. Cada método recibe self, lee o modifica el estado y devuelve un resultado. Ahí está la diferencia entre un diccionario y un objeto.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: métodos que cambian el estado

2.1 · Del dato a la acción

El método valor_total no recibe el precio ni la cantidad como parámetros: los lee de self. El método vender sí recibe las unidades, porque es una acción nueva, y modifica self.cantidad. El objeto es el dueño de su estado.

producto.py — métodos con estado 
class Producto:
    IVA = 0.19

    def __init__(self, nombre: str, precio: float, cantidad: int = 0) -> None:
        self.nombre = nombre
        self.precio = precio
        self.cantidad = cantidad

    def valor_total(self) -> float:
        return self.precio * self.cantidad

    def precio_con_iva(self) -> float:
        return round(self.precio * (1 + self.IVA), 2)

    def aplicar_descuento(self, porcentaje: float) -> None:
        self.precio = round(self.precio * (1 - porcentaje / 100), 2)

    def vender(self, unidades: int) -> None:
        if unidades > self.cantidad:
            raise ValueError(f"No hay stock suficiente: quedan {self.cantidad}")
        self.cantidad -= unidades

    def reponer(self, unidades: int) -> None:
        self.cantidad += unidades


p = Producto("Teclado", 189900, 12)
print(p.valor_total())        # 2278800
p.vender(2)
print(p.cantidad)             # 10
p.aplicar_descuento(10)
print(p.precio)               # 170910.0
Método de instancia
Recibe self y trabaja con los atributos de ese objeto. Es el tipo normal de método.
Estado
El conjunto de atributos en un momento dado. vender cambia el estado; valor_total solo lo lee.
Efecto lateral
Un cambio que el método produce fuera de su valor de retorno: modificar self.cantidad es un efecto lateral intencional.
IVA
Un atributo de clase: vale lo mismo para todos los productos y se lee como self.IVA o Producto.IVA.

2.2 · Un método puede llamar a otro

Dentro de la clase no necesitas repetir la fórmula: precio_con_iva puede usar self.precio, y un método más complejo puede llamar a self.valor_total(). Esa es la misma reutilización de funciones de la clase 6, pero con el objeto como contexto.

un método que usa otro método 
class Carrito:
    def __init__(self) -> None:
        self.productos: list[Producto] = []

    def agregar(self, producto: Producto) -> None:
        self.productos.append(producto)

    def total(self) -> float:
        return sum(p.valor_total() for p in self.productos)

    def unidades(self) -> int:
        return sum(p.cantidad for p in self.productos)
Nota — composición: un objeto dentro de otro

Carrito no hereda de Producto: tiene productos. Esa relación se llama composición y suele ser más flexible que la herencia. La verás otra vez en la unidad 5 y en el taller.

2.3 · El atributo de clase que se comparte por accidente

Si defines una lista como atributo de clase, todas las instancias apuntan a la misma lista. Es uno de los errores más caros para principiantes porque no falla al escribir: falla cuando dos carritos empiezan a mezclar productos.

el error de la lista compartida 
class CarritoMalo:
    items = []          # ¡compartido por todas las instancias!

    def agregar(self, item):
        self.items.append(item)


a = CarritoMalo()
b = CarritoMalo()
a.agregar("teclado")
print(b.items)          # ['teclado']: b nunca agregó nada


class CarritoBueno:
    def __init__(self):
        self.items = []  # cada instancia tiene su propia lista

    def agregar(self, item):
        self.items.append(item)
Advertencia — los mutables van en __init__

Listas, diccionarios y conjuntos son mutables. Si los pones como atributo de clase, se comparten. Si los pones dentro de __init__ con self.items = [], cada objeto recibe una lista nueva. La regla es simple: estado mutable, en la instancia.

2.4 · @dataclass: menos código para los mismos datos

Cuando una clase es sobre todo un contenedor de datos, @dataclass genera __init__, __repr__ y __eq__ a partir de las anotaciones. Puedes seguir añadiendo métodos normales.

producto.py — la versión con dataclass 
from dataclasses import dataclass


@dataclass
class Producto:
    nombre: str
    precio: float
    cantidad: int = 0

    def valor_total(self) -> float:
        return self.precio * self.cantidad


p = Producto("Teclado", 189900, 12)
print(p)                    # Producto(nombre='Teclado', precio=189900, cantidad=12)
print(p.valor_total())      # 2278800
print(p == Producto("Teclado", 189900, 12))  # True

Unidad 03 · Las reglas

Un objeto válido desde que nace

Un objeto con precio negativo no es un producto: es un error esperando a ocurrir. La validación en el constructor garantiza que ninguna instancia nazca rota. Es la misma idea que Pydantic usará después, pero escrita a mano para que veas qué hay debajo.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: invariantes y objetos que rechazan datos inválidos

3.1 · Validar en __init__

El constructor es la aduana del objeto. Si un dato no cumple la regla, lanza ValueError antes de crear una instancia inválida. El resto del programa puede confiar en que todo Producto que existe tiene nombre, precio positivo y cantidad no negativa.

producto.py — invariantes en el constructor 
class Producto:
    def __init__(self, nombre: str, precio: float, cantidad: int = 0) -> None:
        if not isinstance(nombre, str) or not nombre.strip():
            raise ValueError("El nombre es obligatorio.")
        if not isinstance(precio, (int, float)) or precio <= 0:
            raise ValueError("El precio debe ser mayor que cero.")
        if not isinstance(cantidad, int) or cantidad < 0:
            raise ValueError("La cantidad debe ser un entero mayor o igual que cero.")

        self.nombre = nombre.strip()
        self.precio = float(precio)
        self.cantidad = cantidad

    def __repr__(self) -> str:
        return f'Producto("{self.nombre}", {self.precio}, {self.cantidad})'


try:
    p = Producto("", -10, 2)
except ValueError as error:
    print(error)  # El nombre es obligatorio.
Advertencia — validar solo al principio no basta

El constructor protege el nacimiento, pero después alguien puede escribir p.precio = -1. En Python los atributos son públicos por defecto. Para el nivel de esta clase, valida también en los métodos que cambian estado y, si necesitas más control, usa @property o un modelo de Pydantic. Lo importante es que la regla viva en una sola capa, no repetida en cada pantalla.

3.2 · Validar con @dataclass y __post_init__

producto.py — dataclass con validación 
from dataclasses import dataclass, field


@dataclass
class Producto:
    nombre: str
    precio: float
    cantidad: int = 0
    etiquetas: list[str] = field(default_factory=list)

    def __post_init__(self) -> None:
        if not self.nombre.strip():
            raise ValueError("El nombre es obligatorio.")
        if self.precio <= 0:
            raise ValueError("El precio debe ser mayor que cero.")
        if self.cantidad < 0:
            raise ValueError("La cantidad no puede ser negativa.")

    def valor_total(self) -> float:
        return self.precio * self.cantidad
Precisión — default_factory crea una lista por objeto

Si escribieras etiquetas: list[str] = [], todas las instancias compartirían la misma lista. field(default_factory=list) le pide a dataclass una lista nueva para cada objeto. Es la versión elegante de «el mutable va en la instancia».

3.3 · El puente: la validación declarativa

Pydantic hace lo mismo que acabas de escribir, pero declara las reglas en las anotaciones y devuelve todos los errores juntos. No lo vas a implementar aquí: lo estudiarás en la clase 7 para los formularios y, con más detalle, en la Parte 0 de la serie SQLModel. Lo importante es que reconozcas la idea: un objeto que no acepta datos inválidos.

Unidad 05 · Relaciones

Herencia y composición: es un o tiene un

Dos objetos pueden relacionarse de dos formas muy distintas. Un producto digital es un producto: hereda. Un carrito tiene productos: compone. Elegir bien evita jerarquías artificiales y te prepara para los modelos de Pydantic y del ORM, que también usan estas relaciones.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: una jerarquía y una composición bien elegidas

5.1 · Herencia: «es un» producto

Un producto digital es un producto, pero además tiene un archivo. En vez de copiar todos los atributos, se hereda de Producto y se añade lo nuevo. La clase hija llama a super().__init__ para que el padre inicialice la parte común.

producto.py — heredar y especializar 
class Producto:
    def __init__(self, nombre: str, precio: float, cantidad: int = 0) -> None:
        self.nombre = nombre
        self.precio = precio
        self.cantidad = cantidad

    def entregar(self) -> str:
        return "Envío físico"


class ProductoDigital(Producto):
    def __init__(
        self, nombre: str, precio: float, cantidad: int, archivo: str
    ) -> None:
        super().__init__(nombre, precio, cantidad)
        self.archivo = archivo

    def entregar(self) -> str:
        return f"Descarga del archivo {self.archivo}"

    def __repr__(self) -> str:
        return f'ProductoDigital("{self.nombre}", {self.precio}, "{self.archivo}")'


digital = ProductoDigital("Curso de Git", 49900, 999, "git.pdf")
print(digital.entregar())              # Descarga del archivo git.pdf
print(isinstance(digital, Producto))   # True
super()
Llama al método de la clase padre. Aquí inicializa nombre, precio y cantidad antes de añadir archivo.
Sobrescribir
La clase hija define entregar con otro comportamiento. Al llamar digital.entregar(), gana la versión hija.
isinstance
Un ProductoDigital también es un Producto. Es la prueba de la relación «es un».
Herencia
Útil cuando la relación es realmente «es un». Si es «tiene un», conviene composición.

5.2 · Composición: «tiene» productos

Un carrito no es un producto: tiene productos. Por eso no hereda; guarda una lista de objetos y delega en ellos. En el taller vas a usar esta relación porque es la que aparece en casi todos los modelos de negocio.

Herencia o composición
RelaciónSe leeEjemploHerramienta
Es unUn producto digital es un productoProductoDigital(Producto)Herencia
Tiene unUn carrito tiene productosself.productos: list[Producto]Composición
Usa unUna tienda usa un repositorioself.repo = repositorioComposición / inyección
Precisión — heredar no es «reutilizar porque sí»

La herencia crea un acoplamiento fuerte: si cambia el padre, cambia la hija. Úsala cuando la relación «es un» sea verdadera y estable. Si solo quieres reutilizar dos métodos, una función o una clase auxiliar suele ser mejor que una jerarquía inventada.

Unidad 06 · Los tropiezos

Errores de diseño: cuando el objeto miente

6.2 · El objeto que acepta cualquier cosa

un objeto sin invariantes no protege nada

Un objeto sin reglas es un diccionario con otra sintaxis. La clase empieza a valer la pena cuando impide estados imposibles: precio positivo, cantidad entera, nombre no vacío. Esa es la diferencia entre escribir class y diseñar un modelo.

6.4 · Igualdad, representación y depuración

por qué __repr__ y __eq__ importan

Nota — la identidad también es un dato

Dos productos con el mismo nombre y precio no son necesariamente el mismo producto. En la base de datos, el id resuelve esa ambigüedad. En el dominio, puedes comparar por valores (dataclass) o por identidad (clase normal); elige según lo que signifique «igual» en tu negocio.

7.2 · El modelo base

tienda.py — Producto y Carrito 
class Producto:
    def __init__(self, nombre: str, precio: float, cantidad: int = 0) -> None:
        if not nombre.strip():
            raise ValueError("El nombre es obligatorio.")
        if precio <= 0:
            raise ValueError("El precio debe ser mayor que cero.")
        if cantidad < 0:
            raise ValueError("La cantidad no puede ser negativa.")

        self.nombre = nombre.strip()
        self.precio = float(precio)
        self.cantidad = cantidad

    def __repr__(self) -> str:
        return f'Producto("{self.nombre}", {self.precio}, {self.cantidad})'

    def valor_total(self) -> float:
        return self.precio * self.cantidad

    def aplicar_descuento(self, porcentaje: float) -> None:
        if not 0 <= porcentaje <= 100:
            raise ValueError("El descuento debe estar entre 0 y 100.")
        self.precio = round(self.precio * (1 - porcentaje / 100), 2)

    def vender(self, unidades: int) -> None:
        if unidades <= 0:
            raise ValueError("Las unidades deben ser positivas.")
        if unidades > self.cantidad:
            raise ValueError("No hay stock suficiente.")
        self.cantidad -= unidades

    def reponer(self, unidades: int) -> None:
        if unidades <= 0:
            raise ValueError("Las unidades deben ser positivas.")
        self.cantidad += unidades


class Carrito:
    def __init__(self) -> None:
        self.productos: list[Producto] = []

    def agregar(self, producto: Producto) -> None:
        self.productos.append(producto)

    def total(self) -> float:
        return sum(p.valor_total() for p in self.productos)

    def __repr__(self) -> str:
        return f"Carrito({len(self.productos)} productos, total={self.total()})"

test_tienda.py — cinco caminos 
import pytest

from tienda import Carrito, Producto


def test_producto_valido_calcula_total():
    p = Producto("Teclado", 100000, 2)
    assert p.valor_total() == 200000


def test_producto_invalido_lanza_value_error():
    with pytest.raises(ValueError):
        Producto("", 100000, 2)


def test_descuento_cambia_el_precio():
    p = Producto("Teclado", 100000, 1)
    p.aplicar_descuento(10)
    assert p.precio == 90000


def test_vender_sin_stock_falla():
    p = Producto("Mouse", 50000, 1)
    with pytest.raises(ValueError):
        p.vender(2)


def test_carrito_suma_sus_productos():
    carrito = Carrito()
    carrito.agregar(Producto("Teclado", 100000, 1))
    carrito.agregar(Producto("Mouse", 50000, 2))
    assert carrito.total() == 200000
Advertencia — cada prueba crea sus propios objetos

No uses una lista global de productos entre pruebas: una prueba modificaría el estado de la siguiente. Cada test construye sus propios objetos. Es la misma independencia entre instancias que viste en la unidad 1, aplicada a las pruebas.

7.4 · Refactorizar sin cambiar el contrato

Cuando las pruebas pasen, reescribe Producto como @dataclass con __post_init__ o como modelo de Pydantic. Las pruebas deben seguir pasando: el contrato es el mismo, cambia la herramienta. Ese ejercicio es el corazón del curso: aprender a mover una idea entre implementaciones sin perder el comportamiento.

refactor con dataclass — mismo contrato 
from dataclasses import dataclass


@dataclass
class Producto:
    nombre: str
    precio: float
    cantidad: int = 0

    def __post_init__(self) -> None:
        if not self.nombre.strip():

        if self.precio <= 0:
            raise ValueError("El precio debe ser mayor que cero.")
        if self.cantidad < 0:
            raise ValueError("La cantidad no puede ser negativa.")

    def valor_total(self) -> float:
        return self.precio * self.cantidad

    def aplicar_descuento(self, porcentaje: float) -> None:
        if not 0 <= porcentaje <= 100:
            raise ValueError("El descuento debe estar entre 0 y 100.")
        self.precio = round(self.precio * (1 - porcentaje / 100), 2)

7.6 · Síntesis: siete ideas para llevarse

01

Una clase es un molde; un objeto es una instancia con su propio estado.

02

__init__ inicializa la instancia y self es el objeto que recibe el método.

03

Los métodos convierten datos en comportamiento: calcular, descontar, vender, reponer.

04

Valida en el constructor y en los métodos que cambian estado; un objeto inválido no debería existir.

05

La composición («tiene») suele ser más flexible que la herencia («es un»).

06

Pydantic y los ORM son clases con superpoderes: la misma base conceptual que acabas de escribir.

07

No conviertas todo en clase: úsala cuando haya reglas, comportamiento o identidad que conservar.
