Del trabajo manual al proceso automático

La clase anterior te dio el lenguaje: variables, tipos, condiciones. Esta clase le da la pieza que convierte un programa en un proceso: la repetición. Con ella, un programa deja de hacer una cosa y empieza a hacer diez mil.

0.1 · El proceso que hoy se hace a mano

Es el último viernes de mes. La bibliotecaria tiene que cerrar el archivo de préstamos. Abre el cuaderno, busca cada préstamo, copia el título en una columna, anota los días en otra, y marca con una rayita los que llevan más de veinte días. Al final tiene que escribir un informe: cuántos préstamos hubo, cuál se prestó más, cuál fue el promedio.

Con trece préstamos, el trabajo toma un rato. Con trescientos —que es lo que tiene la biblioteca del colegio— toma una mañana entera. Y en una mañana entera, es fácil que se escape uno. Un préstamo que no se cuenta no es un error de escritura: es un estudiante que no aparece en el informe, y una multa que no se cobra.

Distinción — automatizar no es «hacerlo más rápido»

Automatizar un proceso no significa dedicarse a hacerlo en menos tiempo: significa que el proceso se ejecuta siempre igual. El programa no se distrae, no se salta el préstamo número 147 porque ya está cansado y no confunde el día 20 con el 21. Esa diferencia —velocidad frente a fiabilidad— es la que hace que un proceso automático valga la pena, incluso con tres préstamos.

0.3 · La idea central de la clase

Aquí está la diferencia entre hacer el trabajo a mano y dejarlo en manos de un programa. A mano, el trabajo está escrito tantas veces como hace falta. En un programa, se escribe una vez, y el programa se encarga de repetirlo.

ejemplo — la misma tarea, escrita de dos maneras 
# A mano: hay que escribir una línea por cada préstamo
print("El principito")
print("Pedro Páramo")
print("Cien años de soledad")

# Con un bucle: se escribe una vez y se repite por cada elemento
for titulo in ["El principito", "Pedro Páramo", "Cien años de soledad"]:
    print(titulo)
Nota — un bucle es una promesa

La línea for titulo in prestamos: es una promesa: «esto que sigue se ejecutará una vez por cada elemento de la lista, sin importar cuántos haya». Quien lee el código no necesita saber cuántos préstamos hay: eso es problema del dato, no del programa. Es el mismo criterio con el que se escribe una función que no sabe cuántos registros vendrán de la base de datos.

Unidad 01 · El recorrido

El bucle for: recorrer lo que ya tienes

Hay dos maneras de repetir en Python. Esta es la primera y la más frecuente: la que se usa cuando ya sabes qué hay que repetir. Recorrer una lista, un texto, un rango de números. Y los dos ayudantes que evitan el trabajo de contar a mano.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: recorridos con range, enumerate y zip

1.1 · La anatomía de un for

Un for tiene siempre tres piezas, y conviene saber cómo se llama cada una porque los mensajes de error las nombran.

ejemplo — la anatomía de un for 
prestamos = ["El principito", "Pedro Páramo", "Cien años de soledad"]

for titulo in prestamos:
    print(f"Préstamo: {titulo}")
La colección
Lo que se va a recorrer: una lista, un texto, un diccionario, un rango de números. Puede ser cualquier cosa que se pueda ir tomando elemento a elemento.
La variable del bucle
El nombre que recibe cada elemento. En cada vuelta cambia de valor: primero vale lo que había en la primera posición, después en la segunda, y así.
El cuerpo
Lo que está sangrado. Se ejecuta una vez por cada elemento de la colección, siempre en el mismo orden.
Nota — la variable del bucle no desaparece al terminar

Cuando el bucle acaba, la variable conserva el último valor que tuvo. No es un error, pero sí una sorpresa: si después del for escribes print(titulo) y la lista estaba vacía, recibirás un NameError, porque la variable nunca llegó a crearse. Es el mismo aviso que da Python cuando una lista vacía se recorre y luego se usa lo que debería haber salido del bucle.

Advertencia — recorrer un diccionario da las claves

Es la sorpresa más común del primer día. Si escribes for titulo in prestamos: y prestamos es un diccionario, lo que recibes es el nombre de cada clave, no su valor. Para recorrer clave y valor a la vez hay que pedirlo explícitamente: for titulo, dias in prestamos.items():.

1.3 · range(): el generador de números

Los datos de la biblioteca son textos. Pero casi todos los procesos automáticos empiezan con números, y para eso está range().

ejemplo — las tres formas de range 
for numero in range(5):
    print(numero)          # 0, 1, 2, 3, 4

for numero in range(2, 6):
    print(numero)          # 2, 3, 4, 5

for numero in range(10, 0, -2):
    print(numero)          # 10, 8, 6, 4, 2
Las tres formas de escribir un range
Se escribeProduceEquivale a
range(fin)De 0 hasta fin - 1range(0, fin, 1)
range(inicio, fin)De inicio hasta fin - 1range(inicio, fin, 1)
range(inicio, fin, paso)De inicio hasta fin, de paso en pasoCon incremento o decremento
Precisión — el final queda fuera, siempre

range(1, 4) produce 1, 2, 3. Nunca el 4. La razón es práctica: si el final fuera incluido, range(10) daría diez números del 0 al 9, y un ciclo for i in range(10) tocaría el índice 10, que no existe. Con el final fuera, el ciclo que recorre una lista de diez elementos usa exactamente los índices del 0 al 9.

Y una segunda precisión: range no construye una lista. Es un generador: produce los números uno a uno, en el momento en que se necesitan. Por eso range(10**9) no agota la memoria. Si quieres verlo como lista, conviértelo explícitamente: list(range(5)).

1.4 · enumerate() y zip(): los dos ayudantes

A veces hay que recorrer la lista y además saber en qué posición se está. Y a veces hay dos listas que van de la mano. Escribir eso a mano es la fuente clásica de errores de una posición: el índice + 1 que se olvida, el índice que se descuadra. Python trae dos funciones que resuelven ambos casos.

ejemplo — enumerate y zip 
titulos = ["El principito", "Pedro Páramo", "Cien años de soledad"]
dias = [15, 22, 30]

for posicion, titulo in enumerate(titulos, start=1):
    print(f"{posicion}. {titulo}")

for titulo, duracion in zip(titulos, dias):
    print(f"{titulo}: {duracion} días")
Aplicación — cuándo usar cada ayudante

enumerate() cuando necesitas el número de posición y el elemento. zip() cuando dos listas se corresponden una a una: títulos y días, nombres y notas, fechas y cantidades. Y si solo necesitas el elemento, no uses ninguno de los dos: el for titulo in titulos: a secas es más corto y más claro.

Advertencia — el range(len(...)) que no hace falta

Es tentador escribir for i in range(len(lista)): para tener el índice disponible. Si el índice no se usa, es ruido: obliga a leer dos líneas para entender una, y es la causa clásica de los errores «fuera de rango». Escribe for elemento in lista: y, si de verdad necesitas la posición, añade enumerate.

Unidad 02 · La condición

El bucle while: repetir mientras algo siga siendo cierto

El for se usa cuando sabes cuántas repeticiones hay. El while se usa cuando no lo sabes: repite mientras una condición siga siendo cierta. Esta unidad explica cómo escribirlo sin que se cuelgue, y cómo salir de él a tiempo.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: bucle con estado, break y continue

2.1 · Dos maneras de repetir

for y while, lado a lado

La pregunta que responde «¿Qué hay en esta lista?» «¿Cuánto falta para que se cumpla?»
Ejemplo for prestamo in prestamos: while deuda > 0:

Nota — no son sinónimos, son dos preguntas distintas

La tentación es escribir while para todo, porque parece más flexible. Pero while traslada la responsabilidad de demostrar que el bucle termina: hay que quedarse tres veces. El for termina solo, y eso es una garantía que vale dinero. Usa for siempre que puedas, y reserva el while para cuando de verdad no sabes cuántas vueltas hay.

2.2 · Las tres piezas de un while

Todo while que funciona tiene tres piezas. Si falta la tercera, el programa se cuelga; esa es la diferencia entre un bucle y un bucle infinito.

ejemplo — las tres piezas de un while 
deuda = 1250
pago_diario = 500

while deuda > 0:              # 1. la condición
    pago = min(pago_diario, deuda)
    deuda -= pago              # 2. el avance
    print(f"Pagaste {pago}, quedan {deuda}")
1. La condición
Lo que se comprueba antes de cada vuelta. Si es cierta, el cuerpo se ejecuta; si es falsa, el bucle termina.
2. El cuerpo
Lo que se repite. Puede haber una instrucción o muchas.
3. El avance
La instrucción que cambia el valor que aparece en la condición. Sin ella, la condición nunca cambia y el bucle no termina.
Advertencia — el bucle que se cuelga

Quitar el avance del ejemplo anterior deja el programa imprimiendo «Pago 1», «Pago 2», «Pago 3»… sin parar. Se llama bucle infinito, y es el error más común de quien empieza. Tiene dos caras: si el avance falta, el programa no termina; y si el avance está pero la condición nunca llega a ser falsa, pasa lo mismo. Cuando un programa no parece terminar, lo primero que hay que mirar es si la variable de la condición está cambiando.

2.3 · break y continue

A veces el bucle tiene que detenerse antes de tiempo, o saltarse un elemento sin terminar. Para eso hay dos palabras.

ejemplo — continue: saltar un elemento 
prestamos = [
    {"titulo": "El principito", "devuelto": True},
    {"titulo": "Pedro Páramo", "devuelto": False},
    {"titulo": "Cien años de soledad", "devuelto": True},
]

for prestamo in prestamos:
    if not prestamo["devuelto"]:
        continue               # este no se cuenta: sigue con el siguiente
    print(f"Devuelto: {prestamo['titulo']}")

Y break hace lo contrario: termina el bucle en cuanto se cumple la condición. Si lo que se busca es el primer elemento que cumple algo, no hace falta seguir mirando.

ejemplo — break: dejar de buscar 
catalogo = ["El principito", "Pedro Páramo", "Cien años de soledad"]

for titulo in catalogo:
    if titulo == "Pedro Páramo":
        print("¡Encontrado!")
        break                   # deja de buscar: ya lo tiene
Distinción — break sale, continue salta

break abandona el bucle: el programa sigue por la línea que hay después del bucle. continue abandona la vuelta actual y empieza la siguiente: el resto del cuerpo no se ejecuta. En el ejemplo, continue salta los préstamos que no están devueltos y sigue con el siguiente; break deja de buscar en cuanto encuentra el primero.

2.4 · El else del bucle

Un detalle de Python que no existe en la mayoría de los lenguajes: el bucle puede llevar un else que se ejecuta solo si el bucle terminó sin un break.

ejemplo — el else del bucle 
catalogo = ["El principito", "Cien años de soledad"]

for titulo in catalogo:
    if titulo == "Pedro Páramo":
        print("¡Encontrado!")
        break
else:
    print("No estaba en el catálogo")
Aplicación — el else como detector de «no encontré nada»

Es la forma más limpia de expresar una búsqueda que puede no tener resultado. Si el break dispara, significa que lo encontraste y el else no se ejecuta. Si el bucle se recorre entero sin break, no lo encontraste, y el else es el lugar natural para decirlo. Evita la variable bandera, que es la manera larga de hacer lo mismo.

2.5 · while True y break

Hay una forma de while que merece nombre propio: while True con un break dentro. Es el bucle de «haz esto hasta que se cumpla algo», y se usa cuando la condición de salida está en el interior del cuerpo y no se puede expresar arriba.

ejemplo — while True con break 
while True:
    texto = input("Escribe un número: ")
    try:
        numero = int(texto)
    except ValueError:
        print("Eso no es un número. Inténtalo otra vez.")
        continue
    print(f"Has escrito {numero}")
    break
Nota — es el mismo patrón que escribiste en la clase 4

La función leer_dias() de la clase anterior era exactamente esto: un while True que repite la pregunta y un break —o un return— en cuanto el valor es válido. Reconocer ese patrón es la diferencia entre escribir bucles que se leen y bucles que se descifran a fuerza de probar.

2.6 · Ejemplo guiado 2.1 — Adivinar el número (8 min)

Ejemplo guiado 2.1 — Un bucle que termina 8 min

El enunciado es: «el programa piensa un número del 1 al 10 y el jugador adivina; el programa dice si va bien y, cuando acierta, dice en cuántos intentos lo consiguió.»

1
Decidir qué se repite

Se repite la acción de pedir un número. Cuántas veces se repite, no lo sabemos al principio: depende del jugador. Por eso este proceso es un while y no un for.

2
Escribir la condición y el avance

La condición es «el jugador todavía no ha acertado». El avance es intentos += 1: cada vuelta cuenta un intento más. Si se olvida esa línea, el intentos siempre vale 1 y el programa nunca anuncia la respuesta.

Piensa: el número de intentos es un contador. Ya has usado el patrón sin darte cuenta: se inicializa antes del bucle y se incrementa dentro.

3
Decidir cómo se sale

Cuando la propuesta coincide con el número secreto, hay que terminar el bucle. Se hace con break, o con return si la función devuelve el número de intentos. Las dos opciones son correctas; break es la más fácil de ver.

4
Comprobar que termina

Antes de darlo por bueno, pregúntate: «¿hay algún camino en el que la condición siga siendo cierta para siempre?». Si la respuesta es sí, falta algo. En este caso no la hay: break garantiza la salida, y el continue implícito (la vuelta siguiente) no puede volver atrás.

Unidad 03 · Los patrones

Contadores y acumuladores

Con el for y el while ya sabes repetir. Ahora vas a aprender para qué: dos patrones que aparecen en todos los procesos automáticos del mundo, y un error de inicialización que costó años de historia de la programación.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: los dos patrones dominados

3.1 · El patrón del contador

Un contador responde a una pregunta: ¿cuántas veces ocurre algo? Se inicializa a cero antes del bucle y se incrementa una unidad cada vez que se cumple la condición.

ejemplo — el patrón del contador 
prestamos = [
    {"titulo": "El principito", "dias": 15},
    {"titulo": "Pedro Páramo", "dias": 22},
    {"titulo": "Cien años de soledad", "dias": 30},
]

largos = 0

for prestamo in prestamos:
    if prestamo["dias"] > 20:
        largos += 1

print(f"Préstamos de más de 20 días: {largos}")
Nota — el contador tiene tres líneas y ni una más

Un contador son siempre tres cosas, en este orden: la declaración antes del bucle, el incremento dentro del bucle, y nada más. Si falta la declaración, el programa falla al empezar; si falta el incremento, el contador siempre vale lo mismo. Es el esqueleto más repetido de la programación, y conviene poder escribirlo sin pensarlo.

3.2 · El patrón del acumulador

Un acumulador responde a otra pregunta: ¿cuánto suman, en total, todas las cosas? La estructura es idéntica; lo único que cambia es la operación: en vez de sumar uno, se suma el valor del elemento.

ejemplo — el patrón del acumulador 
prestamos = [
    {"titulo": "El principito", "dias": 15},
    {"titulo": "Pedro Páramo", "dias": 22},
    {"titulo": "Cien años de soledad", "dias": 30},
]

total = 0

for prestamo in prestamos:
    total += prestamo["dias"]

print(f"Total de días: {total}")
Contador y acumulador, cara a cara
ContadorAcumulador
Pregunta ¿Cuántas veces? ¿Cuánto en total?
Valor inicial 0 0, o el valor neutro de la operación
Se actualiza con contador += 1 acumulador += valor
Ejemplo Cuántos préstamos superaron los 20 días Cuántos días se prestaron en total
También sirve para Contar palabras de un texto, días de un mes, errores de un registro Acumular texto, construir una lista, sumar precios
Precisión — el acumulador no siempre empieza en cero

El valor inicial del acumulador es el valor neutro de la operación que vas a hacer. Para sumar días, es 0. Para multiplicar precios, es 1. Para concatenar textos, es "" (cadena vacía). Empezar en 0 un acumulador de productos da siempre 0, y ese error —el más silencioso de todos— no lanza ningún aviso: el programa simplemente calcula mal.

3.3 · El error más frecuente: inicializar dentro del bucle

Aquí está el error que casi todo el mundo comete una vez, y que después de una hora de desconcierto resulta evidente. Son las dos versiones del mismo programa.

ejemplo — la versión que falla 
prestamos = [
    {"titulo": "El principito", "dias": 15},
    {"titulo": "Pedro Páramo", "dias": 22},
    {"titulo": "Cien años de soledad", "dias": 30},
]

# Versión que falla: el contador se declara DENTRO del bucle
for prestamo in prestamos:
    if prestamo["dias"] > 20:
        largos = 0
        largos += 1

print(largos)          # 1 — solo cuenta el último, no todos

La versión correcta es la misma, con una línea en otro sitio: la declaración del contador antes del bucle, para que cada vuelta sume sobre lo que ya había.

ejemplo — la versión correcta 
prestamos = [
    {"titulo": "El principito", "dias": 15},
    {"titulo": "Pedro Páramo", "dias": 22},
    {"titulo": "Cien años de soledad", "dias": 30},
]

# Versión correcta: se declara ANTES del bucle
largos = 0

for prestamo in prestamos:
    if prestamo["dias"] > 20:
        largos += 1

print(largos)          # 2 — cuenta todos
Advertencia — por qué la versión mala no da error

La versión que inicializa el contador dentro del bucle no falla: Python acepta el código y el programa responde 1 en cada vuelta. Lo que está mal es lo que cuenta: en lugar de contar todos los préstamos, cuenta los préstamos de la última vuelta. El contador se reinicia a cero en cada iteración, así que al final solo conserva el valor del último elemento. Es el error más peligroso de esta clase, porque no se ve: el programa funciona, imprime un número y ese número es incorrecto.

3.4 · Los atajos que Python ya trae

Para algunas operaciones, el bucle ya está escrito. Reconocer cuándo es el caso no solo te ahorra líneas: te ahorra errores.

Atajos y cuándo hacen falta
AtajoEquivale aCuándo hace falta el bucle

sum(lista) Acumulador de días Nunca, si solo quieres el total
max(lista) / min(lista) Acumulador de máximo o mínimo Nunca, si solo quieres el valor

Aplicación — cuándo el atajo no basta

Los atajos dan un resultado: el total, el máximo, la cantidad. En cuanto el proceso necesita dos cosas a la vez —el total de días y cuántos préstamos hubo— el atajo se queda corto y hay que escribir el bucle. O cuando el acumulador es de otra cosa: sum() suma números, pero no puede contar cuántos textos empiezan por «El». Para eso, un bucle con un contador.

3.5 · El acumulador de diccionario: contar por categoría

El patrón más útil de todos: un contador que no cuenta del uno al total, sino que cuenta cuántos hay de cada cosa. Se necesita un diccionario, porque cada categoría necesita su propia casilla.

ejemplo — el acumulador de diccionario 
prestamos = [
    {"titulo": "El principito", "dias": 15},
    {"titulo": "Pedro Páramo", "dias": 22},
    {"titulo": "Cien años de soledad", "dias": 30},
]

conteo = {}

for prestamo in prestamos:
    titulo = prestamo["titulo"]
    conteo[titulo] = conteo.get(titulo, 0) + 1

print(conteo)
Precisión — diccionario.get(clave, 0) en lugar de KeyError

La línea conteo[titulo] = conteo.get(titulo, 0) + 1 dice: «si esta categoría ya existe, súmale uno; si no, empieza en cero y súmale uno». Sin el get, la primera vez que aparece un título el programa falla con KeyError, porque la clave todavía no existe en el diccionario. Es un pequeño detalle que hace toda la diferencia entre un programa que funciona y uno que falla en la primera vuelta.

5.2 · Abrir un archivo y recorrerlo línea por línea

La biblioteca de Python trae una función para abrir archivos, open(), que devuelve un objeto de archivo. Ese objeto se puede recorrer con un for, y cada vuelta entrega una línea.

ejemplo — abrir un archivo y recorrerlo 
with open("prestamos.txt", encoding="utf-8") as archivo:
    for linea in archivo:
        print(repr(linea))
Nota — por qué la línea empieza con with

with open(...) as archivo: es una forma de decir «abre esto, úsalo, y ciérralo cuando termine el bloque». Python se encarga del cierre solo, incluso si el programa falla a mitad del recorrido. Sin el with, el archivo se cerraría al final del programa y el recurso quedaría abierto mientras tanto. En Python, el with es la norma para trabajar con archivos.

Precisión — por qué encoding="utf-8" va siempre

Un archivo de texto no son bytes: son caracteres codificados con una tabla. Si Python usa la tabla por defecto del sistema —en un equipo español suele ser latin-1— y el archivo tiene tildes o la «ñ» en UTF-8, aparece una lista de caracteres raros donde debería haber texto. Escribir encoding="utf-8" es barato y evita el problema antes de que aparezca.

5.3 · Partir la línea en tres datos

La línea del archivo es una cadena de texto con tres datos separados por punto y coma. Para convertirla en tres valores se usa split(), que devuelve una lista, y el desempaquetado, que reparte esa lista en variables.

ejemplo — partir una línea en tres datos 
linea = "Ana Torres;El principito;15"

limpio = linea.strip()              # quita el salto de línea del final
datos = limpio.split(";")           # ['Ana Torres', 'El principito', '15']
estudiante, titulo, dias = datos    # desempaquetado: tres variables

print(dias)                         # '15' — todavía es texto
Advertencia — la línea vacía

Si el archivo termina con un salto de línea —que es lo normal— o si alguien dejó una línea en blanco, split(";") no devolverá tres valores y el programa fallará con ValueError. La guarda if not linea.strip(): continue salta esas líneas y deja el programa preparado para archivos reales, que siempre tienen alguna línea suelta de más.

Ejercicio 6.1 · Liquidar una deuda

6.1 · El enunciado

Ejercicio

La multa que se paga a plazos

Un estudiante tiene una multa de 1 250 pesos y paga 500 pesos cada día. Escribe un programa, deuda.py, que simule los pagos: día a día, muestre cuánto paga y cuánto queda, y termine cuando la deuda esté saldada.

Ficha del sistema

Entrada La deuda inicial (1 250 pesos) y el pago diario (500 pesos), como constantes
Salida Una línea por día con el pago y lo que queda, y al final el total pagado y el número de días
Condición de salida El bucle termina cuando ya no queda nada por pagar
Restricción El último pago puede ser menor que los demás: nunca se paga de más
Restricción La simulación va en una función liquidar() que devuelve el total pagado y los días

Requisitos

  1. Dos constantes al principio del archivo: DEUDA_INICIAL y PAGO_DIARIO.
  2. liquidar(deuda, pago_diario): un while que salda la deuda y devuelve dos valores: el total pagado y el número de días que se tardó.
  3. El último pago se ajusta: si quedan 250 pesos y el pago diario es de 500, se pagan 250 y se termina. La deuda nunca queda en negativo.
  4. Un contador y un acumulador: los días que se tardó y el total pagado.
  5. Una línea de salida por día, con el número de pago, lo pagado y lo que queda.
  6. Anotaciones de tipo y cadenas de documentación en todas las funciones.

Modelo de respuesta

La línea que hace todo el trabajo es pago = min(pago_diario, deuda). min() devuelve el menor de los dos valores: si queda menos de lo que toca pagar, paga lo que queda y el bucle termina.

deuda.py — solución de referencia 
"""Simulación de la liquidación de una multa de la biblioteca."""

DEUDA_INICIAL = 1250
PAGO_DIARIO = 500


def liquidar(deuda: int, pago_diario: int) -> tuple[int, int]:
    """Salda la deuda con pagos diarios.

    Devuelve el total pagado y el número de días que se tardó.
    """
    pagado = 0
    dias = 0
    while deuda > 0:
        dias += 1
        pago = min(pago_diario, deuda)
        deuda -= pago
        pagado += pago
        print(f"Pago {dias}: {pago} pesos — quedan {deuda}")
    return pagado, dias


def main() -> None:
    print("=== Liquidación de la multa ===")
    print(f"Deuda inicial: {DEUDA_INICIAL} pesos")
    pagado, dias = liquidar(DEUDA_INICIAL, PAGO_DIARIO)
    print(f"Total pagado: {pagado} pesos en {dias} días")


if __name__ == "__main__":
    main()

Una variación que algunos preferirán: en lugar de min(pago_diario, deuda), se puede comprobar if deuda <= pago_diario: y pagar la deuda entera con un break. Las dos funcionan; la primera es más corta y no necesita dos salidas del bucle.

6.2 · El while y su variable de estado

En este ejercicio las tres piezas del while se ven con total claridad, porque el proceso es un estado que cambia.

Las tres piezas del bucle, en la liquidación
PiezaEn este programa
La condición while deuda > 0: — «mientras quede algo por pagar»
El cuerpo Calcular el pago, restarlo de la deuda, mostrar la línea del día
El avance deuda -= pago — la deuda baja, y por eso el bucle termina
Distinción — por qué aquí no puede usarse un for

El número de pagos depende de la deuda, y la deuda no se conoce de antemano. Con range(3) el bucle haría tres vueltas siempre: con una deuda de 3 000 pesos dejaría una deuda pendiente, y con una de 100 pagaría de más. El while se adapta al dato, que es exactamente para lo que sirve.

6.3 · El error del último pago

La versión que casi todo el mundo escribe primero resta siempre el pago diario completo. El programa no falla: el programa cobra de más. Y se nota en la salida.

deuda.py — la versión que cobra de más 
# La versión que casi todo el mundo escribe primero
deuda = 1250
pagado = 0
dias = 0

while deuda > 0:
    dias += 1
    pagado += 500
    deuda -= 500
    print(f"Pago {dias}: 500 pesos — quedan {deuda}")

print(f"Total pagado: {pagado} pesos en {dias} días")
Advertencia — un error que no lanza excepciones

El mensaje «quedan −250 pesos» no es un aviso de Python: es una operación aritmética perfectamente válida. El programa terminó bien y el resultado está mal. Esta es la categoría de error más peligrosa en un proceso automático, porque no se anuncia: si este programa calculara el saldo de una cuenta, el saldo negativo pasaría desapercibido.

La corrección es una línea: pago = min(pago_diario, deuda). Con ella, el último pago nunca supera lo que queda.

6.4 · El error que no termina

El segundo error es el de la unidad 2: olvidar el avance. Aquí el efecto es desconcertante, porque el programa no se cuelga del todo: sigue escribiendo, pero para siempre.

deuda.py — la versión que no termina 
# Falta el avance: la deuda nunca cambia, y el bucle no termina
deuda = 1250
dias = 0

while deuda > 0:
    dias += 1
    print(f"Pago {dias}")

print("Este mensaje nunca aparece")
Aplicación — cómo se reconoce un bucle infinito

La señal es que el programa no termina nunca y, si imprime algo, imprime lo mismo una y otra vez. En la consola, se interrumpe con Ctrl + C. Y hay un detalle importante: un programa con un bucle infinito no se «cuelga» por casualidad, se cuelga porque la condición sigue siendo cierta. Por eso la revisión de un while empieza siempre por la misma pregunta: ¿la variable de la condición cambia?

        "=== Informe mensual de préstamos ===",
        f"Préstamos registrados: {len(prestamos)}",
        f"Total de días:         {suma}",
        f"Promedio de días:      {suma / len(prestamos):.1f}",
        f"Título más prestado:   {titulo_top} ({veces} préstamos)",
        f"Préstamos de más de {DIAS_MAXIMOS} días: {len(largos)}",
        "",
        "Préstamos por título:",
    ]
    for titulo, veces_titulo in sorted(conteo.items(), key=lambda par: par[1], reverse=True):
        lineas.append(f"  {titulo}: {veces_titulo}")
    return "\n".join(lineas)


def main() -> None:
    prestamos = leer_prestamos("prestamos.txt")
    print(generar_informe(prestamos))


if __name__ == "__main__":
    main()

El párrafo escrito (modelo): decidí que el informe se construyera como una lista de líneas que al final se unen con "\n".join(...), en vez de escribir prints sueltos, porque así el informe es un valor que se puede devolver, guardar en un archivo o mandar por correo sin tocar el programa. La función que devuelve los datos —generar_informe()— no imprime nada: imprimirse es cosa de main(). Me aparté del enunciado en un punto: el enunciado pedía imprimir el informe, y yo pedí que se devuelva, para que el módulo sirva también para un servidor web.

7.3 · El mismo problema, escrito de dos maneras

La biblioteca tiene un cupo: en circulación no puede haber más de 100 días de préstamo. Los préstamos se atienden en orden, y cuando el siguiente no cabe, se deja de atender. Es un problema de for con break, y también podría ser un while. Vale la pena ver las dos.

informe.py — el cupo de días en circulación 
def llenar_cupo(prestamos: list[dict], cupo: int) -> list[dict]:
    """Devuelve los préstamos que caben en el cupo de días en circulación."""
    admitidos = []
    ocupados = 0
    for prestamo in prestamos:
        if ocupados + prestamo["dias"] > cupo:
            break
        ocupados += prestamo["dias"]
        admitidos.append(prestamo)
    return admitidos
Precisión — dos estilos, un mismo resultado

La versión con while necesita una bandera —cupo_cabia— para saber si el último préstamo se admits: es el precio de no poder recorrer la lista con un break. La versión con for usa el break y sale directamente. Cuando las dos son posibles, prefiere la que no necesita una bandera auxiliar: menos estado significa menos formas de equivocarse.

7.5 · Síntesis: siete ideas para llevarse

01

Un bucle es una promesa: «esto se repite tantas veces como haga falta». Quien lo lee no necesita saber cuántos datos hay.

02

for para cuando sabes qué hay que recorrer; while para cuando solo sabes que hay que seguir.

03

Todo while que funciona tiene tres piezas: condición, cuerpo y avance. Sin la tercera, no termina.

04

Contador y acumulador son el mismo esqueleto: se inicializan antes del bucle y se actualizan dentro.

05

El error más peligroso no es el que se cuelga: es el que termina bien y calcula mal.

06

Automatizar no es hacer la tarea más rápido: es hacer que el proceso se ejecute siempre igual.

07

Una función que devuelve se puede probar y reutilizar; una que solo imprime, no. Por eso conviene devolver.
