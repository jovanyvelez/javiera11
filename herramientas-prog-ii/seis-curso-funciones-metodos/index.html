Unidad 00 · Apertura

La misma lógica, escrita tres veces

La clase anterior te dio el motor: los bucles recorren los datos y los contadores los cuentan. Pero aquel programa tenía un defecto invisible: la lógica de la multa estaba escrita dentro del programa, en un solo lugar. Esta clase le da la pieza que convierte ese programa en algo que se puede mantener: las funciones.

⏱ 20 minutos 📄 Lectura y preparación 🧭 Producto: diagnóstico de código repetido

0.1 · La regla que hoy se rompe tres veces

La biblioteca no tiene una multa: tiene muchas multas. En la pantalla del registro, cuando un estudiante devuelve el libro. En el reporte del mes, cuando la bibliotecaria cierra el archivo. En el correo de recordatorio, cuando avisa que el préstamo lleva demasiado tiempo. Y dentro de cada una de esas pantallas hay la misma pregunta: ¿cuánto se cobra por este retraso?

Hoy, esa pregunta está resuelta tres veces, con el mismo cálculo escrito tres veces. Y la tarifa se cambió el mes pasado —de 50 a 60 pesos por día—, así que el cálculo se tuvo que cambiar tres veces también. La tercera se olvidó.

ejemplo — la misma lógica, escrita tres veces 
# En la pantalla de registro
dias = 30
multa = dias * 50
if multa > 500:
    multa = 500

# En el reporte del mes
dias = 30
multa = dias * 50
if multa > 500:
    multa = 500

# En el correo de recordatorio
dias = 30
multa = dias * 60      # ¡esta vez con 60!
if multa > 500:
    multa = 500
Distinción — repetir no es reutilizar

Repetir es volver a escribir lo mismo. Reutilizar es que el mismo texto del programa esté en un solo sitio y lo usen varios lugares. La diferencia no se ve en el momento en que escribes: se ve el día que hay que cambiarlo. Con el código repetido de arriba, cambiar la tarifa significa buscar tres lugares y acordarse de los tres. Con una función, significa cambiar una línea.

Y hay un segundo efecto, más difícil de medir: el código repetido no se puede probar por partes. Si la multa está escrita tres veces, no hay forma de comprobar «¿la multa de 30 días es 500?» sin ejecutar el programa entero. Si está en una función, basta con llamarla.

0.3 · La idea central de la clase

Una función es un bloque con nombre que hace un trabajo y te entrega el resultado. Escribes el trabajo una vez; después lo llamas tantas veces como quieras, con datos distintos cada vez.

ejemplo — la misma tarea, escrita de dos maneras 
# A mano: hay que escribir el cálculo cada vez
print("Multa por 30 días: 500")
print("Multa por 3 días: 150")

# Con una función: se escribe una vez y se llama con datos distintos
def calcular_multa(dias: int, tarifa: int = 50, tope: int = 500) -> int:
    """Devuelve la multa por un préstamo retrasado."""
    return min(dias * tarifa, tope)

print(calcular_multa(30))
print(calcular_multa(3))
Nota — una función es una promesa

La línea def calcular_multa(dias, tarifa=50, tope=500): es una promesa: «si me das unos días, te devuelvo una multa». Quien lee el código no necesita saber si el préstamo viene del registro, del reporte o del correo: eso es problema del dato, no del cálculo. Es el mismo criterio con el que se escribe una función que no sabe cuántos registros vendrán de la base de datos.

Unidad 01 · El bloque con nombre

La anatomía de una función

Cuatro piezas y ninguna más: el nombre, los parámetros, el cuerpo y el return. Esta unidad las presenta una por una y explica la diferencia que decide el resto del curso: una función que devuelve no es lo mismo que una función que imprime.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: la primera función que devuelve

1.1 · La primera función

Una función se escribe con la palabra def, el nombre, los paréntesis con los parámetros, dos puntos y el cuerpo sangrado. No hay nada mágico: es un bloque con nombre.

ejemplo — la anatomía de una función 
def saludar(nombre: str) -> str:
    """Devuelve un saludo con el nombre recibido."""
    saludo = f"Hola, {nombre}"
    return saludo
La palabra def
Significa «definición»: a partir de aquí empieza el bloque de la función. Todo lo que está sangrado debajo forma su cuerpo.
El nombre
Es el identificador con el que se la llama después. Elija un nombre que diga qué hace: calcular_multa es mejor que cosas.
Los parámetros
Los nombres entre paréntesis. Son los datos que la función necesita para trabajar. Aquí, un nombre.
La anotación de salida
El -> str dice qué tipo de dato devuelve. Python no lo obliga, pero ayuda a quien lee el código.
La cadena de documentación
El texto entre comillas triples, justo debajo. Explica en una frase qué hace la función. Es lo primero que se lee.
El return
La salida. Entrega un valor y termina la función en ese punto.
Precisión — definir no es llamar

Escribir la función no la ejecuta: solo la registra con su nombre. El programa sigue exactamente igual hasta que alguien la llama escribiendo su nombre y sus argumentos. Por eso puedes definir veinte funciones y no usar ninguna: el programa no se quejará.

1.2 · Cómo se llama una función

ejemplo — definir, llamar, guardar el resultado 
def saludar(nombre: str) -> str:
    """Devuelve un saludo con el nombre recibido."""
    return f"Hola, {nombre}"

mensaje = saludar("Sara")
print(mensaje)

print(saludar("Julián"))
print(saludar("Ana"))
terminal — uv run python saludo.py
uv run python saludo.py
Hola, Sara
Hola, Julián
Hola, Ana
Aplicación — el nombre de la función es su documentación

Cuando leas el programa dentro de seis meses, no vas a leer el cuerpo de la función: vas a leer su firma y su llamada. Si el nombre dice lo que hace —calcular_multa, total_dias, generar_informe—, ya sabes el80 % de lo que hace sin abrirla. Por eso en Python se usan verbos y frases cortas en snake_case: escribir_linea, buscar_estudiante.

1.3 · Imprimir o devolver: la diferencia que decide todo

Esta es la idea más importante de la clase. Hay dos maneras de dejar un resultado: imprimirlo o devolverlo. Las dos se ven iguales en la pantalla la primera vez, y se comportan de forma completamente distinta en cuanto el programa crece.

ejemplo — la función que imprime y la función que devuelve 
def calcular_multa(dias: int, tarifa: int = 50, tope: int = 500) -> int:
    """Devuelve la multa por un préstamo retrasado."""
    return min(dias * tarifa, tope)


def mostrar_multa(dias: int) -> None:
    """Imprime la multa. No devuelve nada."""
    print(f"Multa por {dias} días: {calcular_multa(dias)}")


def obtener_multa(dias: int) -> int:
    """Devuelve la multa para poder guardarla o sumarla."""
    return calcular_multa(dias)


mostrar_multa(30)
total = obtener_multa(30)
total += obtener_multa(5)
print(f"Total: {total}")
terminal — uv run python multas.py
uv run python multas.py
Multa por 30 días: 500
Total: 750
Imprimir y devolver no son intercambiables
Función que imprimeFunción que devuelve
Qué produce Texto en la pantalla Un valor que puedes guardar
Se puede sumar No: mostrar_multa(30) vale None Sí: obtener_multa(30) + 5
Se puede probar Casi no: hay que mirar la pantalla Sí: se compara con el valor esperado
Dónde va el resultado Solo a la terminal A donde tú quieras: variable, archivo, web
Se puede reutilizar No: queda atada a la pantalla Sí: es el objeto de la reutilización
Advertencia — la función que imprime y devuelve a la vez

Es tentador escribir una función que imprima el resultado y que además lo devuelva. Funciona, pero rompe la regla que estás aprendiendo: si la función imprime, ya decidió dónde va el resultado, y el lugar que la llama no puede elegir otro. Escribe una función, una tarea: o calcula y devuelve, o muestra. Si más adelante hace falta mostrar, se llama a la que devuelve desde el sitio que decide mostrar.

1.4 · El ámbito: lo de dentro y lo de fuera

Una función tiene su propio mundo. Las variables que se crean dentro de ella solo existen dentro: se llaman variables locales. Al terminar la función, desaparecen. Por eso dos funciones pueden usar la misma variable de nombre sin interferir.

ejemplo — una constante global y una variable local 
TARIFA = 50   # constante del módulo: visible para todos


def multa_con_global(dias: int) -> int:
    """Usa la tarifa del módulo."""
    return dias * TARIFA


def multa_con_local(dias: int) -> int:
    """Usa su propia tarifa, que desaparece al terminar."""
    tarifa = 60
    return dias * tarifa


print(multa_con_global(10))
print(multa_con_local(10))
terminal — uv run python ambito.py
uv run python ambito.py
500
600
Nota — modificar una variable de fuera es un caso especial

Leer una constante global está bien. Cambiarla es otra historia: Python exige que declares que te refieres a la de fuera con la palabra global. Y aunque funcione, es una mala idea casi siempre, porque cualquier parte del programa podría cambiar el valor sin que nadie lo note. Si necesitas «contar» algo, devuélvelo y que lo guarde quien llama.

1.5 · El orden de las cosas y el bloque main()

Las funciones se definen antes de usarse. Y el programa tiene una puerta de entrada, que es la convención de Python: if __name__ == "__main__":.

ejemplo — la estructura de un programa con funciones 
def calcular_multa(dias: int) -> int:
    """Devuelve la multa por un préstamo retrasado."""
    return min(dias * 50, 500)


def main() -> None:
    """El programa principal: aquí sí se muestra."""
    prestamos = [30, 7, 22]
    for dias in prestamos:
        print(f"{dias} días -> {calcular_multa(dias)}")


if __name__ == "__main__":
    main()
Precisión — por qué el main() con esa puerta

__name__ vale "__main__" solo cuando ejecutas el archivo directamente. Si otro archivo hace import informe, el código se carga pero main() no se ejecuta. Ese detalle es exactamente lo que hace posible la reutilización: tu módulo puede tener funciones que se importan sin arrancar nada. En el taller final lo vas a ver funcionando.

Unidad 02 · La entrada

El paso de parámetros

Una función que no recibe datos hace siempre lo mismo. Esta unidad explica las tres formas de pasarle datos: por posición, con nombre y por defecto— y por qué la última es la que hace que una función se pueda reutilizar en lugares distintos.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: una función con tres formas de llamarse

2.1 · Parámetros posicionales

La forma más simple: se escriben los datos en el orden en que la función los espera. El primer valor que escribes es el primer parámetro, el segundo es el segundo, y así.

ejemplo — parámetros posicionales 
def calcular_multa(dias: int, tarifa: int = 50, tope: int = 500) -> int:
    """Devuelve la multa por un préstamo retrasado."""
    return min(dias * tarifa, tope)


print(calcular_multa(3))              # 3 días, tarifa 50
print(calcular_multa(3, 60))          # 3 días, tarifa 60
Advertencia — el orden importa y no se nota

Si la función espera (dias, tarifa) y tú escribes calcular_multa(60, 3), Python no protestará: le has dicho que hay 60 días y una tarifa de 3. El resultado será un número, pero será el número equivocado. Estos son los errores más difíciles de encontrar, porque el programa funciona.

2.2 · Parámetros con nombre

La segunda forma es más segura: se escribe el nombre del parámetro junto al valor. El orden deja de importar, y quien lee la llamada sabe qué número es cuál.

ejemplo — parámetros con nombre 
print(calcular_multa(dias=3, tarifa=60))
print(calcular_multa(dias=3, tope=100))

2.3 · Parámetros por defecto

La tercera forma es la que hace posible la reutilización. Un parámetro con valor por defecto se puede omitir al llamar: la función usa ese valor. Y el valor por defecto puede cambiarse, sin tocar el cuerpo de la función.

Aplicación — el valor por defecto es una decisión de negocio

¿Por qué tarifa=50 y no tarifa=60? Porque 50 es el valor que la biblioteca usa hoy. El día que suba a 60, se cambia una línea — y todos los que llamaban a la función sin especificar tarifa se actualizan solos. Si la tarifa estuviera escrita en el cuerpo de la función, habría que buscarla en cada sitio.

2.4 · Las reglas de los parámetros

Precisión — los parámetros sin valor por defecto son obligatorios

Si un parámetro no tiene valor por defecto, hay que darlo al llamar. Si te olvidas, Python responde con un TypeError que dice exactamente qué falta: calcular_multa() missing 1 required positional argument: 'dias'. Ese mensaje es tu amigo: te dice qué parámetro no llegó y en qué forma se esperaba.

2.5 · *args y **kwargs: cuando la cantidad no es fija

A veces no sabes de antemano cuántos datos llegan: la suma de una lista de días, o un conjunto de campos que arma el usuario. Python tiene dos herramientas para eso.

ejemplo — cantidad variable de argumentos 
def sumar(*valores: int) -> int:
    """Suma todos los valores recibidos, sean los que sean."""
    return sum(valores)


def tarjeta(**campos: str) -> str:
    """Construye una tarjeta con los campos recibidos."""
    return " | ".join(f"{clave}: {valor}" for clave, valor in campos.items())


print(sumar(1, 2, 3))            # 6
print(sumar())                          # 0
print(sumar(10, 20, 30, 40))     # 100
print(tarjeta(titulo="El principito", autor="Saint-Exupéry"))
terminal — uv run python variables.py
uv run python variables.py

titulo: El principito | autor: Saint-Exupéry
Advertencia — *args no es un comodín de uso libre

Que exista no significa que haya que usarla. Una función con *args no dice nada sobre qué espera: puede recibir dos valores o doscientos, y quien la llama no tiene forma de saberlo. Úsala solo cuando la cantidad de datos sea de verdad variable (una lista de días, un formulario con campos libres). Para todo lo demás, dos o tres parámetros con nombre se leen mucho mejor.

Unidad 03 · La salida

El retorno de valores

Ya sabes que la función devuelve. Ahora la unidad trata de qué devuelve y cómo se declara ese contrato: el conjunto de reglas que dicen qué entra, qué sale y qué pasa en los casos raros. Un contrato escrito es la diferencia entre un programa que se puede probar y uno que no.

⏱ 30 minutos 📄 Lectura y práctica 🧭 Producto: funciones con contrato y pruebas

3.1 · return: la puerta de salida

return entrega un valor y termina la función en ese punto. Todo lo que esté escrito después, en esa función, no se ejecuta nunca.

ejemplo — el return termina la función 
def clasificar(dias: int) -> str:
    """Clasifica un préstamo por sus días."""
    if dias <= 5:
        return "en plazo"
    if dias <= 20:
        "vuelve tarde pero no se multa"
        return "retrasado"
    return "muy retrasado"
Advertencia — el return que se olvidó

En el fragmento de arriba hay una línea que no hace nada: "vuelve tarde pero no se multa". Es una cadena suelta, sin return, y Python la descarta en silencio. La función sigue funcionando, pero el resultado para ese caso sería None en vez de "retrasado". Es el error más silencioso que hay: el programa no se rompe, solo devuelve la respuesta equivocada.

3.2 · Devolver varios valores: la tupla

A veces una función produce dos o tres datos relacionados. Python los devuelve juntos, en una tupla, y quien llama los separa al instante.

ejemplo — una función que devuelve dos valores 
def calcular_multa(dias: int, tarifa: int = 50, tope: int = 500) -> int:
    """Devuelve la multa por un préstamo retrasado."""
    return min(dias * tarifa, tope)


def evaluar_prestamo(dias: int) -> tuple[str, int]:
    """Devuelve el estado del préstamo y la multa que corresponde."""
    if dias <= 5:
        return ("en plazo", 0)
    return ("retrasado", calcular_multa(dias))


estado, multa = evaluar_prestamo(30)
print(f"{estado}: {multa}")
terminal — uv run python tupla.py
uv run python tupla.py
retrasado: 500
Precisión — devuelve la tupla, no sus partes

return ("retrasado", 500) devuelve un dato: una tupla de dos elementos. La línea estado, multa = evaluar_prestamo(30) es lo que la separa en dos variables, y por eso a la izquierda hay dos nombres. Si te sobran o te faltan, Python te avisa con ValueError.

3.3 · None: cuando no hay nada que devolver

Toda función devuelve algo, aunque no haya escrito return. Si no hay return, Python devuelve None por su cuenta: el valor «nada».

ejemplo — una función que puede no encontrar nada 
def buscar_estudiante(nombre: str) -> str | None:
    """Devuelve el nombre completo, o None si no está en la lista."""
    if nombre == "Sara":
        return "Sara Ríos"
    if nombre == "Julián":
        return "Julián Mora"
    return None


print(buscar_estudiante("Sara"))     # Sara Ríos
print(buscar_estudiante("Ana"))      # None
print(buscar_estudiante("Nadie"))   # None
terminal — uv run python ninguno.py
uv run python ninguno.py
Sara Ríos
None
None
Nota — None no es lo mismo que una cadena vacía

None significa «no hay valor». La cadena vacía "" significa «hay un valor, y es texto sin contenido». Esa diferencia importa al escribir la anotación de salida: -> str | None deja claro que el valor puede faltar, y quien use la función sabrá que tiene que comprobarlo.

3.4 · El contrato de una función

Cuando una función está bien escrita, su contrato se puede leer sin ver su cuerpo: qué recibe, qué devuelve y qué pasa con los casos raros. Ese contrato es lo que hace que la función se pueda usar sin miedo.

El contrato de evaluar_prestamo(dias)
PreguntaRespuesta
¿Qué recibe?Un entero: los días que lleva prestado el libro
¿Qué devuelve?Una tupla con el estado (texto) y la multa (número)
¿Y si los días son negativos?No está contemplado: es un dato inválido y lo decide quien llama
¿Imprime algo?No. Imprimir es responsabilidad de quien la llama
¿Puede fallar?No: no hay entradas de archivo ni de red
Aplicación — el contrato se escribe antes del cuerpo

Cuando te pidan una función, escribe primero la frase que responde «¿qué recibe y qué devuelve?» y la anotación de tipo. Solo después el cuerpo. Si no sabes qué devolver, es que todavía no sabes qué tarea le estás pidiendo: ese es el momento de pensarlo, no de programar a ciegas.

3.5 · Por qué devolver permite probar

Una función que devuelve un valor se puede comprobar sin mirarla. Se le da una entrada, se compara la salida con lo que debería ser, y se sabe si funciona.

ejemplo — comprobar una función con assert 
def sumar_dias(dias: list[int]) -> int:
    """Devuelve la suma de los días de la lista."""
    return sum(dias)


assert sumar_dias([1, 2, 3]) == 6
assert sumar_dias([]) == 0
assert sumar_dias([30]) == 30
print("Todas las pruebas pasaron")
terminal — uv run python pruebas.py
uv run python pruebas.py
Todas las pruebas pasaron
Precisión — assert no es un print

Un print te dice lo que pasó; un assert te dice lo que tenía que pasar. Si la comprobación falla, Python detiene el programa con un AssertionError y te dice qué línea falló. Por eso la comprobación va antes de escribir el código: primero la regla, después el cumplimiento.

3.6 · La regla de oro: una función, una tarea

Distinción — «calcular» y «mostrar» son dos tareas

La tentación más fuerte al escribir funciones es hacerlas útiles de más: que lean el archivo, que calculen, que formateen y que impriman, todo en un solo bloque. Funciona la primera vez. La segunda vez, cuando alguien quiera usar solo el cálculo, no puede: el archivo se lee, la pantalla se ensucia y el resultado no se puede guardar.

La regla que resuelve esto: una función hace una tarea y devuelve el resultado. Si necesita leer datos, que los reciba como parámetro. Si necesita mostrarlos, que lo haga quien la llama. Con esa regla, cada pieza se puede probar por separado y el programa se puede armar como un rompecabezas.

La parte que más se olvida es la lectura del archivo. Las demás funciones son acumuladores y contadores que ya sabes escribir. Fíjate sobre todo en las dos primeras líneas de leer_prestamos(): todo el recorrido depende de ellas.

biblioteca.py — el módulo de funciones 
"""Funciones de la biblioteca. Este módulo no imprime nada: solo calcula."""

LIMITE_DIAS = 20
TARIFA_MULTA = 50
TOPE_MULTA = 500


def leer_prestamos(ruta: str) -> list[dict]:
    """Lee el archivo de préstamos y devuelve la lista de diccionarios."""
    prestamos = []
    with open(ruta, "r", encoding="utf-8") as archivo:
        for linea in archivo:
            linea = linea.strip()
            if not linea:
                continue
            estudiante, titulo, dias = linea.split(";")
            prestamos.append({
                "estudiante": estudiante,
                "titulo": titulo,
                "dias": int(dias),
            })
    return prestamos


def total_dias(prestamos: list[dict]) -> int:
    """Devuelve la suma de los días de todos los préstamos."""
    suma = 0
    for prestamo in prestamos:
        suma += prestamo["dias"]
    return suma


def promedio_dias(prestamos: list[dict]) -> float:
    """Devuelve el promedio de días; 0.0 si no hay préstamos."""
    if not prestamos:
        return 0.0
    return total_dias(prestamos) / len(prestamos)


def contar_por_titulo(prestamos: list[dict]) -> dict[str, int]:
    """Devuelve cuántos préstamos hay de cada título."""
    conteo = {}
    for prestamo in prestamos:
        titulo = prestamo["titulo"]
        conteo[titulo] = conteo.get(titulo, 0) + 1
    return conteo


def prestamos_largos(prestamos: list[dict], limite: int = LIMITE_DIAS) -> list[dict]:
    """Devuelve los préstamos que superan el límite de días."""
    largos = []
    for prestamo in prestamos:
        if prestamo["dias"] > limite:
            largos.append(prestamo)
    return largos


def generar_informe(prestamos: list[dict], limite: int = LIMITE_DIAS) -> str:
    """Devuelve el informe del mes como un texto."""
    lineas = []
    lineas.append("=== Recuento del mes ===")
    lineas.append(f"Préstamos registrados: {len(prestamos)}")
    lineas.append(f"Total de días:          {total_dias(prestamos)}")
    lineas.append(f"Promedio de días:       {promedio_dias(prestamos):.1f}")
    largos = prestamos_largos(prestamos, limite)
    lineas.append(f"Préstamos de más de {limite} días: {len(largos)}")
    return "\n".join(lineas)
informe.py — el programa que solo muestra 
"""Imprime el informe del mes. Toda la lógica vive en biblioteca.py."""

from biblioteca import generar_informe, leer_prestamos


def main() -> None:
    """El programa principal: lee los datos y muestra el informe."""
    prestamos = leer_prestamos("prestamos.txt")
    print(generar_informe(prestamos))


if __name__ == "__main__":
    main()

Ejercicio 6.1 · De función a método

Tus funciones del ejercicio anterior reciben datos sueltos y devuelven números. Ahora vas a dar un paso más: reunir cada préstamo en un objeto que sepa calcular su propia multa y su propio estado. En 35 minutos escribirás la clase Prestamo.

6.1 · Por qué una clase

El problema de las funciones sueltas es que los datos viajan sueltos. Si una función necesita el estudiante, el título y los días, tiene que recibir tres parámetros; y quien la llama puede equivocarse de orden. Una clase agrupa esos tres datos en un objeto y le da las operaciones que se pueden hacer con él.

ejemplo — la misma pregunta, con funciones y con un objeto 
# Con funciones sueltas: los datos viajan sueltos
def multa_de(dias: int) -> int:
    return min(dias * 50, 500)

multa_de(30)   # ¿y esto de quién es?


# Con una clase: el objeto lleva sus datos y sabe lo suyo
class Prestamo:
    def __init__(self, estudiante: str, titulo: str, dias: int) -> None:
        self.estudiante = estudiante
        self.titulo = titulo
        self.dias = dias

    def multa(self) -> int:
        return min(self.dias * 50, 500)


prestamo = Prestamo("Ana Torres", "El principito", 30)
print(prestamo.multa())   # 500, y se sabe de quién es
Precisión — self es el objeto que llama

Cuando escribes prestamo.multa(), Python mete el objeto prestamo dentro de la función, en el primer parámetro, que por eso se llama self. Por eso self.dias es «los días de este préstamo». Dentro de la función, self no es un nombre reservado: puedes llamarlo como quieras, pero todo el mundo le pone self, y es mejor no inventar.

Ejercicio

La clase Prestamo

Restricción Un método que no usa self debe ser @staticmethod

Restricción El método multa() no imprime: devuelve el número

Requisitos

  1. __init__(self, estudiante, titulo, dias): guarda los tres datos en el objeto con self..
  2. El atributo de clase DIAS_DE_GRACIA = 5: los días que un préstamo puede tener sin considerarse retrasado.
  3. multa(self): devuelve la multa del préstamo, con el tope de 500 pesos.
  4. atrasado(self): devuelve True o False según si pasó el período de gracia.
  5. estado(self): devuelve el texto "en plazo" o "retrasado".
  6. __str__(self): devuelve una descripción legible del préstamo.
  7. normalizar(titulo) como @staticmethod: limpia un título y lo deja con mayúsculas iniciales.
  8. desde_linea(linea) como @classmethod: construye un préstamo a partir de una línea del archivo.

Pista — la diferencia entre staticmethod y classmethod

Un @staticmethod es una función que vive dentro de la clase pero no necesita el objeto: recibe solo lo que tú le pases. Un @classmethod recibe la clase en el primer parámetro, que por eso se llama cls, y por eso puede construir objetos de esa misma clase. Con cls puedes escribir cls(estudiante, titulo, dias) y obtener un Prestamo aunque el método esté en otra subclase.

Modelo de respuesta

La línea que hace todo el trabajo es self.normalizar(titulo) dentro de __init__: el título se limpia una sola vez, al construir el objeto, y todas las demás respuestas usan la versión limpia.

prestamo.py — la clase Prestamo 
"""La clase Prestamo: un préstamo con sus propios métodos."""

TARIFA_MULTA = 50
TOPE_MULTA = 500


class Prestamo:
    """Un préstamo de la biblioteca."""

    DIAS_DE_GRACIA = 5

    def __init__(self, estudiante: str, titulo: str, dias: int) -> None:
        self.estudiante = estudiante
        self.titulo = self.normalizar(titulo)
        self.dias = dias

    def multa(self) -> int:
        """Devuelve la multa de este préstamo."""
        return min(self.dias * TARIFA_MULTA, TOPE_MULTA)

    def atrasado(self) -> bool:
        """True si el préstamo pasó el período de gracia."""
        return self.dias > self.DIAS_DE_GRACIA

    def estado(self) -> str:
        """Devuelve 'en plazo' o 'retrasado'."""
        return "retrasado" if self.atrasado() else "en plazo"

    def __str__(self) -> str:
        """Devuelve una descripción legible del préstamo."""
        return f"{self.titulo} — {self.estudiante} ({self.dias} días, {self.estado()})"

    @staticmethod
    def normalizar(titulo: str) -> str:
        """Limpia un título: sin espacios de más y con mayúsculas iniciales."""
        return " ".join(titulo.split()).title()

    @classmethod
    def desde_linea(cls, linea: str) -> "Prestamo":
        """Construye un préstamo a partir de una línea del archivo."""
        estudiante, titulo, dias = linea.strip().split(";")
        return cls(estudiante, titulo, int(dias))

from prestamo import Prestamo


def prestamos_como_objetos(lineas: list[str]) -> list[Prestamo]:
    """Convierte líneas del archivo en objetos Prestamo."""
    prestamos = []
    for linea in lineas:
        if not linea.strip():
            continue
        prestamos.append(Prestamo.desde_linea(linea))
    return prestamos


def resumen_de_estados(prestamos: list[dict]) -> dict[str, int]:
    """Devuelve cuántos préstamos hay en plazo y cuántos retrasados."""
    resumen = {"en plazo": 0, "retrasado": 0}
    for prestamo in prestamos:
        estado = "retrasado" if prestamo["dias"] > 5 else "en plazo"
        resumen[estado] = resumen.get(estado, 0) + 1
    return resumen

7.4 · Síntesis: siete ideas para llevarse

01

Una función es un bloque con nombre que hace un trabajo y devuelve el resultado.

02

Devolver no es imprimir: lo devuelto se puede guardar, comparar y reutilizar; lo impreso, no.

03

El return es la puerta de salida: entrega el valor y termina la función ahí.

04

Un parámetro con valor por defecto hace que una función sirva en varios sitios y que el negocio cambie en una línea.

05

Las variables de dentro son locales: por eso dos funciones pueden usar el mismo nombre sin chocarse.

06

Un método es una función que vive en una clase y recibe el objeto en self.

07

Reutilizar no es repetir: es que el mismo texto del programa esté en un solo sitio y lo usen muchos.

7.5 · Puente hacia la próxima clase

Hoy tu informe es un texto: una cadena con líneas y todo, construida a mano. Es un informe que se puede leer en una terminal y también en el navegador, pero sigue siendo texto plano: no tiene títulos, ni listas, ni colores.

La próxima clase resuelve exactamente eso, con las herramientas de las clases 2 y 3. Cuatro cosas de hoy siguen vivas allí:

  1. La función que devuelve el contenido es el modelo de lo que hará la plantilla: un generar_informe() que devuelve el texto y una plantilla que decide cómo se ve.
  2. La lista de diccionarios que devuelve leer_prestamos() es exactamente lo que la plantilla va a recibir para pintar una tabla de libros.
  3. Los bucles que recorren los datos son los mismos que usará el motor de plantillas. El {% for %} es un for de Python con otra sintaxis, y la idea es la misma.
  4. El módulo biblioteca.py es el archivo que la plantilla importará. Lo que hoy se importa con from biblioteca import ... se importará igual, y la lógica del negocio no cambiaría ni una línea.
Antes de la próxima clase

Guarda tu taller en un repositorio de Git con un mensaje de commit claro, y comprueba que uv run python informe.py imprime el informe, que uv run python -c "from biblioteca import total_dias; print(total_dias([]))" devuelve 0 sin romperse, y que la ruta /informe del servidor devuelve el mismo texto que la terminal.

Has cerrado el ciclo de la estructura: el servidor recibe datos (clase 4), los recorre con bucles (clase 5) y ahora los organiza en funciones y métodos que se pueden volver a usar desde cualquier parte.
