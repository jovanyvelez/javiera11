💡 ¿Por qué plantillas?

Escribir HTML a mano para cada dato es imposible. Una plantilla es un HTML con huecos que se rellenan con datos. Jinja2 rellena esos huecos y genera el HTML final. Es como una carta con espacios en blanco que se completan.

📄 Jinja2: el motor de plantillas

⏱️ 35 minutos · "HTML con huecos que se rellenan"

🧠 ¿Qué es Jinja2?

Jinja2 es un motor de plantillas para Python. Te permite escribir HTML con variables ({{ variable }}) y lógica ({% for %}, {% if %}). FastAPI lo usa para generar páginas web con datos reales.

autores.html — variables y bucles 
<h1>Autores</h1>

<ul>
  {% for autor in autores %}
    <li>{{ autor.nombre }} — {{ autor.pais }}</li>
  {% endfor %}
</ul>

💡 Dos tipos de llaves

{{ ... }} imprime una variable (el valor). {% ... %} ejecuta lógica (bucles, condiciones). Con {% for %} recorres una lista y generas HTML por cada elemento.

🧬 Herencia: una base para todas las páginas

⏱️ 35 minutos · "No repitas el HTML común"

🧠 La idea central

Todas las páginas comparten cosas: el <head>, los estilos, el menú. Con herencia, defines una plantilla base con bloques ({% block %}) y las demás páginas la extienden ({% extends %}) rellenando solo lo que cambia.

base.html — la plantilla base 
<!DOCTYPE html>
<html>
<head>
  <title>{% block title %}Autores{% endblock %}</title>
</head>
<body>
  {% block content %}{% endblock %}
</body>
</html>
autores.html — extiende la base 
{% extends "base.html" %}

{% block content %}
  <h1>Lista de autores</h1>
{% endblock %}

🦹 El villano: el HTML repetido

Si cada página repite el <head> completo, y mañana cambias el título o agregas un estilo, tienes que editar todas las páginas. Con herencia, editas solo la base y todas se actualizan.

🧩 Macros: componentes reutilizables

⏱️ 35 minutos · "Al estilo de React o Svelte"

🧠 La idea central

Una macro es como una función que devuelve HTML. La defines una vez y la usas muchas veces, pasándole datos. Es la forma de Jinja2 de crear componentes, como los de React o Svelte.

componentes/tabla_autores.html — una macro 
{% macro tabla_autores(autores) %}
<table>
  {% for autor in autores %}
    <tr><td>{{ autor.nombre }}</td></tr>
  {% endfor %}
</table>
{% endmacro %}
autores.html — usar la macro 
{% from "componentes/tabla_autores.html" import tabla_autores %}

{{ tabla_autores(autores) }}

💡 Macro = componente

Igual que en React tienes <TablaAutores />, en Jinja2 tienes {{ tabla_autores(autores) }}. La idea es la misma: un bloque de interfaz reutilizable que recibe datos y devuelve HTML.

🔲 Partials: fragmentos de página

⏱️ 35 minutos · "Devolver solo un pedazo de HTML"

🧠 La idea central

Un partial es una plantilla que devuelve solo un fragmento de HTML, no la página completa. Es clave para htmx (que veremos en la próxima clase): cuando creas un autor, el servidor devuelve solo la tabla actualizada, no toda la página.

partials/tabla_autores.html — un fragmento 
{% from "componentes/tabla_autores.html" import tabla_autores %}

{{ tabla_autores(autores) }}

💡 Página completa vs partial

La página completa (autores.html) extiende la base y tiene todo. El partial (partials/tabla_autores.html) es solo la tabla, sin <head> ni menú. El partial se usa para actualizar una parte de la página sin recargarla.

📨 TemplateResponse: renderizar la plantilla

⏱️ 35 minutos · "Cómo la ruta devuelve HTML"

🧠 La idea central

Para devolver HTML en vez de JSON, la ruta usa TemplateResponse. Le pasas el request, el nombre de la plantilla y el contexto (los datos). Jinja2 rellena la plantilla con esos datos y devuelve el HTML.

vistas.py — renderizar 
from fastapi.templating import Jinja2Templates

templates = Jinja2Templates(directory="templates")

@router.get("/autores")
async def listar_autores(request, conn):
    autores = await obtener_autores(conn)
    return templates.TemplateResponse(
        request=request,
        name="autores.html",
        context={"autores": autores},
    )

💡 Tres argumentos

request es la petición (FastAPI la necesita). name es el archivo de la plantilla. context es un diccionario con los datos que la plantilla usará (aquí, la lista de autores).
