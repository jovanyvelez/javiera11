⚡ Una página interactiva sin JavaScript

Ya tenemos plantillas que muestran datos. Hoy vamos a hacerlas interactivas: crear, editar y borrar autores sin recargar la página. Usaremos Bootstrap para el estilo y htmx para la interactividad, sin escribir una sola línea de JavaScript.

⌘ terminal — dev@app
dev@app:~$ # htmx envía el formulario sin recargar
hx-post="/autores" hx-target="#tabla-autores"
dev@app:~$ # el servidor devuelve solo la tabla actualizada
dev@app:~$

💡 ¿Por qué htmx?

Normalmente, hacer una página interactiva requiere escribir JavaScript. htmx te permite hacerlo solo con atributos HTML (hx-post, hx-target...). Es más simple y perfecto para aprender.

🎨 Bootstrap: estilos listos para usar

⏱️ 35 minutos · "CSS bonito sin escribirlo"

🧠 ¿Qué es Bootstrap?

Bootstrap es una librería de CSS con estilos ya hechos: botones, tablas, formularios, tarjetas. En vez de escribir CSS desde cero, agregas clases como btn, table o card y todo se ve bien automáticamente.

base.html — incluir Bootstrap por CDN 
<head>
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.8/dist/css/bootstrap.min.css" rel="stylesheet">
</head>
🔘

Botones

btn btn-primary crea un botón azul bonito.

📊

Tablas

table table-striped crea una tabla con filas alternadas.

🃏

Tarjetas

card crea un contenedor con borde y sombra.

📐

Grid

row y col organizan el contenido en columnas.

💡 CDN = sin instalar nada

Incluimos Bootstrap por CDN (un enlace a internet). No hay que descargar ni instalar nada: el navegador carga los estilos directamente desde el enlace. Lo mismo haremos con htmx.

⚡ htmx: interactividad sin JavaScript

⏱️ 35 minutos · "Atributos HTML que hacen magia"

🧠 ¿Qué es htmx?

htmx es una librería de JavaScript que te permite hacer peticiones HTTP desde atributos HTML. En vez de escribir JavaScript, agregas atributos como hx-post a un elemento y htmx se encarga de todo. Es la forma moderna y simple de hacer páginas interactivas.

base.html — incluir htmx por CDN 
<head>
  <script src="https://unpkg.com/htmx.org@2.0.10"></script>
</head>

🦹 El villano: recargar toda la página

Sin htmx, cada acción (crear, editar, borrar) recarga la página entera. Eso es lento y molesto. Con htmx, solo se actualiza la parte que cambió. Es la diferencia entre "recargar todo" y "actualizar solo lo necesario".

💡 htmx = HTML + interactividad

La idea de htmx es que el HTML mismo describa la interactividad. hx-post="/autores" significa "cuando se envíe este formulario, haz un POST a /autores". Sin JavaScript a mano.

📤 hx-post: enviar el formulario

⏱️ 35 minutos · "Crear un autor sin recargar"

🧠 La idea central

Para que un formulario envíe datos con htmx, le agregas hx-post="/autores". Cuando el usuario presiona "Crear", htmx envía los datos del formulario a esa ruta sin recargar la página. El servidor procesa y devuelve HTML.

formulario_autor.html — con hx-post 
<form hx-post="/autores" hx-target="#tabla-autores" hx-swap="outerHTML">
  <input type="text" name="nombre" placeholder="Nombre">
  <input type="text" name="pais" placeholder="País">
  <input type="number" name="nacimiento" placeholder="Año">
  <button type="submit">Crear</button>
</form>

🦹 El villano: el formulario que no envía

Si olvidas el hx-post, el formulario se envía de la forma tradicional (recargando la página) o no se envía. El atributo hx-post es lo que le dice a htmx "intercepta este envío y hazlo sin recargar".

💡 name = clave del dato

Cada <input> tiene un atributo name. Ese nombre es la clave con la que el dato viaja al servidor. En el backend lo recibimos con Form() usando ese mismo nombre.

🎯 hx-target: dónde insertar la respuesta

⏱️ 35 minutos · "Decirle a htmx dónde poner el HTML"

🧠 La idea central

Cuando htmx recibe la respuesta del servidor, necesita saber dónde ponerla. El atributo hx-target indica el elemento destino, usando un selector CSS. Por ejemplo, hx-target="#tabla-autores" apunta al elemento con id tabla-autores.

tabla_autores.html — el destino 
<div class="card" id="tabla-autores">
  <table>
    {% for autor in autores %}
      <tr><td>{{ autor.nombre }}</td></tr>
    {% endfor %}
  </table>
</div>

💡 El id conecta todo

El formulario tiene hx-target="#tabla-autores" y la tabla tiene id="tabla-autores". Así, cuando creas un autor, htmx reemplaza la tabla con la nueva versión que devuelve el servidor. El # significa "busca por id".

🔁 hx-swap: cómo reemplazar el contenido

⏱️ 35 minutos · "Reemplazar o insertar"

🧠 La idea central

hx-swap le dice a htmx cómo colocar la respuesta en el destino. outerHTML reemplaza el elemento completo; innerHTML reemplaza solo su contenido. Es la diferencia entre "cambia la caja entera" y "cambia lo que hay dentro".

📦

outerHTML

Reemplaza el elemento completo, incluyendo su etiqueta.

📥

innerHTML

Reemplaza solo el contenido interno del elemento.

⬆️

beforebegin

Inserta antes del elemento.

⬇️

afterend

Inserta después del elemento.

💡 outerHTML para reemplazar la tabla

En nuestro caso, el servidor devuelve la tabla completa (con su <div id="tabla-autores">). Por eso usamos hx-swap="outerHTML": reemplazamos la tabla vieja por la nueva, incluyendo su contenedor.

🛠️ Taller: el CRUD interactivo

⏱️ 40 minutos · "Aplica todo lo aprendido"

🛠️ Taller final Haz la página de autores interactiva

Tu misión es diseñar los atributos htmx para que la página de autores permita crear, editar y borrar sin recargar.

🧠 Lo que debe tener

  1. Un formulario con hx-post="/autores" y hx-target="#tabla-autores".
  2. Un botón "Borrar" con hx-delete="/autores/{id}".
  3. Un botón "Editar" con hx-get="/autores/{id}/editar".
  4. La tabla con id="tabla-autores".

🔄 Actividad en pareja — 10 minutos

Con su compañero/a, respondan por escrito:

  1. ¿Qué atributo htmx usarías para crear un autor?
  2. ¿Qué atributo para borrar un autor?
  3. ¿Qué atributo para editar un autor?
  4. ¿Qué hace hx-target y hx-swap juntos?

💡 Respuesta esperada

Crear usa hx-post, borrar usa hx-delete, editar usa hx-get. hx-target dice dónde poner la respuesta y hx-swap dice cómo reemplazarla. Juntos actualizan solo la parte que cambió.
