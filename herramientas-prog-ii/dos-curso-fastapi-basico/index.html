🧩 FastAPI: el framework moderno

⏱️ 35 minutos · "El framework que hace el trabajo pesado"

🧠 ¿Qué es FastAPI?

FastAPI es un framework web de Python para construir APIs (interfaces que otras apps usan para pedir datos). Es moderno, rápido y muy popular. Su superpoder: es asíncrono (usa async/await) y genera documentación automática.

⚡

Rápido

Es uno de los frameworks más rápidos de Python, comparable a los de Node.js y Go.

📚

Documentado solo

Genera la documentación de tu API automáticamente en /docs.

🛡️

Valida datos

Con Pydantic valida los datos de entrada y salida automáticamente.

🔁

Asíncrono

Usa async/await para atender a muchos usuarios a la vez.

📝 La app más simple del mundo

main.py — la app mínima 
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def inicio():
    return {"mensaje": "Hola mundo"}

💡 Tres líneas que lo cambian todo

app = FastAPI() crea la aplicación. @app.get("/") define una ruta. La función devuelve un diccionario que FastAPI convierte en JSON. Con eso ya tienes un servidor web funcionando.

🛣️ Rutas: los caminos de tu API

⏱️ 35 minutos · "Cómo el servidor sabe qué responder"

🧠 ¿Qué es una ruta?

Una ruta (o endpoint) es una dirección de tu API. Cuando alguien visita /autores, FastAPI ejecuta la función asociada a esa ruta y devuelve su resultado. Cada ruta se define con un decorador que indica el método HTTP.

main.py — rutas con métodos HTTP 
@app.get("/autores")          # leer (GET)
async def listar_autores():
    return [{"id": 1, "nombre": "Gabo"}]

@app.post("/autores")         # crear (POST)
async def crear_autor():
    return {"mensaje": "Autor creado"}

💡 El decorador define el método

@app.get responde a peticiones GET, @app.post a POST, @app.put a PUT y @app.delete a DELETE. La misma ruta /autores puede tener varios métodos, cada uno con su función.

🦹 El villano: la ruta que no responde

Si escribes mal la ruta (por ejemplo /autores en vez de /autor), el servidor responde 404 Not Found. O si defines la ruta con @app.get pero el cliente envía un POST, también falla. La ruta y el método deben coincidir exactamente.

🔄 Lifespan: el ciclo de vida de la app

⏱️ 35 minutos · "Qué pasa al arrancar y al apagar"

🦹 El villano: el recurso que nunca se cierra

Muchas apps necesitan abrir recursos al arrancar (conectar a la base de datos) y cerrarlos al apagar. Si abres la conexión pero nunca la cierras, cada reinicio deja conexiones "zombis" y la base de datos se satura. La solución es el lifespan.

🧠 La idea central

El lifespan es un bloque de código que FastAPI ejecuta al arrancar (antes de recibir requests) y al apagar (después del último request). Se define con @asynccontextmanager y la palabra yield marca el punto medio.

main.py — lifespan 
from contextlib import asynccontextmanager

@asynccontextmanager
async def lifespan(app: FastAPI):
    # Código ANTES del yield: se ejecuta al arrancar
    await db.connect(DATABASE_URL)
    yield
    # Código DESPUÉS del yield: se ejecuta al apagar
    await db.close()

app = FastAPI(lifespan=lifespan)

💡 yield = "la app vive aquí"

Todo lo que está antes de yield corre al arrancar. Todo lo que está después corre al apagar. Mientras la app está viva, se queda "pausada" en el yield. Es como abrir la tienda, atender clientes y cerrar la tienda.

🔄 Actividad en pareja — 2 minutos

Con su compañero/a: imaginen que la app es un restaurante. ¿Qué haría el restaurante "antes del yield" y qué "después del yield"? (pista: abrir la cocina / cerrar la cocina).

🔍 En la vida real

En nuestro proyecto, el lifespan conecta a la base de datos al arrancar y la desconecta al apagar. Sin esto, cada vez que reinicias el servidor quedaría una conexión abierta. Es una buena práctica que verás en todo backend profesional.

🔗 Depends: inyección de dependencias

⏱️ 35 minutos · "Cómo una ruta pide lo que necesita"

🧠 La idea central

Muchas rutas necesitan lo mismo: una conexión a la base de datos. En vez de repetir el código en cada ruta, FastAPI usa dependencias con Depends. Le dices a la ruta "necesito una conexión" y FastAPI se la consigue automáticamente.

main.py — dependencia con Depends 
from fastapi import Depends

async def get_connection():
    # consigue una conexión y la "presta"
    async with db.pool.acquire() as conn:
        yield conn

@app.get("/autores")
async def listar_autores(conn = Depends(get_connection)):
    # conn ya está lista para usar
    return await conn.fetch("SELECT * FROM autores")

💡 Depends = "pídeselo a FastAPI"

Con Depends(get_connection), FastAPI llama a get_connection, obtiene la conexión y se la pasa a la ruta. Cuando la ruta termina, FastAPI ejecuta el código después del yield para devolver la conexión. Todo automático.

🔄 Actividad en pareja — 2 minutos

Con su compañero/a: ¿por qué creen que es mejor usar Depends que escribir el código de conexión en cada ruta? (pista: ¿qué pasa si hay 50 rutas y cambia la forma de conectar?).

🔍 En la vida real

En un backend con 50 endpoints, todos necesitan la conexión a la BD. Con Depends, defines la dependencia una sola vez y la reutilizas en las 50 rutas. Si mañana cambias de base de datos, solo tocas un lugar. Eso es código profesional.

📚 Documentación automática

⏱️ 35 minutos · "Tu API se documenta sola"

🧠 El superpoder de FastAPI

FastAPI genera documentación interactiva de tu API automáticamente. Solo tienes que abrir /docs en tu navegador y verás todas tus rutas, con sus métodos, parámetros y ejemplos. Incluso puedes probar las rutas desde ahí.

📖

/docs

Interfaz Swagger UI: lista todas las rutas y permite probarlas.

🔍

Explorar

Ves cada endpoint, su método HTTP y qué devuelve.

🧪

Probar

Puedes enviar requests de prueba sin escribir código.

🎁

Gratis

No tienes que escribir la documentación: se genera sola.

💡 ¿Por qué importa la documentación?

En un equipo real, el backend lo usa el frontend. La documentación le dice al equipo del frontend qué rutas existen y qué devuelven, sin tener que leer el código. Es como el menú de un restaurante: te dice qué puedes pedir.

Cuando un desarrollador se une a un proyecto, lo primero que hace es abrir /docs para entender la API. Es una de las razones por las que FastAPI es tan querido: la documentación siempre está actualizada porque se genera del código mismo.
