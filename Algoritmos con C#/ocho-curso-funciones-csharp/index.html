🧠 ¿Qué es una función?

⏱️ 25 minutos · "Un pedazo de código con nombre"

🧠 La definición que sí sirve

Una función (en C# también se le dice método cuando vive dentro de una clase) es un bloque de código con nombre que hace una sola cosa, recibe datos (parámetros) y devuelve un resultado (valor de retorno). Es la unidad con la que se construyen los programas grandes: en vez de escribir 300 líneas, escribes 15 funciones de 15 líneas. 🔨

csharp — la anatomía de una función 
// Anatomía de una función
static double CalcularPromedio(double[] notas)   // ← firma
{
    if (notas.Length == 0)
        return 0;                                // ← cuerpo

    double suma = 0;
    foreach (double nota in notas)
        suma += nota;

    return suma / notas.Length;
}

// Cómo se usa
double[] notas = [4.5, 3.8, 5.0];
double promedio = CalcularPromedio(notas);
Console.WriteLine($"El promedio es {promedio:F2}");
ParteEn el ejemplo¿Para qué sirve?
Tipo de retornodoubleQué tipo de dato devuelve la función. Si no devuelve nada, es void.
NombreCalcularPromedioLa etiqueta con la que la llamas. Se escribe en PascalCase.
Parámetrosdouble[] notasLos datos que recibe. Cada uno necesita tipo y nombre.
Cuerpo{ ... }Las instrucciones. Si el tipo de retorno no es void, debe terminar con return.
ModificadorstaticLa función no depende de ningún objeto: se puede llamar sin crear nada.

🏠 ¿Dónde vive una función?

Hay dos lugares posibles, y ninguno de los dos es "el lugar correcto" por ley: lo importante es que lo entiendas.

csharp — función local vs. método de clase 
// 1) Función LOCAL: vive dentro de otra función.
//    Solo se puede usar desde adentro. Ideal para un dato auxiliar.
static void MostrarReporte()
{
    static string Formatear(double valor) => $"$ {valor:N2}";

    Console.WriteLine(Formatear(1250.5));
}

MostrarReporte();

// 2) Método de clase: vive en una clase y se llama con el nombre de la clase.
//    Se puede reutilizar desde cualquier parte del programa.
Console.WriteLine(Calculadora.Sumar(2, 3));

class Calculadora
{
    public static int Sumar(int a, int b) => a + b;
}

💡 ¿Y por qué static?

static significa "esta función no necesita de un objeto para funcionar". Una calculadora de área no necesita de nadie: la llamas directo. En la Clase 10 (POO) verás funciones sin static, que usan los datos del objeto. Por ahora: todas tus funciones van con static. 👌

🦹 El villano: una función sin static en un programa de consola

Si escribes double CalcularPromedio(double[] notas) (sin static) dentro de un programa con instrucciones de nivel superior, el compilador te responde "no se puede acceder a un miembro no estático sin una instancia". La solución: agrega static delante. Es el error número uno de esta clase. ⚠️

📥 Parámetros de entrada y retorno

⏱️ 30 minutos · "Los ingredientes y el plato"

📦 Un parámetro es un espacio con nombre

Un parámetro es una variable que la función recibe por la puerta. Al invocarla, le entregas los datos: por posición (el primero va al primero) o por nombre (CalcularArea(ancho: 5, alto: 3)), que es mucho más fácil de leer. El retorno es lo que la función te devuelve con return. 🍽️

csharp — argumentos con nombre y parámetros opcionales 
// Parámetros con nombre: el orden deja de importar
static double CalcularArea(double ancho, double alto) => ancho * alto;

// Parámetro opcional: tiene un valor por defecto
static int Sumar(int a, int b = 10) => a + b;

Console.WriteLine(CalcularArea(ancho: 5, alto: 3));   // 15
Console.WriteLine(Sumar(5));      // 5 + 10 = 15
Console.WriteLine(Sumar(5, 2));   // 7
csharp — `params`: muchos argumentos sin crear un arreglo 
// Con `params` puedes pasar los valores directo, sin llaves
static int Sumar(params int[] numeros)
{
    int total = 0;
    foreach (int numero in numeros)
        total += numero;

    return total;
}

Console.WriteLine(Sumar(1, 2, 3));   // 6
Console.WriteLine(Sumar(10, 20));    // 30
Console.WriteLine(Sumar());          // 0
csharp — `void`, tuplas y retorno temprano 
// `void` = la función no devuelve nada (solo hace cosas)
static void MostrarBienvenida(string nombre)
{
    Console.WriteLine($"¡Bienvenido, {nombre}!");
}

// Una tupla: la función devuelve DOS valores de una vez
static (int suma, int resta) Dividir(int a, int b)
{
    return (a + b, a - b);
}

// Retorno temprano: sales de la función antes de llegar al final
static string EvaluarNota(double nota)
{
    if (nota < 0 || nota > 10)
        return "Nota inválida";

    if (nota >= 7)
        return "Aprobó";

    return "Debe repetir";
}

MostrarBienvenida("Ana");

// Puedes descomponer la tupla con paréntesis
(int suma, int resta) = Dividir(10, 4);
Console.WriteLine($"Suma: {suma} | Resta: {resta}");

// ...o con `var` y otro estilo de nombres
var (producto, cociente) = Dividir(10, 4);
Console.WriteLine($"{producto} / {cociente}");

Console.WriteLine(EvaluarNota(8.5));
Tipo de parámetroEjemplo¿Qué hace?
PosicionalCalcularArea(5, 3)El primer argumento va al primer parámetro.
Con nombreCalcularArea(alto: 3, ancho: 5)El orden deja de importar y se lee mejor.
Opcionalint b = 10Si no lo mandas, se usa el valor por defecto.
paramsparams int[] numerosRecibe cero, uno o muchos argumentos.
outout int resultadoDevuelve un dato adicional (lo vemos en el módulo 6).
ref / inref int notaModificar el dato original o solo leerlo (módulo 3 y 6).

🦹 El villano: base es palabra reservada

Querías escribir CalcularArea(base: 5, altura: 3), pero base es una palabra reservada de C# (sirve para las clases que heredan) y el compilador te lo rechaza. La solución es renombrar: CalcularArea(ancho: 5, alto: 3). Un buen nombre de parámetro es un seguro contra errores. 🛡️

💡 Truco: el retorno temprano

Si tienes muchos if anidados, prueba a invertir el orden: primero saca los casos raros con return temprano, y deja el caso normal al final, sin else. El código queda plano y se lee de arriba hacia abajo, como una lista de reglas. 🪜

🔗 Valor vs. referencia: el corazón de la clase

⏱️ 35 minutos · "El fotocopiador vs. la casa con la dirección"

🧠 Dos formas de "entregar" un dato a una función

Cuando pasas un dato a una función, C# hace una de dos cosas: copiar el dato (el fotocopiador) o copiar la dirección (la casa con la dirección en un sobre). En el primer caso, los cambios se quedan en la copia. En el segundo, los cambios se ven desde ambos lados. 🔑

csharp — el experimento que lo aclara todo 
// Tipo de VALOR (int): la función recibe una COPIA
static void SubirNota(int nota)
{
    nota += 1;   // sube la copia, no la variable original
}

// Tipo de REFERENCIA (int[]): la función recibe la DIRECCIÓN del arreglo
static void DuplicarNotas(int[] notas)
{
    for (int i = 0; i < notas.Length; i++)
        notas[i] *= 2;   // sí cambia el arreglo original
}

int nota = 5;
SubirNota(nota);
Console.WriteLine($"La nota sigue en {nota}");   // 5  (¡no cambió!)

int[] notas = [4, 6, 8];
DuplicarNotas(notas);
Console.WriteLine($"La primera nota ahora es {notas[0]}");   // 8  (¡sí cambió!)
Tipo de datoEjemplosAl pasarlo a una función…
Tipo de valorint, double, bool, char, struct, enumSe copia el dato. Cambios dentro = cambios solo dentro.
Tipo de referenciastring, class, record, int[], List<T>Se copia la dirección. Cambios dentro = cambios fuera (salvo en string, que es inmutable).

🏠 La analogía de la casa

📄 El fotocopiador (por valor)

Le entregas una copia del papel a la función. Si ella le escribe encima, tu papel original queda intacto. Así funciona un int.

🏡 El sobre con la dirección (por referencia)

Le entregas el sobre con la dirección de la casa. La función puede entrar y pintar la casa: tu casa original queda pintada. Así funciona un arreglo o un objeto.

🔧 Cuando quieres modificar de verdad

Si necesitas que la función modifique la variable original, pásala con ref: SubirNota(ref nota). Como el int es una caja chiquita, copiarlo no cuesta nada… pero ref te da el poder de modificarlo. 🪄

csharp — `ref` modifica la variable original 
static void SubirNota(ref int nota)
{
    nota += 1;   // con `ref` se modifica la variable original
}

int nota = 5;
SubirNota(ref nota);
Console.WriteLine(nota);   // 6 (¡ahora sí cambió!)
csharp — con una clase propia: objeto vs. copia 
// 1) La función recibe el OBJETO y lo modifica
Estudiante ana = new Estudiante { Nombre = "Ana", Promedio = 3.5 };
SubirPromedio(ana, 4.8);
Console.WriteLine($"{ana.Nombre} tiene {ana.Promedio}");   // Ana tiene 4.8

// 2) "Copiar" un objeto copia la DIRECCIÓN: los dos nombres
//    apuntan al mismo objeto
Estudiante copia = ana;
copia.Nombre = "Copia";
Console.WriteLine(ana.Nombre);   // "Copia" -> es el MISMO objeto

// 3) Para una copia REAL hay que crear un objeto nuevo
Estudiante copiaReal = new Estudiante { Nombre = "Real", Promedio = ana.Promedio };
copiaReal.Nombre = "Otra";
Console.WriteLine(ana.Nombre);   // "Copia" -> el original no cambió

static void SubirPromedio(Estudiante e, double valor)
{
    e.Promedio = valor;   // cambia el objeto original
}

// En un archivo con instrucciones de nivel superior,
// las clases se declaran AL FINAL del archivo.
class Estudiante
{
    public string Nombre { get; set; } = "";
    public double Promedio { get; set; }
}
csharp — `in`: solo lectura y sin copias 
// `in` = la función puede LEER el dato, pero no cambiarlo.
// Además evita hacer una copia, así es útil con structs grandes.
static double CalcularIMC(in double peso, in double altura)
{
    double metros = altura / 100.0;
    return peso / (metros * metros);
}

double peso = 68.5;
double altura = 172;
double imc = CalcularIMC(in peso, in altura);
Console.WriteLine($"IMC: {imc:F2}");
ModoEjemplo¿Puede cambiar el dato original?¿Hace copia?
Por valor (el normal)SubirNota(nota)NoSí
Por referenciaSubirNota(ref nota)SíNo
Solo lecturaCalcularIMC(in peso, in altura)NoNo
Arreglo / ListDuplicarNotas(notas)Sí (los elementos)No (copia la dirección)

🦹 Ojo con string: es de referencia, pero no se puede modificar

string es un tipo de referencia, pero los textos son inmutables: no existen "textos mutables". Por eso texto += "!" no modifica el texto original, crea uno nuevo en memoria y lo asigna a la variable. Si necesitas "cambiar" un texto, siempre estás creando otro texto. 🧊

💡 Truco para no equivocarte: pregúntate "¿el tipo es una caja o es una dirección?"

int, double, bool y los struct son cajas: se copian. Las clases, los arreglos y las listas son direcciones: se comparten. Si la variable es una dirección y quieres otra copia de verdad, crea el objeto de nuevo (como copiaReal en el ejemplo). 📦

🧬 Sobrecarga, funciones locales y lambdas

⏱️ 30 minutos · "El mismo nombre, distinto disfraz"

🧬 Sobrecarga: mismo nombre, distinta firma

La sobrecarga (overload) es tener varios métodos con el mismo nombre pero diferentes parámetros. El compilador elige solo cuál usar según los argumentos que le pases. Como un "imprenta": escribes "texto" y sale un cartel; escribes "número" y sale una matriz. 🖨️

csharp — sobrecarga de métodos 
// Tres versiones de "Calcular" con el mismo nombre
Console.WriteLine(Calculadora.Calcular(2, 3));      // 5    -> versión int
Console.WriteLine(Calculadora.Calcular(2.5, 3.5));  // 6    -> versión double
Console.WriteLine(Calculadora.Calcular(2, 3, 4));   // 9    -> versión de 3 parámetros

static class Calculadora
{
    public static int Calcular(int a, int b) => a + b;

    public static double Calcular(double a, double b) => a + b;

    public static int Calcular(int a, int b, int c) => a + b + c;
}

🦹 El villano: las funciones locales NO se pueden sobrecargar

Si declaras dos funciones locales con el mismo nombre, el compilador responde "ya se ha definido en este ámbito" (error CS0128). Para sobrecargar, la función debe ser un método de una clase, como el ejemplo de arriba. Regla práctica: si vas a sobrecargar, mete las funciones en una clase. 🎭

csharp — lambdas: funciones sin nombre 
// Una lambda es una función SIN nombre, escrita en una línea.
// `Func` significa "devuelve un valor"; `Action` significa "no devuelve nada".
Func<int, int> cuadrado = x => x * x;
Func<double, double> mitad = x => x / 2;
Action<string> saludar = nombre => Console.WriteLine($"Hola, {nombre}!");
Action<int, int> sumar = (a, b) => Console.WriteLine(a + b);

Console.WriteLine(cuadrado(7));   // 49
Console.WriteLine(mitad(10));     // 5
saludar("Ana");
sumar(3, 4);
csharp — curiosidad: bloques `extension` de C# 14 
// C# 14 agrega los bloques `extension`: permiten agregar
// métodos a cualquier tipo, sin heredar de nada.

Console.WriteLine(1234.5678.Redondeado(2));

static class Extensiones
{
    extension(string texto)
    {
        public int ConteoVocales()
        {
            int total = 0;
            foreach (char c in texto)
                if ("aeiou".Contains(c))

            return total;

    extension(double numero)
    {
        public double Redondeado(int decimales) => Math.Round(numero, decimales);

💡 Truco: una lambda con más de una línea se vuelve una función local

Si la lambda crece (varias instrucciones), lo más limpio es convertirla en una función local con nombre, porque un nombre propio se documenta solo. Las lambdas brillan cuando son pequeñas: un cálculo, una comparación, un mensaje. ✨

♻️ out, ref y recursión

⏱️ 30 minutos · "Devolver dos cosas y llamarse a sí misma"

📤 out: la función te entrega un dato extra

Normalmente una función devuelve un valor. Con out puede entregar otro por la puerta de atrás: el dato vuelve por el mismo out que le pasaste. Se usa mucho cuando la función dice "esto funcionó y este es el resultado". 📬

csharp — `out`: un resultado adicional 
// Devuelve true/false (¿funcionó?) Y el resultado por `out`
static bool IntentarDividir(int a, int b, out int cociente)
{
    if (b == 0)
    {
        cociente = 0;   // hay que asignarlo SIEMPRE, aunque no sirva
        return false;
    }

    cociente = a / b;
    return true;
}

if (IntentarDividir(10, 2, out int resultado))
    Console.WriteLine($"10 / 2 = {resultado}");
else
    Console.WriteLine("No se puede dividir entre cero");

if (IntentarDividir(10, 0, out int otro))
    Console.WriteLine(otro);
else
    Console.WriteLine("No se puede dividir entre cero");
csharp — `ref`, `in` y `ref readonly` juntos 
// `ref`: modificar las dos variables originales
static void Intercambiar(ref int a, ref int b)
{
    (a, b) = (b, a);
}

// `in`: solo leer, sin hacer copias
static double Area(in double ancho, in double alto) => ancho * alto;

// `ref readonly`: devuelve una referencia que NO se puede modificar
static ref readonly int Primero(ref int[] datos) => ref datos[0];

int x = 3;
int y = 7;
Intercambiar(ref x, ref y);
Console.WriteLine($"{x} y {y}");   // 7 y 3

double area = Area(4, 5);
Console.WriteLine(area);          // 20

int[] datos = [10, 20, 30];
ref readonly int primero = ref Primero(ref datos);
Console.WriteLine(primero);       // 10

🪆 La recursión: la función que se llama a sí misma

Una función recursiva es la que se llama a sí misma con un problema más pequeño, hasta llegar a un caso que puede resolver de una. Ese último caso es la condición de parada: si falta, la función se llama para siempre y el programa se cae con un error de pila (StackOverflowException). 🪜

csharp — recursión: factorial, Fibonacci y suma de dígitos 
// Cada llamada resuelve un problema más pequeño
static long Factorial(int n)
{
    if (n <= 1)              // ← CONDICIÓN DE PARADA
        return 1;

    return n * Factorial(n - 1);
}

static int Fibonacci(int n)
{
    if (n < 2)
        return n;

    return Fibonacci(n - 1) + Fibonacci(n - 2);
}

static int SumaDigitos(int numero)
{
    if (numero == 0)
        return 0;

    return numero % 10 + SumaDigitos(numero / 10);
}

Console.WriteLine($"5! = {Factorial(5)}");
Console.WriteLine($"Fibonacci(10) = {Fibonacci(10)}");
Console.WriteLine($"Suma de dígitos de 2026 = {SumaDigitos(2026)}");
csharp — el error clásico: recursión sin condición de parada 
// ⚠️ CÓDIGO PELIGROSO: esta función se llama a sí misma
//    SIN condición de parada. La pila de llamadas crece sin
//    control hasta que el programa se cae (StackOverflow).
static int CuentaInfinita(int n)
{
    Console.WriteLine(n);
    return CuentaInfinita(n + 1);
}

// NO descomentes la línea siguiente: el programa se cae.
// Console.WriteLine(CuentaInfinita(0));

csharp — curiosidad de C# 14: `params ReadOnlySpan<T>` 
// C# 13+ permite `params` con un ReadOnlySpan: la función recibe
// los valores SIN crear un arreglo temporal en memoria.
static int Resumir(params ReadOnlySpan<int> numeros)
{
    int total = 0;
    foreach (int numero in numeros)
        total += numero;

    return total;
}

Console.WriteLine(Resumir(1, 2, 3, 4));   // 10
Console.WriteLine(Resumir());             // 0

💡 Truco: la recursión siempre es una escalera más profunda

Imagina una escalera de escalones: la recursión es subir un escalón y volver a llamar a la función con un escalón menos de altura. Cuando llegas al suelo (la condición de parada), devuelves la respuesta y vas bajando: cada escalón recibe el resultado del de abajo y lo usa. La pila de llamadas es justamente esa escalera de escalones. 🪜

🛠️ Taller: calculadora estadística modularizada

⏱️ 40 minutos · "Todo lo de hoy en un solo programa"

🛠️ Taller final Calculadora estadística

El colegio necesita una calculadora estadística que resuelva varios cálculos con funciones limpias. Tu misión: modularizar el programa en funciones y demostrar, con el arreglo y con un ref, cómo funciona el paso por valor y por referencia. 🧮

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n CalculadoraEstadistica y ábrelo con code ..
  2. Escribe una función por cada cálculo: área de un rectángulo, perímetro, IMC, conversión de °C a °F y promedio de un arreglo de notas.
  3. El programa principal pide los datos y llama a las funciones: ninguna operación matemática se escribe dos veces.
  4. Demuestra el paso por valor: una función que recibe un int y le suma 1 sin ref (el original no cambia).
  5. Demuestra el paso por referencia: la misma operación pero con ref (el original sí cambia), y otra que duplica un arreglo recibido como parámetro.
  6. Usa interpolación y formato :F2 para todos los resultados.
  7. Ejecuta con dotnet run y comprueba que el arreglo sí cambia y el int no.
csharp — guía de estilo (es el molde, no la solución) 
// ============================================
// CALCULADORA ESTADÍSTICA
// Cada cálculo vive en su propia función.
// ============================================

// 1. Datos del rectángulo
Console.Write("Ancho del rectángulo: ");
double ancho = 5;

double alto = 3;

// 3. Se demuestra el paso por valor y por referencia
int nota = 5;
SubirNotaPorValor(nota);
Console.WriteLine($"Por valor la nota sigue en {nota}");

static double CalcularArea(double ancho, double alto) => 0;
static double CalcularPerimetro(double ancho, double alto) => 0;
static void SubirNotaPorValor(int nota) => nota += 1;

💡 Pista: el orden de las funciones no importa

Puedes escribir CalcularArea antes o después de usarla: C# las encuentra igual. Pero por costumbre, pon las funciones al final del archivo, con el programa principal arriba. Se lee como una receta: primero qué haces, después cómo. 📖

csharp — solución del taller 
// ============================================
// CALCULADORA ESTADÍSTICA — solución del taller
// ============================================

Console.WriteLine("=== CALCULADORA ESTADÍSTICA ===");

// 1. ÁREA Y PERÍMETRO DE UN RECTÁNGULO
Console.Write("Ancho del rectángulo: ");
double ancho = double.Parse(Console.ReadLine() ?? "0");
Console.Write("Alto del rectángulo: ");
double alto = double.Parse(Console.ReadLine() ?? "0");
Console.WriteLine($"Área: {CalcularArea(ancho, alto):F2}");
Console.WriteLine($"Perímetro: {CalcularPerimetro(ancho, alto):F2}");

// 2. IMC
Console.Write("Peso (kg): ");
double peso = double.Parse(Console.ReadLine() ?? "0");
Console.Write("Altura (cm): ");
double altura = double.Parse(Console.ReadLine() ?? "0");
Console.WriteLine($"IMC: {CalcularIMC(peso, altura):F2}");

// 3. CONVERSIÓN DE TEMPERATURA
Console.Write("Temperatura en °C: ");
double celsius = double.Parse(Console.ReadLine() ?? "0");
Console.WriteLine($"En °F: {CelsiusAFahrenheit(celsius):F2}");

// 4. PROMEDIO DE UN ARREGLO
double[] notas = [4.5, 3.8, 4.2];
Console.WriteLine($"Promedio: {CalcularPromedio(notas):F2}");

// 5. VALOR VS REFERENCIA
int nota = 5;
SubirNotaPorValor(nota);
Console.WriteLine($"Por valor la nota sigue en {nota}");

SubirNotaPorReferencia(ref nota);
Console.WriteLine($"Por referencia la nota quedó en {nota}");

int[] lista = [4, 6, 8];
DuplicarNotas(lista);
Console.WriteLine($"La primera nota ahora es {lista[0]}");

// ============================================
// LAS FUNCIONES
// ============================================
static double CalcularArea(double ancho, double alto) => ancho * alto;

static double CalcularPerimetro(double ancho, double alto) => 2 * (ancho + alto);

static double CalcularIMC(double pesoKg, double alturaCm)
{
    double metros = alturaCm / 100.0;
    return pesoKg / (metros * metros);
}

static double CelsiusAFahrenheit(double celsius) => celsius * 9 / 5 + 32;

static double CalcularPromedio(double[] notas)
{
    if (notas.Length == 0)
        return 0;

    double suma = 0;
    foreach (double nota in notas)
        suma += nota;

    return suma / notas.Length;
}

// Por valor: el original NO cambia
static void SubirNotaPorValor(int nota)
{
    nota += 1;
}

// Por referencia: el original SÍ cambia
static void SubirNotaPorReferencia(ref int nota)
{
    nota += 1;
}

// El arreglo es un tipo de referencia: el original SÍ cambia
static void DuplicarNotas(int[] notas)
{
    for (int i = 0; i < notas.Length; i++)
        notas[i] *= 2;
}

  • El proyecto se llama CalculadoraEstadistica y corre con dotnet run.
  • Hay una función por cada cálculo y ninguna operación matemática está escrita dos veces.
  • Todas las funciones llevan static y devuelven el tipo correcto (double, void).
  • El int no cambia con SubirNotaPorValor y sí cambia con ref.
  • El arreglo sí queda duplicado después de DuplicarNotas.
  • Todos los resultados se muestran con interpolación y :F2.
