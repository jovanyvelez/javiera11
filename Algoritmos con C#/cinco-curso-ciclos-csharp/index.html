🔁 while y do-while

⏱️ 30 minutos · "Mientras se cumpla, repite (y repito por lo menos una vez)"

🧠 El ciclo con tres piezas

Todo ciclo tiene las mismas tres piezas: una condición que dice si sigues o te paras, un cuerpo con lo que haces cada vuelta y algo que cambia para que la condición algún día se vuelva falsa. El while es el más simple: mientras la condición sea verdadera, ejecuta el cuerpo. Piensa en una bolsa de gomitas: sigues sacando mientras haya en la bolsa… y si nunca vacías la bolsa, nunca sales. 😱

csharp — el while: pregunta primero 
// El while PREGUNTA PRIMERO y después hace.
int contador = 1;

Console.Write("¿Hasta dónde contamos? ");
int limite = int.TryParse(Console.ReadLine() ?? "", out int n) ? n : 5;

while (contador <= limite)
{
    Console.WriteLine($"Número {contador}");
    contador++;      // sin esta línea, el bucle nunca termina
}

💡 ¿Qué hace?

Qué hace: revisa contador <= limite; mientras sea verdadera, imprime y suma 1. Por qué funciona: el contador++ es el motor del ciclo: en algún momento contador supera a limite, la condición da false y el while termina. Ojo: si el contador nunca cambia, el ciclo es infinito.

csharp — el do-while: hace primero, pregunta después 
// El do-while HACE PRIMERO y después pregunta.
string opcion;

do
{
    Console.WriteLine("1. Saludar   2. Salir");
    opcion = Console.ReadLine() ?? "";
    Console.WriteLine(opcion == "1" ? "¡Hola!" : "Chao...");
} while (opcion != "2");

Console.WriteLine("Aquí siempre llegas: te hayas equivocado o no.");

🦹 El villano: el bucle infinito

Un bucle infinito es un ciclo cuya condición nunca se vuelve falsa. El programa se queda trabajando y la terminal no responde: ni el mouse ni el teclado. ¿Cómo salir? Con Ctrl+C en la terminal: le mandas la señal de "para" al proceso. Y en el código, la única forma de salir de un bucle infinito es con un break (Módulo 5).

csharp — bucle infinito con una única salida: el break 
// while (true) dice: "mientras sea verdad, repite" (y SIEMPRE lo es).
int intentos = 0;

while (true)
{
    intentos++;
    Console.WriteLine($"Intento {intentos}");

    if (intentos >= 3)
    {
        break;      // la única salida del bucle
    }
}

Console.WriteLine("Salí del bucle infinito.");
csharp — la condición mal puesta (error de lógica: el bucle no termina) 
// ERROR DE LÓGICA: la condición nunca se vuelve falsa.
// i solo toma 0, 2, 4, 6... nunca llega a 5: el bucle NO termina.
int i = 0;

while (i != 5)
{
    Console.WriteLine(i);
    i += 2;
}

// La forma segura: comparar con ">=" y no con "!="
// while (i < 5) { ... i++; }  →  sí termina

🔂 El for: repetir un número exacto de veces

⏱️ 30 minutos · "Inicio, condición, incremento: las tres piezas del for"

🧠 El for es un while con la estructura apretada

El while te obliga a separar el avance del contador en otra línea. El for mete las tres cosas —inicio, condición e incremento— en la misma línea, entre paréntesis y separadas por punto y coma: for (inicio; condición; incremento). Cuando ya sabes cuántas vueltas vas a dar, el for es más corto y más legible.

csharp — el for clásico y sus tres piezas 
// for (inicio; condición; incremento)
for (int i = 1; i <= 10; i++)
{
    Console.WriteLine($"Número {i}");
}

// Las tres piezas, por separado:
//   int i = 1   → INICIO: se ejecuta UNA sola vez, antes de la primera vuelta
//   i <= 10     → CONDICIÓN: se revisa en cada vuelta (si da false, se sale)
//   i++         → INCREMENTO: se ejecuta al final de cada vuelta
csharp — while y for son el mismo ciclo 
// Con for
for (int i = 0; i < 5; i++)
{
    Console.WriteLine(i);
}

// Con while (exactamente lo mismo, pero en dos líneas más)
int j = 0;
while (j < 5)
{
    Console.WriteLine(j);
    j++;
}

💡 Los límites son excluyentes: cuidado con el < o el <=

Si escribes for (int i = 0; i < 5; i++), el i vale 0, 1, 2, 3 y 4: 5 vueltas. Si escribes i <= 5, son 6 vueltas (aparece el 5). El < es exclusivo, el <= es inclusivo. Esta es la fuente número uno de "me faltan un número" y "me sobra un número" en las notas de un parcial.

csharp — for con decremento, saltos y var 
// Contar hacia atrás
for (int i = 10; i > 0; i--)
{
    Console.Write(i + " ");
}
Console.WriteLine();

// De dos en dos
for (int i = 0; i < 20; i += 2)
{
    Console.Write(i + " ");
}
Console.WriteLine();

// Con var: el tipo se deduce solo. i++ y ++i dan el MISMO resultado
// en la parte del incremento de un for: el valor que se guarda es el mismo.
for (var i = 0; i < 3; ++i)
{
    Console.WriteLine(i);
}
csharp — el for infinito: for (;;) 
// for (;;) es un bucle infinito: no tiene condición, no se evalúa nada.
int i = 0;

for (;;)
{
    Console.WriteLine($"Vuelta {i}");
    i++;

    if (i == 3)
    {
        break;      // la única salida
    }
}

Console.WriteLine("Fin.");

📦 foreach: recorrer sin índices

⏱️ 35 minutos · "Pásame cada elemento, uno por uno"

🧠 La colección se encarga del índice

El foreach es un for que te quita el trabajo de manejar el índice. Tú dices: "por cada elemento de esta lista, haz esto" y ya. C# se encarga de saber cuál es el siguiente, cuándo se acaba y de sacar el valor. Por eso es el ciclo más seguro: no puedes equivocarte escribiendo arreglo[i] ni pasarte del final.

csharp — foreach sobre un string (recorre caracteres) 
// Un string es una colección de caracteres.
string frase = "Hola";

foreach (char letra in frase)
{
    Console.WriteLine($"'{letra}'");
}

// También sirve para contar letras sin usar el índice:
string palabra = "colegio";
int vocales = 0;

foreach (char letra in palabra)
{
    if (letra is 'a' or 'e' or 'i' or 'o' or 'u')
    {
        vocales++;
    }
}

Console.WriteLine($"Vocales: {vocales}");
csharp — foreach sobre un arreglo 
// La colección de C# moderno: corchetes, sin "new int[]".
double[] notas = [4.5, 3.8, 2.9];

foreach (double nota in notas)
{
    Console.WriteLine($"Nota: {nota:F1}");
}

// Con var también funciona, y el tipo se deduce solo.
foreach (var nota in notas)
{
    Console.WriteLine(nota);
}
csharp — foreach sobre un List<T> 
// Un List<T> es una lista que CRECE: puedes agregarle cosas.
List<string> materias = ["Matemáticas", "Física", "Química"];

foreach (string materia in materias)
{
    Console.WriteLine($"Materia: {materia}");
}

// Y el clásico: agregar al final, quitar, contar.
materias.Add("Biología");
materias.Remove("Física");
Console.WriteLine($"Total: {materias.Count} materias");
csharp — foreach sobre un Dictionary (con desestructuración) 
// Un Dictionary guarda pares CLAVE → VALOR.
Dictionary<string, int> asistencia = new()
{
    ["Ana"] = 18,
    ["Julián"] = 15,
    ["Sara"] = 20
};

// Versión 1: foreach con "par" (clave y valor juntos)
foreach (var par in asistencia)
{
    Console.WriteLine($"{par.Key}: {par.Value} días de asistencia");
}

// Versión 2: DESESTRUCTURACIÓN: el par se abre en dos variables.
// (nombre, dias) es una forma de escribir (par.Key, par.Value).
foreach (var (nombre, dias) in asistencia)
{
    Console.WriteLine($"{nombre} faltó {20 - dias} día(s)");
}
csharp — foreach sobre un Span (lo moderno) 
// Un ReadOnlySpan es una "ventana" sobre la memoria: no copia el texto.
// En C# moderno se usa para trabajar con pedazos de cadenas sin copiarlos.
ReadOnlySpan<char> trozo = "Hola mundo"[..4];

foreach (char c in trozo)
{
    Console.Write(c);
}
Console.WriteLine();

// Y sobre un arreglo, el Span evita copiarlo.
int[] numeros = [1, 2, 3, 4, 5];
Span<int> ventana = numeros.AsSpan(0, 3);

foreach (int n in ventana)
{
    Console.Write(n + " ");
}
Console.WriteLine();

💡 foreach vs. for: ¿cuál uso?

Usa foreach cuando solo quieres ver los datos: imprimir, sumar, buscar. Es más corto, no tiene índice que se te pueda salir y el compilador te avisa si intentas modificar la colección mientras la recorres. Usa for cuando necesitas el número de la posición (mostrar "1.Ana, 2.Julián…"), cuando vas a modificar la colección, o cuando necesitas salir antes de tiempo con un break condicional. ¿Legibilidad? Gana el foreach casi siempre.

💡 ¿Sabías que…?

En 1960 Ada Lovelace le escribió a Charles Babbage un algoritmo para calcular las Bernoulli usando la "máquina analítica" — y tenía un ciclo dentro: repetía una serie de operaciones para refinar aproximaciones. O sea: el primer programa de la historia ya tenía un bucle. Y el foreach se inventó después de for justamente porque los programadores se cansaron de escribir el índice a mano una y otra vez.

🛑 break y continue: el control del ciclo

⏱️ 30 minutos · "Salir del todo o saltar esta vuelta"

🧠 Dos palabras que manejan el ciclo por dentro

Hasta ahora los ciclos solo se paran porque la condición deja de cumplirse. Pero a veces quieres salir antes (ya encontré lo que buscaba) o saltarte una vuelta (este dato no me interesa). Para eso: break rompe el ciclo y sale; continue continúa con la siguiente vuelta, saltándose el resto del cuerpo.

csharp — break: sale del bucle 
// break: sale COMPLETAMENTE del bucle.
for (int i = 1; i <= 10; i++)
{
    if (i == 5)
    {
        break;              // aquí el ciclo se detiene
    }

    Console.WriteLine(i);   // imprime 1, 2, 3, 4
}

Console.WriteLine("Después del ciclo");
csharp — continue: salta a la siguiente vuelta 
// continue: salta a la SIGUIENTE iteración.
// Lo que queda del cuerpo NO se ejecuta en esa vuelta.
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        continue;           // los pares se saltan
    }

    Console.WriteLine(i);   // imprime 1, 3, 5, 7, 9
}

// continue también sirve para descartar datos inválidos:
int[] datos = [5, -3, 8, 0, 12];
int positivos = 0;

foreach (int numero in datos)
{
    if (numero <= 0)
    {
        continue;           // este dato no cuenta
    }

    positivos++;
}

Console.WriteLine($"Positivos: {positivos}");
csharp — return dentro de un bucle 
// return sale del MÉTODO entero, no solo del bucle.
static int PrimerNumeroPar(int[] numeros)
{
    foreach (int n in numeros)
    {
        if (n % 2 == 0)
        {
            return n;        // se acabó: el for también y el método también
        }
    }

    return -1;               // no había ningún par
}

Console.WriteLine(PrimerNumeroPar([3, 7, 8, 2]));

🦹 Peligro 1: el continue antes del avance

En un while, el continue salta directo a la condición. Si el avance del contador estaba después del continue, el contador nunca cambia y el ciclo no termina nunca. La regla de oro: pon el avance (o el i++) al principio del cuerpo, antes de cualquier continue.

csharp — el continue peligroso (error de lógica: el programa no termina) 
// ERROR DE LÓGICA: el continue salta el i++ y el bucle NO termina.
int i = 0;

while (i < 5)
{
    if (i == 2)
    {
        continue;        // aquí i nunca se vuelve 3: bucle infinito
    }

    i++;
    Console.WriteLine(i);
}
csharp — la forma segura: el avance va primero 
// La forma segura: el avance va PRIMERO, antes del continue.
int i = 0;

while (i < 5)
{
    i++;                  // el avance nunca se salta

    if (i == 2)
    {
        continue;         // ahora sí: salta solo el Console.WriteLine
    }

    Console.WriteLine(i); // imprime 1, 3, 4, 5
}

🦹 Peligro 2: el break en el bucle equivocado

Cuando hay dos ciclos anidados, el break solo rompe el bucle más interno (el que está más cerca). Si querías salir de los dos, un solo break no alcanza: necesitas una bandera (bool) o el return. Y ojo con el break "mal puesto": si lo dejas fuera del if que debía protegerlo, el ciclo se rompe en la primera vuelta y tu programa no hace nada.

csharp — a cuál bucle afecta el break 
for (int fila = 1; fila <= 3; fila++)
{
    for (int columna = 1; columna <= 3; columna++)
    {
        if (columna == 2)
        {
            break;   // sale SOLO del bucle interno (el de columnas)
        }

        Console.Write($"{fila}{columna} ");
    }
}

Console.WriteLine("Fin");

// Salida: 11 21 31 Fin
// El bucle externo siguió: solo se detuvo el interno.

🪆 Ciclos anidados: tablas y matrices

⏱️ 35 minutos · "Un ciclo dentro de otro ciclo: la tabla de multiplicar nace aquí"

🧠 Dos datos que varían, dos ciclos

Un ciclo anidado es un ciclo dentro del cuerpo de otro ciclo. ¿Cuándo lo necesitas? Cuando tienes dos cosas que cambian al mismo tiempo: la fila y la columna de una tabla, el estudiante y sus tres cortes, la tabla de multiplicar del 1 al 5. El ciclo de afuera maneja una variable y el de adentro la otra.

csharp — la tabla de multiplicar con for anidado 
// La tabla de multiplicar del 1 al 5.
for (int fila = 1; fila <= 5; fila++)
{
    for (int columna = 1; columna <= 5; columna++)
    {
        Console.Write($"{fila * columna,4}");   // el 4 alinea las columnas
    }

    Console.WriteLine();   // salto de línea al final de cada fila
}

csharp — matriz de notas: estudiante por corte 
// Una "matriz" de notas: una fila por estudiante y una columna por corte.
double[,] notas = new double[,]
{
    { 3.5, 4.0, 2.8 },
    { 4.2, 4.5, 4.8 },
    { 1.5, 2.0, 3.0 }
};

for (int i = 0; i < notas.GetLength(0); i++)
{
    double suma = 0;

    for (int j = 0; j < notas.GetLength(1); j++)
    {
        suma += notas[i, j];        // acumula los cortes del estudiante
    }

    double promedio = suma / notas.GetLength(1);
    Console.WriteLine($"Estudiante {i + 1}: {promedio:F2}");
}

// Salida esperada:
// Estudiante 1: 3.43
// Estudiante 2: 4.50
// Estudiante 3: 2.17

🦹 Ojo con el rendimiento: O(n²)

Un ciclo dentro de otro ciclo hace el doble de trabajo: si el de afuera da 100 vueltas y el de adentro 100, se ejecutan 10 000 iteraciones. Eso se llama complejidad O(n²). A veces es justo lo que quieres (una tabla), pero muchas veces estás haciendo que el computador busque lo mismo una y otra vez. Regla práctica: antes de anidar, pregúntate si el trabajo se puede hacer en una sola pasada.

csharp — O(n²) innecesario frente a una sola pasada 
int[] numeros = [4, 8, 15, 16, 23, 42];
int buscado = 15;
bool existe = false;

// Versión torpe: dos ciclos, 36 comparaciones para 6 datos.
for (int i = 0; i < numeros.Length; i++)
{
    for (int j = 0; j < numeros.Length; j++)
    {
        if (numeros[i] == numeros[j])
        {
            existe = true;
        }
    }
}

// Versión eficiente: una sola pasada, 6 comparaciones.
bool existeRapido = numeros.Contains(buscado);

Console.WriteLine($"Lento: {existe}, rápido: {existeRapido}");

💡 Adelanto: el acumulador y el contador (Clase 6)

En el ejemplo de las notas apareció algo nuevo: suma += cortes[j]. Esa variable suma es un acumulador: guarda la suma de todo lo que pasa por el ciclo. Y el i y el j son contadores: cuentan vueltas. En la Clase 6 vamos a estudiarlos a fondo, con banderas y más patrones. Por hoy, solo mira que el acumulador se inicializa en 0 antes del ciclo y se reinicia en el lugar correcto (en el ejemplo, dentro del ciclo de estudiantes).

🛠️ Taller: promedios de una clase

⏱️ 45 minutos · "while para leer, for anidado para la tabla"

🛠️ Taller final Promedios de una clase + tabla de multiplicar

El departamento académico quiere un programa que reciba las notas de un curso, calcule el promedio y muestre la escala. Tu misión: construir PromediosClase, una aplicación de consola con while + TryParse para leer, y un for anidado para la tabla de multiplicar.

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n PromediosClase y ábrelo en VS Code (code .).
  2. Pide cuántas notas se van a promediar. Si el número no es válido o es cero, avisa y termina.
  3. Lee las notas con un while y valida cada una con double.TryParse: solo cuentan las notas entre 0 y 5. Las demás se descartan con un continue.
  4. Permite que el usuario escriba "fin" para terminar antes de tiempo (usa un break con sentido).
  5. Calcula el promedio (solo de las notas válidas) y clasifícala en escala A–D con una switch expression.
  6. Al final, imprime la tabla de multiplicar del 1 al 5 con un for anidado.
csharp — guía de estilo (no es la solución, es el molde) 
// ============================================
// PROMEDIOS DE UNA CLASE — molde
// ============================================

Console.Write("¿Cuántas notas vas a promediar? ");
int cantidad = int.TryParse(Console.ReadLine() ?? "", out int n) && n > 0 ? n : 0;

// Acumulador y contador (esto lo vemos a fondo en la Clase 6)
double suma = 0;
int notasValidas = 0;
int i = 1;

// 1. LEE LAS NOTAS CON UN while
while (i <= cantidad)
{
    Console.Write($"Nota {i}: ");
    string entrada = Console.ReadLine() ?? "";
    i++;

    // 2. DESCARTA LO QUE NO ES UNA NOTA VÁLIDA
    if (!double.TryParse(entrada, out double nota) || nota is < 0 or > 5)
    {
        continue;
    }

    suma += nota;
    notasValidas++;
}

// 3. PROMEDIO
double promedio = notasValidas > 0 ? suma / notasValidas : 0;

// 4. TABLA DE MULTIPLICAR CON for ANIDADO
for (int fila = 1; fila <= 5; fila++)
{
    for (int columna = 1; columna <= 5; columna++)
    {
        Console.Write($"{fila * columna,4}");
    }
    Console.WriteLine();
}

💡 La trampa del i++

En el molde el i++ está justo después de leer, antes del continue. ¿Por qué? Porque el continue salta directo a la condición del while: si el i++ quedara más abajo, una nota inválida dejaría el contador congelado y el programa nunca terminaría de pedir notas. Avance primero, después decide.

csharp — solución del taller 
// ============================================
// PROMEDIOS DE UNA CLASE — solución del taller
// ============================================

Console.Write("¿Cuántas notas vas a promediar? ");
int cantidad = int.TryParse(Console.ReadLine() ?? "", out int n) && n > 0 ? n : 0;

if (cantidad == 0)
{
    Console.WriteLine("Debes indicar al menos una nota.");
    return;
}

Console.WriteLine("Escribe cada nota (de 0 a 5). Escribe 'fin' para terminar antes.");

double suma = 0;          // ACUMULADOR
int notasValidas = 0;     // CONTADOR
int i = 1;

// --- 1. LECTURA CON while ---
while (i <= cantidad)
{
    Console.Write($"Nota {i}: ");
    string entrada = Console.ReadLine() ?? "";
    i++;                                  // el avance va PRIMERO

    // --- 2. break: el usuario quiere parar ---
    if (entrada.Trim().Equals("fin", StringComparison.OrdinalIgnoreCase))
    {
        Console.WriteLine("  ⏹️ Terminó la entrada de notas.");
        break;
    }

    // --- 3. continue: esta nota no cuenta ---
    if (!double.TryParse(entrada, out double nota) || nota is < 0 or > 5)
    {
        Console.WriteLine("  ⚠️ Nota no válida: se descarta.");
        continue;
    }

    suma += nota;
    notasValidas++;
    Console.WriteLine($"  ✅ Nota {nota:F1} registrada.");
}

// --- 4. PROMEDIO ---
if (notasValidas == 0)
{
    Console.WriteLine("No se registró ninguna nota válida.");
    return;
}

double promedio = suma / notasValidas;

string escala = promedio switch
{
    >= 4.5 => "A — Excelente",
    >= 4.0 => "B — Muy bien",
    >= 3.0 => "C — Bien",
    _ => "D — Insuficiente"
};

Console.WriteLine();
Console.WriteLine("=== RESULTADO ===");
Console.WriteLine($"Notas válidas: {notasValidas} de {cantidad}");
Console.WriteLine($"Promedio: {promedio:F2}");
Console.WriteLine($"Escala: {escala}");

// --- 5. TABLA DE MULTIPLICAR con for ANIDADO ---
Console.WriteLine();
Console.WriteLine("=== TABLA DE MULTIPLICAR DEL 1 AL 5 ===");

for (int fila = 1; fila <= 5; fila++)
{
    for (int columna = 1; columna <= 5; columna++)
    {
        Console.Write($"{fila * columna,4}");
    }
    Console.WriteLine();
}

✅ Antes de entregar, verifica

  • El proyecto se llama PromediosClase y corre con dotnet run.
  • Las notas se leen con un while y el i++ está antes del continue.
  • Si escribes "fin", el programa termina la lectura con break y calcula el promedio con lo que lleva.
  • Una nota inválida (letra o número mayor que 5) se descarta sin tumbar el programa.
  • El promedio se calcula solo con las notas válidas (revisa que no dividas entre cantidad).
  • La tabla de multiplicar sale cuadrada: 5 filas de 5 números.
