🔀 El if: la decisión más básica

⏱️ 30 minutos · "Si cumple, haz esto; si no, seguimos de largo"

🧠 ¿Qué es un condicional?

Un condicional es una instrucción que le dice al programa: evalúa esta pregunta y, según la respuesta, haz esto o aquello. La pregunta se llama condición y SIEMPRE es una pregunta de sí o no: en C# eso es un bool, o sea true o false. Piensa en un guardián en la puerta del colegio: si tu carné está bien, pasas; si no, no. La condición del guardián es tieneCarné.

csharp — un if sencillo 
// La condición DEBE ser un bool: true o false.
int edad = 17;

if (edad >= 18)
{
    Console.WriteLine("Ya puede sacar la licencia de conducir.");
}

Console.WriteLine("El programa sigue hacia abajo.");

💡 ¿Qué hace?

Qué hace: evalúa edad >= 18. Como da false (17 no es mayor que 18), el bloque entre llaves no se ejecuta y el programa sigue de largo. Por qué funciona: el if es una sentencia de control: no siempre se ejecuta, depende del dato. Por eso el computador no puede "saltarse" la decisión ni la condición: siempre tiene que preguntar.

🦹 Villano número 1: la condición que no es bool

C# es estrictamente tipado: la condición de un if tiene que ser bool. Si le pasas un int, el compilador te frena con el error CS0029: "no se puede convertir de 'int' a 'bool'". Fíjate que C# no adivina: en otros lenguajes un número distinto de cero es "verdadero", pero en C# eso NO existe.

csharp — este bloque NO compila (error CS0029) 
int edad = 17;

// ERROR CS0029: no se puede convertir de 'int' a 'bool'
if (edad)
{
    Console.WriteLine("Esto nunca compila.");
}

// La forma correcta es preguntar con un operador de comparación:
if (edad != 0)
{
    Console.WriteLine("Ahora sí compila.");
}

🧱 Las llaves: no son decorativas

Si escribes el if sin llaves, C# toma solo la siguiente instrucción como el cuerpo del if. Las demás líneas se ejecutan siempre, se cumple o no. Es el error que más apoyazos causa en clase.

csharp — el if sin llaves (error de lógica, no de sintaxis) 
int edad = 17;

// Sin llaves, SOLO la línea siguiente es el cuerpo del if.
// La segunda línea se ejecuta SIEMPRE, haya o no verdadera la condición.
if (edad >= 18)
    Console.WriteLine("Ya puede sacar la licencia.");
    Console.WriteLine("Este mensaje sale siempre.");
csharp — la versión correcta, con llaves 
int edad = 17;

// Con llaves, TODO el bloque depende de la condición.
if (edad >= 18)
{
    Console.WriteLine("Ya puede sacar la licencia.");
}
else
{
    Console.WriteLine("Todavía le faltan años.");
}

// Regla del curso: SIEMPRE llaves, aunque el bloque tenga una línea.
// LaTe indentamos con 4 espacios y el código queda como una torre de control.

csharp — &&, || y el bool como variable de decisión 
int nota = 72;
int asistencia = 80;

bool aprobado = nota >= 60 && asistencia >= 75;

}

if (urgente)
{

}

💡 El "if invertido" y la guardaClause

Cuando lo que no se cumple es lo raro, invierte la pregunta: en vez de if (cumple) { hago } else { aviso }, escribe if (NO cumple) { aviso y me devuelvo }. Ese "me devuelvo" es el return temprano, y el bloque que valida se llama guardClause (una "guardia" que frena el programa si algo está mal). El resultado es un código más plano, sin else giganticotes. Lo vas a ver a fondo en el Módulo 5.

csharp — el if invertido con return temprano (guardClause) 
// El "if invertido": primero descartas lo inválido, luego sigues.
// Cada return temprano es una "guardia" que frena el programa.
static bool EsMayorDeEdad(int edad)
{
    if (edad < 0)
    {
        Console.WriteLine("Edad inválida.");
        return false;
    }

    if (edad < 18)
    {
        Console.WriteLine("Es menor de edad.");
        return false;
    }

    // Si llegamos aquí, todo está bien: no hace falta else.
    return true;
}

Console.WriteLine(EsMayorDeEdad(20));

🧩 else y else if: las otras salidas

⏱️ 30 minutos · "La primera condición que se cumple gana"

🧠 Dos caminos, y luego muchos

Un if solo tiene una salida: la del "sí". El else agrega la salida del "no": "si no, haz esto otro". Y cuando hay más de dos opciones, se encadena con else if: un if seguido de else if seguidos de un else final. En una cadena, gana la primera condición que se cumple y las demás ya no se miran.

csharp — if / else if / else 
int nota = 74;

if (nota >= 90)
{
    Console.WriteLine("A — Excelente");
}
else if (nota >= 80)
{
    Console.WriteLine("B — Muy bien");
}
else if (nota >= 70)
{
    Console.WriteLine("C — Bien");
}
else
{
    Console.WriteLine("D — Debe reforzar");
}

💡 ¿Qué hace?

Qué hace: como 74 no es >= 90, ni >= 80, ni >= 70, se cae hasta el else final. Por qué funciona: la cadena se evalúa de arriba hacia abajo y en cuanto una condición da true, se ejecuta ese bloque y se salta todo lo demás. Por eso el orden importa muchísimo: si pones primero nota >= 60, el 74 se iría por ahí y las otras escalas nunca se verían.

csharp — el orden de evaluación se nota 
int puntos = 85;
Console.WriteLine("1. Reviso la primera condición...");

if (puntos >= 90)
{
    Console.WriteLine("A");
}
else if (puntos >= 80)
{
    Console.WriteLine("2. La segunda se cumplió: B");
}
else if (puntos >= 70)
{
    Console.WriteLine("3. Esta NO se revisa: la cadena ya ganó");
}

Console.WriteLine("4. Fin de la cadena.");

🦹 El else sospechoso

Se llama else sospechoso a un else que nunca se ejecuta, porque la condición del if ya cubre todos los casos posibles. Ejemplo clásico: if (nota >= 0) { ... } else { Console.WriteLine("nota negativa"); } — si notas siempre son de 0 a 100, ese else es un adorno. Otro clásico es el else que repite lo que ya dijo el if. La solución no es borrar el else a ciegas: es preguntarse si la condición realmente puede ser falsa.

csharp — else sospechoso y else de último recurso 
// El "else sospechoso": la condición ya era una pregunta completa.
int edad = 17;

if (edad >= 0 && edad <= 120)
{
    Console.WriteLine("Edad válida.");
}
else
{
    // ¿Cuándo se ejecuta esto? Solo si el usuario miente de casual.
    Console.WriteLine("¿Edad qué?");
}

// El "else de último recurso": SIEMPRE tiene sentido como defecto.
Console.Write("Escribe 1 para la matriz o 2 para la lista: ");
string opcion = Console.ReadLine() ?? "";

if (opcion == "1")
{
    Console.WriteLine("Mostrando la matriz...");
}
else
{
    // Aquí el else es el plan B, no un adorno.
    Console.WriteLine("Mostrando la lista...");
}

🎛️ Entra switch: cuando las opciones son muchas

Cuando las opciones son muchas y todas del mismo tipo (un día de la semana, un menú, un código), una cadena de else if se vuelve larga y fea. Para eso existe el switch clásico:

csharp — switch clásico: case, break, default 
Console.Write("Escribe el día de la semana (1-7): ");
string entrada = Console.ReadLine() ?? "";
int dia = int.TryParse(entrada, out int numero) ? numero : 0;

switch (dia)
{
    case 1:
        Console.WriteLine("Lunes");
        break;                 // break SALTA a lo que sigue del switch
    case 2:
    case 3:
    case 4:
    case 5:                    // cases agrupados: comparten el mismo bloque
        Console.WriteLine("Día hábil de colegio");
        break;
    case 6:
    case 7:
        Console.WriteLine("Fin de semana");
        break;
    default:                    // se ejecuta si NINGÚN case coincidió
        Console.WriteLine("Día no válido");
        break;
}
PiezaPara qué sirveError típico
case 1:Una de las opciones posibles del switch.Meter un if dentro de un case por descuido.
break;Termina ese case y sale del switch.Olvidarlo: el programa "se cae" al siguiente case.
case 2: case 3:Agrupar varios valores en el mismo bloque.Repetir el mismo código 5 veces en vez de agrupar.
default:El caso "por si nada de lo anterior coincidió".Dejarlo de lado: el programa no avisa del dato inválido.
goto case 2;Salta a otro case (se usa para no repetir un bloque).Usarlo mucho: el código se vuelve un laberinto.
csharp — goto case: reutilizar un bloque 
int opcion = 2;

switch (opcion)
{
    case 1:
        Console.WriteLine("Cargando datos...");
        goto case 2;        // cae al case 2 y ejecuta su bloque
    case 2:
        Console.WriteLine("Datos cargados.");
        break;
    default:
        Console.WriteLine("Opción desconocida.");
        break;
}

🎛️ switch clásico vs. switch expression

⏱️ 35 minutos · "Del switch de 20 líneas a una expresión de 7"

🧠 Dos maneras de decir lo mismo

El switch clásico es una sentencia: recibe un valor, lo compara con cada case y ejecuta el que coincida. La switch expression (C# 8 en adelante) es una expresión: devuelve un valor. Se escribe con el operador => (la flecha) y termina con un _ que dice "si no era ninguno de los anteriores, devuelve esto". ¿Por qué importa? Porque una expresión se puede guardar en una variable o usar dentro de otra línea.

csharp — el switch clásico (sentencia) completo 
int nota = 84;
string escala;

switch (nota)
{
    case >= 90:                       // el switch clásico SÍ admite relaciones
        escala = "A — Excelente";
        break;
    case >= 80:
        escala = "B — Muy bien";
        break;
    case >= 70:
        escala = "C — Bien";
        break;
    case >= 60:
        escala = "D — Suficiente";
        break;
    default:
        escala = "E — Insuficiente";
        break;
}

Console.WriteLine(escala);
csharp — la misma lógica como switch expression 
int nota = 84;

string escala = nota switch
{
    >= 90 => "A — Excelente",
    >= 80 => "B — Muy bien",
    >= 70 => "C — Bien",
    >= 60 => "D — Suficiente",
    _    => "E — Insuficiente"          // el "_" es el "si no fue ninguno"
};

Console.WriteLine(escala);

// Y como es una EXPRESIÓN, se puede usar al vuelo:
Console.WriteLine(nota switch
{
    >= 90 => "¡Excelente!",
    _ => "A seguir practicando"
});

💡 ¿Qué hace?

Qué hace: las dos versiones devuelven lo mismo, pero la expresión tiene la mitad de líneas, no necesita break, no necesita declarar la variable antes y se puede usar dentro de otra expresión. Por qué funciona: el switch expression evalúa los patrones de arriba hacia abajo y devuelve el valor del primer patrón que coincide. El _ (patrón "comodín") es obligatorio: garantiza que la expresión siempre tenga un valor, aunque el dato sea raro.

🧬 switch expression con patrones

Aquí está lo bueno: los case de una switch expression no son solo valores, son patrones. Puedes preguntar por el tipo (como is string), por el rango (como is > 10) o por la forma del dato, y el compilador te da la respuesta con el dato ya convertido al tipo correcto:

csharp — switch expression con patrones de tipo y de rango 
object dato = "Hola";

string descripcion = dato switch
{
    int n when n > 100 => "Un entero grande",
    int n => $"Un entero: {n}",
    double d => $"Un decimal: {d}",
    string s when s.Length > 5 => $"Texto largo: {s}",
    string s => $"Texto corto: {s}",
    null => "Nulo",
    _ => "Tipo desconocido"
};

Console.WriteLine(descripcion);
csharp — switch con tuplas (patrón posicional) 
int x = 3;
int y = 4;

// (x, y) es una TUPLA: un par de valores que viaja junto.
string resultado = (x, y) switch
{
    (0, 0) => "El origen",
    (var a, 0) => $"Sobre el eje X, en {a}",
    (0, var b) => $"Sobre el eje Y, en {b}",
    (var a, var b) when a == b => $"Sobre la diagonal ({a})",
    _ => $"Punto normal ({x}, {y})"
};

Console.WriteLine(resultado);

🦹 La Exhaustividad: tu mejor aliado

La exhaustividad es la promesa de la switch expression: si te olvidas de un caso, el compilador te avisa. Desde C# 8, cuando la switch expression trabaja con un enum y no cubre todos sus valores, el compilador muestra el aviso CS8509 ("la expresión switch no controla todos los valores posibles"). Ese aviso es oro: te dice antes de ejecutar que te falta un caso.

csharp — el aviso CS8509 cuando falta un caso 
// FALTA el caso "Viernes": el compilador avisa CS8509.
DiaSemana dia = ObtenerDia();

string nombre = dia switch
{
    DiaSemana.Lunes => "Lunes",
    DiaSemana.Martes => "Martes",
    DiaSemana.Miercoles => "Miércoles",
    DiaSemana.Jueves => "Jueves"
};

Console.WriteLine(nombre);

static DiaSemana ObtenerDia() => DiaSemana.Viernes;

enum DiaSemana { Lunes, Martes, Miercoles, Jueves, Viernes }

💡 ¿Sabías que…?

La palabra if viene del inglés "if", que en español es "si", y el else es "si no". El switch se llama así porque el programa "cambia" de caso según el dato, como un interruptor de luz. Y el switch expression nació porque a los programadores de C# les molestaba tanto escribir break; que en 2019 (C# 8) Microsoft lo rediseñó: el resultado fue tan popular que hoy casi nadie escribe switch clásico a mano.

🪆 Condicionales anidados: el "if hell"

⏱️ 30 minutos · "Cuando el if se mete dentro del if…"

🦹 El villano: el if hell

Cuando metes un if dentro de otro if dentro de otro if, el código se vuelve un laberinto de llaves: hay que contar cuántas llaves abres y cuántas cierras, y para saber qué hace una línea toca leer 40 líneas hacia arriba. A ese monstruo lo llaman if hell. No es un error de compilación: el programa funciona. Solo que ya nadie lo entiende — y eso también es un error.

csharp — un if hell (compila, pero nadie lo entiende) 
int nota = 78;
int asistencia = 92;

if (nota >= 60)
{
    if (asistencia >= 70)
    {
        if (nota >= 90)
        {
            Console.WriteLine("Excelente");
        }
        else
        {
            Console.WriteLine("Bien");
        }
    }
    else
    {
        Console.WriteLine("Falta asistencia");
    }
}
else
{
    Console.WriteLine("Reprobó");
}

🪓 Tres formas de aplanar el infierno

TécnicaEn qué consisteCuándo usarla
Return tempranoSi algo está mal, return de una vez y sal del método.Cuando hay varios "si no, no sigas".
GuardClauseLas validaciones al principio, cada una con su propio if plano.Al principio de un método: valida y descarta.
Condición compuestaJuntar con && lo que siempre va junto.Cuando las dos mitades se cumplan siempre juntas.
Switch expressionUna tabla de "valor de entrada → valor de salida".Cuando hay varias opciones del mismo tipo.
csharp — aplanado con return temprano y guard clauses 
// Versión plana: cada "guardia" descarta el caso inválido y sale.
static string Clasificar(int nota, int asistencia)
{
    if (nota < 0 || nota > 100) return "Nota inválida";
    if (asistencia < 0 || asistencia > 100) return "Asistencia inválida";
    if (nota < 60) return "Reprobó";
    if (asistencia < 70) return "Falta asistencia";

    return nota >= 90 ? "Excelente" : "Bien";
}

Console.WriteLine(Clasificar(85, 90));
csharp — aplanado con switch expression y patrones de tupla 
int nota = 78;
int asistencia = 92;

// La tupla (nota, asistencia) viaja junta: una sola pregunta, un solo resultado.
string nivel = (nota, asistencia) switch
{
    (< 60, _) => "Reprobó",
    (_, < 70) => "Falta asistencia",
    (>= 90, >= 90) => "Excelente",
    _ => "Bien"
};

Console.WriteLine(nivel);

💰 La decisión del monto: un condicional de la vida real

Los descuentos de una tienda son un condicional disfrazado de tabla. Mira cómo la switch expression convierte la política del negocio en 5 líneas legibles:

csharp — decisión del monto de compra 
double total = 185000;

// La política del negocio escrita como una tabla de patrones.
double descuento = total switch
{
    >= 500000 => 0.20,
    >= 300000 => 0.15,
    >= 150000 => 0.10,
    _ => 0
};

double precioFinal = total * (1 - descuento);

Console.WriteLine($"Total: {total:C0}");
Console.WriteLine($"Descuento: {descuento:P0}");
Console.WriteLine($"Pagas: {precioFinal:C0}");

   └─────────┬──────────┘
             ▼
   ┌────────────────────┐
   │ contador = cont +1 │
   └─────────┬──────────┘
             │
             └────────────► (vuelve a la condición)

Reglas del diagrama:
  · El rombo (◆) es la CONDICIÓN: siempre tiene SÍ y NO.
  · El rectángulo (▭) es una ACCIÓN.
  · Solo hay UNA flecha de salida del programa: el "SALIR".

💡 Truco: el if hell se ve venir

Cuando estés escribiendo un if y notes que dentro hay otro if que no comparte nada con la condición de afuera, casi siempre es un caso para un return temprano. Y si lo que tienes es una lista de "valor → texto", lo que necesitas es un switch expression. Ponle nombre a las reglas: si puedes decir la decisión en una frase, puedes escribirla en una línea de código.

🧬 Patrones modernos: is, rangos y formas

⏱️ 35 minutos · "Preguntar por el tipo, por el rango y por la forma"

🧠 El pattern matching (C# 7 en adelante)

Un patrón es una forma de preguntarle algo a un dato: "¿eres un texto?", "¿estás entre 0 y 10?", "¿tiene más de 5 letras?". Antes tenías que esconder la respuesta con as, is y conversiones manuales; hoy preguntas directo y el compilador te da la respuesta con el dato ya convertido al tipo correcto. Eso se llama pattern matching.

csharp — is not null y el patrón en el if 
string? nombre = null;

// "is not null" = "no es nulo". Evita el clásico != null.
if (nombre is not null)
{
    Console.WriteLine($"Hola {nombre}");
}
else
{
    Console.WriteLine("No hay nombre");
}

// Y con el patrón, C# además TE SOBRA el tipo: no necesitas convertirlo.
object dato = "C#";
if (dato is string texto && texto.Length > 2)
{
    Console.WriteLine($"Es un texto largo: {texto}");
}
csharp — rangos: is > 0 and < 10 
int nota = 7;

// "and" une dos condiciones: mayor que 0 Y menor que 10.
if (nota is > 0 and < 10)
{
    Console.WriteLine("Nota baja pero positiva.");
}

// También sirve "or" y el signo de exclamación para negar.
if (nota is not (0 or 10))
{
    Console.WriteLine("No es 0 ni 10.");
}

// Patrón de rango con dos puntos (C# 11 en adelante).
if (nota is >= 0 and <= 100)
{
    Console.WriteLine("Dentro del rango válido de una nota.");
}
csharp — property patterns: is { Length: > 5 } 
// Un "property pattern" pregunta por las PROPIEDADES del objeto.
string? usuario = "Julián";

if (usuario is { Length: > 5 })
{
    Console.WriteLine($"El nombre tiene más de 5 letras: {usuario}");
}

// También puedes combinar varias propiedades y comprobar que no sea null.
if (usuario is { Length: > 5, Length: < 20 })
{
    Console.WriteLine("Nombre razonable para una base de datos.");
}

// Y con el patrón de tipo + propiedad, todo junto:
if (usuario is { Length: > 0 } texto)
{
    Console.WriteLine($"Texto no vacío: {texto}");
}
csharp — case null y case not null 
object? valor = null;

// En el switch, "null" y "not null" son patrones de primera clase.
string descripcion = valor switch
{
    null => "No hay valor",
    not null => $"Hay valor: {valor}"
};

Console.WriteLine(descripcion);

// Y con "when" puedes filtrar dentro de un case.
int? edad = 22;

string categoria = edad switch
{
    null => "Sin edad",
    < 0 => "Edad inválida",
    not null when edad < 18 => "Menor de edad",
    _ => "Mayor de edad"
};

Console.WriteLine(categoria);

🎚️ when: el filtro del case

En el switch clásico, cada case es un valor exacto. Si necesitas una condición extra, le pegas when:

csharp — switch clásico con when 
int edad = 22;

switch (edad)
{
    case < 0:
        Console.WriteLine("Edad inválida");
        break;
    case > 0 when edad < 18:      // "> 0" Y ADEMÁS "< 18"
        Console.WriteLine("Menor de edad");
        break;
    case > 0:
        Console.WriteLine("Mayor de edad");
        break;
}

🦹 La trampa de C# 14: ?. sí asigna, ?.= no existe

C# 14 (el lenguaje de .NET 10) permite usar ?. como destino de una asignación: persona?.Nombre = "Ana"; asigna el valor solo si persona no es null. Antes había que escribir un if (persona is not null) de tres líneas. Ojo: lo que no existe es el operador ?.= — si lo escribes, el compilador responde CS1001: se esperaba un identificador. Es un malentendido muy común, porque en los blogs de la versión preview se mencionaba con otra notación.

csharp — este bloque NO compila (?.= no es un operador de C#) 
// ERROR CS1001: el compilador no reconoce el operador ?.=
int? puntos = null;
puntos?.= 10;

// Cómo se hace de verdad en C# 14:
// 1) con el patrón "is not null" (la "guardia" moderna)
int? otros = null;

if (otros is not null)
{
    otros = 10;
}

// 2) con el operador ?? (nulo-coalescente): "si es null, pon este valor".
int? contador = null;
int resultado = contador ?? 0;
csharp — C# 14: ?. como destino de la asignación (esto SÍ funciona) 
// Novedad de C# 14: asignar a una propiedad SOLO si el objeto no es null.
Persona? persona = null;
persona?.Nombre = "Ana";          // si persona es null, no pasa nada (no revienta)

Persona? otra = new Persona("Luis", 30);
otra?.Nombre = "Luis Andrés";     // sí asigna: otra no es null
Console.WriteLine(otra.Nombre);    // Luis Andrés

public class Persona
{
    public string Nombre { get; set; }
    public int Edad { get; set; }
}
csharp — ?. y ??: el acceso condicional que sí existe 
string? usuario = "Julián";

// ?. = "si NO es null, accede". Si es null, devuelve null y no revienta.
Console.WriteLine(usuario?.Length);
Console.WriteLine(usuario?.ToUpper() ?? "SIN USUARIO");

// ?? = "si es null, usa este plan B".
string nombre = usuario ?? "Invitado";
Console.WriteLine(nombre);

// Con esto YA puedes hacer la asignación condicional que antes se "!=":
Perfil? perfil = null;

if (perfil is null)
{
    perfil = new Perfil { Nombre = "Ana" };
}

Console.WriteLine(perfil.Nombre);

class Perfil
{
    public string Nombre { get; set; } = "";
}

🛠️ Taller final Sistema de notas con escala A–E

El colegio necesita un programa que reciba la nota y la asistencia de un estudiante y le diga en qué escala quedó y si aprobó. Tu misión: construir SistemaNotas, una aplicación de consola que use if, switch expression y validación de entrada sin romperse nunca.

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n SistemaNotas y ábrelo en VS Code (code .).
  2. Pide la nota (decimal de 0 a 100) y la asistencia (entero de 0 a 100).
  3. Valida la entrada con double.TryParse y int.TryParse: si el dato no es un número o está fuera del rango, avisa y no continues con datos inventados.
  4. Clasifica la nota en la escala A (90-100) · B (80-89) · C (70-79) · D (60-69) · E (0-59) usando una switch expression.
  5. Decide el estado final combinando nota y asistencia en un condicional que antes habría sido un if anidado: aquí lo resuelves con una switch expression sobre la tupla (nota, asistencia).
  6. Muestra un resumen con interpolación: nota, asistencia, escala y estado.

💡 Pista para el paso 5

La tupla (nota, asistencia) permite preguntar por las dos cosas a la vez: (nota, asistencia) switch { (< 60, _) => "Reprobado por nota", (_, < 75) => "Reprobado por asistencia", _ => "Aprobado" }. El _ significa "me da igual este valor". Así el "if hell" del enunciado se vuelve una sola tabla de tres filas.

csharp — solución del taller 
// ============================================
// SISTEMA DE NOTAS — solución del taller
// ============================================

Console.WriteLine("=== SISTEMA DE NOTAS ===");

// --- 1. ENTRADA ---
Console.Write("Ingresa la nota (0 a 100): ");
string entradaNota = Console.ReadLine() ?? "";

Console.Write("Ingresa la asistencia (0 a 100): ");
string entradaAsistencia = Console.ReadLine() ?? "";

// --- 2. VALIDACIÓN (TryParse no se cae nunca) ---
bool notaOk = double.TryParse(entradaNota, out double nota) && nota is >= 0 and <= 100;
bool asistenciaOk = int.TryParse(entradaAsistencia, out int asistencia) && asistencia is >= 0 and <= 100;

if (!notaOk || !asistenciaOk)
{
    Console.WriteLine("❌ Los datos no son válidos. Revisa e intenta de nuevo.");
    return;
}

// --- 3. ESCALA con switch expression ---
string escala = nota switch
{
    >= 90 => "A — Excelente",
    >= 80 => "B — Muy bien",
    >= 70 => "C — Bien",
    >= 60 => "D — Suficiente",
    _ => "E — Insuficiente"
};

// --- 4. ESTADO: el if anidado resuelto con una tupla ---
string estado = (nota, asistencia) switch
{
    (< 60, _) => "Reprobado por nota",
    (_, < 75) => "Reprobado por asistencia",
    _ => "Aprobado"
};

// --- 5. SALIDA ---
Console.WriteLine("------------------------------");
Console.WriteLine($"Nota:       {nota:F1}");
Console.WriteLine($"Asistencia: {asistencia}%");
Console.WriteLine($"Escala:     {escala}");
Console.WriteLine($"Estado:     {estado}");
Console.WriteLine("------------------------------");

  • Si escribes letras en vez de números, el programa avisa y no se cae.
  • La escala se calcula con una switch expression (con => y _).
  • El estado final usa una tupla (nota, asistencia), no un if anidado.
  • Probaste los 5 caminos: notas 95, 85, 75, 65, 40 y una asistencia baja (por ejemplo 50).
  • La salida usa interpolación y una línea separadora.
