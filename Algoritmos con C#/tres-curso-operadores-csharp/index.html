💡 ¿Por qué las reglas de precedencia existen?

Porque en las matemáticas nadie escribe 2 + 3 * 4 queriendo decir 20. Todos leemos primero el 4 * 3 y después sumamos. C# hace exactamente lo mismo, y esa tabla de precedencia es el acuerdo silencioso entre el que escribe el código y el que lo lee. Entenderla es un superpoder. 🦸

➗ Operadores aritméticos: la calculadora de C#

⏱️ 35 minutos · "Cinco símbolos que hacen todo el trabajo"

🧠 Los cinco operadores básicos

C# trae una calculadora integrada: los operadores aritméticos +, -, *, / y %. Con esos cinco (más el ++ y el --) resuelves la mayoría de los cálculos de la vida real: promedios, totales, porcentajes y el resto de una división…

csharp — las cinco operaciones básicas 
// Las cinco operaciones básicas
int a = 17;
int b = 5;

Console.WriteLine($"{a} + {b} = {a + b}");   // 22
Console.WriteLine($"{a} - {b} = {a - b}");   // 12
Console.WriteLine($"{a} * {b} = {a * b}");   // 85
Console.WriteLine($"{a} / {b} = {a / b}");   // 3   (división ENTERA)
Console.WriteLine($"{a} % {b} = {a % b}");   // 2   (residuo o módulo)

✂️ División entera vs. división real: el gran engaño

csharp — ojo con la división entera 
// Si los DOS operandos son int, la división es ENTERA: se descarta el decimal.
Console.WriteLine($"5 / 2 = {5 / 2}");       // 2
Console.WriteLine($"5.0 / 2 = {5.0 / 2}");   // 2.5
Console.WriteLine($"7 / 2.0 = {7 / 2.0}");   // 3.5

// La regla: si AL MENOS uno es double, el resultado es double.
int cantidad = 3;
double precio = 19999.0;
Console.WriteLine($"Total: {cantidad * precio}");

// Y ojo con el orden: la división va primero que la multiplicación.
Console.WriteLine($"3 / 2 * 2 = {3 / 2 * 2}");       // 2  (primero 3/2 = 1, luego 1*2)
Console.WriteLine($"3.0 / 2 * 2 = {3.0 / 2 * 2}");   // 3  (primero 1.5, luego 1.5*2)

🦹 El villano: 5 / 2 da 2, no 2.5

Cuando ambos números son int, C# hace división entera: tira la parte decimal sin avisar. Esto no es un error, es el comportamiento correcto para contar cosas (¿cuántas cajas completas de 5 caben en 17? → 3). Pero si estabas pensando en un promedio o un porcentaje, el resultado te va a sorprender. Regla práctica: si el resultado puede tener decimales, mete al menos un double o un decimal en la cuenta.

⬆️ ++ y --: antes o después

csharp — prefijo vs. postfijo 
// POSTFIJO (x++): primero USA el valor, después suma 1.
int x = 5;
int y = x++;
Console.WriteLine($"x = {x}, y = {y}");   // x = 6, y = 5

// PREFIJO (++x): primero suma 1, después usa el valor nuevo.
int a = 5;
int b = ++a;
Console.WriteLine($"a = {a}, b = {b}");   // a = 6, b = 6

// El decremento funciona exactamente igual.
int contador = 3;
contador--;
Console.WriteLine($"contador = {contador}");   // 2
ExpresiónValor de x antesValor que recibe la variableValor de x después
int y = x++;55 (el viejo)6
int y = ++x;56 (el nuevo)6
x--; (solo)5—4
--x; (solo)5—4

🔁 El módulo %: el residuo que responde preguntas

csharp — par, impar y múltiplos con % 
// El módulo (%) devuelve el RESIDUO de la división.
int numero = 17;

if (numero % 2 == 0)
{
    Console.WriteLine($"{numero} es PAR.");
}
else
{
    Console.WriteLine($"{numero} es IMPAR.");
}

// También sirve para saber si es múltiplo de 3, 5, 10...
int diaDelMes = 15;
Console.WriteLine($"¿Es múltiplo de 5? {diaDelMes % 5 == 0}");
Console.WriteLine($"¿Es múltiplo de 3? {diaDelMes % 3 == 0}");

// Y para repartir: ¿cuántos grupos de 4 caben en 10? → 2 grupos, sobran 2.
Console.WriteLine($"10 / 4 = {10 / 4} grupos, sobran {10 % 4}");

🧰 La clase Math: atajos matemáticos

csharp — Math.Abs, Round, Max, Min, Sqrt y Pow 
// La clase Math trae las herramientas matemáticas listas para usar.
double nota = 3.7;
double negativo = -8.5;

Console.WriteLine($"Math.Abs({negativo}) = {Math.Abs(negativo)}");   // 8.5
Console.WriteLine($"Math.Round({nota}) = {Math.Round(nota)}");         // 4
Console.WriteLine($"Math.Max(3, 7) = {Math.Max(3, 7)}");               // 7
Console.WriteLine($"Math.Min(3, 7) = {Math.Min(3, 7)}");               // 3
Console.WriteLine($"Math.Sqrt(81) = {Math.Sqrt(81)}");                 // 9
Console.WriteLine($"Math.Pow(2, 10) = {Math.Pow(2, 10)}");             // 1024

// Math.Round con MidpointRounding decide qué hacer cuando el decimal es 0.5 exacto.
// Por defecto usa "ToEven" (redondea al par más cercano: 2.5 -> 2, 3.5 -> 4).
Console.WriteLine($"Math.Round(2.5) = {Math.Round(2.5)}");
Console.WriteLine($"Math.Round(3.5) = {Math.Round(3.5)}");

// Con AwayFromZero el 0.5 siempre sube: 2.5 -> 3.
Console.WriteLine($"Math.Round(2.5, MidpointRounding.AwayFromZero) = {Math.Round(2.5, MidpointRounding.AwayFromZero)}");

💡 Truco: Math.Round siempre redondea, nunca trunca

(int)3.9 da 3 (trunca) pero Math.Round(3.9) da 4 (redondea). Para notas y promedio usa siempre Math.Round, y si quieres ver exactamente dos decimales, escribe Math.Round(nota, 2). Y si necesitas el 0.5 siempre hacia arriba (como cuando se reparte el IVA), usa MidpointRounding.AwayFromZero. 🧮

⚖️ Operadores de comparación: ¿igual o no igual?

⏱️ 35 minutos · "La pregunta que decide el rumbo del programa"

🧠 Comparar es preguntar

Los operadores de comparación responden con true o false. Son la base de todas las decisiones del programa: si la nota es mayor o igual a 3, si la edad es menor que 18, si el nombre es igual al guardado. Su resultado es un bool, y ese bool es lo que después se combina con &&, || y !.

csharp — los seis operadores de comparación 
int edad = 17;
int limite = 18;

Console.WriteLine(edad == limite);   // igual          → False
Console.WriteLine(edad != limite);   // distinto      → True
Console.WriteLine(edad > limite);    // mayor         → False
Console.WriteLine(edad < limite);    // menor         → True
Console.WriteLine(edad >= limite);   // mayor o igual → False
Console.WriteLine(edad <= limite);   // menor o igual → True

// Ojo con el orden: == es "comparar", = es "asignar".
int contador = 0;
contador = 5;         // asignar (guarda 5)
bool iguales = contador == 5;   // comparar (pregunta)
Console.WriteLine($"iguales = {iguales}");

🔤 Comparar textos: no es lo mismo que comparar números

csharp — ==, Equals, Compare y CompareTo 
string a = "juan";
string b = "JuaN";

// == en strings compara el CONTENIDO, y distingue mayúsculas.
Console.WriteLine($"a == b                   → {a == b}");   // False
Console.WriteLine($"a.Equals(b)             → {a.Equals(b)}");   // False
Console.WriteLine($"OrdinalIgnoreCase       → {a.Equals(b, StringComparison.OrdinalIgnoreCase)}");   // True

// string.Compare devuelve un NÚMERO: menor, igual o mayor.
Console.WriteLine($"string.Compare(\"a\", \"b\") → {string.Compare("a", "b")}");   // -1 (a va antes)
Console.WriteLine($"string.Compare(\"b\", \"a\") → {string.Compare("b", "a")}");   // 1  (b va después)
Console.WriteLine($"string.Compare(\"a\", \"a\") → {string.Compare("a", "a")}");   // 0  (son iguales)

// CompareTo hace lo mismo, pero como método del propio texto.
Console.WriteLine($"\"a\".CompareTo(\"b\")      → {"a".CompareTo("b")}");   // -1

💡 Ordinal vs. cultura: dos maneras de ordenar

Ordinal compara carácter por carácter según su código: la "B" (66) va antes que la "a" (97). Es rápido y predecible, ideal para códigos y claves. Cultura usa las reglas del idioma configurado, como lo haría una persona: "Álvarez" va antes que "Bautista" y "ana" va antes que "Beto". Para listas de nombres de personas usa cultura; para identificadores técnicos, ordinal. 🎓

csharp — char, double y NaN: comparar con cuidado 
// Los char se comparan por su código: 'A' (65) va antes que 'a' (97).
char inicial = 'M';
char otra = 'a';
Console.WriteLine($"'M' < 'a' → {inicial < otra}");   // True
Console.WriteLine($"Código de 'M' → {(int)inicial}");       // 77

// Con NÚMEROS DECIMALES, el == es peligroso: no compares doubles con ==.
double x = 0.1 + 0.2;
double y = 0.3;
Console.WriteLine($"0.1 + 0.2 == 0.3 → {x == y}");   // False (¡sorpresa!)

// La forma segura: comparar la diferencia con una tolerancia.
Console.WriteLine($"¿Son iguales? → {Math.Abs(x - y) < 0.0001}");   // True

// NaN significa "Not a Number": no es igual ni a sí mismo.
double nan = double.NaN;
Console.WriteLine($"NaN == NaN → {nan == double.NaN}");                    // False
Console.WriteLine($"double.IsNaN(nan) → {double.IsNaN(nan)}");             // True
csharp — comparar un int? (nullable) 
// Un int? puede estar "vacío". Las comparaciones siguen funcionando:
int? edad = null;

Console.WriteLine($"edad > 18 → {edad > 18}");          // False (null no es mayor que 18)
Console.WriteLine($"edad == null → {edad == null}");        // True
Console.WriteLine($"edad is null → {edad is null}");        // True

// Con HasValue y Value lo manejas como un entero normal.
edad = 17;
Console.WriteLine($"edad > 18 → {edad > 18}");          // False
Console.WriteLine($"edad.Value → {edad.Value}");            // 17
Console.WriteLine($"edad.HasValue → {edad.HasValue}");      // True

🦹 El villano: double comparado con ==

Un double guarda el número en binario, y muchos decimales no se pueden representar exactos. Por eso 0.1 + 0.2 da un numero cercanísimo a 0.3, pero no exactamente igual, y el == responde false. La solución profesional es comparar la diferencia con una tolerancia: Math.Abs(a - b) < 0.0001. Con decimal esto no pasa (por eso es el tipo del dinero).

🔀 Operadores lógicos y precedencia

⏱️ 40 minutos · "La tabla que decide el orden de todo"

🧠 Tres operadores, todo un mundo

&& es "y" (las dos cosas tienen que ser ciertas), || es "o" (con que una sea cierta basta) y ! es "no" (da la vuelta al booleano). Con esos tres puedes expresar cualquier decisión. Pero C# no solo te da esos: también existen & y |, que son operadores de bits y funcionan de forma distinta.

csharp — &&, || y ! 
// Los tres operadores lógicos
bool mayorDeEdad = true;
bool tieneBoleto = false;

Console.WriteLine($"mayorDeEdad && tieneBoleto → {mayorDeEdad && tieneBoleto}");   // False
Console.WriteLine($"mayorDeEdad || tieneBoleto → {mayorDeEdad || tieneBoleto}");   // True
Console.WriteLine($"!mayorDeEdad → {!mayorDeEdad}");                                 // False

// El resultado SIEMPRE es un bool, nunca el dato original.
Console.WriteLine($"&& devuelve: {true && false} (tipo bool)");
Console.WriteLine($"|| devuelve: {true || false} (tipo bool)");

⚡ El cortocircuito: tu mejor aliado

csharp — cortocircuito: no evaluar lo que no hace falta 
// Con &&, si el primer operando es FALSE, el segundo NI SE EVALÚA.
int divisor = 0;
int numero = 10;

// Primero se pregunta "¿divisor es distinto de cero?" → False → se detiene ahí.
bool divisionSegura = divisor != 0 && numero / divisor > 1;
Console.WriteLine($"división segura: {divisionSegura}");   // False, y NO hubo error

// Si el orden fuera el revés, el programa se caería con DivideByZeroException.
// bool peligro = numero / divisor > 1 && divisor != 0;   ← ¡error en ejecución!

// Con || el cortocircuito es al revés: si el primero es TRUE, el segundo no se evalúa.
int cero = 0;
bool segunda = true;
bool resultado = segunda || 10 / cero > 1;
Console.WriteLine($"resultado con || → {resultado}");   // True, sin error

💡 Truco: && primero lo "barato", || primero lo "certeza"

En a && b, pon primero la condición más barata y segura: la que puede fallar (dividir por cero) va a la derecha. En a || b, pon primero la condición que casi siempre es cierta. Esta costumbre te va a ahorrar exceptions en el futuro. ⚡

csharp — los paréntesis mandan 
// SIN paréntesis, * y / ganan sobre + y -.
Console.WriteLine($"2 + 3 * 4 = {2 + 3 * 4}");          // 14

// CON paréntesis, cambias el resultado.
Console.WriteLine($"(2 + 3) * 4 = {(2 + 3) * 4}");      // 20

// Unario también gana: el signo se aplica primero.
int x = 5;
Console.WriteLine($"-x + 2 = {-x + 2}");                // -3
Console.WriteLine($"-(x + 2) = {-(x + 2)}");            // -7

// Regla de oro: si tienes dudas, pon paréntesis.
// Se lee peor que el código sin paréntesis... no. Se lee MEJOR.
Console.WriteLine($"{((2 + 3) * 4) - 5}");

🧷 & vs && (y | vs ||)

csharp — operadores de bits 
// & y | son operadores de BITS: trabajan con el 0 y el 1 de cada byte.
int a = 6;   // 0110
int b = 3;   // 0011
Console.WriteLine($"6 & 3 = {a & b}");   // 0010 → 2
Console.WriteLine($"6 | 3 = {a | b}");   // 0111 → 7
Console.WriteLine($"6 ^ 3 = {a ^ b}");   // 0101 → 5

// Con bool, & y | también funcionan, PERO evalúan los dos lados siempre.
bool primero = false;
bool segundo = true;
Console.WriteLine($"false & true = {primero & segundo}");   // False
Console.WriteLine($"false && true = {primero && segundo}");   // False

// OJO: con & NO hay cortocircuito, así que esto se rompe:
int divisor = 0;
int numero = 10;
// bool peligro = numero / divisor > 1 & primero;   ← DivideByZeroException
Console.WriteLine("El programa llegó aquí sin romperse.");

🦹 Por qué C# tiene dos "y" y dos "o"

&& y || son para decisiones: cortocircuitan, trabajan con booleanos y devuelven un bool. & y | son para bits: miran cada bit de los números y no cortocircuitan. Si los usas por error (un & donde iba un &&), el programa compila, pero te puede tirar un error feo en tiempo de ejecución.

🔗 Asignación compuesta: atajos que hacen más

⏱️ 30 minutos · "Sumar sin que el nombre de la variable cambie"

🧠 x = x + 5 es cansón

Cuando a una variable le sumas, le restas o la multiplicas usando su propio valor, C# te da un atajo: x += 5 significa exactamente x = x + 5. No es magia: es azúcar sintáctico, una forma más corta de escribir lo mismo. Y tiene un detalle muy importante: la asignación devuelve el valor asignado, así que se puede encadenar.

csharp — los operadores de asignación compuestos 
int total = 0;
total += 15;    // total = total + 15
total -= 5;     // total = total - 5
total *= 2;     // total = total * 2
total /= 4;     // total = total / 4
total %= 5;     // total = total % 5

Console.WriteLine($"total final = {total}");

// La asignación devuelve el valor asignado, así que se puede encadenar:
int x = 0;
int y = (x += 10);   // x queda en 10 y y también vale 10
Console.WriteLine($"x = {x}, y = {y}");
AtajoEquivale aAtajoEquivale a
x += 5x = x + 5x /= 5x = x / 5
x -= 5x = x - 5x %= 5x = x % 5
x *= 5x = x * 5x ??= 5si x es null, vale 5
x++x = x + 1x &^= moperación de bits (poco usada)

🧵 La asignación se evalúa de derecha a izquierda

csharp — += con texto y ??= 
// ??= asigna SOLO si la variable es null. Ideal para valores por defecto.
string? nombre = null;
nombre ??= "Visitante";
Console.WriteLine($"nombre = {nombre}");

// El += con TEXTO es una concatenación.
string saludo = "Hola";
saludo += ", ";
saludo += "María";
Console.WriteLine(saludo);

// Y con números funciona igual de bien.
int contador = 0;
contador += 1;
contador += 1;
Console.WriteLine($"contador = {contador}");

🦹 El bug clásico: el ++ escondido en la condición

El ++ dentro del while se ejecuta antes de la comparación, y eso desplaza todos los valores. Es el error que hace que un contador empiece en 1, o que un bucle termine una vuelta antes de tiempo. La regla: el incremento va en una línea aparte, al final del bloque.

csharp — el ++ escondido (bug) y su solución 
// BUG: el ++ está en la condición, así que se evalúa ANTES de comparar.
int i = 0;
Console.WriteLine("Con i++ en la condición:");
while (i++ < 3)
{
    Console.WriteLine($"  i = {i}");
}
// Imprime 1, 2, 3 → se salta el 0 y se pasa un número.

// La forma CORRECTA: comparar y luego incrementar.
int j = 0;
Console.WriteLine("Con j++ dentro del bloque:");
while (j < 3)
{
    Console.WriteLine($"  j = {j}");
    j++;
}
// Imprime 0, 1, 2 ✅

💡 Truco: += es tu mejor aliado en los bucles

Un acumulador se escribe siempre igual: total += valor;. Como la asignación devuelve el valor, también sirve para cosas curiosas como contador++ dentro de una condición, pero mejor no: ya vimos que es una trampa. Y ojo: total += 5 es más rápido que total = total + 5, porque el compilador lo optimiza por ti. 🚀

🪤 Trampas del lenguaje: las que muerden

⏱️ 35 minutos · "Los errores que no son de sintaxis"

🧠 El peor tipo de error

Un error de sintaxis te lo señala el compilador con el número de la línea: no duele. Los errores de esta clase compilan perfecto y se descubren cuando el programa ya está corriendo (o peor: cuando el resultado sale mal). Son los que se quedan en producción. Hoy los cazamos todos. 🪤

💥 Trampa 1: dividir entre cero

csharp — división entre cero: excepción vs. Infinity 
int divisor = 0;
int numero = 10;

// Con int, esto LANZA DivideByZeroException y el programa se cae:
// int resultado = numero / divisor;

try
{
    int resultado = numero / divisor;
    Console.WriteLine(resultado);
}
catch (DivideByZeroException)
{
    Console.WriteLine("No se puede dividir entre cero (villano derrotado 🦹).");
}

// Con double NO hay excepción: el resultado es Infinity.
double d = 10;
double cero = 0;
Console.WriteLine($"{d} / {cero} = {d / cero}");
Console.WriteLine($"¿Es infinito? {double.IsInfinity(d / cero)}");

// Ojo: 0.0 / 0.0 da NaN, no Infinity.
Console.WriteLine($"0.0 / 0.0 = {cero / cero} · ¿Es NaN? {double.IsNaN(cero / cero)}");

💥 Trampa 2: el int que se desborda

csharp — desbordamiento (overflow) de int 
int maximo = int.MaxValue;
Console.WriteLine($"int.MaxValue = {maximo}");

// UNCHECKED (por defecto): la cuenta "da la vuelta" y el programa sigue
// como si nada. ¡Esta es la trampa más silenciosa!
int desbordado = unchecked(maximo + 1);
Console.WriteLine($"unchecked → {desbordado}");

// CHECKED: el desbordamiento lanza OverflowException y te avisa.
try
{
    int controlado = checked(maximo + 1);
    Console.WriteLine(controlado);
}
catch (OverflowException)
{
    Console.WriteLine("Overflow detectado: el valor no cabe en un int.");
}

// Si el dato es grande de verdad, usa long: ahí sí cabe.
long enorme = (long)maximo + 1;
Console.WriteLine($"En long sí cabe: {enorme}");

💥 Trampa 3: 0.1 + 0.2 no es 0.3

csharp — la trampa de los decimales binarios 
// Los double guardan el número en base 2, y 0.1 no se puede escribir exacto ahí.
double suma = 0.1 + 0.2;
double esperado = 0.3;

Console.WriteLine($"0.1 + 0.2 = {suma}");
Console.WriteLine($"0.1 + 0.2 == 0.3 → {suma == esperado}");   // False

// La comparación correcta: mirar la diferencia, no el signo igual.
Console.WriteLine($"¿Son iguales? → {Math.Abs(suma - esperado) < 0.0000001}");

// Con decimal la aritmética es decimal exacta: aquí sí da True.
decimal sumaDecimal = 0.1m + 0.2m;
Console.WriteLine($"0.1m + 0.2m == 0.3m → {sumaDecimal == 0.3m}");   // True

💥 Trampa 4: la precedencia que sorprende

csharp — sorpresas de precedencia 
// * gana sobre +: el resultado NO es 20.
Console.WriteLine($"2 + 3 * 4 = {2 + 3 * 4}");            // 14
Console.WriteLine($"(2 + 3) * 4 = {(2 + 3) * 4}");        // 20

// && gana sobre ||: el resultado NO es el que parece.
bool a = true;
bool b = true;
bool c = false;

Console.WriteLine($"a || b && c = {a || b && c}");          // True  → true || (true && false)
Console.WriteLine($"(a || b) && c = {(a || b) && c}");      // False → (true || true) && false

// Para que no haya dudas, escribe SIEMPRE los paréntesis.
Console.WriteLine($"a || (b && c) = {a || (b && c)}");       // True

// Y el signo pegado al número cambia el resultado:
Console.WriteLine($"-2 * 3 = {-2 * 3}");      // -6
Console.WriteLine($"-(2 * 3) = {-(2 * 3)}");   // -6 (pero ojo con la suma)
Console.WriteLine($"-2 + 3 = {-2 + 3}");      // 1

💡 La regla de oro de las trampas

Pon paréntesis siempre que combines operadores de distintas familias. El computador nunca se equivoca: la ambigüedad la pones tú. Y cuando un resultado te sorprenda, no lo arregles a ojo: parte la expresión en varios pasos y revisa cada paso. 🕵️

El compañero tiene que encontrar el error sin leer el código, solo mirando la salida. Quien lo encuentre, gana un punto. Luego lo arreglan juntos. 🎯

🛠️ Taller: Calculadora BLACKFRIDAY

⏱️ 45 minutos · "Aritmética, comparación, lógicos y validación en un solo programa"

🛠️ Taller final Calculadora BLACKFRIDAY

La tienda del colegio tiene su gran día de descuentos y necesita un programa que calcule el total de cada compra, con descuentos por tramos, IVA del 19 %, envío y validación de entrada. Tu misión: construir BlackFriday, una aplicación de consola que use aritmética, comparación, operadores lógicos, precedencia y TryParse sin fallar nunca. 🛍️

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n BlackFriday y ábrelo en VS Code (code .).
  2. Pide el nombre del cliente (string), el precio unitario (decimal) y la cantidad (int).
  3. Valida con decimal.TryParse e int.TryParse: si el precio no es un número o es negativo, avisa y usa 0. Si la cantidad es inválida o menor que 1, avisa y usa 1.
  4. Pregunta si es día Black Friday (bool, leyendo "s" o "n").
  5. Calcula el subtotal (precio * cantidad).
  6. Aplica el descuento: 30 % si es Black Friday, 5 % si no. Y súmele 5 % extra si el subtotal supera los 500 000 COP.
  7. Calcula el IVA (19 %) sobre el valor ya descontado, y el total.
  8. El envío cuesta 15 000 COP, pero es gratis si el total (con IVA) supera 300 000 COP.
  9. Muestra todo con interpolación y el formato {total:N0}. Si el total quedó en 0, muestra un aviso de "compra no válida".
  10. Prueba el programa con: compra normal, compra Black Friday grande (que activa el 5 % extra), precio escrito como texto ("abc") y cantidad 0.
csharp — guía de estilo (no es la solución, es el molde) 
// ============================================
// CALCULADORA BLACKFRIDAY
// Descuentos por tramos + IVA + envío + validación.
// ============================================

const decimal IVA = 0.19m;
const decimal DescuentoNormal = 0.05m;
const decimal DescuentoBlackFriday = 0.30m;
const decimal ExtraPorCompraGrande = 0.05m;
const decimal ValorEnvio = 15000m;
const decimal EnvioGratisDesde = 300000m;

Console.WriteLine("=== BLACKFRIDAY · Calculadora de descuentos ===");

// 1. ENTRADA
Console.Write("Nombre del cliente: ");
string nombre = Console.ReadLine() ?? "";

Console.Write("Precio unitario: ");
decimal precio = 0m;
if (!decimal.TryParse(Console.ReadLine(), out precio) || precio <= 0m)
{
    Console.WriteLine("Precio inválido: se asume 0.");
    precio = 0m;
}

Console.Write("Cantidad: ");
int cantidad = 0;
if (!int.TryParse(Console.ReadLine(), out cantidad) || cantidad < 1)
{
    Console.WriteLine("Cantidad inválida: se asume 1.");
    cantidad = 1;
}

Console.Write("¿Es día Black Friday? (s/n): ");
string respuesta = (Console.ReadLine() ?? "").Trim().ToLower();
bool esBlackFriday = respuesta == "s";

// 2. PROCESO
decimal subtotal = precio * cantidad;
decimal porcentaje = esBlackFriday ? DescuentoBlackFriday : DescuentoNormal;
decimal extra = subtotal >= 500000m ? ExtraPorCompraGrande : 0m;
decimal descuento = (porcentaje + extra) * subtotal;
decimal baseImponible = subtotal - descuento;
decimal iva = baseImponible * IVA;
decimal totalSinEnvio = baseImponible + iva;
decimal envio = totalSinEnvio >= EnvioGratisDesde ? 0m : ValorEnvio;
decimal total = totalSinEnvio + envio;

// 3. SALIDA
Console.WriteLine("--------------------------------");
Console.WriteLine($"Cliente: {nombre}");
Console.WriteLine($"Subtotal:  {subtotal:N0} COP");
Console.WriteLine($"TOTAL:     {total:N0} COP");
Console.WriteLine("--------------------------------");

💡 Mira bien el ternario anidado

esBlackFriday ? DescuentoBlackFriday : DescuentoNormal es un operador condicional (el ? : de la tabla de precedencia): una forma compacta de escribir un if que solo tiene dos caminos. Y el subtotal >= 500000m es un operador de comparación. Un solo renglón, tres conceptos. 🎯

csharp — solución del taller 
// ============================================
// CALCULADORA BLACKFRIDAY — solución del taller
// Descuentos por tramos + IVA + envío + validación.
// ============================================

const decimal IVA = 0.19m;
const decimal DescuentoNormal = 0.05m;
const decimal DescuentoBlackFriday = 0.30m;
const decimal ExtraPorCompraGrande = 0.05m;
const decimal ValorEnvio = 15000m;
const decimal EnvioGratisDesde = 300000m;
const decimal UmbralCompraGrande = 500000m;

Console.WriteLine("=== BLACKFRIDAY · Calculadora de descuentos ===");

// ---------- 1. ENTRADA ----------
Console.Write("Nombre del cliente: ");
string nombre = Console.ReadLine() ?? "";

Console.Write("Precio unitario: ");
decimal precio = 0m;
if (!decimal.TryParse(Console.ReadLine(), out precio) || precio <= 0m)
{
    Console.WriteLine("⚠ Precio inválido: se asume 0.");
    precio = 0m;
}

Console.Write("Cantidad: ");
int cantidad = 0;
if (!int.TryParse(Console.ReadLine(), out cantidad) || cantidad < 1)
{
    Console.WriteLine("⚠ Cantidad inválida: se asume 1.");
    cantidad = 1;
}

Console.Write("¿Es día Black Friday? (s/n): ");
string respuesta = (Console.ReadLine() ?? "").Trim().ToLower();
bool esBlackFriday = respuesta == "s";

// ---------- 2. PROCESO ----------
decimal subtotal = precio * cantidad;

// El descuento depende del día (operador condicional ? :).
decimal porcentaje = esBlackFriday ? DescuentoBlackFriday : DescuentoNormal;

// Si la compra es grande, hay un 5 % extra (comparación con &&).
decimal extra = subtotal >= UmbralCompraGrande ? ExtraPorCompraGrande : 0m;

decimal descuento = (porcentaje + extra) * subtotal;
decimal baseImponible = subtotal - descuento;
decimal iva = baseImponible * IVA;
decimal totalSinEnvio = baseImponible + iva;

// El envío es gratis si el total ya supera el umbral (comparación simple).
decimal envio = totalSinEnvio >= EnvioGratisDesde ? 0m : ValorEnvio;
decimal total = totalSinEnvio + envio;

// Un double para el promedio por unidad (no es dinero, es un cálculo).
double promedioUnidad = cantidad > 0 ? (double)total / cantidad : 0;

// ---------- 3. SALIDA ----------
Console.WriteLine("--------------------------------");
Console.WriteLine($"Cliente: {nombre}");
Console.WriteLine($"Subtotal:            {subtotal:N0} COP");
Console.WriteLine($"Descuento ({porcentaje * 100:N0}% + {extra * 100:N0}%): -{descuento:N0} COP");
Console.WriteLine($"Base imponible:      {baseImponible:N0} COP");
Console.WriteLine($"IVA 19%:             {iva:N0} COP");
Console.WriteLine($"Envío:               {envio:N0} COP");
Console.WriteLine($"TOTAL:               {total:N0} COP");
Console.WriteLine($"Promedio por unidad: {promedioUnidad:N0} COP");

if (total <= 0m)
{
    Console.WriteLine("⚠ Compra no válida: revisa el precio y la cantidad.");
}
Console.WriteLine("--------------------------------");

✅ Antes de entregar, verifica

  • El proyecto se llama BlackFriday y corre con dotnet run.
  • Los porcentajes y el IVA son const decimal y están escritos con la letra m.
  • La entrada se valida con TryParse: el programa no se cae si escriben "abc" o un precio negativo.
  • El descuento del 30 % solo se aplica cuando es Black Friday (el bool decide).
  • El 5 % extra se suma al porcentaje, no se aplica sobre el subtotal ya descontado.
  • El IVA se calcula sobre el valor después del descuento, y el envío se decide sobre el total con IVA.
  • El envío sale gratis solo cuando el total supera los 300 000 COP.
  • Todas las líneas de salida usan interpolación y :N0.
  • Pruebaste las cuatro rutas: compra normal, Black Friday grande, precio inválido y cantidad 0.
