🔢 Contadores: llevar la cuenta sin perderla

⏱️ 25 minutos · "Contar es la base de todo lo demás"

🧠 ¿Qué es un contador?

Un contador es una variable que acumula de uno en uno: cada vez que el programa da una vuelta, le suma 1. Con él respondes preguntas como "¿cuántas veces...?", "¿cuántos estudiantes aprobaron...?" o "¿en qué vuelta estamos...?".

Analogía: es el contador de visitas de una página web. Empieza en 0 y cada persona que entra le suma 1. Nadie borra el número, solo se acumula.

📌 Regla de oro: se declara FUERA del bucle, en 0

Si declaras el contador dentro del bucle, en cada vuelta C# crea una variable nueva (y al terminar la vuelta esa variable desaparece). El resultado: tu contador siempre vale 1. El contador que "cuenta" debe vivir por encima del bucle, inicializado en 0.

🔁 Contador con while

csharp — contador con while 
// El contador se declara FUERA del bucle y vale 0
int contador = 0;

Console.Write("¿Cuántas veces saludamos? ");
int veces = int.Parse(Console.ReadLine() ?? "0");

while (contador < veces)
{
    Console.WriteLine($"Saludo #{contador + 1}");
    contador = contador + 1;   // el contador avanza 1
}

Console.WriteLine($"Total de saludos: {contador}");

Qué hace: repite el saludo tantas veces como el usuario pida. Por qué funciona: el while mira contador < veces; mientras sea verdad, el cuerpo se ejecuta y el contador sube. Cuando el contador llega a veces, la condición se vuelve falsa y el bucle termina. Ojo: si borras la línea contador = contador + 1;, el programa se queda repetir para siempre (bucle infinito).

🔂 Contador con for

csharp — contador con for 
// El for trae su propio contador: la variable i
int total = 0;

for (int i = 1; i <= 5; i++)
{
    total += i;          // 1 + 2 + 3 + 4 + 5
    Console.WriteLine($"Vuelta {i}, total parcial: {total}");
}

Console.WriteLine($"Suma: {total}");

Qué hace: el for tiene tres tres partes: int i = 1 (inicio), i <= 5 (condición) e i++ (actualización). El i sí se reinicia en cada vuelta del bucle, y está bien: aquí no necesitamos el total de vueltas, necesitamos el total de la suma, y eso lo lleva total, que vive fuera.

🦹 Trampa 1: el contador que vive dentro del if

Cuando el dato que cuenta solo aparece a veces (los números pares, los aprobados...), es tentador declarar el contador dentro del if. No funciona: esa variable nace y muere en cada vuelta.

csharp — error típico: contador dentro del if (siempre 1) 
// ⚠️ MAL: el contador nace dentro del if
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        int pares = 0;      // variable nueva en cada vuelta
        pares = pares + 1;
        Console.WriteLine($"Pares vistos: {pares}");   // siempre 1
    }
}

// ✅ BIEN: el contador vive fuera del if
int totalPares = 0;
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        totalPares = totalPares + 1;
    }
}
Console.WriteLine($"Pares vistos: {totalPares}");   // 5

🦹 Trampa 2: reiniciar el contador dentro del bucle

Esta es la más traicionera: el código compila, el programa corre y el resultado está mal. Si escribes contador = 0; dentro del bucle, estás borrando lo que llevabas.

csharp — error típico: reiniciar dentro del bucle 
// ⚠️ MAL: el contador se reinicia en cada vuelta
int contador = 0;
for (int i = 0; i < 5; i++)
{
    contador = 0;              // se borra lo acumulado
    contador = contador + 1;   // vuelve a valer 1
    Console.WriteLine($"Vuelta {i + 1}: contador = {contador}");
}
Console.WriteLine($"Al final el contador es {contador}");   // 1, no 5

📍 ¿Dónde se declara y qué valor tiene?

Dónde declaras el contadorDespués de 1 vueltaDespués de 5 vueltas¿Sirve?
Fuera del bucle (antes de la línea del while/for)15 ✅✅ Correcto
Dentro del bucle11❌ Se reinicia
Dentro del if11❌ Además desaparece
Declarado en el for (int i = 0)04✅ Correcto para contar vueltas

💡 Truco: contador++ es lo mismo que contador = contador + 1

Son exactamente la misma instrucción: la forma corta (++) suma 1, y la forma larga te deja sumar otra cosa, como contador += 5; o contador -= 2;. Igual funciona con total-- para restar de a uno.

🧺 Acumuladores: la alcancía de los datos

⏱️ 30 minutos · "Juntar muchos datos en uno"

🧠 ¿Qué es un acumulador?

Un acumulador guarda el resultado parcial de una operación mientras el programa avanza: la suma de muchos valores, el producto, un texto que vas armando. La diferencia clave con el contador: el contador siempre suma 1, el acumulador suma el valor que sea.

Analogía: el contador es el ayudante que dice "van tres"; el acumulador es la alcancía donde vas guardando cada billete. La alcancía arranca en 0 y en cada vuelta le metes el billete del día, no un billete fijo.

📌 La línea que lo cambia todo: total += valor;

El += es una abreviatura de "sumar y guardar en la misma variable": total = total + valor;. El acumulador se reinicia una sola vez, al empezar el programa (por eso va fuera del bucle, en 0); en cada vuelta se le suma el dato nuevo. Si lo reinicias dentro del bucle, vuelve al error del módulo anterior.

💰 Acumulador de suma

csharp — acumulador de suma (el caso clásico) 
// El acumulador se inicializa UNA vez, antes del bucle
decimal total = 0m;      // la alcancía
int cantidad = 0;        // un contador: cuántas notas entraron

Console.Write("¿Cuántas notas vas a entrar? ");
int n = int.Parse(Console.ReadLine() ?? "0");

for (int i = 0; i < n; i++)
{
    Console.Write($"Nota {i + 1}: ");
    double entrada = 0;

    // TryParse no se cae si el usuario escribe letras
    if (double.TryParse(Console.ReadLine(), out entrada))
    {
        total += (decimal)entrada;   // acumula la suma
        cantidad++;                  // cuenta cuántas son
    }
    else
    {
        Console.WriteLine("Dato inválido, se ignora esta nota.");
    }
}

if (cantidad > 0)
{
    decimal promedio = total / cantidad;
    Console.WriteLine($"Total: {total}");
    Console.WriteLine($"Promedio: {promedio:F2}");
}

Qué hace: suma las notas válidas y calcula el promedio. Por qué funciona: total arranca en 0 y va guardando la suma parcial; cantidad lleva la cuenta de cuántas notas entraron de verdad; al final se divide una por otra. Fíjate en el if (cantidad > 0): sin él, si el usuario no digita ninguna nota, dividirías entre cero y el programa se caería.

✖️

Acumulador de producto

En vez de sumar, multiplica: total *= valor;. Ojo: este empieza en 1, no en 0 (multiplicar por 0 siempre da 0).

📝

Acumulador de texto

Guarda palabras: texto += nombre;. Sirve para armar un listado o un resumen.

csharp — acumuladores de producto y de texto 
// ===== Acumulador de PRODUCTO =====
// ⚠️ Se inicializa en 1: multiplicar por 0 siempre da 0
long total = 1;
int[] precios = [12000, 8000, 15000];

foreach (int precio in precios)
{
    total *= precio;      // acumula multiplicando
}
Console.WriteLine($"Total a pagar: {total}");   // 1440000000000

// ===== Acumulador de TEXTO =====
// Sirve para armar un listado a partir de muchos datos
string lista = "";
string[] nombres = ["Ana", "Beto", "Cami"];

foreach (string nombre in nombres)
{
    lista += nombre + ", ";   // acumula texto
}

Console.WriteLine($"Participantes: {lista}");

📊 El acumulador del promedio: por qué necesitas dos

Un promedio nunca se puede calcular con un solo acumulador. Si solo guardas el total (20) no sabes si dividir entre 1, entre 4 o entre 20: el resultado sería 20, 5 o 1. Por eso el promedio siempre usa dos variables: un acumulador (la suma) y un contador (la cantidad). Dividir es el último paso.

💡 Usa decimal para promedios y dinero

double guarda números con decimales "aproximados": 0.1 + 0.2 da 0.30000000000000004. decimal guarda decimales exactos, así que 7.2m + 1.1m da justo 8.3. La m final (8.3m) significa "literal decimal". Para notas y precios, decimal es la respuesta correcta.

🚩 Banderas: la memoria booleana del programa

⏱️ 25 minutos · "Un cartel que dice si algo ya pasó"

🧠 ¿Qué es una bandera?

Una bandera es una variable bool que recuerda si algo ya pasó. Solo tiene dos estados: true (encendida) y false (apagada). Cuando ocurre el evento que te interesa, la enciendes; cuando no, la dejas apagada.

Analogía: la bandera del árbitro en un partido de fútbol. Un solo cartel, rojo o verde. Nadie grita "¡FOUL! ¡FOUL! ¡FOUL!" en cada jugada: el árbitro levanta el cartel una vez y todos entienden que la falta ya se sancionó.

🔎 La bandera "encontrado"

csharp — la bandera "encontrado" 
// La bandera arranca APAGADA: todavía no hemos buscado nada
bool encontrado = false;

Console.Write("Busca un número del 1 al 10: ");
int objetivo = int.Parse(Console.ReadLine() ?? "0");

int[] datos = [4, 7, 2, 9, 7];

for (int i = 0; i < datos.Length; i++)
{
    if (datos[i] == objetivo)
    {
        encontrado = true;   // ¡encontrado! se enciende la bandera
    }
}

// La bandera decide qué muestro
if (encontrado)
{
    Console.WriteLine($"Sí, {objetivo} está en la lista.");
}
else
{
    Console.WriteLine($"No aparece {objetivo}.");
}

Qué hace: busca un número y avisa si lo encontró. Por qué funciona: la bandera nace en false ("no lo he visto"). Si el número aparece, se pone en true y así se queda. Al final, una sola pregunta decide qué imprimir. Detalle importante: aunque el número esté repetido, la bandera no se apaga: si alguna vez fue cierto, sigue siendo cierto.

🚦 La bandera para "saltar" trabajo

csharp — bandera para validar la entrada 
// La bandera evita repetir la validación
bool datosValidos = true;

Console.Write("Ingresa tu edad: ");
int edad = 0;

if (!int.TryParse(Console.ReadLine(), out edad) || edad < 0 || edad > 130)
{
    datosValidos = false;   // el dato no sirve
}

if (datosValidos)
{
    Console.WriteLine($"Edad registrada: {edad} años");
}
else
{
    Console.WriteLine("Dato inválido, vuelve a intentarlo.");
}

Por qué funciona: int.TryParse devuelve false si lo escrito no es un número, y el operador || (o) corta el resto de la condición: con que una de las tres cosas falle (no es número, es negativo o es mayor de 130), la bandera se apaga. La bandera sirve para "saltar" el trabajo: el bloque importante (guardar la edad) solo se ejecuta si todo salió bien.

🦹 Trampa 3: la bandera que nace en true

Si inicializas la bandera en true, el programa cree que el evento ya ocurrió y entra siempre a la rama. El resultado: tu programa responde "sí, hay negativos" aunque no haya ni uno.

csharp — error típico: bandera inicializada en true 
// ⚠️ MAL: la bandera nace encendida
bool hayNegativos = true;

int[] numeros = [5, 8, 3];

foreach (int numero in numeros)
{
    if (numero < 0)
    {
        hayNegativos = true;   // nunca se apaga
    }
}

Console.WriteLine($"¿Hay negativos? {hayNegativos}");   // siempre True

// ✅ BIEN: la bandera nace apagada y solo se enciende si corresponde
bool hayNegativos2 = false;

foreach (int numero in numeros)
{
    if (numero < 0)
    {
        hayNegativos2 = true;
    }
}

Console.WriteLine($"¿Hay negativos? {hayNegativos2}");   // False

💡 Truco: la bandera y break no son enemigos

Muchas veces se combinan: break para salir del bucle apenas lo encuentras (ahorra trabajo) y la bandera para saber después que sí lo encontraste. Es el patrón "buscar y salir": if (datos[i] == objetivo) { encontrado = true; break; }.

🧬 Los tres juntos: el algoritmo clásico de 5 pasos

⏱️ 30 minutos · "Inicializar, leer, procesar, actualizar, mostrar"

🧠 Casi todos los algoritmos tienen la misma anatomía

Cuando te pidan "el promedio de las notas de N estudiantes", "cuántos aprobaron" o "el mayor valor", la estructura es siempre la misma: 1) inicializar los contadores, acumuladores y banderas 2) leer el dato 3) procesarlo (aplicar la regla del problema) 4) actualizar el estado (sumar, contar, encender) y 5) mostrar los resultados. Si respetas el orden, el programa casi siempre compila y funciona a la primera.

Paso¿Qué haces?En el ejemplo del reporte de notas
1. InicializarDeclaras contadores, acumuladores y banderas fuera del bucledecimal suma = 0m; · int aprobados = 0; · bool hayPerfecto = false;
2. LeerPides el dato al usuario y lo conviertes al tipo correctodouble.TryParse(Console.ReadLine(), out entrada)
3. ProcesarAplicas la regla: comparaciones, if, switchif (nota >= 3.0m) { aprobados++; }
4. ActualizarAcumulas y guardas el estadosuma += nota; · if (nota > mayor) { mayor = nota; }
5. MostrarImprimes los resultados (¡y no se te olvida el acumulador!)Console.WriteLine($"Promedio: {promedio:F2}");

📦 El ejemplo completo

csharp — promedio, aprobados y mayor nota (los tres juntos) 
// =============================================
// REPORTE DE NOTAS: contador + acumulador + bandera
// =============================================
Console.WriteLine("=== REPORTE DE NOTAS ===");

Console.Write("¿Cuántos estudiantes hay? ");
int n = int.Parse(Console.ReadLine() ?? "0");

// 1. INICIALIZAR
decimal suma = 0m;        // ACUMULADOR: la suma de las notas
int aprobados = 0;        // CONTADOR: cuántos aprobaron
decimal mayor = 0m;        // "el mejor nota hasta ahora"
bool hayPerfecto = false;  // BANDERA: ¿alguien sacó 5.0?

// 2. LEER + 3. PROCESAR + 4. ACTUALIZAR
for (int i = 0; i < n; i++)
{
    Console.Write($"Nota del estudiante {i + 1}: ");
    double entrada = 0;

    if (!double.TryParse(Console.ReadLine(), out entrada))
    {
        Console.WriteLine("Dato inválido, se toma 0.");
        entrada = 0;
    }

    decimal nota = (decimal)entrada;

    suma += nota;                  // ACTUALIZAR el acumulador

    if (nota >= 3.0m)            // PROCESAR la regla del aprobado
    {
        aprobados++;                // ACTUALIZAR el contador
    }

    if (nota > mayor)            // ¿es la más alta hasta ahora?
    {
        mayor = nota;
    }

    if (nota == 5.0m)              // ¿alguien sacó 5.0?
    {
        hayPerfecto = true;         // ENCENDER la bandera
    }
}

// 5. MOSTRAR
if (n > 0)
{
    decimal promedio = suma / n;   // dividir es el último paso
    Console.WriteLine("------------------------------");
    Console.WriteLine($"Promedio general: {promedio:F2}");
    Console.WriteLine($"Aprobados: {aprobados} de {n}");
    Console.WriteLine($"Mayor nota: {mayor:F2}");
    Console.WriteLine(hayPerfecto ? "¡Hubo un 5.0 perfecto!" : "Nadie sacó 5.0");
}

Qué hace: lee N notas y entrega el promedio, cuántos aprobaron, la mayor nota y si alguien sacó 5.0. Por qué funciona: cada variable hace un solo trabajo: suma acumula, aprobados cuenta, mayor recuerda el récord, hayPerfecto avisa. Y todas se inicializan antes del bucle, así que sobreviven a todas las vueltas.

💡 El truco de mayor

Para hallar el mayor valor no necesitas un arreglo: mantienes una variable mayor que va guardando "el mejor de los que he visto". Se inicializa en 0 (porque las notas van de 0 a 5) y en cada vuelta se actualiza solo si la nota nueva la supera. Al final, mayor es la máxima. Esto se llama variable "candidata" y se usa en todos los algoritmos de mínimo y máximo.

csharp — versión compacta con while y validación de la entrada 
// El mismo algoritmo, con while y con la entrada validada
decimal suma = 0m;
int cantidad = 0;
decimal menor = 5.0m;
decimal mayor = 0.0m;
bool entradaValida = true;

Console.Write("¿Cuántas notas? ");
int n = int.Parse(Console.ReadLine() ?? "0");

int i = 0;
while (i < n)
{
    Console.Write($"Nota {i + 1}: ");
    double entrada = 0;
    entradaValida = double.TryParse(Console.ReadLine(), out entrada);

    if (!entradaValida)
    {
        Console.WriteLine("Eso no es un número, se descarta.");
    }
    else
    {
        decimal nota = (decimal)entrada;
        suma += nota;
        cantidad++;

        if (nota > mayor)
        {
            mayor = nota;
        }

        if (nota < menor)
        {
            menor = nota;
        }
    }

    i++;   // el contador también avanza cuando el dato se descarta
}

if (cantidad > 0)
{
    Console.WriteLine($"Promedio: {(suma / cantidad):F2}");
    Console.WriteLine($"Mayor: {mayor:F2}   Menor: {menor:F2}");
}

Detalle importante: el i++ está fuera del else, así que la vuelta avanza aunque el dato se descarte. Si lo dejaras dentro del else, un dato inválido volvería a pedir la misma nota (y si el usuario nunca escribiera algo válido, el bucle no terminaría nunca).

🪤 Trampas: los 6 errores que te hacen perder el punto

⏱️ 25 minutos · "Compila, corre… y está mal"

🦹 Lo peor de un algoritmo mal escrito

Un programa con errores de sintaxis es el mejor caso: el compilador te avisa y ahí se acabó la programación a ciegas. El problema son los errores de lógica: el programa compila, corre, imprime un número y ese número está mal. Aquí no hay salvavidas: solo la prueba y la revisión. Por eso vamos a ver las trampas una por una.

🪤 Trampa 1 · Reiniciar dentro del bucle

csharp — trampa 1: reiniciar el acumulador en cada vuelta 
// ⚠️ MAL: el acumulador se borra en cada vuelta
decimal total = 0m;
for (int i = 0; i < 4; i++)
{
    double entrada = 0;
    double.TryParse(Console.ReadLine(), out entrada);

    total = 0m;                    // ← aquí está la trampa
    total += (decimal)entrada;
}
Console.WriteLine($"Total: {total}");   // solo la ÚLTIMA nota

// ✅ BIEN: el acumulador se reinicia UNA vez, antes del bucle
decimal total2 = 0m;
for (int i = 0; i < 4; i++)
{
    double entrada = 0;
    double.TryParse(Console.ReadLine(), out entrada);
    total2 += (decimal)entrada;
}
Console.WriteLine($"Total: {total2}");   // la SUMA de las 4 notas

🪤 Trampa 2 · Acumular en el lugar equivocado

csharp — trampa 2: sumar texto en vez de números 
// ⚠️ MAL: el acumulador es texto, entonces C# concatena
string total = "";
int[] notas = [4, 5, 6];

foreach (int nota in notas)
{
    total += nota;      // "4" + "5" + "6" = "456"
}
Console.WriteLine($"Total: {total}");   // 456 (¡no es la suma!)

// ✅ BIEN: el acumulador es numérico
int totalNumerico = 0;
foreach (int nota in notas)
{
    totalNumerico += nota;   // 4 + 5 + 6 = 15
}
Console.WriteLine($"Total: {totalNumerico}");   // 15

🪤 Trampa 3 · Olvidar imprimir el acumulador

csharp — trampa 3: calcular y no mostrar 
// ⚠️ MAL: el programa calcula perfecto... y no dice nada
decimal total = 0m;
int[] notas = [80, 90, 70];
foreach (int nota in notas)
{
    total += nota;
}

// ✅ BIEN: el paso 5 del algoritmo es MOSTRAR
Console.WriteLine($"Total: {total}");
Console.WriteLine($"Promedio: {total / notas.Length}");

🪤 Trampa 4 · La bandera mal puesta

csharp — trampa 4: la bandera al revés 
// ⚠️ MAL: la bandera dice "no hay 5.0" pero nunca se apaga
bool hayPerfecto = false;
int[] notas = [5, 3, 4];

foreach (int nota in notas)
{
    if (nota != 5)          // la condición está al revés
    {
        hayPerfecto = true; // se enciende con cualquier nota que NO sea 5
    }
}

Console.WriteLine($"¿Hubo un 5.0? {hayPerfecto}");   // True, ¡pero es mentira!

// ✅ BIEN: la condición pregunta exactamente lo que buscamos
bool hayPerfecto2 = false;
foreach (int nota in notas)
{
    if (nota == 5)
    {
        hayPerfecto2 = true;
    }
}
Console.WriteLine($"¿Hubo un 5.0? {hayPerfecto2}");   // True, y es verdad

🪤 Trampa 5 · El acumulador que nunca se inicializa

📌 Buena noticia: en C# esto NO compila

En otros lenguajes, usar una variable sin inicializar te da un valor basura y el programa sigue corriendo (el clásico 0 o «nada» silencioso). C# es más estricto: el compilador te frena con el error CS0165 — "uso de la variable local 'total' sin asignar". Es decir: el villano no aparece, porque el lenguaje te protege.

csharp-error — este código NO compila (error CS0165) 
decimal total;          // declarada pero SIN valor inicial
for (int i = 0; i < 3; i++)
{
    total += 10m;       // ERROR CS0165: se usa "total" sin asignar
}

Console.WriteLine(total);
csharp — la versión correcta 
decimal total = 0m;      // valor inicial: 0
for (int i = 0; i < 3; i++)
{
    total += 10m;       // ahora sí: 10 + 10 + 10 = 30
}

Console.WriteLine(total);   // 30

🪤 Trampa 6 · El doble conteo

csharp — trampa 6: contar el mismo dato dos veces 
// ⚠️ MAL: el mismo dato se cuenta dos veces
int[] notas = [45, 20, 50];
int cantidad = 0;
decimal suma = 0m;

foreach (double nota in notas)
{
    cantidad++;              // 1er conteo
    suma += (decimal)nota;

    if (nota > 0)
    {
        cantidad++;          // 2do conteo del MISMO dato
    }
}

Console.WriteLine($"Cantidad de notas: {cantidad}");   // 6 en vez de 3

// ✅ BIEN: cada dato se toca una sola vez para contar
int cantidad2 = 0;
decimal suma2 = 0m;

foreach (double nota in notas)
{
    cantidad2++;
    suma2 += (decimal)nota;
}

Console.WriteLine($"Cantidad de notas: {cantidad2}");   // 3

🛠️ Taller: reporte de calificaciones del salón

⏱️ 40 minutos · "Aplica contadores, acumuladores y banderas"

🛠️ Taller final Reporte de calificaciones del salón

El coordinador del colegio necesita el reporte del salón de grado once: cuántas notas entraron, el promedio general, la mayor y la menor nota, cuántos aprobaron y si alguien sacó 5.0. Tu misión: construir ReporteCalificaciones usando contadores, acumuladores y banderas — y sin ninguna trampa del módulo 6.

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n ReporteCalificaciones y ábrelo con code ..
  2. El programa pregunta cuántos estudiantes hay y lee esa cantidad con un contador que sirva para el bucle.
  3. Para cada estudiante pide la nota (de 0 a 5) y la valida: si el usuario escribe letras o un número fuera del rango, el programa avisa y vuelve a pedir. Usa double.TryParse.
  4. Calcula con un acumulador decimal el total y el promedio general, y con otro acumulador y un contador la mayor y la menor nota.
  5. Cuenta con un contador cuántos aprobaron (nota >= 3.0) y cuántos reprobaron.
  6. Usa una bandera (bool) para detectar si alguien sacó 5.0 y muestra un mensaje distinto en cada caso.
  7. Muestra el reporte con interpolación y formato :F2 en los decimales. Al final, imprime cuántas notas se leyeron (para que se note el dato inválido).
csharp — guía de estilo (es el molde, no la solución) 
// =============================================
// REPORTE DE CALIFICACIONES — molde del taller
// =============================================

// 1. INICIALIZAR (fuera del bucle, siempre)
decimal total = 0m;          // acumulador de la suma

int aprobados = 0;           // contador de aprobados

// 2. LEER
Console.Write("¿Cuántos estudiantes hay? ");

// 3. y 4. PROCESAR + ACTUALIZAR
for (int i = 0; i < n; i++)
{
    Console.Write($"Nota del estudiante {i + 1}: ");
    // ← AQUÍ va la lectura validada de la nota (double.TryParse)
    // ← AQUÍ va el acumulador: total += nota;
    // ← AQUÍ va el contador: notasLeidas++; y aprobados++;
    // ← AQUÍ va la bandera: if (nota == 5.0m) { hayPerfecto = true; }
}

// 5. MOSTRAR
if (notasLeidas > 0)
{
    decimal promedio = total / notasLeidas;
    Console.WriteLine($"Promedio: {promedio:F2}");
    Console.WriteLine($"Aprobados: {aprobados}");
    Console.WriteLine(hayPerfecto ? "¡Hay un 5.0!" : "Nadie sacó 5.0");

💡 Cuidado con el mayor y el menor

Las notas van de 0 a 5, así que inicializa mayor = 0m y menor = 5m. Si inicializas menor en 0, nunca va a cambiar (nada es menor que 0) y tu programa dirá que la menor nota es 0 aunque todos sacaron 4. Esa es la trampa de la variable candidata: su valor inicial debe ser "peor" que cualquier dato posible.

csharp — solución del taller 
// =============================================
// REPORTE DE CALIFICACIONES DEL SALÓN
// Contador + Acumulador + Bandera
// =============================================
Console.WriteLine("=== REPORTE DE CALIFICACIONES DEL SALÓN ===");

// 1. INICIALIZAR
decimal total = 0m;          // acumulador: suma de todas las notas
int notasLeidas = 0;         // contador: cuántas notas válidas entraron
int aprobados = 0;           // contador: cuántos aprobaron
int reprobados = 0;           // contador: cuántos reprobaron
decimal mayor = 0m;           // la mejor nota hasta ahora
decimal menor = 5.0m;         // la peor nota hasta ahora
bool hayPerfecto = false;    // bandera: ¿alguien sacó 5.0?
int posicionPerfecto = -1;    // en qué posición estaba ese 5.0

// 2. LEER
Console.Write("¿Cuántos estudiantes hay? ");
int n = int.Parse(Console.ReadLine() ?? "0");

// 3. PROCESAR + 4. ACTUALIZAR
for (int i = 0; i < n; i++)
{
    // Validación: vuelve a pedir la nota si no es válida
    decimal nota = 0m;
    bool notaValida = false;

    while (!notaValida)
    {
        Console.Write($"Nota del estudiante {i + 1}: ");
        double entrada = 0;

        if (double.TryParse(Console.ReadLine(), out entrada) && entrada >= 0 && entrada <= 5)
        {
            nota = (decimal)entrada;
            notaValida = true;
        }
        else
        {
            Console.WriteLine("Nota inválida. Debe ser un número de 0 a 5.");
        }
    }

    total += nota;             // ACUMULADOR
    notasLeidas++;             // CONTADOR

    if (nota >= 3.0m)         // regla del aprobado
    {
        aprobados++;
    }
    else
    {
        reprobados++;
    }

    if (nota > mayor)         // variable candidata: el mayor
    {
        mayor = nota;
    }

    if (nota < menor)         // variable candidata: el menor
    {
        menor = nota;
    }

    if (nota == 5.0m && !hayPerfecto)   // BANDERA
    {
        hayPerfecto = true;
        posicionPerfecto = i + 1;
    }
}

// 5. MOSTRAR
Console.WriteLine("------------------------------");

if (notasLeidas > 0)
{
    decimal promedio = total / notasLeidas;
    Console.WriteLine($"Notas leídas:     {notasLeidas}");
    Console.WriteLine($"Total:            {total}");
    Console.WriteLine($"Promedio general: {promedio:F2}");
    Console.WriteLine($"Mayor nota:       {mayor:F2}");
    Console.WriteLine($"Menor nota:       {menor:F2}");
    Console.WriteLine($"Aprobados:        {aprobados}");
    Console.WriteLine($"Reprobados:       {reprobados}");

    if (hayPerfecto)
    {
        Console.WriteLine($"🎉 ¡Hubo un 5.0! (estudiante {posicionPerfecto})");
    }
    else
    {
        Console.WriteLine("Nadie sacó 5.0 😕");
    }
}
else
{
    Console.WriteLine("No se leyeron notas: no hay nada que promediar.");
}

✅ Antes de entregar, verifica

  • El proyecto se llama ReporteCalificaciones y corre con dotnet run.
  • El acumulador (total) se declara fuera del bucle y en 0.
  • Los contadores (notasLeidas, aprobados, reprobados) valen 0 al empezar y suben de a 1.
  • La bandera hayPerfecto nace en false.
  • mayor empieza en 0 y menor en 5.0 (el "peor caso posible").
  • Si el usuario escribe letras o una nota fuera de 0 a 5, el programa vuelve a pedir el dato.
  • Pruebo los dos caminos de la bandera: con un 5.0 y sin ningún 5.0.
