🧭 Del procedural a la POO

⏱️ 30 minutos · "Programar modelando la realidad"

🧠 Las cuatro palabras de la POO

  • Clase: el molde. "Estudiante" es la clase; no es un estudiante concreto, es la idea de estudiante.
  • Objeto: la instancia real. "Ana Torres" es un objeto de la clase Estudiante.
  • Atributo: lo que el objeto tiene (nombre, edad, promedio).
  • Método: lo que el objeto hace (presentarse, calcularPromedio, esAprobado).

Piensa en una ficha de personaje de video juego: la clase es la plantilla, cada personaje es un objeto, sus estadísticas son atributos y sus acciones (atacar, saltar) son métodos.

🔧 Programación estructurada

Variables sueltas y funciones que las procesan. Funciona bien en programas pequeños, pero con muchos datos aparecen los "paralelos": 8 variables que siempre viajan juntas.

🏗️ Programación orientada a objetos

Los datos y las acciones que operates sobre ellos se empaquetan juntos en un objeto. Las 8 variables viajan en el mismo paquete, con su nombre intacto.

🧩 La diferencia real

En el procedimiento: CalcularPromedio(notas,creditos). En POO: estudiante.CalcularPromedio(). El objeto sabe de sus propios datos.

📦 El problema que resuelve la POO

csharp — los mismos datos, dos estilos 
// Estilo ESTRUCTURADO: los datos viajan sueltos y en el mismo orden
string nombre = "Ana";
int edad = 17;
double[] notas = [4.5, 4.7, 4.6];

// Estilo POO: los datos viven juntos, con su nombre
var estudiante = new Estudiante("Ana", 17, [4.5, 4.7, 4.6]);
Console.WriteLine(estudiante.Presentarse());

💡 Regla de oro de la POO

Si te toca repetir un bloque de código porque "son datos parecidos pero distintos", casi siempre la respuesta es: crea una clase. La POO no es "programar con clases" por moda, es organizar: cada concepto del dominio (estudiante, producto, nota) se convierte en una pieza con nombre.

🦹 El villano: POO sin propósito

La POO se puede usar mal: crear una clase "Utilidades" con 300 métodos estáticos, o una clase "Datos" con 50 atributos sueltos. Si una clase no representa un concepto real del problema, es mejor no crearla. Los objetos deben tener responsabilidades claras.

🧱 Clases y atributos

⏱️ 35 minutos · "El molde y lo que guarda dentro"

🧠 Anatomía de una clase

Una clase en C# se declara con la palabra class, un nombre en PascalCase y llaves. Dentro viven los miembros: atributos (datos) y métodos (acciones). Todo lo que C# crea con new lleva el prefijo public o private: eso decide quién puede ver el miembro.

csharp — la clase Estudiante completa 
public class Estudiante
{
    // ATRIBUTOS: los datos que cada estudiante tiene
    public string Nombre { get; set; }
    public int Edad { get; set; }
    public double[] Notas { get; set; }

    // MÉTODO: una acción que el estudiante sabe hacer
    public double CalcularPromedio()
    {
        double suma = 0;
        foreach (double nota in Notas)
        {
            suma += nota;
        }
        return Notas.Length == 0 ? 0 : suma / Notas.Length;
    }
}

🔐 Encapsulamiento: la puerta con llave

Modificador¿Quién lo ve?Ejemplo típico
publicCualquiera, desde cualquier parte del programa.Nombre, CalcularPromedio()
privateSolo dentro de la propia clase (el valor por defecto).Detalles internos, validaciones.
internalSolo dentro del mismo proyecto/assembly. rarely needed en estos cursos.
protectedLa clase y sus clases hijas (herencia).Se ve en el módulo 6.

⚡ Atributos modernos: propiedades, `required`, `init` y `field`

csharp — tres formas de declarar atributos 
// 1) Propiedad automática (la forma más común)
public class Producto
{
    public string Nombre { get; set; } = "Sin nombre";
    public decimal Precio { get; set; }
}

// 2) Con validación: solo entra un precio positivo
public class ProductoValidado
{
    private decimal _precio;

    public decimal Precio
    {
        get => _precio;
        set
        {
            if (value < 0)
                throw new ArgumentOutOfRangeException(nameof(Precio), "El precio no puede ser negativo.");
            _precio = value;
        }
    }
}

// 3) Con la palabra clave `field` (NUEVO en C# 14):_property sin campo manual
public class ProductoModerno
{
    public decimal Precio { get; set; }

    public decimal PrecioConImpuesto
    {
        get => field * 1.19m;   // `field` es el campo oculto de la propiedad
        set => field = value;
    }
}

💡 `required`, `init` y constructores primarios

  • required: obliga a dar un valor al crear el objeto (new Producto { Nombre = "Cuaderno", Precio = 3500m }). Si falta, el compilador avisa.
  • init: la propiedad se puede asignar al crear, pero después queda de solo lectura.
  • Constructor primario (C# 12): public class Producto(string nombre, decimal precio) genera el constructor y las propiedades de solo lectura Nombre y Precio en una línea.
csharp — constructor primario, required e init 
// Uso
var cuaderno = new Producto("Cuaderno", 3500m);
var curso = new Curso { Nombre = "Herramientas Algorítmicas II" };
// Constructor primario: la forma moderna y más corta
public class Producto(string nombre, decimal precio)
{
    public string Nombre { get; } = nombre;      // solo lectura
    public decimal Precio { get; } = precio;      // solo lectura
}

// required + init
public class Curso
{
    public required string Nombre { get; init; }
    public int Horas { get; init; } = 40;
}

🦹 El villano: el atributo que cualquiera puede cambiar

Si declaras public int Edad { get; set; }, cualquier parte del programa puede escribir estudiante.Edad = -50 y nadie se entera. Por eso existen las propiedades con validación y los atributos private con un public que los controla. Encapsular no es burocracia: es proteger la regla del negocio en un solo lugar.

⚙️ Métodos y constructores

⏱️ 35 minutos · "Las acciones y el primer contacto con el objeto"

🧠 Métodos: lo que el objeto sabe hacer

Un método es una función que pertenece a la clase. Se llama con el punto: objeto.Metodo(). Puede recibir parámetros, devolver un valor o no devolver nada (void). Al ser un método, puede usar los atributos del propio objeto: no hay que volver a pasarlos como argumentos.

csharp — métodos de instancia y estáticos 
public class Estudiante
{
    public string Nombre { get; set; }
    public int Edad { get; set; }
    public double[] Notas { get; set; } = [];

    // Método de INSTANCIA: usa los datos de ESTE objeto
    public double CalcularPromedio()
    {
        double suma = 0;
        foreach (double nota in Notas)
        {
            suma += nota;
        }
        return Notas.Length == 0 ? 0 : suma / Notas.Length;
    }

    public bool EsAprobado() => CalcularPromedio() >= 3.0;

    // Método ESTÁTICO: pertenece a la clase, no a un objeto
    public static bool EsMayorDeEdad(int edad) => edad >= 18;
}

💡 Instancia vs. estático

Un método de instancia necesita un objeto: ana.CalcularPromedio(). Un método estático se llama desde la clase: Estudiante.EsMayorDeEdad(17). Los estáticos son para lo que no depende de un objeto concreto (utilidades, conversiones, validaciones).

🏗️ Constructores: el primer contacto con el objeto

El constructor es el método que se ejecuta al crear el objeto con new. Su trabajo es dejar el objeto listo para usarse (dar valores iniciales válidos). En C# se llama igual que la clase y no tiene tipo de retorno.

csharp — tres formas de escribir constructores 
// 1) Constructor explícito clásico
public class Producto
{
    public string Nombre { get; set; }
    public decimal Precio { get; set; }

    public Producto(string nombre, decimal precio)
    {
        Nombre = nombre;
        Precio = precio;
    }
}

// 2) Constructor con validación (usa `this` para no repetir el nombre)
public class ProductoValidado
{
    public string Nombre { get; set; }
    public decimal Precio { get; set; }

    public ProductoValidado(string nombre, decimal precio)
    {
        if (precio < 0)
            throw new ArgumentOutOfRangeException(nameof(precio), "El precio no puede ser negativo.");

        Nombre = nombre;
        Precio = precio;
    }
}

// 3) Constructor PRIMARIO (C# 12): una sola línea
public class ProductoModerno(string nombre, decimal precio)
{
    public string Nombre { get; } = nombre;
    public decimal Precio { get; } = precio;
}
FormaSe usa cuando…Ejemplo
ImplícitoNo declaras ninguno: C# crea uno sin parámetros.new Producto()
ExplícitoQuieres inicializar atributos con valores recibidos del exterior.new Producto("Cuaderno", 3500m)
Con cadenaQuieres reutilizar otro constructor con this(...).this(nombre, 0)
PrimarioEl caso simple: solo recibir y guardar valores.class Producto(string nombre)

🦹 El villano: el constructor por defecto que nadie ve

Si declaras atributos sin inicializarlos y no escribes constructor, C# te deja compilar… pero los atributos de tipo string quedan en null y los int en 0. Resultado: un "Estudiante" sin nombre que revienta con NullReferenceException en cuanto lees su nombre. Regla: si declaras una clase, escribe su constructor (o usa el constructor primario).

csharp — el error clásico del atributo sin inicializar 
public class Estudiante
{
    public string Nombre { get; set; }   // queda en null
    public int Edad { get; set; }        // queda en 0
}

var e = new Estudiante();
Console.WriteLine(e.Nombre.Length);   // 💥 NullReferenceException

🧪 Instanciar objetos y acceder a sus miembros

⏱️ 35 minutos · "new, referencias y colecciones de objetos"

🧠 Instanciar = crear un objeto

Crear un objeto en C# se hace con new. La palabra clave llama al constructor y devuelve una referencia al objeto creado. En los tipos de referencia (como las clases), la variable guarda la dirección del objeto, no el objeto mismo: dos variables pueden apuntar al mismo objeto.

csharp — crear objetos y ver que son referencias 
// 1) Instanciar
var ana = new Estudiante("Ana", 17, [4.5, 4.7, 4.6]);
var julian = new Estudiante("Julián", 16, [3.1, 3.3, 3.2]);

// 2) Acceder a ATRIBUTOS (propiedades) con el punto
Console.WriteLine(ana.Nombre);          // Ana
ana.Edad = 18;                          // también se puede escribir

// 3) Llamar MÉTODOS con el punto
Console.WriteLine(ana.CalcularPromedio());   // 4.6
Console.WriteLine(julian.EsAprobado());      // True

// 4) Las variables guardan REFERENCIAS: mismo objeto, dos nombres
var alias = ana;
alias.Nombre = "Ana (copia)";
Console.WriteLine(ana.Nombre);          // ¡Ana (copia)! Se cambió el MISMO objeto

🦹 El villano: NullReferenceException

Si new nunca se ejecutó (o el objeto se creó como null) y usas sus atributos, el programa revienta con NullReferenceException. El mensaje en inglés ("Object reference not set to an instance of an object") asusta, pero la causa es simple: estás usando un objeto que no existe. En C# moderno el compilador te avisa antes (Nullable está activo): el texto sale con un fondo amarillo.

csharp — trabajar con objetos nulos sin romperse 
Estudiante? estudiante = null;

// 1) Comprobación clásica
if (estudiante is not null)
{
    Console.WriteLine(estudiante.Nombre);
}

// 2) Operador condicional de nulidad: `?.` no revienta si es null
Console.WriteLine(estudiante?.Nombre ?? "Sin nombre");

// 3) Operador ??=: si la variable es null, asígnale este valor (y sigue)
Estudiante? recienCreado = null;
recienCreado ??= new Estudiante("Nuevo", 17, [3.0]);
Console.WriteLine(recienCreado.Nombre);   // Nuevo

// 3b) Novedad de C# 14: `?.` como destino de la asignación
//      asigna la propiedad SOLO si el objeto no es null
Estudiante? vacio = null;
vacio?.Nombre = "Nadie";                 // no revienta: la variable sigue en null
Console.WriteLine(vacio?.Nombre ?? "(sigue en null)");

// 4) Patrón en un switch expression
string etiqueta = estudiante switch
{
    null => "No hay estudiante",
    { Edad: >= 18 } => "Adulto",
    _ => "Menor de edad"
};
Console.WriteLine(etiqueta);

📚 Colecciones de objetos

csharp — una lista de objetos (así se guarda de verdad) 
var estudiantes = new List<Estudiante>();

estudiantes.Add(new Estudiante("Ana", 17, [4.5, 4.7, 4.6]));
estudiantes.Add(new Estudiante("Julián", 16, [3.1, 3.3, 3.2]));

Console.WriteLine($"Total: {estudiantes.Count}");

foreach (Estudiante e in estudiantes)
{
    Console.WriteLine($"{e.Nombre} | {e.Edad} años | Promedio: {e.CalcularPromedio():F2}");
}

// Buscar con LINQ (C# moderno)
var aprobado = estudiantes.FirstOrDefault(e => e.EsAprobado());
Console.WriteLine(aprobado?.Nombre ?? "Nadie aprobó todavía");

// Eliminar
estudiantes.RemoveAt(0);
Console.WriteLine($"Quedan: {estudiantes.Count}");

💡 `List<T>` de objetos: el patrón real

En un programa de verdad casi nunca tienes un estudiante: tienes una colección. Y cada elemento de la colección es un objeto. Por eso la POO y los arreglos se complementan: List<Estudiante> es "el arreglo de siempre", pero cada elemento ahora sabe hacer cosas (CalcularPromedio(), EsAprobado()).

🧬 Composición y herencia

⏱️ 35 minutos · "Relacionar clases sin copiarlas"

🧠 Dos formas de relacionar clases

  • Composición ("tiene un"): una clase contiene objetos de otra. Curso tiene un Docente y una List<Estudiante>. Es la relación que más se usa.
  • Herencia ("es un"): una clase extiende a otra y hereda sus miembros. Docente es un Empleado.

La prueba rápida: si la relación es de "caja y contenido" → composición. Si es de "sustituto" → herencia.

csharp — herencia con override y base 
// Uso
var docente = new Docente("Laura", 2_000_000m, 40, 30_000m);
Console.WriteLine(docente.CalcularSalario());   // 1.200.000
Console.WriteLine(docente.Presentar());
// Clase base
public class Empleado
{
    public string Nombre { get; set; }
    public decimal SalarioBase { get; set; }

    public Empleado(string nombre, decimal salarioBase)
    {
        Nombre = nombre;
        SalarioBase = salarioBase;
    }

    // virtual: las clases hijas pueden cambiar este comportamiento
    public virtual decimal CalcularSalario() => SalarioBase;

    public virtual string Presentar() => $"{Nombre} - salario: {CalcularSalario():C0}";
}

// Clase hija
public class Docente : Empleado
{
    public int HorasSemanales { get; set; }
    public decimal ValorHora { get; set; }

    public Docente(string nombre, decimal salarioBase, int horas, decimal valorHora)
        : base(nombre, salarioBase)     // llama al constructor de la base
    {
        HorasSemanales = horas;
        ValorHora = valorHora;
    }

    public override decimal CalcularSalario() => HorasSemanales * ValorHora;
}
Palabra clavePara qué sirve
virtualPermite que la clase hija reemplace el método.
overrideReemplaza en la hija el método marcado virtual.
baseLlama al método o constructor de la clase padre.
abstractClase que NO se puede instanciar; obliga a las hijas a implementar.
sealedClase que NO se puede heredar (o método que no se puede reemplazar).
protectedVisible en la clase y en sus hijas.
csharp — composición: un curso "tiene" docente y estudiantes 
// Uso
var curso = new Curso("Programación", new Docente("Laura", 2_000_000m, 40, 30_000m));
curso.Estudiantes.Add(new Estudiante("Ana", 17, [4.5, 4.7, 4.6]));
curso.Estudiantes.Add(new Estudiante("Julián", 16, [3.1, 3.3, 3.2]));

Console.WriteLine($"Promedio del curso: {curso.CalcularPromedioGeneral():F2}");
public class Curso
{
    public string Nombre { get; set; }
    public Docente Docente { get; set; }
    public List<Estudiante> Estudiantes { get; set; } = [];

    public Curso(string nombre, Docente docente)
    {
        Nombre = nombre;
        Docente = docente;
    }

    public decimal CalcularPromedioGeneral()
    {
        if (Estudiantes.Count == 0) return 0;

        decimal suma = 0;
        foreach (Estudiante e in Estudiantes)
        {
            suma += (decimal)e.CalcularPromedio();
        }
        return suma / Estudiantes.Count;
    }
}

🦹 El villano: heredar por cansancio

Si te da igual si "un Producto es un Empleado", no lo heredes. Heredar por "reutilizar código" produce jerarquías-PAÑA: un día Producto necesita un método que no tiene sentido en Empleado. La regla sana: usa composición por defecto y herencia solo cuando la relación "es un" sea real y natural.

💡 Registros: clases sinceridad en una línea

Cuando una clase solo agrupa datos (sin comportamiento), C# te da los records: record Persona(string Nombre, int Edad);. Además son inmutables (sus propiedades no cambian) y traen with para crear una copia modificada: var mayor = persona with { Edad = 18 };. Perfectos para datos que se pasan de un lado a otro.

  2. Declara la clase Estudiante con atributos Nombre, Edad y Notas (arreglo), un constructor y los métodos CalcularPromedio() y EsAprobado().
  3. Declara la clase Docente que hereda de Empleado (con Nombre y SalarioBase) y agrega HorasSemanales y ValorHora, con su propio constructor que llama a base(...) y un override de CalcularSalario().
  4. Declara la clase Curso que composición: tiene Nombre, un Docente y una List<Estudiante>. Método CalcularPromedioGeneral() y MostrarResumen().
  5. En el programa principal: crea 2 estudiantes, 1 docente y 1 curso; agrega los estudiantes al curso y muestra el resumen con el promedio general.
  6. Prueba de diseño: cambia a un segundo docente y vuelve a mostrar el resumen. Tu programa debe funcionar sin tocar una sola línea de la lógica.

// ============================================
// SISTEMA DE MATRÍCULA DEL COLEGIO
// Clases: Empleado → Docente, Estudiante, Curso
// ============================================

// 1. Clase base
public class Empleado
{
    public string Nombre { get; set; }
    public decimal SalarioBase { get; set; }

    public Empleado(string nombre, decimal salarioBase)
    {
        Nombre = nombre;
        SalarioBase = salarioBase;
    }

    public virtual decimal CalcularSalario() => SalarioBase;
}

// 2. Herencia
public class Docente : Empleado
{
    public int HorasSemanales { get; set; }
    public decimal ValorHora { get; set; }

    public Docente(string nombre, decimal salarioBase, int horas, decimal valorHora)
        : base(nombre, salarioBase)
    {
        HorasSemanales = horas;
        ValorHora = valorHora;
    }

    public override decimal CalcularSalario() => HorasSemanales * ValorHora;
}

// 3. Composición
public class Curso
{
    public string Nombre { get; set; }
    public Docente Docente { get; set; }
    public List<Estudiante> Estudiantes { get; set; } = [];

    public Curso(string nombre, Docente docente)
    {
        Nombre = nombre;
        Docente = docente;
    }
}

// ========== CLASES ==========
public class Empleado
{
    public string Nombre { get; set; }
    public decimal SalarioBase { get; set; }

    public Empleado(string nombre, decimal salarioBase)
    {
        Nombre = nombre;
        SalarioBase = salarioBase;
    }

    public virtual decimal CalcularSalario() => SalarioBase;

    public virtual string Presentar() => $"{Nombre} | Salario: {CalcularSalario():C0}";
}

public class Docente : Empleado
{
    public int HorasSemanales { get; set; }
    public decimal ValorHora { get; set; }

    public Docente(string nombre, decimal salarioBase, int horas, decimal valorHora)
        : base(nombre, salarioBase)
    {
        HorasSemanales = horas;
        ValorHora = valorHora;
    }

    public override decimal CalcularSalario() => HorasSemanales * ValorHora;
}

public class Estudiante
{
    public string Nombre { get; set; }
    public int Edad { get; set; }
    public double[] Notas { get; set; }

    public Estudiante(string nombre, int edad, double[] notas)
    {
        Nombre = nombre;
        Edad = edad;
        Notas = notas;
    }

    public double CalcularPromedio()
    {
        double suma = 0;
        foreach (double nota in Notas)
        {
            suma += nota;
        }
        return Notas.Length == 0 ? 0 : suma / Notas.Length;
    }

    public bool EsAprobado() => CalcularPromedio() >= 3.0;

    public string Presentar() => $"{Nombre} | {Edad} años | Promedio: {CalcularPromedio():F2}";
}

public class Curso
{
    public string Nombre { get; set; }
    public Docente Docente { get; set; }
    public List<Estudiante> Estudiantes { get; set; } = [];

    public Curso(string nombre, Docente docente)
    {
        Nombre = nombre;
        Docente = docente;
    }

    public decimal CalcularPromedioGeneral()
    {
        if (Estudiantes.Count == 0) return 0;

        decimal suma = 0;
        foreach (Estudiante e in Estudiantes)
        {
            suma += (decimal)e.CalcularPromedio();
        }
        return suma / Estudiantes.Count;
    }

    public void MostrarResumen()
    {
        Console.WriteLine($"=== {Nombre} ===");
        Console.WriteLine($"Docente: {Docente.Nombre}");
        foreach (Estudiante e in Estudiantes)
        {
            Console.WriteLine($"  - {e.Presentar()}");
        }
        Console.WriteLine($"Promedio general: {CalcularPromedioGeneral():F2}");
    }
}

✅ Antes de entregar, verifica

  • El proyecto se llama SistemaColegio y corre con dotnet run.
  • Hay 4 clases (Empleado, Docente, Estudiante, Curso) y cada una tiene constructor.
  • Docente hereda de Empleado y usa base(...) en su constructor.
  • Curso contiene a los estudiantes (composición) y calcula el promedio general.
  • El código tiene comentarios que explican cada clase.
  • No hay bloques de código repetidos: si te diste cuenta de que copiaste algo, eso es una señal para crear un método o una clase.
