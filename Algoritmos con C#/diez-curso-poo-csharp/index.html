1️⃣ ¿Qué es la Programación Orientada a Objetos?

⏱️ 30 minutos · 🧠 El cambio de mentalidad más grande del curso

🍳 Dos formas de describir el mundo

Imagina que quieres explicarle a un robot cómo hacer un sándwich. Tienes dos opciones:

  • 📋 Estilo estructurado (receta): "Paso 1: toma dos rebanadas de pan. Paso 2: unta mantequilla. Paso 3: pon jamón..."
  • 🥪 Estilo orientado a objetos (cosas): "Tienes un objeto pan con atributos (tipo, grosor) y un objeto cuchillo con métodos (untar, cortar). Combínalos."

Ambas opciones hacen lo mismo. La diferencia es la mentalidad: en POO piensas en cosas que tienen datos y habilidades.

📖 Las dos filosofías en una frase

🔧 Programación estructurada: "El programa es una secuencia de pasos que transforman datos."

🏗️ Programación orientada a objetos: "El programa es un conjunto de objetos que se envían mensajes entre sí."

🤔 ¿Por qué existe la POO?

En los años 60 y 70, los programas empezaron a hacerse muy grandes. La forma estructurada funcionaba, pero al juntar millones de líneas, todo se volvía un lío imposible de mantener. La POO nació para resolver un problema concreto:

  • 🧩 Reutilizar código: si ya hice un "Auto", no quiero reescribirlo para hacer una "Moto".
  • 📦 Organizar: agrupar datos y funciones que tienen sentido juntas.
  • 🛡️ Proteger: que cada parte solo pueda hacer lo que le corresponde.
  • 🤝 Trabajar en equipo: cada programador hace su "objeto" y luego se conectan.

📜 Una historia rápida

La POO nació con un lenguaje llamado Simula (1967), creado por dos noruegos, Ole-Johan Dahl y Kristen Nygaard, para simular fábricas. Después vino Smalltalk, y mucho más tarde C++ y Java. Hoy casi todo se programa así: videojuegos, apps, páginas web, robots, cohetes. 🚀

🔑 Las 4 ideas centrales de la POO

En esta clase vamos a ver las dos primeras; las otras dos las verás en clases siguientes:

📐

1. Clase y objeto

Una clase es el plano. Un objeto es la casa construida con ese plano.

🔒

2. Encapsulamiento

Ocultar los detalles internos y mostrar solo lo que el objeto necesita compartir.

🧬

3. Herencia

Crear clases nuevas a partir de otras, reutilizando lo que ya existe.

🎭

4. Polimorfismo

El mismo mensaje puede dar respuestas diferentes según el objeto que lo reciba.

👀 Una comparación rápida en código

Mira el mismo problema resuelto de las dos formas. No te preocupes si no entiendes todo: la idea es que veas la diferencia:

❌ Estructurado (datos sueltos y funciones separadas):

// Datos sueltos por ahí
string autoMarca     = "Toyota";
string autoColor     = "Rojo";
int    autoVelocidad = 0;

// Función separada que recibe los datos
void Acelerar(string marca, ref int velocidad, int cantidad)
{
    velocidad = velocidad + cantidad;
    Console.WriteLine(marca + " ahora va a " + velocidad + " km/h");
}

Acelerar(autoMarca, ref autoVelocidad, 20);

✅ Orientado a objetos (datos y funciones juntos, en una sola "caja"):

// Una clase que agrupa datos Y funciones
class Auto
{
    public string marca;
    public int    velocidad;

    public void Acelerar(int cantidad)
    {
        velocidad = velocidad + cantidad;
        Console.WriteLine(marca + " ahora va a " + velocidad + " km/h");
    }
}

// Crear un objeto (una instancia) y usarlo
Auto miAuto = new Auto();
miAuto.marca = "Toyota";
miAuto.Acelerar(20);

¿Ves la diferencia? En POO, los datos (marca, velocidad) y las acciones (Acelerar) viven juntos dentro de la misma "caja" (la clase). Es como tener un control remoto: solo necesitas saber qué botones tiene, no cómo funciona la electrónica interna. 📱

2️⃣ Clases: el plano de construcción

⏱️ 25 minutos · 📐 Tu primer "molde" para crear objetos

📐 La analogía del plano

Un arquitecto no construye una casa dibujándola a mano alzada. Primero hace un plano con todas las medidas. Con ese plano, la constructora puede hacer muchas casas iguales o parecidas.

  • 📐 La clase es el plano
  • 🏠 El objeto (o instancia) es la casa ya construida
  • 🏘️ Con un mismo plano puedes hacer muchas casas diferentes (cada una con su color o su dueño)

🔍 ¿Cómo se ve una clase en C#?

Una clase es, en su forma más simple, una "caja" con un nombre y un cuerpo. Mira el ejemplo más pequeño posible:

class Auto
{
    // Aquí dentro van los atributos y métodos
}

Ya está. Con esas cinco líneas tienes una clase llamada Auto. Todavía no hace nada, pero ya existe como "plano".

🆚 Clase vs Objeto: la diferencia crucial

⚠️ Mucha gente confunde estos dos términos. La diferencia:

Clase = el plano (la definición, la idea). Existe solo en el código fuente.

Objeto = una instancia concreta, creada a partir de la clase. Vive en la memoria del programa.

Para crear un objeto a partir de una clase, usamos la palabra new:

// 1) Definimos la clase (el plano)
class Auto
{
}

// 2) En el Main, creamos objetos a partir de la clase
Auto miAuto    = new Auto();   // objeto 1
Auto tuAuto    = new Auto();   // objeto 2 (¡es independiente!)
Auto autoProfe = new Auto();   // objeto 3

Es como decir: "tengo este plano → constrúyeme una casa. Y otra. Y otra más". Cada new Auto() crea un objeto nuevo, independiente de los demás. 🏘️

🧬 Anatomía de una declaración de clase

Mira este ejemplo con todas sus partes. No te asustes: la mayoría son opcionales y poco a poco las vamos a entender.

[modificadores] class NombreDeLaClase
{
    // atributos (datos)
    // métodos (funciones)
    // constructores
}
  • 📛 NombreDeLaClase: empieza con mayúscula. Por convención, una palabra por nombre (Auto, Estudiante, Libro).
  • 🔧 Modificadores: por ahora usaremos solo public (visible desde cualquier parte).
  • 📦 Las llaves { } delimitan todo lo que pertenece a la clase.

🗂️ Una clase vacía es válida (pero aburrida)

Sí, puedes tener una clase sin nada adentro. En los próximos módulos le vamos a poner atributos y métodos para que cobre vida.

🎨 Reglas de oro para nombrar clases

  • ✅ Empieza con mayúscula: Auto, no auto.
  • ✅ Usa sustantivos (cosas), no verbos: Libro, no Leer.
  • ✅ Si tiene varias palabras, sin espacios: CuentaBancaria, no Cuenta Bancaria.
  • ❌ Evita abreviaturas raras: mejor Estudiante que Est.

3️⃣ Atributos: las características del objeto

⏱️ 20 minutos · 🎨 Los datos que viven dentro de la clase

🎨 La analogía de la ficha técnica

Cuando compras un celular en una tienda, el vendedor te muestra una ficha técnica con cosas como:

  • 📱 Marca: Samsung
  • 🌈 Color: Negro
  • 💾 Almacenamiento: 128 GB
  • 🔋 Batería: 5000 mAh

Esas son las características del celular. En POO se llaman atributos (o propiedades). Son los datos que cada objeto "recuerda" sobre sí mismo.

🧬 Los atributos van dentro de la clase

Para definir un atributo, escribimos su tipo de dato y su nombre dentro de las llaves de la clase:

class Auto
{
    public string marca;       // texto
    public string color;       // texto
    public int    velocidad;   // número entero
    public bool   encendido;   // verdadero o falso
}

Ahora nuestra clase Auto "sabe" que cualquier auto tendrá esos cuatro datos. Cada auto concreto podrá tener valores distintos.

🆕 Dar valores a los atributos

Una vez creado un objeto, le asignamos valores a sus atributos con un punto (.):

Auto miAuto = new Auto();

miAuto.marca     = "Toyota";
miAuto.color     = "Rojo";
miAuto.velocidad = 0;
miAuto.encendido = false;

Console.WriteLine("Mi auto es un " + miAuto.marca + " " + miAuto.color);
// Imprime: Mi auto es un Toyota Rojo

El punto (.) se llama operador de acceso. Se lee como "del objeto, dame el atributo X". En miAuto.marca estás diciendo: "del objeto miAuto, dame la marca". 🎯

🏘️ Cada objeto tiene sus propios valores

La magia de la POO: puedes tener muchos objetos de la misma clase, y cada uno tiene sus propios atributos.

Auto auto1 = new Auto();
auto1.marca = "Toyota";
auto1.color = "Rojo";

Auto auto2 = new Auto();
auto2.marca = "Mazda";
auto2.color = "Azul";

// Son dos autos distintos, con marcas y colores distintos.
Console.WriteLine(auto1.marca);   // Toyota
Console.WriteLine(auto2.marca);   // Mazda

🔐 La palabra public

¿Ves la palabra public antes de cada atributo? Es un modificador de acceso. Por ahora, simplemente recuerda:

  • 🔓 public = "este atributo es visible desde fuera de la clase". Por ahora siempre lo usaremos.
  • 🔒 private = "este atributo está protegido y solo la propia clase puede tocarlo". Lo veremos más adelante.

📊 Tipos de datos más comunes en atributos

🧠 ¿Qué es el "estado" de un objeto?

El estado de un objeto es el conjunto de valores de TODOS sus atributos en un momento dado. Si un auto tiene velocidad=60 y encendido=true, ese es su estado. Cuando llamas a un método, el estado puede cambiar (por ejemplo, la velocidad sube). 🔄

4️⃣ Métodos: lo que el objeto sabe hacer

⏱️ 25 minutos · ⚙️ Las acciones que viven dentro de la clase

🎮 La analogía del control remoto

Piensa en tu celular como un objeto:

  • 📦 Atributos: nivel de batería, color, marca, almacenamiento
  • ⚙️ Métodos: hacer una llamada, sacar una foto, mandar un mensaje, subir el volumen

Los métodos son las acciones que el objeto puede hacer. Y aquí viene lo importante: los métodos pueden usar los atributos del propio objeto.

⚙️ Definir un método dentro de la clase

¿Recuerdas las funciones del curso pasado? Los métodos son exactamente lo mismo, solo que viven dentro de una clase.

class Auto
{
    public string marca;
    public int    velocidad;

    // Este es un método de la clase Auto
    public void Acelerar(int cuanto)
    {
        velocidad = velocidad + cuanto;
        Console.WriteLine(marca + " va a " + velocidad + " km/h");
    }
}

Fíjate en velocidad = velocidad + cuanto;: el método está usando el atributo velocidad del propio objeto. No necesita que se lo pasemos, ya lo "conoce" porque está dentro de la misma clase. 🎯

📞 Llamar a un método

Para usar un método de un objeto, usamos otra vez el operador punto (.):

Auto miAuto = new Auto();
miAuto.marca = "Toyota";

miAuto.Acelerar(20);   // imprime: Toyota va a 20 km/h
miAuto.Acelerar(30);   // imprime: Toyota va a 50 km/h

Se lee: "del objeto miAuto, llama al método Acelerar con 20". 🚀

📦 Tipos de métodos

Igual que las funciones, los métodos pueden:

  • 📢 Ser void: hacen algo pero no devuelven nada.
  • 📤 Devolver un valor: int, string, bool, etc.
  • 📥 Recibir parámetros (o no).

Ejemplo completo: una clase con varios métodos

class Auto
{
    public string marca;
    public string color;
    public int    velocidad;
    public bool   encendido;

    public void Encender()
    {
        if (encendido)
            Console.WriteLine("El auto ya estaba encendido 💡");
        else
        {
            encendido = true;
            Console.WriteLine("¡Brum brum! " + marca + " encendido.");
        }
    }

    public void Acelerar(int cuanto)
    {
        velocidad = velocidad + cuanto;
        Console.WriteLine(marca + " ahora va a " + velocidad + " km/h");
    }

    public string Describir()
    {
        return marca + " " + color + " a " + velocidad + " km/h";
    }
}

🔍 Diferencia entre "función" y "método"

Técnicamente, una función que vive suelta (fuera de una clase) y un método que vive dentro de una clase son cosas parecidas. En C# casi todo son métodos, porque hasta el Main está dentro de una clase. Así que si oyes "función" o "método", piensa que es la misma idea: un bloque de código con nombre. 🧠

🎯 Los métodos pueden llamarse entre sí

Un método puede llamar a otro método del mismo objeto sin necesidad de usar el punto:

class Estudiante
{
    public string nombre;
    public double nota1, nota2, nota3;

    public double CalcularPromedio()
    {
        return (nota1 + nota2 + nota3) / 3;
    }

    public void MostrarReporte()
    {
        double prom = CalcularPromedio();   // llama a otro método del mismo objeto
        Console.WriteLine(nombre + " tiene promedio: " + prom);
    }
}

5️⃣ Constructores: cómo nacen los objetos

⏱️ 20 minutos · 🎂 La "ceremonia de nacimiento" de cada objeto

👶 La analogía del nacimiento

Cuando un bebé nace, alguien tiene que decidir su nombre, registrarlo, pesarlo, medirlo. Esos datos "iniciales" son los que se asignan en el momento exacto de nacer.

Un constructor hace exactamente eso con los objetos: es un método especial que se ejecuta automáticamente cuando haces new. Sirve para que el objeto nazca ya con sus datos importantes. 👶

🆕 El constructor "por defecto" (que ya viene gratis)

Si no escribes ningún constructor, C# crea uno invisible que no recibe parámetros. Por eso new Auto() ha funcionado hasta ahora.

Pero escribir tu propio constructor te da control: puedes obligar a que todos los objetos nazcan con datos obligatorios.

✍️ Escribir tu primer constructor

Un constructor se ve así:

class Estudiante
{
    public string nombre;
    public int    edad;
    public string grado;

    // 👇 Este es el constructor
    public Estudiante(string n, int e, string g)
    {
        nombre = n;
        edad   = e;
        grado  = g;
    }
}

Características de un constructor:

  • ✅ Se llama igual que la clase (en este caso, Estudiante).
  • ✅ No devuelve nada (ni siquiera void).
  • ✅ Se ejecuta automáticamente cuando escribes new.

🎂 Usar el constructor al crear el objeto

Ahora, para crear un estudiante, tienes que pasarle los datos:

// ANTES (con el constructor por defecto)
Estudiante ana = new Estudiante();
ana.nombre = "Ana";      // 👈 tres líneas extra
ana.edad   = 16;          // 👈
ana.grado  = "10°";       // 👈

// AHORA (con tu propio constructor)
Estudiante ana = new Estudiante("Ana", 16, "10°");  // ¡una sola línea!

👀 Mucho más limpio, ¿no? Y además te aseguras de que nadie pueda crear un estudiante sin nombre, sin edad o sin grado.

🔁 Sobrecarga: varios constructores para la misma clase

En C# puedes tener varios constructores en la misma clase, siempre que reciban distintos parámetros. Esto se llama sobrecarga (overloading).

class Estudiante
{
    public string nombre;
    public int    edad;
    public string grado;

    // Constructor 1: con todos los datos
    public Estudiante(string n, int e, string g)
    {
        nombre = n;
        edad   = e;
        grado  = g;
    }

    // Constructor 2: solo con el nombre (los demás quedan "por defecto")
    public Estudiante(string n)
    {
        nombre = n;
        edad   = 0;
        grado  = "Sin asignar";
    }
}

Ahora puedes crear estudiantes de dos formas:

Estudiante ana   = new Estudiante("Ana", 16, "10°");
Estudiante nuevo = new Estudiante("Sin nombre aún");

🔑 La palabra this (opcional pero útil)

Cuando un parámetro se llama igual que un atributo, podemos usar this para aclarar cuál es cuál:

class Estudiante
{
    public string nombre;
    public int    edad;

    public Estudiante(string nombre, int edad)
    {
        this.nombre = nombre;   // this.nombre = el atributo del objeto
        this.edad   = edad;     // edad (a la derecha) = el parámetro
    }
}

Se lee: "el atributo nombre de este objeto (this) recibe el valor del parámetro nombre". Útil cuando los nombres se repiten, aunque muchos principiantes lo evitan simplemente usando nombres diferentes en los parámetros. 🧹

🚗 Clase 2: Auto

using System;

class Auto
{
    public string marca;
    public string color;
    public int    velocidad;
    public bool   encendido;

    public Auto(string marca, string color)
    {
        this.marca     = marca;
        this.color     = color;
        this.velocidad = 0;
        this.encendido = false;
    }

    public void Encender()
    {
        if (!encendido)
        {
            encendido = true;
            Console.WriteLine("🔑 ¡Brum brum! " + marca + " encendido.");
        }
        else
        {
            Console.WriteLine("Ya estaba encendido 💡");
        }
    }

    public void Apagar()
    {
        if (velocidad > 0)
        {
            Console.WriteLine("⚠️ Detén el auto primero");
            return;
        }
        encendido = false;
        Console.WriteLine("🔇 " + marca + " apagado.");
    }

    public void Acelerar(int cuanto)
    {
        if (!encendido)
        {
            Console.WriteLine("❌ Enciende el auto antes");
            return;
        }
        velocidad = velocidad + cuanto;
        Console.WriteLine("💨 " + marca + " ahora va a " + velocidad + " km/h");
    }

    public void Frenar(int cuanto)
    {
        velocidad = velocidad - cuanto;
        if (velocidad < 0) velocidad = 0;
        Console.WriteLine("🛑 " + marca + " frenó a " + velocidad + " km/h");
    }

    public void TocarBocina()
    {
        Console.WriteLine("📣 ¡PIP PIP! (" + marca + " " + color + ")");
    }
}

📚 Clase 3: Libro

using System;

class Libro
{
    public string titulo;
    public string autor;
    public int    paginas;
    public int    leidas;

    public Libro(string titulo, string autor, int paginas)
    {
        this.titulo  = titulo;
        this.autor   = autor;
        this.paginas = paginas;
        this.leidas  = 0;
    }

    public void Leer(int cantidad)
    {
        if (leidas + cantidad > paginas)
        {
            cantidad = paginas - leidas;
            Console.WriteLine("📖 Solo te quedan " + cantidad
                              + " páginas por leer");
        }
        leidas = leidas + cantidad;
        Console.WriteLine("📖 Has leído " + cantidad
                          + " páginas de " + titulo);
    }

    public double ObtenerProgreso()
    {
        return (leidas * 100.0) / paginas;
    }

    public bool EstaTerminado()
    {
        return leidas >= paginas;
    }

    public void MostrarInfo()
    {
        Console.WriteLine("📕 " + titulo + " — " + autor);
        Console.WriteLine("   Progreso: " + leidas + "/" + paginas
                          + " (" + ObtenerProgreso().ToString("F1") + "%)");
        if (EstaTerminado())
            Console.WriteLine("   ✅ ¡Terminado!");
        else
            Console.WriteLine("   ⏳ Te faltan " + (paginas - leidas)
                              + " páginas");
    }
}

    l.Leer(30);

    l.MostrarInfo();
}

using System;

class Mascota
{
    public string nombre;
    public string tipo;
    public int    energia;

    public Mascota(string nombre, string tipo, int energia)
    {
        this.nombre  = nombre;
        this.tipo    = tipo;
        this.energia = energia;
    }

        if (energia < 0) energia = 0;

8️⃣ 🧩 Análisis: estructurado vs orientado a objetos

⏱️ 20 minutos · 🪞 El mismo problema, dos estilos

🪞 Una comparación honesta

Ya tienes clara la POO. Ahora vamos a comparar las dos formas de resolver el mismo problema para que veas con tus propios ojos las diferencias. Spoiler: ambas funcionan, pero la POO escala mejor cuando los programas crecen. 🏗️

📋 El problema

Supongamos que queremos representar a 3 estudiantes con sus notas, calcular el promedio de cada uno y decir si aprobó. Un problema pequeño, fácil de leer. 👀

❌ Versión estructurada (variables sueltas y funciones)

// 1) Datos sueltos por todos lados
string e1Nombre = "Ana";
int    e1Edad   = 16;
double e1Nota1  = 4.5;
double e1Nota2  = 3.8;
double e1Nota3  = 4.2;

string e2Nombre = "Juan";
int    e2Edad   = 17;
double e2Nota1  = 2.5;
double e2Nota2  = 3.0;
double e2Nota3  = 2.8;

string e3Nombre = "Sofía";
int    e3Edad   = 16;
double e3Nota1  = 4.8;
double e3Nota2  = 5.0;
double e3Nota3  = 4.7;

// 2) Funciones que reciben cada dato por separado 😱
double CalcularPromedio(double n1, double n2, double n3)
{
    return (n1 + n2 + n3) / 3;
}

string ObtenerEstado(double promedio)
{
    if (promedio >= 3.0) return "Aprobado";
    return "Reprobado";
}

void MostrarEstudiante(string nombre, int edad,
                       double n1, double n2, double n3)
{
    double prom = CalcularPromedio(n1, n2, n3);
    Console.WriteLine(nombre + " (" + edad + " años): "
                      + prom + " — " + ObtenerEstado(prom));
}

// 3) Main lleno de llamadas feas
public static void Main()
{
    MostrarEstudiante(e1Nombre, e1Edad, e1Nota1, e1Nota2, e1Nota3);
    MostrarEstudiante(e2Nombre, e2Edad, e2Nota1, e2Nota2, e2Nota3);
    MostrarEstudiante(e3Nombre, e3Edad, e3Nota1, e3Nota2, e3Nota3);
}

👀 ¿Ves el problema? Las variables de cada estudiante están mezcladas con las de los demás. Si quisieras agregar un cuarto estudiante, tienes que crear 5 variables más con nombres diferentes. Las funciones reciben 5 parámetros. Es un caos. 😵

✅ Versión orientada a objetos (una clase por concepto)

class Estudiante
{
    public string nombre;
    public int    edad;
    public double nota1, nota2, nota3;

    public Estudiante(string n, int e, double n1, double n2, double n3)
    {
        nombre = n;
        edad   = e;
        nota1  = n1;
        nota2  = n2;
        nota3  = n3;
    }

    public double CalcularPromedio()
    {
        return (nota1 + nota2 + nota3) / 3;
    }

    public string ObtenerEstado()
    {
        if (CalcularPromedio() >= 3.0) return "Aprobado";
        return "Reprobado";
    }

    public void Presentarse()
    {
        Console.WriteLine(nombre + " (" + edad + " años): "
                          + CalcularPromedio()
                          + " — " + ObtenerEstado());
    }
}

public static void Main()
{
    Estudiante ana   = new Estudiante("Ana",   16, 4.5, 3.8, 4.2);
    Estudiante juan  = new Estudiante("Juan",  17, 2.5, 3.0, 2.8);
    Estudiante sofia = new Estudiante("Sofía", 16, 4.8, 5.0, 4.7);

    ana.Presentarse();
    juan.Presentarse();
    sofia.Presentarse();
}

¿Ves la diferencia? Cada estudiante es un objeto. Si quieres añadir uno nuevo, solo creas otro objeto. No tienes que inventar 5 variables nuevas, ni cambiar las funciones, ni reordenar nada. 🪄

⚖️ La comparación directa

AspectoEstructuradoOrientado a objetos
Cómo se organizaVariables sueltas y funciones separadasDatos y funciones juntos en "objetos"
Añadir un estudiante másCrear 5 variables nuevas con nombres diferentesCrear un nuevo objeto con new
Las funcionesReciben muchos parámetrosUsan los atributos del propio objeto
Escala (muchos datos)Se vuelve un caos rápidoSigue siendo ordenado
Para aprenderMás fácil al principioMás natural a largo plazo
Ideal paraProgramas pequeños y scriptsSoftware grande y de equipo

💡 Una analogía final

La programación estructurada es como tener tu ropa mezclada en una caja grande: un pantalón por aquí, un calcetín por allá. Funciona. La POO es como tener un cajón para camisas, otro para pantalones, otro para medias. Es la misma ropa, pero ahora todo está donde debe estar. 👕👖🧦
