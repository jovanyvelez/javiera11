💡 ¿Por qué importa tanto el tipo?

En C# el tipo no es solo una etiqueta: es una promesa. Si declaras int edad, el compilador te promete que ahí solo cabe un número entero y que siempre habrá valor. Esa promesa es la que te salva de los bugs más caros de la programación, y por eso C# se llama un lenguaje de tipado estático.

📦 Declarar variables: la caja con etiqueta

⏱️ 30 minutos · "Cada dato merece su propia caja"

🧠 ¿Qué es una variable?

Una variable es un pedazo de memoria con nombre donde guardas un dato para usarlo más tarde. Piénsala como una caja etiquetada en un depósito: la etiqueta dice qué tipo de cosa cabe (números, texto, sí/no) y qué tan grande es la caja. En la etiqueta también va el nombre, para poder encontrar la caja después sin adivinar.

En C# la etiqueta se escribe con dos palabras: el tipo y el nombre. Y como todo dato guardado, hay que declararlo (decidir su tipo y su nombre) e inicializarlo (darle el primer valor).

csharp — declarar e inicializar variables 
// Declarar E inicializar en una sola línea (lo normal).
int edad = 17;
double altura = 1.72;
string nombre = "María";

// Declarar primero e inicializar después: también es válido.
int asistencia;
asistencia = 20;

// Los textos se escriben entre comillas dobles, los caracteres entre comillas simples.
char inicial = 'M';

// Interpolación: el $ permite meter variables dentro del texto.
Console.WriteLine($"Nombre: {nombre}, edad: {edad}, altura: {altura}");
Console.WriteLine($"Inicial: {inicial} · Asistencia: {asistencia} clases");

💡 Declarar ≠ Inicializar

Declarar es poner la etiqueta: "aquí hay una caja para enteros llamada edad". Inicializar es abrir la caja y meter el primer valor: edad = 17. En C# el compilador te obliga a inicializar antes de usar una variable local: si escribes Console.WriteLine(edad); sin haberle puesto valor, el programa ni compila.

🦹 El villano: ¿por qué C# es de tipado estático?

"Estático" significa que el tipo se decide antes de que el programa ejecute, mientras compila. Si declaras int edad, el compilador ya sabe que ahí solo hay enteros: no te deja meter texto, no te deja restarlo de una cadena y te avisa antes de que el programa corra. Eso se llama comprobación de tipos en tiempo de compilación, y es la razón por la que los programas en C# se rompen menos.

El precio: tienes que declarar el tipo. Pero el beneficio es enorme, y por eso la mayoría de lenguajes modernos (TypeScript, Kotlin, Swift, Rust) hacen lo mismo.

🔢 Números y decimal: cuánto cabe en la caja

⏱️ 35 minutos · "El número que eliges decide lo que pasa después"

🧠 No todos los números son iguales

En la vida real usas números para cosas muy distintas: la cantidad de personas en el salón, la temperatura, el peso de un paquete, el precio de un celular. Cada uso necesita precisión y rango distintos, así que C# te da una caja distinta para cada caso. Elegir mal la caja no es "casi lo mismo": es la causa de los errores de redondeo en las cuentas y de los desbordamientos que rompen el programa.

csharp — sufijos: le dices a C# qué tipo quieres 
// Sufijos: le dicen a C# qué tipo quieres exactamente.
int entero = 10;
long grande = 10L;
double real = 10.5;
float flotante = 10.5f;
decimal dinero = 10.5m;

// Sin sufijo, un número con decimal es double; con "m" es decimal.
Console.WriteLine($"double  10.5  = {10.5}");
Console.WriteLine($"float   10.5f = {10.5f}");
Console.WriteLine($"decimal 10.5m = {10.5m}");

// También se puede escribir un entero en otras bases.
int binario = 0b1010;       // 10 en base 2
int hexadecimal = 0xFF;     // 255 en base 16
Console.WriteLine($"0b1010 = {binario} · 0xFF = {hexadecimal}");

💰 El gran debate: ¿double o decimal?

Usa decimal para dinero. Los double guardan el número en base 2 (binario), y muchos decimales —como 0.1— no se pueden representar exactamente: son como la letra "A" que en un tablero de ajedrez de 8×8 no cabe. El decimal guarda el número en base 10, exactamente como lo escribes tú, y por eso suma 0.1m + 0.2m dando 0.3m sin sorpresas.

Regla práctica: double para física, gráficos y aproximaciones; decimal para precios, salaries y porcentajes de dinero; int para contar cosas.

csharp — checked y unchecked: el desbordamiento 
int maximo = int.MaxValue;
Console.WriteLine($"int.MaxValue = {maximo}");

// UNCHECKED (es el comportamiento por defecto): la cuenta "da la vuelta"
// y el programa sigue como si nada. ¡Cuidado con esto!
int desbordado = unchecked(maximo + 1);
Console.WriteLine($"unchecked → {desbordado}");

// CHECKED: el desbordamiento lanza OverflowException y te avisa.
try
{
    int controlado = checked(maximo + 1);
    Console.WriteLine(controlado);
}
catch (OverflowException)
{
    Console.WriteLine("¡Overflow! checked detectó que el valor no cabe en un int.");
}

// Si el dato es grande de verdad, usa long: ahí sí cabe.
long enorme = (long)maximo + 1;
Console.WriteLine($"En long sí cabe: {enorme}");

💡 Truco: pon siempre el sufijo

Escribes decimal total = 1000m; y no decimal total = 1000;. Aunque C# te dejaría compilarlo (convierte el entero sin problema), con el sufijo m queda clarísimo de un vistazo que esa caja es de decimal y nadie lo confunde con un int.

🔤 Texto y booleanos: letras, frases y sí/no

⏱️ 30 minutos · "Lo que escribes, el computador lo cuenta"

🧠 Tres cajas para el lenguaje

char es una sola letra (o símbolo): la inicial de tu nombre, la letra de un turno. string es una frase completa: tu nombre, un mensaje, un código de barras. bool es una respuesta de sí o no: ¿aprobaste?, ¿es mayor de edad?, ¿el usuario sigue conectado?

csharp — char, string y bool 
// char: UNA sola letra, entre comillas simples.
char inicial = 'M';
char grado = 'A';

// string: una frase, entre comillas dobles.
string nombre = "María";
string gradoTexto = "11°";

// bool: solo true o false (en minúscula, sin comillas).
bool aprobado = true;
bool mayorDeEdad = false;

Console.WriteLine($"Inicial: {inicial} (código {((int)inicial)})");
Console.WriteLine($"Nombre: {nombre} · Grado: {gradoTexto}");
Console.WriteLine($"Largo del nombre: {nombre.Length} caracteres");
Console.WriteLine($"¿Aprobó? {aprobado} · ¿Mayor de edad? {mayorDeEdad}");

// Concatenación clásica con + (la vieja forma).
string saludo = "Hola, " + nombre + "!";
Console.WriteLine(saludo);

💡 La diferencia entre `'M'` y "M"

Las comillas simples son para char (un carácter). Las comillas dobles son para string (texto). Si escribes char c = "M"; el compilador te regaña: el tipo no calza. Y ojo: '11°' tampoco es un char válido, porque tiene tres caracteres: para eso usas string.

🎨 Tres maneras de escribir texto

csharp — interpolada, verbatim y cruda 
// 1. INTERPOLADA ($): la modernita. Mete variables dentro del texto.
string nombre = "Ana";
int edad = 17;
Console.WriteLine($"Hola {nombre}, tienes {edad} años.");

// 2. VERBATIM (@): desactiva los escapes. Ideal para rutas de Windows.
string ruta = @"C:\Users\Ana\Documentos";
Console.WriteLine(ruta);

// Para poner comillas dobles dentro, se repiten: ""Hola""
// string frase = @"Ella dijo: ""¡Hola!""";

// 3. CRUDA ("""): comillas triples, sin escapes, con saltos de línea reales.
// Sirve para textos largos como un menú o una plantilla.
string menu = """
    === TIENDA ESCOLAR ===
    1) Cuadernos
    2) Lápices
    """;
Console.WriteLine(menu);

🦹 El villano: el string es INMUTABLE

Un string en C# no se puede modificar. Cada vez que "cambias" un texto, en realidad C# crea una cadena nueva en memoria. Por eso miTexto[0] = 'X'; da error de compilación: estás intentando modificar algo que es de solo lectura.

Esto no es un defecto: hace que los textos sean seguros de compartir. Pero si vas a concatenar miles de veces (en un bucle), el rendimiento se cae. Para eso existe StringBuilder, que sí es mutable y guarda todo en un solo búfer.

csharp — StringBuilder para concatenar muchas veces 
// Concatenar con + dentro de un bucle: crea una cadena nueva cada vuelta.
string lista = "";
for (int i = 1; i <= 5; i++)
{
    lista += i + " ";
}
Console.WriteLine($"Con +: {lista}");

// StringBuilder: un solo búfer que va creciendo. Es la forma eficiente.
var builder = new System.Text.StringBuilder();
for (int i = 1; i <= 5; i++)
{
    builder.Append(i).Append(" ");
}
Console.WriteLine($"Con StringBuilder: {builder}");

🧠 var y los tipos inferidos

⏱️ 35 minutos · "var no es 'cualquier cosa': es el compilador adivinando bien"

🦹 El gran malentendido: var NO es "cualquier cosa"

Mucha gente cree que var significa "ponle el tipo que quieras". Falso. var es inferencia de tipo: el compilador mira el valor inicial y deduce el tipo exacto. C# sigue siendo de tipado estático: por dentro, var edad = 17; es exactamente lo mismo que int edad = 17;. Solo le estás diciendo al compilador "dedúcelo tú".

csharp — var: el compilador deduce el tipo 
// var NO es "cualquier cosa": el compilador deduce el tipo ESTÁTICO.
var edad = 17;              // deduce: int
var precio = 19999.5;       // deduce: double
var nombre = "Camilo";      // deduce: string
var aprobado = true;        // deduce: bool
var saldo = 1500.75m;       // deduce: decimal

// Esto NO compila: sin valor inicial no hay nada de dónde deducir el tipo.
// var contador;        ← error CS0815

// Y esto tampoco: el tipo queda fijado para siempre.
// edad = "diecisiete";        ← error CS0029

Console.WriteLine($"{edad} · {precio} · {nombre} · {aprobado} · {saldo}");
csharp — object, dynamic y boxing 
// object: el comodín. Puede guardar cualquier cosa, pero pierdes la seguridad de tipos.
object dato = 42;
Console.WriteLine(dato.GetType().Name);   // Int32

object caja = numero;

Console.WriteLine(typeof(int).Name);       // Int32
Console.WriteLine(nameof(Console));        // Console

// Regla de oro: en un proyecto real casi nunca se usa dynamic.

💡 ¿Cuándo usar var y cuándo no?

Úsalo cuando el tipo es evidente a simple vista: var lista = new List<int>(); (el tipo es larguísimo y ya lo estás diciendo). No lo uses cuando el tipo quede escondido: si lees var total = 0; no sabes si es int, double o decimal — y para dinero esa diferencia importa. La regla de oro de Microsoft: si no puedes deducir el tipo leyendo la línea, escribe el tipo.

🛡️ Nullables y conversiones: cuando el dato todavía no existe

⏱️ 35 minutos · "La caja vacía y el truco del ?"

🧠 El problema de la caja vacía

null significa "no hay valor". El problema es que en los años 2000 C# no te avisaba: podías escribir Console.WriteLine(nombre.Length); con nombre en null y el programa se caía con un NullReferenceException en la mitad de la ejecución. Hoy C# te avisa mientras compila si declaras que algo puede ser null, y te da herramientas para manejarlo sin romperse.

csharp — null, ??, ??= y ?. 
// NULL: la variable todavía no tiene valor.
string? nombre = null;
int? edad = null;

Console.WriteLine($"nombre es null: {nombre is null}");
Console.WriteLine($"edad es null: {edad is null}");

// ?? (null-coalescing): si la izquierda es null, usa la derecha.
Console.WriteLine($"Hola, {nombre ?? "visitante"}");

// ??= (null-coalescing assignment): asigna SOLO si era null.
nombre ??= "Ana";
Console.WriteLine($"Ahora el nombre es: {nombre}");

// ?. (null-conditional): la llamada solo ocurre si el objeto NO es null.
Console.WriteLine($"Largo del nombre: {nombre?.Length}");
csharp — Nullable<T>: el int que puede no existir 
// int? es, por dentro, un Nullable<int>: un int que puede no tener valor.
int? edad = null;
Console.WriteLine($"HasValue: {edad.HasValue}");

edad = 17;
Console.WriteLine($"HasValue: {edad.HasValue} · Value: {edad.Value}");

// GetValueOrDefault evita el ".Value" cuando puede ser null.
int? vacio = null;
Console.WriteLine($"Por defecto: {vacio.GetValueOrDefault()}");
Console.WriteLine($"Por defecto con alternativa: {vacio.GetValueOrDefault(18)}");

// Cuidado: pedir ".Value" a un int? que es null lanza InvalidOperationException.
// int peligroso = vacio.Value;   ← no lo hagas sin revisar HasValue
csharp — int.TryParse: leer sin romperse 
// TryParse: pregunta "¿esto es un número?" y NO rompe el programa.
Console.Write("Escribe tu edad: ");
string entrada = Console.ReadLine() ?? "";

if (int.TryParse(entrada, out int edad))
{
    Console.WriteLine($"Edad registrada: {edad}");
}
else
{
    Console.WriteLine("Eso no es un número válido.");
}

// Ojo: si no usas el valor, el compilador se queja (warning CS0219).
// En ese caso escribe: _ = int.TryParse(entrada, out _);
// TryParse devuelve true/false y además entrega el número convertido.
csharp — C# 14: la palabra clave field y la asignación con ??= 
// Operador ??= (C# 8 en adelante): si la variable es null, asígnale este valor.
// Evita el clásico "if (x is null) { x = valor; }"
Persona? persona = null;
persona ??= new Persona("Ana", 17);
Console.WriteLine($"Nombre: {persona.Nombre}");   // Ana

// C# 14: la palabra clave "field" guarda el valor real de una propiedad.
var termometro = new Termometro { Celsius = 36.6 };
Console.WriteLine($"Celsius: {termometro.Celsius}");

public class Persona
{
    public string Nombre { get; }
    public int Edad { get; set; }

    public Persona(string nombre, int edad)
    {
        Nombre = nombre;
        Edad = edad;
    }

public class Termometro
{
    public double Celsius
    {
        get;
        set
        {
            if (value < -273.15)
            {
                throw new ArgumentOutOfRangeException(nameof(value));
            }
            field = value;   // aquí vive el valor real de la propiedad
        }
    }
}

💡 Truco: int.TryParse es tu mejor amigo

Siempre que leas un número del teclado usa TryParse en vez de Parse. Parse lanza FormatException si el usuario escribe "hola" y el programa se cae; TryParse te devuelve false y tú decides qué hacer. Es la diferencia entre un programa que se cae y uno que sigue politely. 🤝

🛠️ Taller: La Caja del Estudiante

⏱️ 45 minutos · "Aplica todo lo aprendido"

🛠️ Taller final La Caja del Estudiante

En el colegio hay una pequeña tienda que vende cuadernos y lápices. Tu misión: construir CajaEstudiante, una aplicación de consola que pida los datos de la compra, calcule el total con descuento e IVA, y que nunca se caiga aunque el usuario escriba basura. Aquí se juntan int, decimal, double, string, bool, char, TryParse y ??.

📋 Requisitos del taller

  1. Crea el proyecto: dotnet new console -n CajaEstudiante y ábrelo en VS Code (code .).
  2. Pide el nombre del estudiante (string), la cantidad de cuadernos (int) y la cantidad de lápices (int).
  3. Usa int.TryParse para leer las cantidades: si el usuario escribe algo que no es número, avisa y usa 0 en vez de romperte.
  4. Pregunta si el cliente tiene cupón de descuento y guárdalo en un bool (respuesta "s" o "n").
  5. Usa const para los precios (decimal) y para el porcentaje del IVA y del descuento.
  6. Calcula: subtotal, descuento (15 % si tiene cupón), base imponible, IVA (19 %) y total.
  7. Muestra todo con interpolación, y el total con el formato {total:N0} para que se vea con separadores de miles.
  8. Agrega la inicial del nombre (char) y el precio promedio por artículo (double) en el resumen.
  9. Ejecuta con dotnet run y pruébalo con datos válidos, con una cantidad inválida ("abc") y sin cupón.
csharp — guía de estilo (no es la solución, es el molde)

// LA CAJA DEL ESTUDIANTE
// Tienda escolar: total de la compra con descuento e IVA.

// Constantes: los precios NUNCA cambian.

csharp — solución del taller 
// ============================================
// LA CAJA DEL ESTUDIANTE — solución del taller
// Tienda escolar: total de la compra con descuento e IVA.
// ============================================

const decimal PrecioCuaderno = 3500m;
const decimal PrecioLapiz = 800m;
const decimal PorcentajeDescuento = 0.15m;
const decimal IVA = 0.19m;

Console.WriteLine("=== LA CAJA DEL ESTUDIANTE ===");

// ---------- 1. ENTRADA ----------
Console.Write("Nombre del estudiante: ");
string nombre = Console.ReadLine() ?? "";

Console.Write("Cantidad de cuadernos: ");
int cuadernos = 0;
if (!int.TryParse(Console.ReadLine(), out cuadernos))
{
    Console.WriteLine("Dato inválido: se asume 0 cuadernos.");
}

Console.Write("Cantidad de lápices: ");
int lapices = 0;
if (!int.TryParse(Console.ReadLine(), out lapices))
{
    Console.WriteLine("Dato inválido: se asumen 0 lápices.");
}

Console.Write("¿Tiene cupón de descuento? (s/n): ");
string cupon = (Console.ReadLine() ?? "").Trim().ToLower();
bool tieneCupon = cupon == "s";

// ---------- 2. PROCESO ----------
decimal subtotal = (cuadernos * PrecioCuaderno) + (lapices * PrecioLapiz);
decimal descuento = tieneCupon ? subtotal * PorcentajeDescuento : 0m;
decimal baseImponible = subtotal - descuento;
decimal iva = baseImponible * IVA;
decimal total = baseImponible + iva;

int articulos = cuadernos + lapices;
double precioPromedio = articulos > 0 ? (double)total / articulos : 0;
char inicial = string.IsNullOrWhiteSpace(nombre) ? '?' : char.ToUpper(nombre[0]);

// ---------- 3. SALIDA ----------
Console.WriteLine("------------------------------");
Console.WriteLine($"Cliente: {nombre} ({inicial})");
Console.WriteLine($"Artículos:      {articulos}");
Console.WriteLine($"Subtotal:      {subtotal:N0} COP");
Console.WriteLine($"Descuento 15%: -{descuento:N0} COP");
Console.WriteLine($"IVA 19%:        {iva:N0} COP");
Console.WriteLine($"TOTAL:         {total:N0} COP");
Console.WriteLine($"Promedio:      {precioPromedio:N0} COP por artículo");
Console.WriteLine("------------------------------");
